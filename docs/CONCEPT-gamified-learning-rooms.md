> מסמך קונספט, טיוטה 1 (2026-11-02). לא נבנה עדיין שום קוד. השאלות הפתוחות בסוף המסמך קובעות את הגרסה הסופית.

| נושא | החלטה |
|---|---|

## 1. הרעיון במשפט אחד

כל Learning Room הופך ל"מבצע": עולם תלת-ממדי מעוצב לפי הנושא, שבו התלמיד עובר מתחנה לתחנה, כל תחנה היא מכניקה אינטראקטיבית (לא "קרא ולחץ הבא"), ובסוף יש "אירוע מסכם" ותחקיר. התוכן הקיים (108+ חדרים, 9 סוגי משימות, ניקוד בצד השרת) נשאר כמו שהוא; אנחנו מוסיפים מעליו שכבת חוויה.

**רמת ה-UX/UI** שמכוונים אליה: כמו בצילומי המסך ששלחת (Hub תלת-ממדי, דמויות, טיימר, יהלומי חיים, פופ-אפ "למה טעית"). **הקונספט עצמו מקורי ל-HACK THE SOC**: לא מעתיקים את הזירה העגולה, השמות או המבנה של המוצר שבתמונות, אלא בונים שפה ויזואלית משלנו שמתאימה לעולם ה-SOC.

## 2. העיקרון הפדגוגי (לא מתפשרים עליו)

1. **מכניקה משרתת את הנושא.** משחק שבו "מזיזים קלפים" על נושא שדורש קריאת לוג הוא קישוט. כל מכניקה חייבת לחקות פעולה אמיתית של אנליסט (לסמן שדה בלוג כראיה, לאשר/לדחות בקשה, לבנות ציר זמן).
2. **כל טעות מלמדת.** אחרי כל שגיאה: למה טעית + מה הרמז שפספסת בלוג (כמו "Should have DENIED" בתמונה, אבל עם הצבעה על השדה הספציפי).
3. **שער שליטה 65% נשמר.** הגיימיפיקציה לא עוקפת את ה-mastery gate ולא מנפחת XP. ה-XP נשאר server-authoritative.
4. **התשובות לא מגיעות לדפדפן.** כל מכניקה חדשה (כולל hotspot/לחיצה על שדה) נבדקת בצד השרת, כמו היום.
5. **מצב קלאסי תמיד זמין.** נגישות WCAG AA, `prefers-reduced-motion`, מחשבי מעבדה חלשים במכללות: כפתור "מצב קלאסי" מחזיר לנגן הנוכחי, עם אותה התקדמות.

## 3. מבנה החוויה (4 שכבות)

```
מפת המערכה (Campaign Map)
  └─ מבצע = חדר (Operation Hub, תלת-ממדי, מעוצב לנושא)
       ├─ תדריך פתיחה (Briefing) + [סרטון 4-8 שנ', שלב מאוחר]
       ├─ תחנה 1..N  (כל תחנה = 1-4 משימות קיימות, מכניקה אחת)
       ├─ אירוע מסכם (Boss Incident): משימה משולבת בלחץ זמן
       └─ תחקיר (Debrief): כוכבים, מה נלמד, מה לחזק, CTA לדשבורד
```

### 3.1 מפת המערכה
במקום רשימת כרטיסים ב-`/rooms`: "בניין ה-SOC" או מפת עולם, שבה כל מסלול (Foundation, Network, Endpoint, Cloud, Identity...) הוא אזור, וכל חדר הוא נקודה. נעול / זמין / הושלם (1-3 כוכבים). נגזר ישירות מ-`isRoomLocked` ומ-`room_progress` הקיימים.

### 3.2 ה-Hub של מבצע: "המסלול" (עודכן 2026-11-02)
במקום זירה עגולה (שהזכירה מדי את המוצר בתמונות), ה-Hub הוא **רחוב איזומטרי**: כל תחנה היא **בניין** אחר לאורך כביש מתפתל (ארכיון, מפעל מיון, מעבדה, משרד, כספת), ו**מעטפה זוהרת נוסעת על הכביש** אל התחנה הפתוחה הבאה. ההתקדמות נראית כמו מסע, לא כמו תפריט. בניין נעול כהה, בניין פתוח מאיר ופועם, בניין שנוקה מואר בירוק עם כוכבים. לחיצה על בניין = זום אליו. סוגי הבניינים (`BuildingKind`) משותפים לכל החדרים, כך שחדר חדש בוחר בניינים ולא בונה סצנה.

### 3.3 ה-HUD הקבוע
- **Integrity** (3 מגינים): טעות מורידה מגן. אובדן כל המגינים = התחנה מתאפסת (לא כל החדר).
- מונה התקדמות ("Evidence 2/6").
- טיימר אופציונלי, רק באירוע המסכם וברמות intermediate+.
- **Intel tokens**: רמזים שנרכשים בקריאת תדריכים, ומוציאים אותם בתחנות קשות. כך הקריאה מקבלת ערך משחקי במקום להיות "מחסום".
- סאונד אווירה + כפתור השתקה, כפתור "?" עם הסבר המכניקה.

## 4. ספריית מכניקות (מיפוי לסוגי המשימות הקיימים)

היתרון הגדול: **כל 9 סוגי המשימות הקיימים כבר ממופים למכניקה**, כך שכל 108 החדרים יכולים לרוץ במצב החדש בלי כתיבת תוכן מחדש.

| סוג משימה קיים | מכניקה במבצע | מה התלמיד עושה בפועל |
|---|---|---|
| `reading` | **Intel Briefing** | החומר נלמד דרך **מעבדות** (סעיף 4.1); הטקסט המלא נשאר זמין כ"Field notes"; ה-checkpoint הוא "מפתח" שמגיש את התדריך ומעניק Intel token |
| `question` | **Lock Terminal** | מנעול עם 4 אפשרויות; תשובה נכונה פותחת דלת/ארון |
| `log_analysis` | **Evidence Board** | הלוג מוצג כמסמך ראיה; התלמיד **לוחץ על השדה** שעונה על השאלה (לא רק בוחר אפשרות) ומצמיד אותו ללוח חקירה עם חוטים |
| `analyst_choice` | **Triage Desk** | דמות/התראה מגיעה לשולחן עם טיימר; TP / FP / Escalate / Info. זה ה-"Approve/Deny" מהתמונות, מותאם ל-SOC |

### 4.1 מעבדות תדריך: ללמוד את החומר, לא לקרוא אותו (עודכן 2026-11-02)

המטרה של חדר הלמידה היא ללמוד **את אותו חומר** בצורה חיה. לכן כל `reading` יכול לקבל סדרת מעבדות קצרות, שבנויות מ-5 אבני בניין שחוזרות על עצמן בכל נושא:

| אבן בניין | מה עושים | דוגמה מחדר הפישינג |
|---|---|---|
| **Inspect** | לוחצים על כל חלק של ארטיפקט אמיתי ומקבלים את הסיפור שלו | Headers גולמיים: מי כתב כל שורה, השולח או השרתים |
| **Sequence** | מקישים פריטים בסדר הנכון ורואים את המסלול נבנה | עקוב אחרי שרשרת ה-Received מלמטה למעלה; הרצת ה-playbook |
| **Simulate** | בוחרים תרחיש ורואים מנגנון "רץ" צעד אחרי צעד | SPF/DKIM/DMARC על מייל אמיתי, מזויף ו-look-alike |
| **Sort** | ממיינים פריטים לקטגוריות, עם חשיפה ב-hover | "Hover, don't click"; מי באמת הדומיין; איזה verdict |
| **Match** | מחברים פריט לפריט עם הסבר | קובץ מצורף ↔ התרגיל שהוא עושה; שאלה ↔ כלי |

כללים: המעבדות **לא מנוקדות** (בלי XP), ולכן מותר שהתשובות שלהן יהיו בדפדפן; הן משתמשות בדוגמאות **שונות** מהמשימות המנוקדות כדי לא למסור תשובה; הטקסט המלא תמיד נגיש. מעבדות מוגדרות כנתונים ב-`RoomExperience.briefings`, כך שכתיבת מעבדות לחדר חדש היא עבודת תוכן ולא קוד.

**מכניקות חדשות (שלב 2, דורשות סוג משימה חדש):**
- **Spot the Tell**: hotspots על צילום מייל/מסך התחברות/דף פישינג.
- **Containment Choice**: החלטת תגובה (בידוד מכשיר / איפוס סיסמה / חסימת IP) עם השלכות שמוצגות בסצנה.
- **Pivot Chain**: לחיצה על ערך בלוג אחד פותחת את הלוג הבא (IP ← שם מכשיר ← משתמש), בדיוק כמו pivoting אמיתי.

## 5. סיפור ודמויות

- **ה-Handler**: דמות קבועה (מנהלת ה-SOC) שנותנת תדריך ומגיבה להצלחות/כישלונות. קבועה בכל המבצעים, יוצרת המשכיות.
- **דמויות לכל תרחיש**: עובדים, ספקים, תוקף. תמונת פורטרט + תפקיד (כמו "Data Protection Officer" בתמונה). בחדרי Approve/Deny הן מה שהופך את ההחלטה לאנושית.
- **שם מבצע**: כל חדר מקבל שם קוד (למשל "Operation Silent Ticket" לחדר Kerberoasting), אבל שם החדר המקורי מוצג תמיד מתחת, כדי שהמדריך במכללה ימצא אותו.

## 7. וידאו (שלב מאוחר, אבל מתכננים את המקום עכשיו)

מכינים את סכמת התוכן כבר עכשיו, כך שהוספת סרטון בעתיד היא רק העלאת קובץ:
- `intro` (4-8 שנ'): כניסה למבצע, עם טקסט מוקלד (כמו תמונה 5) וכפתור Skip.
- `stationCutscene` (3-5 שנ'): אופציונלי לתחנה מרכזית.
- `success` / `fail` (2-3 שנ'): סגירת המבצע.
- תמיד: כתוביות, Skip, השתקה, פוסטר סטטי כגיבוי, ובלי autoplay עם סאונד. יצירה עם צינור ה-Higgsfield/Remotion שכבר קיים אצלנו (סרטוני הפרומו).

## 8. ארכיטקטורה טכנית (המלצה)

**הייבריד 2.5D + 3D קל**, לא מנוע משחק מלא:
- **רקעי סצנה**: תמונות/לופים מעוצבים מראש (render תלת-ממדי או AI) עם parallax בשכבות. נראה תלת-ממדי, נטען מהר, עובד על כל מחשב.
- **ה-Hub ומפת המערכה**: `@react-three/fiber` + `drei` עם מודל קל (מעגל/בניין, נקודות אור, מעבר מצלמה). טעינה עצלה (dynamic import) רק במסלול הזה.
- **אנימציות UI**: `framer-motion` (כבר מותקן).
- **שכבת תוכן**: קובץ חדש `RoomExperience` לכל חדר, **מעל** החדר הקיים, בלי לגעת במשימות:

```ts
interface RoomExperience {
  roomId: string;
  codename: string;            // "Operation Silent Ticket"
  theme: ThemeId;              // "identity-vault"
  accent: string;
  handlerLine: { intro: string; win: string; lose: string };
  characters?: { id: string; name: string; role: string; portrait: string }[];
  stations: {
    id: string;
    label: string;             // "The Ticket Office"
    taskIds: string[];         // מצביע על משימות קיימות
    mechanic?: MechanicId;     // ברירת מחדל: לפי סוג המשימה
    position: [number, number, number];
  }[];
  bossTaskIds: string[];
  media?: { intro?: MediaRef; success?: MediaRef; fail?: MediaRef };
}
```

- **חדר בלי `RoomExperience`** = מקבל אוטומטית ערכת נושא לפי הקטגוריה וחלוקה אוטומטית לתחנות (כל 3-4 משימות). כך **כל הקטלוג עובר למצב החדש ביום הראשון**, וחדרי הדגל מקבלים ליטוש ידני.
- **ניקוד**: אותם API routes. Integrity/כוכבים הם שכבת תצוגה בלבד; הם לא נכנסים ל-XP.
- **שיטת מדידה**: זמן בחדר, אחוז השלמה, נטישה לפי תחנה, ניסיונות חוזרים. משווים מצב קלאסי מול מבצע.

## 10. סיכונים

- **ביצועים** במחשבי מעבדה: 2.5D כברירת מחדל, 3D רק ב-Hub, זיהוי GPU חלש ומעבר אוטומטי לקלאסי.
- **"משחק במקום למידה"**: נשמר ע"י עקרונות סעיף 2 ובדיקה של `soc-pedagogy-architect` + `soc-engagement-designer` על הפיילוט.
- **דליפת תשובות** במכניקות לחיצה: בדיקה בצד השרת, ובדיקת QA ייעודית.
- **זכויות יוצרים**: עיצוב מקורי. תמונות התייחסות משמשות רק לרמת ה-UX.
