Track key: `ai-soc`. Repo worktree: `C:/dev/soc-ai-track` (branch `feat/ai-detection-track`). Staging root: `C:/dev/track-staging/ai-soc/`. One folder per topic: `NN-<slug>/` holding `lesson.json`, `room.json`, `evidence.json`.

Reading budget per room: **3 readings** (narration headroom was 53 un-recorded readings for 15 rooms). Lesson topic label for every lesson: `AI & LLM Security`.

The new track is the operational layer the existing content lacks: which telemetry each AI surface produces, what normal and abnormal look like in it, how to build and write the detections, how to bring the sources into the SIEM, and how to investigate and respond. Every new lesson assumes the taxonomy above exists and spends its space on logs, fields, queries, thresholds and decisions.

## Order and grouping

Tal's list ran: anomalous use, user monitoring, shadow AI, prompt injection, LLM API access, API keys, agents, function calling, unauthorized access, data leakage, use cases, detection rules, SIEM integration, log investigation, incident response. Two changes: user-activity monitoring moves first (a learner has to know what the logs are before judging what is anomalous in them), and prompt injection moves after the API topics so the track runs people, then machine access, then attacks on the AI application itself.
