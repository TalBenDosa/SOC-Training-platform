> נגזר מראיון-הֶפְקַת-דרישות (3 גלים) עם Tal, 2026-09-17, בהמשך לאפיון Tier-1
> ([[SPEC-team-t1]]). מתאר את **התהליך שה-Tier-2 עובר מקצה-לקצה** — מה הוא רואה,
> מה הוא עושה, ואיך הוא מחליט ומעביר. חלק מהמנגנון כבר בנוי; §10 מפריד בין
> מה-שקיים לבין הפערים שהראיון חשף.

**עקרון-על שהודגש במפורש:** ה-Tier-2 **חוקר את האירוע האמיתי מקצה-לקצה — גם את
הלוגים המלאים וגם את ה-EDR** — ולא מסתמך על כמה מילים ש-Tier-1 כתב. החקירה היא
לב-התפקיד, לא פורמליות.

## §1 · התהליך במבט-על

```
תור מתועדף → קח (Acknowledge=claim) → חקור מקצה-לקצה → החלט → כתוב דו״ח → סְגוֹר
                                          │
                                          ├─ הלוג המלא (raw + pivot)
                                          ├─ EDR (עץ-תהליכים → hash → RTR/בידוד)
                                          └─ העשרת threat-intel (hash/IP/domain)
```

מסלול-החיים של הסלמה אצל T2:
`requested → acknowledged(=claimed) → [investigating] → אחת מ:`
- **contain** — איום-אמת → קבע scope → בקש הכלה מהמנהל → בצע בידוד
- **bounce** — לא-אמת/חסר-ביסוס → החזר ל-Tier-1 עם סיבה
- **elevate** — עמוק/מורכב → הסלם ל-Tier-3 לציד
- **resolve** — שפיר/טופל → סגור

## §2 · מה T2 רואה בכניסה — לוגים-רצים + תיבת-טיקטים בצד

**מבנה-המסך (הכרעת Tal):** שתי-עמודות —
- **מרכז: הלוגים רצים.** T2 רואה את **הפיד החי המשותף** בזמן-אמת (אותם לוגים
  שכל הצוות רואה), לא רק את מה שהוסלם — כדי לתפוס הקשר וקורלציה בעצמו.
- **צד: תיבת-הטיקטים מ-Tier-1** ("Escalations for you") — כל טיקט שדורש בדיקה,
  **מלווה בשלושה חלקים מפורשים:** (1) **הלוג** (Open the flagged log — ה-snapshot
  המלא), (2) **חקירה-ראשונית של T1** (observations + assessment), (3) **IOCs**
  (האינדיקטורים ש-T1 אסף). כך הטיקט הוא יחידת-עבודה שלמה, לא כותרת בודדה.

**הכרעה (גל 1+2):** תיבת-הטיקטים אינה כרונולוגית — **תור מתועדף**.

- **מיון אוטומטי** לפי ציון-דחיפות = **חומרה × זמן-המתנה × confidence-של-T1**,
  ועם משקל נוסף למה ש-T1 ביקש (בקשת `contain` דחופה מ-`investigate`). ההסלמה
  הדחופה ביותר תמיד למעלה.
- **SLA לפי חומרה** — ההסלמה הופכת **אדומה** בחריגה:
  - `critical` → דקה
  - `high` → 3 דקות
  - `medium` → 10 דקות
- כל כרטיס מציג: כותרת-T1, observations, IOCs, **מאת מי** + confidence + מה-מבוקש,
  תג **⏱ waiting Nm** (אדום בחריגת-SLA), וסטטוס (מטופל/הוכל-מבוקש/bounced/resolved).
- **claim-on-ack (ניתוב):** מי שלוקח (Acknowledge) ראשון הוא ה-owner; שאר ה-T2
  רואים **🔒 handled by X** ולא עובדים עליו כפול.

## §3 · החקירה מקצה-לקצה — לב-התפקיד (מודגש)

אחרי Acknowledge, T2 **חייב** לעבור את לולאת-החקירה המלאה לפני החלטה. שלושה
ערוצים משלימים:

### 3.1 · הלוג המלא (לא רק מילות-T1)
- **Open the flagged log** פותח את ה-`DetailPanel` המלא של האירוע שה-T1 סימן —
  **כל השדות הגולמיים**, לא רק הסיכום. זה ה-snapshot שנשמר עם ההסלמה, כך שהחקירה
  עצמאית ממצב-הפיד.
- **Pivot** על host/user/IP — מסנן את הפיד המשותף לכל מה שקשור לישות, לבניית
  ציר-האירוע (מה קדם, מה בא אחרי).

### 3.2 · חקירת EDR מקצה-לקצה
- **Investigate in EDR** בונה מחדש את אותה תקיפה מטלמטריית-ה-endpoint ומקפיץ
  לקונסולת `/edr` (Falcon-grounded) טעונה מראש.
- שם T2 עובר **תהליך-חקירה שלם**: עץ-התהליכים (parent→child), שורות-פקודה,
  hash lookup, חיבורי-רשת, ו-RTR/בידוד — עד להבנת שרשרת-התקיפה המלאה.
- כשאין טלמטריית-endpoint (תקיפת-זהות/ענן טהורה) — הכלי אומר זאת במפורש במקום
  לפתוח קונסולה ריקה.

### 3.3 · העשרת threat-intel (פנימית)
- **הכרעה (גל 2):** פאנל-intel **פנימי** — לחיצה על hash/IP/domain בלוג מחזירה
  **verdict** (known-bad / clean / unknown) + הקשר. בלי שירות חיצוני (הדומיינים
  פיקטיביים).
- T2 מאמת כל אינדיקטור לפני שהוא בונה עליו החלטה.

**התוצר של §3:** T2 יודע *מה* קרה, *על מה*, *כמה רחב*, ו*עד כמה בטוח* — ורק אז
מחליט.

## §4 · צומת-ההחלטה + הניתוב

לאחר החקירה, אחד מארבעה מוצאים:

| מוצא | מתי | פעולה |
|------|-----|-------|
| **Request containment** | איום-אמת שדורש בלימה | קבע scope → בקש הכלה מהמנהל (§6) |
| **Bounce to Tier-1** | לא-אמת / חסר-ביסוס | החזר עם **סיבה מרשימה** (§4.1) |
| **Elevate to Tier-3** | ציד-עומק בלבד | תנועה-רוחבית / scope-לא-ברור / חשד-APT (§4.2) |
| **Resolve** | שפיר / טופל | סגור |

### 4.1 · Bounce ל-T1 — סיבה מרשימה
**הכרעה (גל 3):** לא free-text חופשי ולא מחרוזת-קבועה — **בחירה מרשימת-סיבות
נפוצות** (למשל: *חסר אינדיקטור בר-פעולה* · *רעש/שפיר* · *חסר הקשר/עדות* · *כפילות*),
עם שדה-הרחבה חופשי אופציונלי. T1 מקבל פידבק ספֵּציפי, וההסלמה חוזרת אליו כפתוחה
ללימוד.

### 4.2 · Elevate ל-T3 — רק לציד-עומק
**הכרעה (גל 2):** T2 מטפל ברוב המקרים בעצמו. מסלים ל-T3 **רק** כשצריך ציד: חשד
לתנועה-רוחבית, scope שלא מתבהר, או חשד ל-APT. ההסלמה נכנסת לתור **Elevations for
you** ייעודי של T3 (עם הלוג המלא), לא ל-inbox משותף.

## §5 · דו״ח-האירוע + השער-הקשיח

**הכרעה (גל 1+3):** T2 כותב **דו״ח-חקירה מובנה**, ו**חובה למלא אותו לפני סגירה
או בקשת-הכלה** — שער-קשיח (כמו ש-T1 מגובה בדו״ח).

- שדות: **Summary** · **Findings** (≥12 מילים — מה נחקר, העדות, ההיקף) ·
  **Verdict** (true/false-positive · benign · escalate) · **Recommendation**.
- **השער חוסם גם `resolve` וגם `Request containment`** עד שכל השדות מלאים.
- ניקוד-איכות דטרמיניסטי (`reportQualityScore`): summary + עומק-findings + verdict
  + recommendation → מזין את תא-הרובריקה **Incident report**.

---

## §6 · Scope + בקשת-הכלה (scope-first)

**הכרעה (גל 3):** **חובה לקבוע scope לפני בקשת-הכלה**, כדי שהמנהל יבין מה הוא מאשר.

1. T2 קובע **scope**: hosts · users · techniques (מה בתוך-האירוע).
2. רק אז **Request containment** → נכנס לתור-האישורים של **המנהל** (T2 לא מאשר
   בעצמו).
3. משאושר → כרטיס **Approved — execute isolation** צץ אצל T2 → **Execute** מבצע
   את הבידוד; נמדד MTTC (מבקשה עד בידוד).
4. Tier-3 מאשר/מתקן את ה-scope הסופי.

---

## §7 · מה T2 **לא** עושה (גבולות-תפקיד)

- **לא מאשר הכלה** בעצמו — זה המנהל (הפרדת-רשויות).
- **לא קובע scope סופי** — T3 מאשר/מתקן.
- **לא מתייג dispositions** על הפיד-הגולמי — זה T1 (T2 מקבל תיקים מוסלמים).
- **לא כותב rules/playbooks** — זה DE.

## §8 · על מה T2 נמדד (רובריקה 0/4/8/12)

**הכרעה (גל 1):** המדד המרכזי = **נכונות-ההחלטה + איכות-החקירה** (לא מהירות לבדה).

| קריטריון | נמדד מ- |
|----------|---------|
| **Ack latency** | Δ(הסלמה → ack) — לחץ-זמן |
| **Incident report** | `reportQualityScore` של הדו״ח |
| **Scoping completeness** | כמה מימדים (hosts/users/techniques) מולאו |
| **Containment recommendation** | האם בקשת-ההכלה נומקה כראוי |
| **Timeline accuracy** | 🔜 ממתין לאִינְסְטְרוּמֶנְטַצְיָה (בונה-ציר-זמן) |

מהירות (ack/MTTC) נמדדת אך אינה המדד-הדומיננטי.

## §10 · מצב-בנייה — קיים מול פערים (מהראיון)

### ✅ כבר בנוי
- תיבת **Escalations for you** + **Open the flagged log** (DetailPanel מלא + pivot).
- **Investigate in EDR** (deep-link ל-`/edr`) + טלמטריית-endpoint אמיתית.
- **העשרת threat-intel פנימית** (Check Hash/IP/Domain בפאנל-הלוג).
- **claim-on-ack** + **Elevate to Tier-3** + תור-Elevations ל-T3.
- **דו״ח-אירוע מובנה** + `reportQualityScore` ברובריקה.
- **Bounce** (כרגע free-text) · **Request containment** · **Execute isolation** ·
  **Set scope** · **Pin to case** · תג **⏱ waiting**.
- שני מסלולי-סגירה: **resolve** / **containment-executed**.

### ✅ פערי-הראיון — מומשו (2026-09-17)
1. **תור מתועדף + SLA-לפי-חומרה** — התיבה ממוינת עכשיו לפי חומרה×המתנה×confidence
   (עם משקל ל-`contain`), פתוחים-קודם; תג-ההמתנה נצבע אדום בחריגת-SLA לפי חומרה
   (crit 1m / high 3m / med 10m).
2. **שער-קשיח לדו״ח** — הדו״ח עבר לכרטיס-הטיקט עצמו (per-ticket), ו**חוסם גם
   `Resolve` וגם `Request containment`** עד שהוגש (summary + findings≥12w + verdict +
   recommendation). שורת-הנחיה מסבירה מה חסר.
3. **scope-first** — `Request containment` חסום עד שנקבע scope (≥מימד אחד).
4. **Bounce מרשימת-סיבות** — בחירה מרשימת-סיבות נפוצות + שדה-הרחבה אופציונלי
   (במקום free-text חופשי).
5. **חקירת-EDR** — כפתור **Investigate in EDR** גלוי בראש הקונסולה, ומדריך-התפקיד
   מדגיש את לולאת החקירה-המלאה (לוג→EDR→intel).

### 🔜 ממתין לאִינְסְטְרוּמֶנְטַצְיָה
- **Timeline accuracy** — דורש כלי בונה-ציר-זמן שאין עדיין; נשאר n/a ברובריקה.

## §11 · שאלות פתוחות
- האם ה-SLA-clock צריך להיות **גלוי בזמן-אמת** על כל כרטיס (countdown), או רק
  צביעה בחריגה? (הראיון בחר צביעה-לפי-חומרה; countdown חי נשאר להחלטה.)
