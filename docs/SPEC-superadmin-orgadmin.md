# אפיון — סופר-אדמין ומנהל ארגוני (HACK THE SOC)

> מסמך אפיון לתפקיד הסופר-אדמין ולדשבורד מנהל הארגון. לכל יכולת: **מבוקש · קיים היום · פער · הצעת מימוש**. עודכן 2026-08-11.
>
> מקרא סטטוס: ✅ קיים · 🟡 חלקי · 🔴 חסר.

## חלק א׳ — תפקיד הסופר-אדמין

### 1. עמוד-על (Hub) לסופר-אדמין — 🟡 חלקי
| | |
|---|---|
| **מבוקש** | עמוד אחד עם: ניהול תוכן, ניהול לקוחות, כניסה לכל לקוח, ומעבר בין סביבות. |
| **קיים** | שני קונסולות **מנותקות**: `/superadmin` (ניהול לקוחות — רשימת ארגונים, הוצאות AI, קודי כיתה) ו-`/admin` (ניהול תוכן — תרחישים/חידונים/שיעורים). אין קישור ביניהם. |
| **פער** | אין דף-על מאחד. הסופר-אדמין קופץ בין שתי כתובות שלא מודעות זו לזו. |
| **הצעה (P0)** | דף נחיתה `/superadmin` עם 3 כרטיסי-על: **ניהול לקוחות** · **ניהול תוכן** (`/admin`) · **הסביבה הפעילה** (מחוון + מעבר). קישור הדדי בסייד-בר. |

### 2. ניהול תוכן — ✅ קיים (מנותק)
| | |
|---|---|
| **מבוקש** | עמוד לניהול תוכן. |
| **קיים** | `/admin` — יצירה/פרסום של תרחישים, חידונים ושיעורים (מגובה DB: `content_scenarios/quizzes/lessons`, מיגרציה 0019). |
| **פער** | (א) לא מקושר מ-`/superadmin`; (ב) עריכת תוכן **מובנה** (built-in) עדיין ב-localStorage בלבד; (ג) טאב "Users" הוא mock. |
| **הצעה (P1)** | לקשר מדף-העל; להעביר עריכת built-ins ל-DB; להסיר/לחבר את טאב ה-Users. |

### 3. ניהול לקוחות (מכללות) — ✅ קיים
| | |
|---|---|
| **מבוקש** | רשימת לקוחות, יצירה, ניצול מושבים, חוזה. |
| **קיים** | `/superadmin` — גריד ארגונים (שם, slug, סטטוס, מושבים `used/limit`, תפוגה) + הוצאות AI כלל-פלטפורמה. פירוט לכל ארגון ב-`/superadmin/orgs/[id]` (חוזה `organizations.contract`, רישוי, מיתוג, חברים, offboarding). |

### 4. טופס יצירת ארגון חדש — 🟡 צריך התאמה לשדות המבוקשים
| | |
|---|---|
| **מבוקש** | **שם המכללה · חוזה · אדמין ארגוני (שאליו נשלח המייל)** — שלושה שדות בלבד. |
| **קיים** | `CreateOrgModal`: שם · Slug · Seat limit · Expires · Admin email. שולח ל-`POST /api/superadmin/orgs`. הבקאנד **כבר** מרשם את הסופר-אדמין אוטומטית, יוצר הזמנה + קוד כיתה, ושולח את מייל ה-Welcome. |
| **פער** | (א) **חוזה חסר מהטופס** (נערך רק אחרי יצירה בדף הפירוט); (ב) שדות עודפים ביחס למבוקש: Slug / Seat limit / Expires. |
| **הצעה (P0)** | לעצב מחדש את הטופס ל-3 שדות: **שם המכללה · חוזה · אימייל אדמין ארגוני**. Slug ייגזר אוטומטית; Seat limit/Expires יעברו ל"הגדרות מתקדמות" מתקפלות (ברירת מחדל סבירה). להוסיף שמירת `contract` ב-POST. |

### 5. כניסה ללקוח + מעבר בין סביבות — 🟡 חלקי (כניסה קיימת, אין מחליף)

| **פער** | **אין מחליף סביבות גלובלי** — כדי לעבור לסביבה אחרת חוזרים לדף הפירוט ולוחצים "Enter". אין מחוון "אתה כרגע בתוך \<מכללה\>". |

### 6. באנר עליון: שם המכללה + קוד שיוך — 🟡 חלקי
| | |
|---|---|
| **מבוקש** | בראש העמוד: **שם המכללה** + **קוד השיוך**. תזכורת: הקוד **מתחלף כל 24 שעות**, אך השיוך של תלמיד **תקף ל-100 יום** מרגע ההזנה. |

| **פער** | השם והקוד לא מאוחדים לבאנר עליון אחד; ניסוח ה-24ש/100-יום לא מודגש יחד. |
| **הצעה (P0)** | באנר עליון אחד ב-`/manage`: **\<שם המכללה\>** · קוד היום **`XXXXXXXX`** (מתחלף בעוד HH:MM) · שיוך תלמיד תקף 100 יום מההרשמה. |

## חלק ג׳ — דשבורד מנהל ארגוני: מעקב תלמידים

### 8. רשימת תלמידים + ציונים + פעילות אחרונה — ✅ ברובו קיים
| | |
|---|---|
| **מבוקש** | לוח מעקב: מתי נכנסו, ציונים. |
| **קיים** | `/api/org/analytics` + Roster ב-`/manage`: לכל תלמיד — חדרים שהושלמו, תרחישים, **ממוצע ציון תרחיש %** (אדום מתחת 60), XP/רמה, **פעילות אחרונה** (`last_active_at`), ימי-שיוך שנותרו. סיכומי כיתה (ממוצע, פעילים 7 ימים, רדומים 14 יום, חדרים קשים). |
| **פער** | (א) "מתי נכנס" הוא **פעילות אחרונה נגזרת** מרשומות התקדמות — **לא חותמת התחברות אמיתית**; (ב) `joined_at` (תאריך הצטרפות) נאסף אך **לא מוצג**. |
| **הצעה (P0)** | להוסיף עמודת **"הצטרף בתאריך"** ל-Roster (הנתון כבר קיים). (חותמת-login אמיתית — אופציונלי, P2.) |

### 9. Drill-down לפרופיל תלמיד בודד — 🔴 אין עמוד ייעודי
| | |
|---|---|
| **מבוקש** | להיכנס לפרופיל של תלמיד ולראות פירוט מלא עליו. |
| **קיים** | ה-drill-down היום הוא **רק שורת המדדים המוטבעת** ב-Roster. אין עמוד/route ייעודי; לחיצה על תלמיד לא עושה כלום. |
| **הצעה (P1)** | עמוד **`/manage/students/[id]`**: ציר-זמן של חדרים/תרחישים, ציון + זמן לכל תרחיש (`scenario_history.score/time_taken`), פירוט חדר-אחר-חדר, וקצב התקדמות. |

### 10. אינדיקטורים עדינים: איפה טעה · כמה זמן לקח · קצב — 🟡 חלק נאסף ולא מוצג, חלק לא נאסף
| | |
|---|---|
| **מבוקש** | לראות **איפה התלמיד טעה**, **כמה זמן לקח לו לענות**, ואינדיקציות על קצב ההתקדמות. |
| **קיים — זמן-למשימה** | ✅ **נאסף** ב-`room_progress.telemetry` (דרך `useTaskTelemetry`): `shownAt`, `firstInteractionAt`, `submittedAt`, **`decisionLatencyMs`**, `interactionCount`. אך **לא נקרא** ע"י `/api/org/analytics` ולא מוצג בשום מקום. |
| **קיים — ציון/זמן תרחיש** | ✅ `scenario_history.score` + `time_taken`. |
| **חסר — איפה טעה** | 🔴 **לא נאסף כלל.** מסלול ה-submit של החדרים (`/api/rooms/[id]/tasks/[taskId]/submit`) **חסר-מצב** — מחזיר `{correct, xpEarned}` ולא כותב ל-DB. נשמרים רק מזהי משימות שעברו (`completed_task_ids`), בלי תשובות שגויות / מספר ניסיונות / איזו שאלה נכשלה. |
| **הצעה** | **P1 (חינם כמעט):** לחשוף את `decisionLatencyMs` הקיים בעמוד ה-drill-down → "כמה זמן לקח לו לענות" + קצב. **P2 (נתון חדש):** להפוך את מסלול ה-submit ל**שומר-מצב** — אימות + טבלה חדשה `task_attempts` (מיגרציה) שתתעד: משימה, נכון/שגוי, הבחירה השגויה, מס' ניסיונות, זמן. זה מה שיאפשר "**איפה טעה**". |

## תוכנית מימוש מתועדפת

**P0 — התאמות UI מעל נתונים קיימים (ללא מיגרציה):**
1. דף-על לסופר-אדמין (3 כרטיסים) + קישור הדדי ל-`/admin`.
2. מחליף-סביבות גלובלי בהדר.
3. עיצוב מחדש של טופס יצירת ארגון → שם / חוזה / אימייל אדמין (מתקדם מתקפל).
4. באנר עליון "שם מכללה + קוד שיוך (24ש/100-יום)" ב-`/manage`.
5. עמודת "הצטרף בתאריך" ב-Roster.

**P1 — חשיפת נתונים שכבר נאספים:**
6. עמוד drill-down לתלמיד `/manage/students/[id]` — ציר-זמן, ציונים, **זמן-למשימה** מ-`telemetry`, קצב.
7. חיבור ניהול-התוכן לדף-העל.

**P2 — איסוף נתונים חדש (מיגרציה + שינוי submit):**
8. `task_attempts` — תיעוד נכון/שגוי/ניסיונות/זמן per-task → מאפשר "**איפה טעה**".
9. (אופציונלי) חותמת התחברות אמיתית.

### הערה על מודל ההרשאות (כבר נאכף — לא חלק מהבנייה)
סופר-אדמין רשום בכל הסביבות ויכול לצבור מספר ארגונים; מנהל ארגון רשום פעם אחת וגישתו לארגונו בלבד (נאכף ב-`join-environment` ואומת בפרודקשן — 403).
