The system an attacker compromises first is almost never the system they actually want.

Lateral movement is the trip from a low-value foothold to what matters, and the phase where the attacker is most exposed.

What makes it possible is trust: domain credentials and reused local admin passwords are built for legitimate administration and work just as well for attackers.

Section 1 of 10

Why attackers move, and what they are after

Initial access lands anywhere reachable, never directly on the prize.

HACKTHESOCLesson 28Lateral movement6 / 45

Three terms that drive this lesson

Lateral movement

Any technique to move from the first compromised system to another on the same network. In through the shed window, then the spare key opens the house.

Pivot

A compromised host used as a relay to reach systems not reachable from outside. The burglar now operates from inside the property.

Pass-the-hash

Making the next hop without the password: steal the mould the key was cast from, the hash, and some systems accept it directly.

Every technique in the lesson is one way of achieving lateral movement, and several use a pivot or a pass-the-hash-style trick.
HACKTHESOCLesson 28Lateral movement7 / 45

What attackers are actually looking for

Discovery comes first. BloodHound maps AD trust into a graph and finds the shortest path to Domain Admin.

  • Domain controllersCompromising one compromises the whole domain's trust.
  • File and database serversWhere the data worth stealing or encrypting sits.
  • Backup infrastructureDestroying backups turns recoverable ransomware into unrecoverable.
  • IT admin workstationsThe likeliest place to find a cached high-privilege credential in memory.
None of these is the marketing coordinator's laptop, which is exactly why the intrusion does not stop there.
HACKTHESOCLesson 28Lateral movement8 / 45
No follow-up activity does not mean contained.

Careful movement takes days or weeks: enumerate quietly, pick a path, validate a credential, repeat from each new foothold.

Dwell time is the gap between initial access and the real objective. From the attacker's view, the interesting part has not started yet.

SMB and admin shares: the PsExec pattern

T1021.002: copy a binary to ADMIN$ or C$, then start it as a service.

HACKTHESOCLesson 28Lateral movement10 / 45

How PsExec-style movement works

  1. 1Get local admin on the targetOften via password reuse, or a domain account pushed as local admin by group policy.
  2. 2Write to a hidden admin shareC$ or ADMIN$ over port 445. Target logs 5140 and 5145 with RelativeTargetName.
  3. 3Create a service to run itService Control Manager starts the binary. Target logs 7045 with ServiceName and ImagePath.
PsExec installs a service named PSEXESVC by default, but attackers rename it or use tools like Impacket's psexec.py and smbexec.py that randomise the name.
HACKTHESOCLesson 28Lateral movement11 / 45

Workstation-to-workstation is the highest-value signal

Server to server

Common and mostly legitimate: patch management, backup agents, endpoint management. Baseline which accounts and hosts touch admin shares.

Workstation to workstation

A marketing PC hitting another workstation's C$ is almost never business. Pair it with a 7045 whose binary sits in Windows or Temp.

A service binary name that matches nothing in your software inventory turns one suspicious connection into a high-confidence finding.
HACKTHESOCLesson 28Lateral movement12 / 45

Port 445 traffic followed by a new service

Excluding accounts ending in $ removes machine-account traffic so you see what humans and service accounts are doing.

Section 3 of 10

Worked example: reading a PsExec trace

Three log lines on the target, read in the order they happen.

HACKTHESOCLesson 28Lateral movement14 / 45

Write, service, logon: the PsExec chain on FIN-WKS-014

  • RelativeTargetName names the exact file written into ADMIN$
  • ImagePath in 7045 points at that same file: the code that just ran
  • LogonType 3 from the same IP shows how the account got access
7045 always appears with PsExec-style tools, whatever the service happens to be named.
HACKTHESOCLesson 28Lateral movement15 / 45
No single event is alarming. The chain is the finding.

Same account, same source, same target, short window, in this order: logon, write, service creation.

Pull the chain together whenever any one of the three looks slightly out of place, such as a workstation-to-workstation connection or an unknown ServiceName.

RDP, WinRM and WMI

T1021.001 and T1021.006: interactive and remote-execution movement with stolen credentials.

HACKTHESOCLesson 28Lateral movement17 / 45

Three techniques, three distinct footprints

Interactive session

RDP

Logs in like a legitimate admin; everything after looks like normal interactive use. Hunt one source opening RDP to many destinations.

Fileless remoting

WinRM

Enter-PSSession or Invoke-Command over 5985/5986. Without script block logging it is nearly invisible beyond the logon.

T1047

WMI

Remote execution without a binary, e.g. wmiexec.py. Signature: WmiPrvSE.exe spawning cmd.exe or powershell.exe after a network logon.

An analyst who only knows one of these three patterns will miss the other two entirely.

Section 5 of 10

DCOM and remote scheduled tasks

T1021.003 and T1053.005: less monitored, which is why attackers reach for them.

HACKTHESOCLesson 28Lateral movement20 / 45

Two quieter remote-execution paths

DCOM, T1021.003

Invoke a COM object remotely over RPC: MMC20.Application, ShellWindows, ShellBrowserWindow. Nothing dropped, no service.

  • 4624 LogonType 3 on the target
  • Port 135 endpoint mapper, then high ports
  • Tell: mmc.exe or svchost.exe spawning a shell

Remote task, T1053.005

Register a task over RPC (schtasks /s or the ATSVC pipe), often deleted seconds later. Also persistence.

  • 4698 task created, with action XML
  • 4698 does not say it was remote
  • Correlate with a preceding 4624 Type 3
  • Create then delete (4699) within seconds
For DCOM, the parent-to-child process anomaly (Event ID 4688 or Sysmon Event ID 1) is the highest-fidelity signal. The port alone never confirms the technique.

Section 6 of 10

Pass-the-hash and pass-the-ticket

T1550.002 and T1550.003: moving without ever knowing the password.

HACKTHESOCLesson 28Lateral movement24 / 45

Authenticate with material derived from the credential

T1550.002, NTLM

Pass-the-hash

NTLM challenge-response works on the hash itself. A hash from an LSASS dump authenticates to any NTLM host without cracking.

T1550.003, Kerberos

Pass-the-ticket

Steal a TGT or service ticket from memory and replay it for as long as it stays valid.

Variants

Golden / Silver Ticket

Forge tickets from stolen Kerberos secrets instead of replaying a captured one. Same principle.

The attacker literally never learns the user's actual password and does not need to.
HACKTHESOCLesson 28Lateral movement25 / 45

The logon looks legitimate, so look at context

4624 fires with a valid LogonType and a real username because the correct secret was presented.

  • Hash reuse across hostsThe same NTLM hash (LogonProcessName NtLmSsp) authenticating to many hosts in a short window from an unusual source.
  • First-time hostA logon session on a workstation the account has never used, especially outside normal hours.
  • Wrong serviceA service ticket used for a service the account has no reason to access.
There is usually no field that says 'this ticket was stolen', which is why detection leans on behavioural baselining and UEBA.

Who talks to whom beats any single event

Treat the network as a graph: the pattern over time tells the real story.

HACKTHESOCLesson 28Lateral movement27 / 45

Same objective, five different footprints

Any single one of these could be an administrator doing their job. The aggregate is what has no innocent explanation.
HACKTHESOCLesson 28Lateral movement28 / 45

The healthy graph versus the attacker's graph

Healthy shape

Workstations talk to servers: file shares, print servers, DCs. A small known set of admin and jump boxes talk to everything.

Lateral movement

New workstation-to-workstation edges on 445, 3389 or 5985, created in a burst no admin's daily pattern resembles.

Pivot from "show me this alert" to "every authenticated connection this host made in 24 hours, and how many were workstations".

Defender for Identity's lateral movement paths and UEBA products surface this graph anomaly automatically.
HACKTHESOCLesson 28Lateral movement29 / 45

First-seen connections against a 30-day baseline

The leftanti join keeps only edges that never appeared in the previous 30 days. Five or more new destinations in a day is the anomaly.
HACKTHESOCLesson 28Lateral movement30 / 45

Admin tiering shrinks the blast radius

A credential valid at one tier must never authenticate at a more sensitive tier.

AD tierCovers
Tier 0Domain controllers and identity infrastructure
Tier 1Servers and applications
Tier 2End-user workstations

Not the SOC Tier 1/2/3 analyst levels. Same word, two unrelated meanings.

With Privileged Access Workstations used only for admin tasks, a compromised Tier 2 workstation only yields Tier 2 credentials that do not work on Tier 0 or Tier 1.

SSH and Linux lateral movement

On Linux, the currency of movement is usually an SSH key pair.

HACKTHESOCLesson 28Lateral movement32 / 45

What an attacker hunts for on a Linux host

  • Private keys~/.ssh/id_rsa and similar, often with no passphrase: a reusable credential to every host that trusts it.
  • known_hosts and history~/.ssh/known_hosts, .bash_history and configs map which machines this host talks to.
  • Agent hijackingA forwarded agent (ssh -A) lets the attacker authenticate onward without seeing the key.
  • Their own keyAppending to ~/.ssh/authorized_keys is movement enablement and quiet persistence.
Agent hijacking is the Linux cousin of pass-the-ticket.
HACKTHESOCLesson 28Lateral movement33 / 45

Jump hosts, and what to watch in auth.log

Jump hosts

Forcing SSH through one hardened bastion is good design, but a compromised bastion is a master key, and admin traffic camouflages hops.

Detection

auth.log or secure shows Accepted publickey. Watch keys between servers that never talk, odd hours, or service accounts initiating SSH.

The unit of suspicion is the relationship: server A logging into server B for the first time is the story.

Pivoting and tunnelling through a foothold

Defeating segmentation by borrowing the foothold's route.

HACKTHESOCLesson 28Lateral movement35 / 45

The attacker borrows the foothold's route

Segmentation is a real obstacle, which is why attackers need pivoting at all.
HACKTHESOCLesson 28Lateral movement36 / 45

Three ways to tunnel through a foothold

  1. 1Port forwardingThe foothold forwards one internal service back out, e.g. ssh -L.
  2. 2SOCKS / dynamic forwardssh -D, chisel or ligolo make the foothold a gateway to any internal address it can reach.
  3. 3ChainingFoothold to second host to third, each hop reaching a more protected zone.
To the target, connections come from a legitimate internal host. 'It came from an internal IP' is not a clean bill of health.
HACKTHESOCLesson 28Lateral movement37 / 45
Catch pivoting by noticing a host behaving out of character for its role.

A DMZ web server initiating connections to many internal hosts or the domain controller is the shape of a relay.

Know what each host's normal conversations look like, and notice when one starts talking to places it never should.

Containing movement by design

Detection catches movement in progress; architecture makes it fail.

HACKTHESOCLesson 28Lateral movement39 / 45

Structural controls and the mechanism each breaks

ControlWhat it stops
Segmentation, east-west firewalls, microsegmentationFree host-to-host reach; forces noisier, detectable pivoting
Administrative tieringDomain-admin hashes cached on workstations for the next attacker
LAPS: unique, rotating local-admin passwordsOne stolen local-admin hash unlocking the whole fleet via pass-the-hash
Disable legacy protocols, restrict SMB/RDP, jump serversThe easy roads attackers prefer
Domain-admin accounts should never log into ordinary workstations. With LAPS, a stolen key opens exactly one door.
HACKTHESOCLesson 28Lateral movement40 / 45
Least privilege for reachability and credentials keeps a single compromise single.

In a segmented, tiered network, any cross-zone movement or admin login on a workstation is anomalous by design.

That turns 'was this normal?' from a guess into a much sharper question for the analyst.

Key takeaways

  1. 01Initial access rarely lands on the objective; discovery maps the path to DCs, file servers, backups and admin PCs.
  2. 02PsExec-style movement (T1021.002) leaves a chain: 5140/5145 share write, then 7045 service creation.
  3. 03RDP, WinRM, WMI, DCOM and remote tasks each leave a different artifact; the port never confirms the technique.
  4. 04Pass-the-hash and pass-the-ticket produce legitimate-looking logons; the tell is reuse on hosts the account never touches.
  5. 05Workstation-to-workstation edges and hosts acting out of role reveal movement; SSH keys and tunnels count too.
  6. 06Segmentation, tiering and LAPS make movement fail: a compromised laptop cannot yield a domain-admin hash.

Check your understanding, question 1 of 3

Event ID 5145 shows a workstation writing svc_update.exe to another workstation's ADMIN$ share, followed within seconds by Event ID 7045 on that target creating a service pointing at that file. Which technique?

A binary written to ADMIN$ followed within seconds by a 7045 service whose ImagePath points at it is the PsExec-style chain (T1021.002). Pass-the-ticket only authenticates; WMI shows WmiPrvSE.exe spawning a shell; a remote task leaves 4698, not 7045.

Check your understanding, question 2 of 3

A workstation logs on (4624, LogonType 3) to twelve other workstations in four minutes with one account, none contacted in the prior 30 days. Each logon looks valid. What makes this worth escalating?

Workstations rarely talk to each other, so a burst of never-seen edges breaks the graph's normal shape even when every 4624 is valid. Type 3 is an ordinary network logon, lockout counts failures, and a success does not prove theft.

On a server: no 7045, no file written to ADMIN$, yet mmc.exe spawns powershell.exe seconds after a 4624 LogonType 3. The source reached port 135 then a dynamic high port, with no traffic on 5985/5986. Which technique?
