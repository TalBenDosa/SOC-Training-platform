Every IOS command changes the running device at once, and nothing survives a reboot until you save it.

The same device is a sensor: the logs, timestamps and security events it sends are what the SOC sees.

Open with the technician who configures a switch, goes home, and loses everything at the next power cycle. Then flip it: what the device logs is only as good as how it was configured.

The IOS CLI model: modes and configurations

The prompt tells you the mode, and the mode decides which commands exist.

HACKTHESOCLesson 105Cisco IOS operations6 / 49

Four modes, and the prompt tells you which one you are in

An engineer who loses track of the mode types global settings into an interface.

ModePromptHow you enterWhat it is for
User EXECSwitch>Log inBasic checks: ping and a limited set of show commands
Privileged EXECSwitch#enableAll show commands, copy, reload, debug
Global configurationSwitch(config)#configure terminalDevice-wide settings: hostname, logging, users
Sub-modesSwitch(config-if)#, Switch(config-line)#interface, line, and similarSettings scoped to one interface, line or process

'Invalid input' errors very often mean a valid command typed one level up or down.

Have students read the prompt aloud before every command. The prompt is the single fastest way to avoid wrong-mode mistakes.
HACKTHESOCLesson 105Cisco IOS operations7 / 49

Walking down into a mode and back out

  • exit steps back one level; end (or Ctrl+Z) jumps to privileged EXEC
  • In config mode, do runs an EXEC command: do show ip interface brief
Watch the prompt change at every line. Note that exit from config-if lands in global config, but end skips straight to the top.
HACKTHESOCLesson 105Cisco IOS operations8 / 49

Running-config is RAM, startup-config is NVRAM

RAM

Running-config

What the device is using right now. Every command you type changes it immediately.

  • show running-config

NVRAM

Startup-config

Loaded at boot. The two configurations are never synchronized automatically.

  • show startup-config

Easy to forget

The deliberate save

copy running-config startup-config, or the older write memory. Forget it and the next power cycle silently reverts the change.

  • reload in 10 before risky edits
  • reload cancel once proven

A running-config that differs from the startup-config is a device in an unfinished or undocumented state.

The unsaved state is also a safety net: if a risky change locks you out and you have not saved, a reload restores the last good configuration.
HACKTHESOCLesson 105Cisco IOS operations9 / 49

Navigate fast, and read the error messages

  • Question markLists valid commands. After a partial word, or a command and a space, it lists matches or the next argument.
  • Tab and abbreviationsA unique prefix is accepted: conf t equals configure terminal, sh run equals show running-config.
  • Output filtersshow running-config | section line vty, or | include ntp, or | begin interface.
  • no in frontPutting no in front of a command removes it, for example no ip http server.
  • Three error messagesIncomplete: argument missing. Ambiguous: abbreviation matches several. Invalid input at ^: rejected character, often wrong mode.

Log to read: %SYS-5-CONFIG_I: Configured from console by netadmin on vty0 (10.10.99.20) shows who configured, and from where.

For the analyst: ask whether a change window was open and whether the change was saved afterwards.

Baseline device setup

Identity, passwords, lines and banner: close the obvious holes before production.

HACKTHESOCLesson 105Cisco IOS operations11 / 49

Identity first: hostname, enable secret, local user

A new device ships with a generic hostname, no passwords and open console access.

  • The hostname appears in every prompt and syslog line, and SSH keys need it
  • Prefer enable secret over the older enable password
The hostname is how a SOC tells devices apart in the logs. Setting it is not cosmetic.
HACKTHESOCLesson 105Cisco IOS operations12 / 49

Secret, password and type 7 are not the same protection

One-way hash

enable secret

Type 5 MD5 on old releases; type 8 PBKDF2 or type 9 scrypt on current ones, chosen with algorithm-type.

    Weak

    enable password

    Stored in clear text, or with a trivially reversible encoding.

      Type 7

      service password-encryption

      Converts clear-text line and enable passwords to type 7: reversible obfuscation that free tools decode in milliseconds.

        Type 8 and 9 are salted hashes and the real protection. Never post a configuration that contains a type 7 string.

        Type 7 only stops someone reading a password off a screen or a shoulder-surfed config. It is not encryption.
        HACKTHESOCLesson 105Cisco IOS operations13 / 49

        Lines: one shared password, or one account per admin

        Two kinds of line: the console (line console 0) and VTY for remote access (line vty 0 15).

        • Shared passwordpassword plus login: everyone uses one secret, so the logs cannot say who did what.
        • login localChecks the local user database: individual accounts and a meaningful audit trail.
        • Console without loginA console with no login command is open to anyone with a cable.
        • VTY without a passwordRefuses connections with 'Password required, but none set'.
        • exec-timeout 5 0Logs out an idle session after 5 minutes and 0 seconds.
        • logging synchronousStops syslog messages from interrupting what you are typing.
        Ask the baseline questions: who can log in, with what identity, over which path, and does every session leave a record tied to a named account?
        HACKTHESOCLesson 105Cisco IOS operations14 / 49
        A banner is a legal notice, not a welcome mat.

        Wording such as 'Welcome' can be argued to invite access. Never reveal the device model, location or software version.

        Example: banner motd #Authorized use only. Activity is monitored and logged.# The character after motd is a delimiter and must not appear inside the text.

        Section 3 of 8

        Secure remote management: SSH instead of Telnet

        Encrypt the path, restrict the lines, and read the login records.

        HACKTHESOCLesson 105Cisco IOS operations16 / 49

        Telnet exposes credentials, SSH encrypts the session

        TCP 23

        Telnet

        Sends everything, including usernames and passwords, in clear text. Anyone who captures traffic on the path reads the credentials.

          TCP 22

          SSH

          Encrypts the session and authenticates the server with a host key. SSH version 2 should be the only remote path.

            A login on port 23 should itself be an alert: Telnet should not exist on a hardened device.

            On a production device Telnet should be off. Any session that shows up on port 23 is a finding, not a convenience.
            HACKTHESOCLesson 105Cisco IOS operations17 / 49

            SSH setup, and the line that actually disables Telnet

            SSH needs four things: a non-default hostname, a domain name, an RSA key pair and a user authentication method.

            • transport input ssh is the key line: VTY lines accept every protocol until restricted
            • Generating keys alone does not disable Telnet
            Common failures: the key command asks for a domain name or a non-default hostname; version 2 needs a modulus of 768 bits or more (use 2048); after a hostname or domain change run crypto key zeroize rsa and generate again.
            HACKTHESOCLesson 105Cisco IOS operations18 / 49

            Harden the management plane beyond SSH

            The management plane is the set of services that let someone administer the device.

            • Restrict who connectsAn ACL on the VTY lines with access-class, so only the management subnet can even attempt a login.
            • Dedicated managementIts own interface or VLAN and address (interface vlan 99, ip default-gateway), apart from user traffic.
            • Slow down guessinglogin block-for 120 attempts 3 within 60 locks logins 120 seconds after 3 failures in 60 seconds.
            • Record every attemptlogin on-failure log and login on-success log.
            • Turn off what you do not useno ip http server and no ip http secure-server if no web interface is needed; shut down unused ports.
            Setting transport input none on lines you never use removes them as a path completely.
            HACKTHESOCLesson 105Cisco IOS operations19 / 49

            The login records a SOC detects on

            • Is the source inside the management subnet?
            • Is the time inside a change window?
            • Do failures against several usernames precede a success from one address?
            Read both lines aloud and answer the three questions for each. The pattern across lines, not one line alone, is what points to guessing.

            Logging and monitoring

            Syslog, timestamps, NTP and SNMP: the device as a sensor.

            HACKTHESOCLesson 105Cisco IOS operations21 / 49

            Syslog severity: the digit in the middle of the message

            Messages look like %FACILITY-SEVERITY-MNEMONIC: text. A level sends itself and every more severe level.

            LevelKeywordMeaningExample message
            0 and 1emergencies, alertsSystem unusable; immediate action neededHardware or kernel failure; %SEC_LOGIN-1-QUIET_MODE_ON
            2criticalCritical condition%PORT_SECURITY-2-PSECURE_VIOLATION
            3errorsError condition%LINK-3-UPDOWN
            4warningsWarning condition%SEC_LOGIN-4-LOGIN_FAILED
            5notificationsNormal but significant%SYS-5-CONFIG_I
            6informationalInformational%SEC-6-IPACCESSLOGP
            7debuggingDebug outputOutput of debug commands

            logging trap warnings forwards levels 0 to 4.

            The table merges levels 0 and 1 into one row. Students should be able to read a level straight off any message.
            HACKTHESOCLesson 105Cisco IOS operations22 / 49

            Turn the device into a sensor

            • The buffer is a local RAM ring that disappears at reload
            • The host is the remote collector; trap sets which levels are forwarded
            • Source interface: one stable address on every message, so the SIEM recognizes the device
            Everything a SOC knows about a switch comes from what the device reports, so this configuration is a security control in its own right.
            HACKTHESOCLesson 105Cisco IOS operations23 / 49

            Delivery and time decide whether logs are usable

            • UDP 514Classic syslog: RFC 3164 BSD format, RFC 5424 structured format, RFC 5426 UDP transport.
            • Lost or spoofedNo delivery guarantee and no authentication. Newer releases can send over TCP or TLS.
            • No timestampsWithout service timestamps a log line has no time at all.
            • Leading asterisk*Mar 1 00:03:12.451 means the clock is not authoritative, which breaks cross-device correlation.
            • NTPclock timezone UTC 0 and ntp server 10.10.50.5; check show ntp status. NTP authentication stops clock skewing.
            Correlating a firewall block, a switch event and a login needs a common clock. An attacker who skews the clock can hide events.
            HACKTHESOCLesson 105Cisco IOS operations24 / 49

            SNMP: v2c community strings are shared passwords in clear

            v1 and v2c send the community string in clear text in every UDP 161 packet. v3 adds per-user auth (HMAC-SHA), encryption (AES) and views.

            The defaults public and private are scanned for constantly, and a read-write string can let an attacker change the device. If v2c is unavoidable: read-only, an unguessable string, and an ACL. For the SOC to ingest: %SYS-5-CONFIG_I, logins, port-security violations, ACL log hits, link flaps, reloads and SNMP authentication failures.

            Interface and port security

            Limit which MAC addresses may send on an access port, and recover when it trips.

            HACKTHESOCLesson 105Cisco IOS operations26 / 49

            Port security: limit the MACs on an access port

            Addresses are static, dynamic (forgotten at reload) or sticky (learned, then written into the running-config).

            • Set switchport mode access first: IOS rejects the feature on a dynamic port
            • A violation: a MAC beyond the maximum, or a secured MAC seen on another port
            • Automatic recovery loops if the cause is still present
            Port security is covered here as part of securing the device. MAC learning, VLANs and trunks belong to the switching lessons.
            HACKTHESOCLesson 105Cisco IOS operations27 / 49

            Violation modes: protect is silent, restrict is visible

            ModeFrames and port stateSyslog messageViolation counter
            protectViolating frames dropped; port stays upNoNo
            restrictDropped; port stays upYes, plus SNMP trapYes
            shutdown (default)Dropped; port goes err-disabledYesYes

            Protect produces nothing to ingest, so for a SOC it is the worst choice.

            Restrict keeps the port working while still raising a log, useful where an outage costs more than the risk. Shutdown is the strongest response and the default.
            HACKTHESOCLesson 105Cisco IOS operations28 / 49

            From violation to recovery

            1. 1Violation message%PORT_SECURITY-2-PSECURE_VIOLATION names the offending MAC and the port.
            2. 2Port is err-disabled%PM-4-ERR_DISABLE: psecure-violation error detected on Gi0/5.
            3. 3Link goes down%LINK-3-UPDOWN shows the interface down; show port-security shows Secure-shutdown.
            4. 4Fix the cause firstRemove the unknown device or authorize it, before touching the port.
            5. 5Bounce or auto-recovershutdown then no shutdown, or errdisable recovery (interval 600, 10 minutes).
            Useful checks: show port-security interface, show interfaces status err-disabled and show errdisable recovery.
            HACKTHESOCLesson 105Cisco IOS operations29 / 49

            Four pitfalls of port security

            • Maximum of 1Breaks a desk with an IP phone and a PC. Those ports need 2 or 3.
            • Sticky not savedSticky addresses live in the running-config only. Without a save they are learned again after a reload.
            • Not authenticationMAC addresses can be spoofed, so this is a speed bump. 802.1X is the stronger control.
            • A lead worth chasingA violation on a user port with no plugging-in event: who, what device, which desk?
            Tie the last pitfall to the analyst role: a violation message is only useful if someone asks which physical device caused it.

            Access control lists

            Standard, extended, wildcard masks and direction.

            HACKTHESOCLesson 105Cisco IOS operations31 / 49

            Standard and extended ACLs match on different things

            An ACL is an ordered list of permit and deny statements compared against packets.

            1-99 and 1300-1999

            Standard

            Matches on source address only. Placed close to the destination.

              100-199 and 2000-2699

              Extended

              Matches protocol, source, destination, ports and flags. Placed close to the source.

                Named ACLs use sequence numbers: insert a line between 10 and 20, or delete one with no 20.

                Prefer the named form. Appending to a numbered list is error-prone, and ACLs are the source of many outages.
                HACKTHESOCLesson 105Cisco IOS operations32 / 49

                Processing rules and direction decide what an ACL does

                • Top down, first matchEvaluation stops at the first match.
                • Implicit deny anyEvery ACL ends with an invisible deny. A permit-only list blocks everything else.
                • Specific before generalA permit ip any any placed too early makes later denies unreachable.
                • One per directionOnly one ACL per interface, per direction, per protocol.
                • In versus outInbound is checked on arrival, before routing; outbound on leaving, after routing. Outbound skips router-originated traffic.
                • VTY uses access-classRemote-management access uses access-class on the VTY lines, not access-group.
                Applying the right list in the wrong direction either never sees the traffic or blocks the wrong flow.
                HACKTHESOCLesson 105Cisco IOS operations33 / 49

                Wildcard masks: 0 must match, 1 is ignored

                Subtract the subnet mask from 255.255.255.255 to get the wildcard.

                You want to matchWildcard form
                A /24 subnet0.0.0.255
                A /26 subnet0.0.0.63
                A /22 subnet0.0.3.255
                Host 10.1.50.1010.1.50.10 0.0.0.0, or host 10.1.50.10
                Any address0.0.0.0 255.255.255.255, or any

                Classic mistake: 10.1.10.0 255.255.255.0 ignores the first three octets and matches any address ending in .0.

                Have students derive the /26 and /22 rows themselves by subtracting from 255.255.255.255.
                HACKTHESOCLesson 105Cisco IOS operations34 / 49

                Worked example: users to servers, and a management ACL

                • Specific permits first, an explicit deny with log, then permit ip any any
                • log creates the SOC-visible record; the implicit deny never logs
                • access-class, not access-group, on the VTY lines limits management access
                Logging is rate-limited and summarized every five minutes; log-input adds the ingress interface and source MAC. The record looks like %SEC-6-IPACCESSLOGP: list USERS-TO-SERVERS denied tcp 10.1.10.45(51822) -> 10.1.50.20(3389). Use show access-lists to read match counters.

                Compare the release with known vulnerabilities, and confirm host, severity and counters match the design.

                Uptime and the last reload reason make an unexpected reload stand out.
                HACKTHESOCLesson 105Cisco IOS operations38 / 49

                CDP and LLDP help engineers and help attackers

                What they do

                CDP (Cisco-proprietary) and LLDP (IEEE 802.1AB) announce device identity to directly connected neighbors. Good for mapping a network.

                  The risk

                  The advertisement includes the model, software version and management IP: reconnaissance gold.

                    The fix

                    no cdp enable, and disable LLDP transmission, on user-facing and untrusted ports. Enable them only on infrastructure links.

                    • show cdp neighbors detail
                    • show lldp neighbors
                    The same data that finds where a cable leads also tells an attacker exactly which device and software they are facing.
                    HACKTHESOCLesson 105Cisco IOS operations39 / 49

                    Password recovery shows why the console room must be locked

                    A high-level view; exact steps vary by platform.

                    1. 1Reach ROMMONWith console access, interrupt the boot sequence.
                    2. 2Ignore the startup-configSet the config register to 0x2142; the normal value 0x2102 loads it.
                    3. 3BootThe device comes up without its saved configuration.
                    4. 4Copy startup into runningBring the saved startup-config into the running-config.
                    5. 5Set new secretsReplace the enable and user secrets.
                    6. 6Restore 0x2102 and savePut the register back and save the configuration.

                    Physical console access equals control of the device. no service password-recovery makes recovery erase the configuration.

                    That command blocks takeover but makes a lost password costly. Always keep an off-box backup of the configuration.

                    Worked example: hardening a new access switch

                    Baseline, SSH, logging and port security applied to one device.

                    HACKTHESOCLesson 105Cisco IOS operations41 / 49

                    Block 1: identity, credentials, services off, SSH

                    Management subnet 10.10.99.0/24, NTP server 10.10.50.5, syslog collector 10.10.50.10.

                    • Hostname and domain name satisfy SSH prerequisites and label every log line
                    • Secrets are hashes (scrypt where supported); the no ip http lines remove the web surface
                    • block-for slows guessing; the log lines create the records the SOC detects on
                    no ip domain-lookup stops the switch hanging on mistyped commands that it tries to resolve as hostnames. Use plain secret if the release lacks scrypt.

                    BlockReasoning

                    Block 2: management ACL, lines, time and logging

                    The console (line con 0) uses login local and times out after 5 minutes, exec-timeout 5 0. The VTY lines use individual accounts, accept SSH only, apply the ACL with access-class and time out after 10. All logs are sourced from the management interface so the SIEM sees one consistent address.

                      Key takeaways

                      1. 01The prompt shows the mode; the running-config is RAM and takes effect at once, so save with copy running-config startup-config.
                      2. 02Use enable secret with type 8 or 9 hashes and login local; type 7 is reversible obfuscation, not protection.
                      3. 03Disable Telnet with transport input ssh on the VTY lines; keys and version 2 alone do not.
                      4. 04Severity is the middle digit in %FACILITY-SEVERITY-MNEMONIC; trap warnings sends levels 0 to 4; NTP keeps timestamps trustworthy.
                      5. 05Restrict mode keeps the port up and still logs; protect is silent and shutdown err-disables the port.
                      6. 06ACLs run top down with an implicit deny; wildcard masks are inverted, and the log keyword creates the SOC record.

                      Check your understanding, question 1 of 3

                      A technician sets a hostname, enable secret and ACL, confirms them with show running-config, and leaves. After a power failure the switch boots with its old configuration. Most likely cause?

                      The running-config lives in RAM and takes effect at once, but is lost at power loss. Only the startup-config in NVRAM loads at boot, and only copy running-config startup-config (or write memory) updates it. IOS has no commit step or session rollback.

                      Choose an answer, or press R to reveal it.

                      HACKTHESOCLesson 105Cisco IOS operations47 / 49

                      Check your understanding, question 2 of 3

                      A SOC wants a switch to forward warnings and everything more severe to the collector, but no notifications or informational messages. Which setting does that?

                      A trap level sends that level and every numerically lower, more severe one. Warnings is level 4, so levels 0 to 4 go out and 5 and 6 are held back. Errors would drop the failed-login warnings; notifications and debugging add unwanted noise.

                      Choose an answer, or press R to reveal it.

                      HACKTHESOCLesson 105Cisco IOS operations48 / 49

                      Check your understanding, question 3 of 3

                      Desks have an IP phone and a PC on each access port. Security wants a SIEM alert on any unknown MAC, but a violation must not take down the phone. Which violation mode fits?

                      Restrict drops violating frames, keeps the port up, and raises a syslog message, SNMP trap and counter increment. Protect keeps the port up but is silent. Shutdown err-disables the port, taking the phone down. Sticky is not a violation mode.
