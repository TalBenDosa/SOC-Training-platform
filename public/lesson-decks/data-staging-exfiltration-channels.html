A burglar does not carry the silverware out one piece at a time. They gather everything into one bag by the back door, then make a single trip out.

Data theft follows the same logic: reach the files, pile them on one host, package them, then move the package out once.

This analogy is the spine of the lesson. Each of the four stages leaves different telemetry and needs a different detection.

Why data is gathered before it is stolen

The collection-to-exfiltration pipeline, and the tactic boundary analysts get wrong.

HACKTHESOCLesson 96Staging to egress6 / 35

The four-stage pipeline

StageTechniqueTactic
1. Reach the dataT1039 Data from Network Shared DriveCollection
2. ConsolidateT1074.001 Local Data StagingCollection
3. PackageT1560.001 Archive via UtilityCollection
4. RemoveT1041 / T1052.001 / T1567 / T1048 / T1029 / T1030Exfiltration
Sit with the fact that stages 1 to 3 are all Collection. A SOC alerting only on egress anomalies watches stage 4 and misses three stages that already happened on a host EDR was watching.
HACKTHESOCLesson 96Staging to egress7 / 35
A fresh password-protected archive on a host feels like the theft. It is not, not yet.

Nothing has left the host's storage. The tactic becomes Exfiltration only at the step that moves bytes outside the organisation's control.

Getting this backwards is one of the most common technique-mapping mistakes a working analyst makes. Return to it often.
HACKTHESOCLesson 96Staging to egress8 / 35

Why attackers bother staging and packaging

  • EfficiencyOne clean removal of a single object instead of hundreds of scattered connections, each a chance to be noticed.
  • Evasion of content inspectionA password-protected archive is opaque to DLP engines that match on file contents.
  • Bandwidth and reliabilityMoving one compressed file is faster and survives interruption better than re-reaching a share per file.
These three reasons apply equally to an external intruder with stolen credentials and to a malicious insider. The chain is the same regardless of who is behind the keyboard.

Stage 1: collection at the network share

T1039: an account with ordinary read access reads what interests the attacker.

HACKTHESOCLesson 96Staging to egress10 / 35

Shares are the obvious first target

  • Data is already concentratedA legal client-matter share, a finance drive, an engineering repo mirror all pool the useful data in one place.
  • No need to own the serverOne account with legitimate read access is enough, which describes almost every employee.
  • Living off the landmenuPass mounted shares with net use, then copied with Robocopy, a signed Microsoft tool on every Windows host.
  • Automated crawlersBADNEWS hunts .doc .pdf .ppt .txt; CosmicDuke and Gamaredon target Office files; APT28 collects straight from shares.
Robocopy is signed and used constantly for legitimate work, which is exactly why it blends in. The tooling itself is rarely the signal.
HACKTHESOCLesson 96Staging to egress11 / 35

Reading a single Event ID 5145 record

  • One 5145 is unremarkable: shares exist to be read
  • The lead is volume, scope and timing off this account's baseline
The professional question is never did this account access the share. It is whether the volume, scope and timing of this access match what this account normally does on this share.
HACKTHESOCLesson 96Staging to egress12 / 35
A workstation account reaching for ADMIN$ or C$ it has never touched is a lead.

So is one account generating hundreds of file-access records against one share in minutes, outside its normal hours.

These are the deviations that turn routine share reads into something worth pulling the timeline on.

Section 3 of 6

Stage 2: staging on the local host

T1074.001: consolidate the target files into one folder before anything moves.

HACKTHESOCLesson 96Staging to egress14 / 35

Consolidation, not removal

  • Still CollectionThe data moved from the share onto a host the attacker controls. It has not left the network.
  • A finding in its own rightA large, newly created folder of consolidated sensitive files is worth acting on before any outbound connection.
  • Writable staging pathsC:\Windows\Temp, %TEMP%, C:\ProgramData, /tmp: none need admin rights, so staging needs no privilege escalation.
  • Registry stagingDarkWatchman stages data in the Windows registry, defeating monitoring that only watches file-system writes.
PlugX, Kazuar and QakBot all stage locally before exfiltration. DarkWatchman's registry trick is the one that breaks naive file-creation detection, since no file ever appears.
HACKTHESOCLesson 96Staging to egress15 / 35

A staging copy as EDR process creation sees it

  • /E mirror all subfolders, /Z restartable, /MT:16 sixteen threads for speed
  • /NFL /NDL suppress the file and directory output a human might notice
  • SysHelper is tradecraft for a human skimming a listing, not anti-detection
A lone Robocopy or xcopy event proves nothing: both run constantly. The signal is correlation, does this copy follow a share-access burst from the same account within minutes, to a path the host's software never writes to.
HACKTHESOCLesson 96Staging to egress16 / 35
The signal strengthens sharply when the destination path has no history of legitimate application activity.

EDR captures staging as file-creation telemetry keyed on destination path. A path nothing has ever written to before is the tell.

Tie this back to stage 1: the strongest staging alerts are the ones that chain to the share burst that preceded them.

Stage 3: packaging with an archive utility

T1560.001: compress and usually password-protect the staged files into one object.

HACKTHESOCLesson 96Staging to egress18 / 35

An entirely mainstream toolset

  • Third-party archiversRAR is the most cited across real intrusions, with 7-Zip and WinZip close behind.
  • Built-in Windows toolsmakecab and diantz make .cab files; certutil is repurposed just to Base64-encode data.
  • Unix nativeLinux and macOS ship tar as the native archiver.
  • Over eighty documented groupsAPT1, APT28, APT41, Lazarus, Turla, HAFNIUM and ransomware ops Play, INC Ransom, Wizard Spider, consistently favouring password-protected archives.
The breadth matters: seeing the tool run tells you almost nothing, because every one of these tools runs for legitimate reasons too. Context is everything in this stage.
HACKTHESOCLesson 96Staging to egress19 / 35

A WinRAR archive in EDR telemetry: read the flags

  • -hp encrypts contents AND file names; plain -p leaves the listing readable
  • -m5 maximum compression; -v1900m splits to sit under upload limits
  • The password value is masked here; the -hp flag is the detection point
The -v1900m split is a manual, low-tech cousin of the automated T1030 size-limit evasion later in the lesson. Do not reproduce the literal password; the flag is what the analyst keys on.
HACKTHESOCLesson 96Staging to egress20 / 35
A password-protected archive is not a neutral detail: it is what defeats content-inspection DLP.

An archive made with -hp gives a pattern-matching engine nothing to read. At best a mature tool flags the metadata: a large, fresh, password-protected archive in a non-standard location.

A host or department that has never produced a -hp archive suddenly producing one is a materially stronger signal than an unprotected .zip a user made to email a colleague.

Stage 4: the exfiltration channels

C2, USB, cloud and code repositories, alternative protocols, scheduling and size limits: now the tactic is Exfiltration.

HACKTHESOCLesson 96Staging to egress22 / 35

Seven ways the package leaves, and the signal for each

TechniqueChannelDetection signal
T1041 Over C2 channelThe implant's existing C2 connection: the default, no new destinationA known beacon suddenly sends far more bytes than it receives
T1052.001 Over USBCopy to removable media; works in air-gapped networksNo packet capture: device insertion, then large writes to the new drive letter
T1567.002 Cloud storageUpload to a legitimate service, hidden in normal trafficrclone User-Agent, MEGA or Dropbox API hosts from a host that never used them
T1567.001 Code repositoryPush data to a service such as GitHubgit.exe on a non-developer host; large POSTs to git-receive-pack
T1048 Alternative protocolFTP, SMTP, HTTP/S, DNS or SMB, not the C2 channelDNS tunnelling features in DNS logs
T1029 Scheduled transferUploads only at set times, e.g. nightly at 03:00New scheduled task or cron running an archiver or uploader; same-minute daily egress
T1030 Size limitsSmall fixed chunks under a volume thresholdPairs with any channel; defeats volume-only rules
T1041 is the most common path in real intrusions because it costs the attacker nothing extra. The choice of channel comes down to what blends best with the traffic a network already produces: a USB-blocking policy, for instance, pushes an attacker toward DNS tunnelling.

The pivot is the drive letter: find the mount, then every file created on it in the next few minutes.

Then match file names and sizes against the archive created in stage 3. SPACESHIP copies staged data the instant a drive is inserted.

C2, cloud and code-repository evidence

  • C2 direction flip (T1041)bytes_out/SentBytes in the hundreds of MB on a session that moves KB; a run of large POSTs to one rare domain.
  • Proxy or SWG (T1567.002)rclone/v1.x User-Agent; uploads to mega.nz, g.api.mega.co.nz, content.dropboxapi.com, api.dropboxapi.com.
  • Process telemetryrclone copy or rclone sync pointing a local folder at a named remote, often from a renamed binary.
  • rclone.conf on diskUnder %APPDATA%\rclone\ or ~/.config/rclone/: each remote's provider type and account, so where the data went.
  • Code repository (T1567.001)Large POSTs to github.com paths ending git-receive-pack, or repo API uploads from an account with no dev role.
Cloud storage gives real operational cover: APT41 used OneDrive; Scattered Spider used MEGA, Snowflake and S3. Rclone is real IT tooling, so its presence on an odd host is the signal. MEGA storage hosts also appear as *.userstorage.mega.co.nz.
HACKTHESOCLesson 96Staging to egress25 / 35

DNS tunnelling is caught by its features, not one query

Sources: resolver query logs, Zeek dns.log, or Sysmon Event ID 22.

  • Long namesSubdomain labels near the 63-character maximum, full names approaching 253.
  • High entropyEncoded data looks random; real hostnames contain words.
  • Many unique subdomainsHundreds or thousands under one registered domain from one client.
  • Record typesAn unusual share of TXT or NULL queries, which carry more data than A records.

Most effective query: count distinct subdomains per client per registered domain per hour.

T1030 chunking shows why volume rules fail: APT28 under 1MB, LuminousMoth to beat a 5MB limit, Carbanak just over 4096 bytes, Helminth 23-byte segments over DNS. Rclone ships a chunker; Cobalt Strike chunks automatically.

Detecting the chain and the backup trap

Every stage's shape is also what a legitimate nightly backup produces.

HACKTHESOCLesson 96Staging to egress27 / 35

Correlate the chain, part 1: share reads and archives

  • Normalise join keys: lowercase account names from 5145 and EDR
  • 200+ distinct files from one share in 15 minutes
  • Password-protected archive switch (-hp or -p) on rar or 7-Zip
Three individually weak signals from three log sources. 5145 records the account as SubjectUserName, DeviceProcessEvents as AccountName with different casing, and the firewall has no user at all, only SourceIP.
HACKTHESOCLesson 96Staging to egress28 / 35

Correlate the chain, part 2: egress, order and window

  • Join to egress on the workstation IP that 5145 recorded in IpAddress
  • between filters enforce order: archive within 30 min, egress within 30 min
  • A plain join on account matches a Monday read with a Friday archive
Sample hit: m.chen on WKS-0233 reads 642 files from Finance$ at 01:12, a rar -hp archive at 01:29, then 1,873 MB to g.api.mega.co.nz at 01:45. Interactive account, finance share, consumer cloud: none of the backup-legitimacy checks can pass.
HACKTHESOCLesson 96Staging to egress29 / 35

What separates a backup from an attack, and it is not size

The account

A backup runs under a dedicated service account like svc-backup, never a human's interactive login.

The documentation

A legitimate job ties to a change ticket or a standing, approved config IT can point to.

The consistency

Same time, same destination, roughly same volume, night after night. An attack is a one-off with no history.

The destination

The organisation's own sanctioned repository or cloud account, never an unrelated personal service.

If shape and volume alone decided the verdict, every backup would be a permanent false positive.

None of the four discriminators is transfer size. Drill that: the shape and volume are precisely what the attack copies, so they cannot be the thing that clears the case.
HACKTHESOCLesson 96Staging to egress30 / 35

The investigation workflow

  1. 1Identify the triggering stageUnusual share access, a new archive, or a large egress.
  2. 2Walk the chainLook backward and forward for matching activity, same host and account, tight window.
  3. 3Check the account typeInteractive human login, or a documented service account?
  4. 4Check for a ticketA change ticket or standing documentation for the job?
  5. 5Check the baselineHas this exact pattern recurred consistently before?
  6. 6Check the destination, then ruleSanctioned infrastructure closes it; any context check missing escalates to containment.
All four context checks pointing to legitimate closes the case. Any one missing escalates. This is how the four-stage pipeline turns into an actual verdict.

Key takeaways

  1. 01The pipeline is T1039, T1074.001, T1560.001 (all Collection), then an Exfiltration channel. Only the final removal step is Exfiltration.
  2. 02T1041 over C2 is the default: a known beacon suddenly sends far more than it receives. USB lives in 6416, 1006 and UsbDriveMounted.
  3. 03A password-protected archive (WinRAR -hp hides file names too) defeats content-inspection DLP; a fresh one just before egress is telling.
  4. 04Seeing the tool run proves nothing. Correlate stages with normalised join keys and enforced 30-minute windows.
  5. 05T1030 and T1048 sub-techniques beat volume and protocol thresholds; DNS tunnelling is the hardest to catch and high-confidence when found.
  6. 06Backups walk the identical nightly shape. The discriminator is not shape or volume: it is the account, a ticket, a baseline, the target.
