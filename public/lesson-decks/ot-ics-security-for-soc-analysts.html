Section 1 of 5

What OT and ICS actually are

The vocabulary, the Purdue Model, and the one inversion that explains everything.

HACKTHESOCLesson 97OT/ICS for SOC6 / 30

Three terms, built from zero

  • OTOperational Technology: hardware and software that directly monitors and controls physical equipment, a valve, a turbine, a dosing pump.
  • ITInformation Technology: stores, moves and processes information, email, databases, spreadsheets.
  • ICSIndustrial Control System: the umbrella term for the OT that automates an industrial process end to end.
Almost none of this vocabulary appears elsewhere in a SOC curriculum, so define it plainly before anything else.
HACKTHESOCLesson 97OT/ICS for SOC7 / 30

The building blocks you meet in every plant

TermWhat it is
PLCRuggedized computer running a fixed loop: read inputs, run logic, write outputs, continuously
RTULike a PLC but for the field: telemetry over serial links, on pipelines and substations
DCSThe PLC concept scaled to a whole facility under one config, as in refineries
HMIThe operator's screen, usually a Windows PC with vendor software to view values, send commands
SCADANot a device: the architecture of HMIs, servers and links supervising controllers wide-area
SCADA is the common misnomer: students call a device SCADA, but it is the whole supervisory system, not any one box.

The Purdue Model: where everything sits

LevelNameWhat lives here
5EnterpriseCorporate email, internet, enterprise IT
4Business logisticsERP, scheduling, business systems
3.5Industrial DMZFirewalled buffer: all IT-OT traffic should cross here
3Site operationsMES, historian databases logging process values
2Area supervisoryHMI screens, SCADA servers for a plant area
1Basic controlThe PLCs, RTUs and DCS controllers running the logic
0Physical processSensors, actuators, motors, valves, pumps
The rule that matters: each level talks mainly to its neighbours, and every north-south IT-OT hop should cross Level 3.5. An engineering laptop bridging Level 5 straight to Level 1 collapses the whole model.
HACKTHESOCLesson 97OT/ICS for SOC9 / 30
IT ranks Confidentiality, Integrity, Availability. OT inverts it to AIC: Availability first.

A water plant cannot reboot on a patch schedule; downtime has physical, sometimes life-safety consequences. Nobody minds an outsider reading a temperature, everybody minds them changing it.

This single inversion explains why controllers run software ten to twenty years old by design: patching can invalidate the safety certification the device was granted for one exact configuration.

Why OT protocols trust everyone

In their base, legacy form, Modbus, DNP3, S7comm and EtherNet/IP do not authenticate the sender.

HACKTHESOCLesson 97OT/ICS for SOC11 / 30

Four protocols that ask no questions

ProtocolPortTypical use
Modbus/TCP502/TCPMost widely deployed industrial protocol, generic across sectors
DNP320000/TCPPower grid and water utility telemetry, RTUs to a SCADA master
S7comm102/TCPSiemens S7-series PLC programming and engineering traffic
EtherNet/IP44818/TCPDiscrete manufacturing and factory automation (built on CIP)

Secure variants exist (DNP3 SAv5/IEEE 1815, CIP Security, S7CommPlus integrity, Modbus/TCP Security on 802), but few brownfield plants use them.

EtherNet/IP also uses 2222/UDP. In their base form all four share the identical design gap: no username, no password, no encryption. The original, unauthenticated versions still carry most of the traffic.
HACKTHESOCLesson 97OT/ICS for SOC12 / 30
No authentication was not an oversight. It was a closed, physically isolated serial world with no attacker who could reach the wire.

Any host that can route a packet to port 502 can read or write with the same authority as the plant's own engineering workstation. None of the four can ask 'are you allowed to do this?'

The threat model simply did not include someone routing a packet in from outside, because nothing outside could physically reach the wire.
HACKTHESOCLesson 97OT/ICS for SOC13 / 30

On the wire, the function code is the whole story

A read

Modbus function code 3 or 4: an operator display simply refreshing a number on screen. Harmless.

  • Invisible routine noise

A write

Function code 6 (Write Single Register) or 16 (Write Multiple): an instruction that changes what the physical process does.

  • Changes reality, not a display

Same protocol, port and controller, opposite consequences. Only the function code and the source identity tell them apart, never a credential.

Drill this: the protocol name and port number carry no signal on their own. Source and function code are what the analyst actually reads.
HACKTHESOCLesson 97OT/ICS for SOC14 / 30

How the isolation assumption broke, and what exploits it

Air-gapping was the old answer; IT/OT convergence eroded it.

  • ConvergenceHistorians feed data up to Level 4; vendors expect remote VPN support; engineers' laptops touch both networks in a week.
  • T0883 Internet Accessible DeviceICS reachable over weak remote access. The Bowman Avenue Dam was reached via a cellular modem with a brute-forceable password.
  • T0822 External Remote ServicesVPNs, Citrix and other remote-access services used as entry points into the control-system network.
  • T0886 Remote ServicesFiled under BOTH Initial Access and Lateral Movement: RDP, SSH or SMB can be the way in, or the pivot once inside.
  • T1694.001 Default CredentialsOnce inside: vendor defaults, often in a public manual, never changed. Lateral Movement and Persistence, formerly T0812.
Default Credentials is not Initial Access in ATT&CK for ICS; it is now Insecure Credentials: Default Credentials. Each convergence route is a legitimate, often contractually required business need, and also a path from an IT-side compromise into OT.

How attackers operate on the plant floor

Four real incidents, mapped to their ATT&CK for ICS technique IDs.

HACKTHESOCLesson 97OT/ICS for SOC16 / 30

A decade of documented OT attacks

T0836 Modify Parameter

Stuxnet 2010

Drove Siemens S7-300 PLCs to push centrifuge motor speed out of safe bounds, while feeding the HMI falsified readings.

T0886 Remote Services

TRITON 2017

TEMP.Veles reached a Triconex Safety Instrumented System via RDP jump boxes, the first ICS attack built to enable physical harm.

T0855 and T0831

Industroyer 2016

Sandworm toggled Kyiv substation breakers open via native protocols, from a device dual-homed on IT and OT.

T0883 and T0886

Oldsmar 2021

A remote session raised sodium hydroxide dosing 100x. Operator reversed it; alarms would have caught it anyway.

TRITON targeted the one system whose only job is to shut the process down safely, which is why it is regarded as the first attack designed to enable loss of life. It was found only because a bug tripped an unplanned shutdown.

Section 4 of 5

Recognizing an OT intrusion on the wire

What a real intrusion looks like versus routine, legitimate engineering traffic.

HACKTHESOCLesson 97OT/ICS for SOC20 / 30

Five signs, in the order they appear

  1. 1A host that does not belongA corporate or contractor address with zero prior OT-protocol history. The strongest early tell
  2. 2An address sweep (T0846)Short, low-byte connections hitting a range of controllers in seconds. No single task does so.
  3. 3An unauthorized command (T0855)A write (function code 6 or 16) from a source with no engineering history, not a read.
  4. 4A parameter actually changesA register for motor speed, dosing or a breaker moves: T0836 or T0831. Physical consequence.
  5. 5Firmware or logic changesThe control program itself uploaded or modified. Persists across reboots, redefines normal.
T0846 Remote System Discovery has sub-techniques Port Scan (.001) and Multicast Discovery (.003). The decisive moment in every incident here is a write, not a read.
HACKTHESOCLesson 97OT/ICS for SOC21 / 30

A write from an unknown source in a Zeek modbus log

  • 10.4.1.20 reading all day is invisible noise: the engineering station
  • 10.9.3.88 writing 40010 is the incident: unknown source plus a write
  • Zeek reconstructs func, unit, addr and value with no agent on the PLC
Same protocol, same port, same destination controller: only the source identity and the function code separate noise from incident. This is the discriminator the whole section builds to.

Section 5 of 5

Professional OT detection

Passive sensors, Zeek and Suricata, and why you cannot put EDR on a PLC.

HACKTHESOCLesson 97OT/ICS for SOC23 / 30

Why there is no endpoint agent

  • No spare resourcesA PLC runs a minimal real-time OS with barely enough CPU and memory for its own control logic, let alone a security agent.
  • It voids certificationUnapproved software can void vendor support and invalidate the safety certification, granted for one exact tested configuration.
  • The consequenceAlmost nothing below Purdue Level 2 can run an agent, so every sign in this lesson must be caught another way.
This reframes OT detection from the ground up: the EDR-and-Sysmon model the rest of the platform teaches simply is not available here.
HACKTHESOCLesson 97OT/ICS for SOC24 / 30

Two passive sensors read a copy of the traffic

A SPAN port (switch mirroring) or a hardware TAP copies traffic without sitting inline.

Zeek

Reconstructs application-layer meaning: decodes Modbus and DNP3 into structured fields, the exact function code, unit ID, register address and value.

  • Answers read or write, to which register
  • No controller touched

Suricata

Evaluates traffic against ICS-aware signatures: a write code from outside the engineering block, or a client enumerating many unit IDs.

  • Immediate human-readable alert
  • No manual log reading

Passive means read-only: the sensor never sits inline where it could add latency or become a failure point in a safety loop.

Zeek tells you what happened in full detail; Suricata fires the moment a known-bad pattern appears. They complement each other.
HACKTHESOCLesson 97OT/ICS for SOC25 / 30

Passive monitoring detects; these controls prevent

  • Command allowlistingRestrict which sources may issue write function codes to a controller, typically only the plant's engineering workstation.
  • Network segmentationEnforce the Level 3.5 DMZ in practice: a firewall forcing all north-south traffic through a logged chokepoint.
  • NIST SP 800-82r3The standard reference for OT architecture, defense in depth and Purdue-aware network design.
  • CISA ICS advisoriesAn ongoing feed of ICS/SCADA vulnerability and threat advisories, the OT equivalent of the CVE feeds you already track.
Segmentation is exactly the boundary every incident in this lesson crossed uncontrolled, so enforcing it closes the single most common path.

Key takeaways

  1. 01OT ranks Availability over Confidentiality (AIC, not CIA): downtime carries safety consequences, so controllers run old software by design.
  2. 02The Purdue Model runs Level 0 to 5 with Level 3.5 the mandatory IT-OT chokepoint; every incident here is that boundary crossed uncontrolled.
  3. 03Base Modbus (502), DNP3 (20000), S7comm (102), EtherNet/IP (44818) lack authentication: function code and source are the signals.
  4. 04Four incidents map to real ATT&CK for ICS IDs: Stuxnet T0836, TRITON T0886, Industroyer T0855 and T0831, Oldsmar the T0883/T0886 pattern.
  5. 05OT detection is passive: Zeek decodes protocols and Suricata fires ICS signatures off a SPAN or TAP copy, because no agent can run on a PLC.

Check your understanding, question 1 of 3

Zeek shows two Modbus/TCP sessions to one controller on port 502: function code 4 from the usual engineering workstation, and function code 16 from a corporate-VLAN address with no Modbus history. Which reading is correct?

Base Modbus/TCP has no identity check: any host reaching port 502 has the workstation's authority, so source and function code decide. Codes 3 and 4 are reads, 6 and 16 writes. Restricting writers is a network allowlisting control, not a Modbus feature.

Check your understanding, question 2 of 3

Industroyer's payload sent breaker-open commands to substation protective relays from a source those relays were never meant to accept commands from. Which ATT&CK for ICS technique describes sending those commands?

T0855 is sending a command a device was never meant to accept from that source. T0831 is also documented for Industroyer but names the resulting change to the process. T0836 is Stuxnet's technique; T0886 is how intruders enter or move, as in TRITON.

Check your understanding, question 3 of 3

A Suricata ICS signature fires on a Modbus write function code from a host outside the engineering address block. Nothing runs on the destination PLC. What gave Suricata and a companion Zeek sensor visibility into this traffic?

Passive monitoring: a SPAN port or TAP copies traffic to the sensor, never inline in a safety loop. Inline adds latency and a failure point; the write went straight to the PLC, so an HMI agent misses it; allowlisting prevents, it is not the visibility source.
