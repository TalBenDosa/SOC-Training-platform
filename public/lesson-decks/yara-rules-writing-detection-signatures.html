You found one piece of malware. The bigger question is: where else is this, or anything like it, hiding?

YARA, the pattern-matching swiss army knife for malware researchers, answers it by turning a description into a scannable rule.

No prior background assumed. The lesson moves from what a signature is to running, writing and deploying rules.

Section 1 of 10

What YARA is and why it exists

Identify and classify files, memory or processes by patterns you define.

HACKTHESOCLesson 80YARA rules6 / 48

A fingerprint matches one person; a description matches a family

Fingerprint

File hash (SHA-256)

Identifies one exact file. Change a single byte and the hash is completely different, so it misses even trivially modified variants.

Description

YARA rule

Matches on content patterns: strings, byte sequences. One good rule catches a whole family, including future variants tweaked to change the hash.

Like a description given to a sketch artist: 'tall, brown jacket, scar on the left hand' can identify people the artist never saw.
HACKTHESOCLesson 80YARA rules7 / 48

Where YARA is used

  • Malware researchClassifying and grouping samples into families.
  • Threat intelligenceVendors and CERTs publish rules so others can detect a threat.
  • Incident response and huntingScanning an environment for known-bad patterns.
  • Inside security productsEDRs, sandboxes and scanners run YARA rules under the hood.

Rules are just text, so they are shareable: you both consume others' detections and create your own.

Encode what the malware looks like once, then scan everywhere automatically. Checking each file by hand is impossible.

Section 2 of 10

The anatomy of a YARA rule

Three parts: meta, strings, condition.

HACKTHESOCLesson 80YARA rules9 / 48

A complete rule in three sections

  • meta: documentation only, no effect on matching
  • strings: named $ patterns: text, hex (with wildcards) or regex
  • condition: matches on the URL, or the API name and byte pattern together
That 'or' plus grouped 'and' is typical: catch a sample by its obvious marker, and stealthier variants by a combination of weaker signals.
HACKTHESOCLesson 80YARA rules10 / 48
The condition is where rule-writing skill lives.

Boolean logic, counts like 2 of ($a, $b, $c) or all of them, file-size checks like filesize < 200KB, and location tests. Too loose: false positives. Too tight: missed variants.

Good meta is a mark of a professional rule, but the condition controls the core trade-off.
HACKTHESOCLesson 80YARA rules11 / 48

String modifiers change how a string matches

ModifierWhat it does
nocaseCase-insensitive: "powershell" nocase catches POWERSHELL
wide / asciiUTF-16LE, as Windows stores many strings / single-byte; state both to match either
fullwordNot a substring: "cmd" fullword matches cmd, not cmdlet
xorString XOR-encoded with a single byte; xor(0x01-0xff) limits keys
base64 / base64wideThe three Base64 permutations / Base64 stored as UTF-16
privateUsed by the condition but suppressed from -s output

Base64 modifiers never search the plaintext: add a second string, e.g. $u1 = "..." wide plus $u2 = "..." wide base64.

This is the full, finite set. Modifiers combine, e.g. "cmd" nocase wide fullword. YARA applies wide/ascii first and base64/base64wide after.
HACKTHESOCLesson 80YARA rules12 / 48

Hex-string syntax makes signatures resilient

SyntaxMeaningExample
??Any single byte{ 6A ?? 68 }
4? / ?ANibble wildcard{ 4? } matches 40 to 4F
~00Any byte except the given one{ ~00 } any non-zero byte
[n-m]Jump n to m arbitrary bytes{ E8 [2-4] 5D }
[n-] / [-]Unbounded jump{ AA [10-] BB }
( AA | BB )Alternatives at that position{ 68 ( 6A 40 | 56 ) C3 }
Pin bytes that are structurally fixed, like an opcode, and wildcard what the compiler varies, like an operand or address. One rule then matches many builds.
HACKTHESOCLesson 80YARA rules13 / 48

Rule-level structure: tags, global and private rules

Tags

rule Downloader : trojan network { ... }. Filter output to tagged rules with yara -t trojan.

global rule

global rule Only_PE { condition: uint16(0) == 0x5A4D }. Evaluated first; other rules match only if all globals pass.

private rule

Never reported alone; referenced by name in another condition, e.g. Helper and $marker.

Shared building blocks become private rules and file-type gates become global rules, keeping large rule sets DRY.

Section 3 of 10

Running YARA from the command line

Point it at a rule file and a target; it reports matches.

HACKTHESOCLesson 80YARA rules15 / 48

Basic run, and -s to see which strings fired

  • A match prints the rule name and the file path
  • No output means no match: silence is a result, not an error
  • -s shows each string and its offset: strong indicator or weak combo?
No output is a common beginner surprise. -s is invaluable while writing a rule.
HACKTHESOCLesson 80YARA rules16 / 48

Recursive scans and meta in the output

-r recurses, -w suppresses warnings, -m prints meta so an analyst can act without opening the rule file. In pipelines, exit code and match output drive a flag, an alert, or a quarantine action.
HACKTHESOCLesson 80YARA rules17 / 48

Everyday yara flags

FlagWhat it does
-c / -nCount matches per file / print what did not match
-t TAG / -i NAMEOnly rules with a tag / only one named rule
-d VAR=VALSet an external variable the condition can reference
-p NScan with N threads
-a NAbort a file after N seconds, protecting against pathological rules
-f / -L / -g / -eFast scan / string length / tags / namespace

Production sweep: yara -r -w -s -m -p 4 -a 60 rules/ C:\Users\

Read the sweep as: recurse, hide warnings, show strings and meta, four threads, give up on any file after 60 seconds.

Section 4 of 10

Specific but not brittle

Every good rule balances false positives against missed variants.

HACKTHESOCLesson 80YARA rules19 / 48

Two ways a rule fails

False positives

Too broad

Keyed on a common string like CreateProcessA, found in thousands of legitimate programs. A noisy rule is worse than none: it trains analysts to ignore it.

Brittle

Too narrow

Depends on one hyper-specific detail, like the exact C2 URL. Breaks when the attacker tweaks it, adding little over a hash.

The mental model is a dial between precision and coverage, tuned through the condition.
HACKTHESOCLesson 80YARA rules20 / 48

Principles for rules that work

  1. 1Anchor on the hard to changeInternal strings, unusual constants, code bytes tied to function, not cosmetics.
  2. 2Combine weaker indicators2 of them or $a and $b: each is common, the combination is rare.
  3. 3Constrain with contextBound filesize or file type to cut false positives cheaply.
  4. 4Test both waysCatch known-bad samples, stay quiet on known-good files. Document in meta.
  5. 5Avoid over-fittingEvery string from one file is essentially a fancy hash. Capture the family.
A rule you have not tested against clean files is a false-positive incident waiting to happen.

Condition operators in depth

Counting, positioning and bounding matches.

HACKTHESOCLesson 80YARA rules22 / 48

Operators that turn presence into precision

OperatorExampleMeaning
of2 of ($a, $b, $c)At least two matched; also all of them, any of them
for...offor all of ($a, $b, $c) : ( @ < 1000 )Every string occurs before offset 1000
at$a at 100Found starting exactly at offset 100
in$a in (1000..2000)Found within an offset range
filesizefilesize < 500KBCheap size ceiling; file scans only
entrypoint$m in (entrypoint..entrypoint+200)Near where execution starts (PE and ELF)
for...of can test where strings matched, which plain of cannot. Packers and loaders place their unpacking stubs near the entry point.
HACKTHESOCLesson 80YARA rules23 / 48

Several operators describing one shape

  • Under 500KB
  • At least three of four process-injection API names
  • The byte pattern within 200 bytes of the entry point
Meta trimmed to fit. Each clause narrows the match; together they describe a shape far more specific than any single string.

Modules: pe, math and hash

Structural, statistical and exact-fingerprint facts about a file.

HACKTHESOCLesson 80YARA rules25 / 48

The pe module reads the Windows executable format

Field / functionWhat it tells you
pe.is_peA valid PE: a cheap sanity check first
pe.imphash()MD5 of the normalised import table
pe.number_of_sections / pe.machineSection count / target CPU architecture
pe.is_dll() / pe.is_32bit() / pe.is_64bit()Quick structural checks
pe.imports("kernel32.dll", "CreateRemoteThread")Imports a specific function from a specific DLL
pe.exports(...) / pe.timestampExports a function / compiler build timestamp
Modules are activated with an import statement at the top of the rule file.
HACKTHESOCLesson 80YARA rules26 / 48

imphash survives cosmetic changes

  • Variants from one toolchain call the same functions in the same order
  • Different strings and file hash, same imphash
  • A durable, family-level indicator
A direct answer to 'anchor on what is hard for the attacker to change'.
HACKTHESOCLesson 80YARA rules27 / 48

math measures randomness; hash blends exact and pattern

Entropy runs 0 to 8; packed and encrypted data is high, but so are ZIP and JPEG, so treat it as an extra vote. The hash module offers md5, sha1, sha256 and crc32. Two example rules shown together.
HACKTHESOCLesson 80YARA rules28 / 48
A rule spanning several evidence axes is far harder to evade by editing one thing.

pe adds structure, math adds statistics, hash adds exact fingerprints, strings add content. Evasion means changing imports, entropy and strings at once.

Compare that to editing a single URL to break a string-only rule.

Using YARA in the SOC

Turn knowledge about one threat into action across the estate.

HACKTHESOCLesson 80YARA rules33 / 48

Four recurring SOC workflows

  • Hunting across the estateScan files, and also running processes and memory images, to catch fileless and injected malware.
  • Consuming shared intelligenceRun rules from threat-intel reports and CERT advisories to check exposure to a new threat fast.
  • Feeding products and pipelinesSandboxes classify detonated samples, EDRs and scanners run rule sets.
  • RetrohuntingRun a new rule against a historical sample archive to see if the threat was present before.
YARA converts a single discovery into scalable detection.
HACKTHESOCLesson 80YARA rules34 / 48

Memory forensics plus YARA: find every infected host

  1. 1malfind finds injected codeVolatility surfaces an implant in one host's memory.
  2. 2Extract distinctive stringsPull what makes that code recognisable.
  3. 3Write a YARA ruleExpress the implant as a pattern.
  4. 4Scan every endpoint's memoryFind every machine carrying the same implant.
YARA is the content-pattern detector alongside Wireshark (traffic), Volatility (live state) and timeline analysis (sequence).
HACKTHESOCLesson 80YARA rules35 / 48

Three rule languages, split by data source

YARA is only one of three rule languages you will meet in the same threat report.

Files and memory

YARA

Content patterns in files, processes and memory images.

Log events

Sigma

Vendor-neutral YAML detection logic over log events (process creation, sign-ins), converted into your SIEM's query language.

Network traffic

Snort / Suricata

Rules that match packets on the wire.

Pick by data source: files and memory go to YARA, SIEM log fields go to Sigma, network traffic goes to Snort or Suricata.

Scanning memory, fast rules, and YARA tooling

Live processes, memory images, rule performance, and the ecosystem around YARA.

HACKTHESOCLesson 80YARA rules37 / 48

Scan a live process, then a memory image with attribution

  • A PID as the target reads that process's memory as it is now, after unpacking
  • Needs rights to read it: elevated on Windows, root or ptrace on Linux
  • windows.vadyarascan reports the owning PID; yarascan.YaraScan scans more broadly
A hit inside svchost.exe in a VAD region that malfind also flags (private, executable, no backing file) is far stronger evidence than either result alone. Add --pid 4120 to limit vadyarascan to one process.
HACKTHESOCLesson 80YARA rules38 / 48

Slow rules come from bad atoms: fix the warning

YARA picks a short atom (up to four bytes) per string and checks the full string only where an atom hits.

CauseFix
Very short strings, or hex starting with wildcards ({ ?? ?? 00 00 ... })Lengthen the string or start it with fixed, uncommon bytes
Common atoms such as 00 00 00 00 or FF FF FF FFChoose a different, rarer stretch of the same code
Unbounded regex like /http.*\.exe/Bound it (/http[^\s]{1,80}\.exe/) or use two plain strings in the condition
Expensive conditions evaluated firstPut uint16(0) == 0x5A4D and filesize < 2MB before loops, entropy or hash calls

Compile-time warning to treat as a bug: string "$a" may slow down scanning

YARA is fast because it does not try every string against every byte. A string with no good atom forces slow checking everywhere.

Tooling you will see around YARA

  • yarGenDrafts rules from a sample's strings, minus those in a large goodware database. A starting point to prune, never finished.
  • YARA-XVirusTotal's Rust rewrite with its own yr CLI (yr scan implant.yar sample.exe); test your rule set, some edge syntax is rejected.

Livehunt and Retrohunt are how researchers test a rule against millions of real files before deploying it internally.

Section 10 of 10

Limits of YARA and complementary tools

Neither over-trust a match nor under-trust a silent scan.

HACKTHESOCLesson 80YARA rules42 / 48

Packing hides strings until runtime

The problem

Packed or encrypted malware keeps its real strings and code out of the raw file. A rule from static strings may match zero samples once repacked.

Scan memory

Packed malware unpacks itself to run, so a memory image often holds the visible strings the disk file hides.

Target the packer

Flag the packer or loader stub as a triage signal when the payload is too variable.

This is one of the most effective ways around packing.
HACKTHESOCLesson 80YARA rules43 / 48

Other operational limits

  • Deliberate string changesAn attacker reading a published rule swaps a URL or mutex. Durable structural indicators last longer.
  • False positives over timeSoftware inventories change; re-validate rule sets against current known-good baselines.
  • Performance at scaleVery broad hex patterns and unbounded regexes are slow as well as noisy.

Hashing, YARA, sandbox analysis and memory forensics are layers; a clean YARA scan is not proof of a clean estate.

A clean scan is evidence of absence within YARA's niche only.
HACKTHESOCLesson 80YARA rules44 / 48

Key takeaways

  1. 01YARA matches content patterns, so one rule can catch a family where a hash matches one exact file.
  2. 02Rules have meta (docs), strings (text, hex, regex with modifiers) and a condition (the logic).
  3. 03yara rule target prints rule and path on a match; silence means no match; -s, -r and -m help verify.
  4. 04Anchor on hard-to-change indicators, combine weak ones, bound filesize, test against bad and good.
  5. 05Packed malware shows in memory: scan a PID, or an image with windows.vadyarascan, and corroborate with malfind.
  6. 06Fix "may slow down scanning" warnings; YARA covers files and memory, Sigma logs, Snort/Suricata packets.

Check your understanding, question 2 of 3

A family stores its C2 URL (<url>) as UTF-16, and some samples Base64-encode those same UTF-16 bytes into an ordinary ASCII config blob. How do you cover both forms in one rule?

Base64 modifiers search only the encoded forms, never the plain string, so you need $u1 for the raw UTF-16 URL and $u2 for its Base64 as ASCII text. base64wide looks for Base64 stored as UTF-16, and xor is single-byte XOR, unrelated to Base64.
