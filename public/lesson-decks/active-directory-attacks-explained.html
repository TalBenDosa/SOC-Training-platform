Section 2 of 11

Enumeration before exploitation

Mapping the terrain leaves a footprint in volume and pattern, not in any single query.

HACKTHESOCLesson 33Active Directory attacks9 / 46

LDAP reads are normal; the sweep is not

Ordinary LDAP use

Any authenticated user can query users, groups, computers and OUs. Applications make occasional targeted queries. This broad read access is by design.

Enumeration sweep

One account suddenly generates an enormous volume of broad, systematic queries across the whole directory in a short window, unlike its own history.

Enumeration is a threat-hunting problem as much as a detection-engineering one.

No signature fires because every individual query is legitimate. The signal is volume and pattern from one account or source.
HACKTHESOCLesson 33Active Directory attacks10 / 46

Two enumeration signals that predict the next step

  • SPN enumerationA query for every account carrying a Service Principal Name yields a target list of service accounts. Kerberoasting is very likely next.
  • Attack-path graphingBloodHound ingests LDAP data and computes the shortest attack path from one account to Domain Admin through chains of permissions.
  • AD CS container queriesA burst of LDAP queries against the certificate configuration container warns of template abuse ahead.
SPN enumeration is purposeful preparation, not incidental reconnaissance. Seeing it should raise your attention on 4769 for that account.
HACKTHESOCLesson 33Active Directory attacks11 / 46
The risk question is not 'does this account have a dangerous right?' but 'does a chain of rights connect it to Domain Admin?'

Nested groups, delegated permissions and local admin rights each look harmless alone. Assembled as a graph, they become a path.

This reframing is why 'attack path' is central to AD security thinking, and why defenders should run the same graph analysis on their own domain.

Stealing and abusing credentials

Four credential techniques, and the log signal each one leaves.

HACKTHESOCLesson 33Active Directory attacks13 / 46

Four credential techniques, four signals

TechniqueWhat it achievesWhat the defender sees
Kerberoasting T1558.003Service tickets taken offline to recover a service account password4769 bursts with RC4 (0x17) across many SPNs
AS-REP Roasting T1558.004Targets accounts with Kerberos pre-authentication disabled4768 for a pre-auth-disabled account
Pass-the-Hash T1550.002Authenticates with a password hash instead of the passwordLogons from hosts and accounts that do not normally pair
Pass-the-Ticket T1550.003Reuses a stolen Kerberos ticketTicket use from a machine that never requested it
All four end the same way: the attacker holds a usable credential without ever knowing or typing the password.
HACKTHESOCLesson 33Active Directory attacks14 / 46

Why service accounts are the favourite target

Set once, forgotten

Service accounts often keep old, weak or never-rotated passwords because they sit outside normal password hygiene.

RC4 makes it practical

Tickets encrypted with RC4 (0x17) instead of AES are what make offline cracking feasible. Cracking happens offline, generating no further logs.

One legacy setting

A single account with pre-authentication turned off, often left for old application compatibility, opens AS-REP Roasting.

The detection has to happen at ticket-request time, because the cracking itself never touches your network.

Section 4 of 11

Escalation to domain dominance

How a privileged foothold becomes control of the whole domain, sometimes permanently.

HACKTHESOCLesson 33Active Directory attacks16 / 46

Three paths to owning the domain

T1003.006

DCSync

A legitimate-looking replication request from an account entitled to make it. Needs no code on a DC. Signal: 4662 for replication rights from a non-DC source.

T1558.001

Golden Ticket

Forged TGTs built from the krbtgt hash. Remediation: reset the krbtgt password twice, because the previous hash stays valid after one reset.

T1558.002

Silver Ticket

Forged service ticket for one service. Narrower, but stealthier: it never touches a DC, so DC-side Kerberos events are absent.

This is why some AD incidents need remediation far more drastic than resetting one user's password.
HACKTHESOCLesson 33Active Directory attacks17 / 46
Ask whether a credential grants domain-dominance-equivalent capability, not whether the account is a Domain Admin.

krbtgt compromise, DCSync-capable rights and forged tickets all deliver that outcome without ever touching the Domain Admins group.

Group membership is the obvious thing to audit; it is not the only path to the same power.

Where to start when AD compromise is suspected

  1. 14769Pull RC4 usage and SPN-request volume anomalies.
  2. 24768Check activity from pre-auth-disabled accounts.
  3. 34728 / 4732Any unexpected privileged group addition in the window.

A hit on any one checkpoint is a reason to go looking for the others.

A 4769 burst without a matching 4728 does not mean the chain stopped. The next step may not have happened yet, or is logged where you are not looking.

Worked example: an attack chain in the log

Four entries, one account, one workstation IP.

HACKTHESOCLesson 33Active Directory attacks23 / 46

svc-reports, from 10.30.6.19, in order

  • 42 SPNs in 90 seconds with RC4: the Kerberoasting signature
  • The krbtgt 4769 with AES (0x12) is normal: do not over-read it
  • 4662 from a workstation IP, then self-added to Domain Admins
The krbtgt line is included on purpose, to train the reader not to flag ordinary Kerberos activity.
HACKTHESOCLesson 33Active Directory attacks24 / 46

Reading the four entries as one story

  • Line 1Burst of 42 4769 events, 42 services, RC4: Kerberoasting.
  • Line 2A krbtgt service ticket with AES: everyday Kerberos, not a signal.
  • Line 3A reporting account with no replication need invokes Replicating Directory Changes All from a workstation: DCSync.
  • Line 4The same account added to Domain Admins: the expected outcome after the DCSync.

Same account, same source IP, minutes apart: correlate on both, and escalate as domain compromise.

Read alone, the 4728 might be waved through as admin work. Read after the first three lines it is not.

HACKTHESOCLesson 33Active Directory attacks27 / 46
A 5136 write to a computer's RBCD attribute by an account with no admin role over it is the tell.

It is typically reached through a write permission on the object, not through any credential theft.

Unconstrained delegation is the oldest and most dangerous form; constrained was Microsoft's first fix; RBCD moved control to the target.

Section 8 of 11

Abusing the ACL: DACL attacks

Permissions on AD objects as an escalation and persistence path.

HACKTHESOCLesson 33Active Directory attacks29 / 46

The ACEs that matter most

Every AD object has a security descriptor. These rights on a sensitive object are the dangerous ones.

  • GenericAllReset the user's password, change any attribute, or add group members. Subsumes the rest.
  • GenericWriteWrite attributes such as delegation settings or logon scripts; on a group, add members.
  • ForceChangePasswordReset a user's password without knowing the current one.
  • AdminSDHolderRights placed on this object propagate to protected accounts: a persistence technique.
BloodHound draws these as graph edges because the danger is the chain of rights, not any single checklist item.
HACKTHESOCLesson 33Active Directory attacks30 / 46

What defenders watch on the DACL

The event

5136 (a directory service object was modified) where the attribute is nTSecurityDescriptor.

The target

A privileged group, AdminSDHolder itself, or a computer object tied to delegation.

The tell

The change comes from an account with no administrative reason to modify that object's permissions.

Unexplained changes to AdminSDHolder are very high priority, however ordinary the changing account looks.

This is the permissions-world analog of an unusual privileged group addition.

Coercion, NTLM relay, and Zerologon

Three mechanically different techniques with one shared target: the DC.

Detecting certificate abuse on the CA

4886

A certificate request was received by the certificate authority.

4887

A certificate was issued. Watch issuance where the requested subject does not match the requesting account.

The CA server is the log source. If it is not forwarded to the SIEM, this whole technique family is invisible.

A certificate obtained this way can authenticate as the named identity, which is why it substitutes for a password or hash.

Detecting persistence in the directory

GPOs, key credentials, delegation, SID History and trusts: changes that survive a password reset.

HACKTHESOCLesson 33Active Directory attacks38 / 46
These techniques change the directory itself, so you find them in directory-change auditing, not in authentication logs.

Prerequisite on every DC: Audit Directory Service Changes (5136, 5137, 5139, 5141) plus SACLs on the objects you care about. Check coverage before trusting a quiet result.

A default domain logs very little of this. A quiet result with no auditing proves nothing.
HACKTHESOCLesson 33Active Directory attacks39 / 46

None of the delegation or trust changes happen in normal operations outside a planned build: alert on every one and check it against a change ticket.
HACKTHESOCLesson 33Active Directory attacks40 / 46

The high-signal patterns

GPO

A change from an account outside the GPO-admin group, or the Scheduled Tasks extension appearing on a GPO that never had one. Then 4698 on many hosts within one refresh interval.

Shadow credentials

A msDS-KeyCredentialLink write by anyone except Windows Hello provisioning or the Entra Connect sync account, then a first-ever certificate logon.

SID History

Any same-domain SID, or a value ending in -512, -518, -519 or -544. Outside a migration, 4765 is an incident.

Hunt SID History periodically: injection through DCShadow or offline edits never produces 4765.

Defender for Identity covers parts of this: Group Policy Tampering, shadow-credential takeover, Kerberos delegation by a new computer, SID-History injection.
HACKTHESOCLesson 33Active Directory attacks41 / 46

  • gpoAdmins is your list of approved GPO writers
  • Pair a 4716 that disables SID filtering with the SID History hunt
Shortened from the lesson's query: it also extracts ObjectDN and OperationType (%%14674 = value added). Also watch 4769 referral tickets for krbtgt of another domain from hosts that never crossed that trust.

Key takeaways

  1. 01AD compromise is a chain: enumerate, steal a credential, escalate, repeat, until domain dominance.
  2. 024769 with RC4 across many SPNs is Kerberoasting; 4768 on pre-auth-disabled accounts is AS-REP Roasting.
  3. 034662 replication rights from a non-DC source is DCSync; a Golden Ticket needs krbtgt reset twice.
  4. 04Treat Event IDs as checkpoints on one chain: a hit on one means hunt for the others.
  5. 055136 covers delegation and DACL abuse; 4742 off-schedule on a DC account flags Zerologon.
  6. 06AD CS and directory changes create durable access: watch 4886/4887, 5136 on key attributes, 4765 and trust events.
