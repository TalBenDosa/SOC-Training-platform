Section 1 of 7

What antivirus is and how it detects

Four detection methods, each with a blind spot.

HACKTHESOCLesson 75Antivirus fundamentals6 / 65

Five terms the rest of the lesson relies on

  • Antivirus (AV)Software on endpoints (laptops, servers) that detects, blocks and removes malicious programs.
  • MalwareMalicious software: trojans, worms, ransomware, password stealers and so on.
  • SignatureA fingerprint of known malware, such as a file hash or a distinctive byte pattern.
  • False positiveA benign file wrongly flagged as malicious.
  • Detection methodThe way AV decides something is malicious. Each method has strengths and a blind spot.
AV is the most established endpoint layer and, for most machines, the first automated line stopping known threats.
HACKTHESOCLesson 75Antivirus fundamentals7 / 65

AV blends four ways of deciding something is malicious

Signature

Matches a file's hash or byte pattern against a database of known-malware fingerprints. Fast and accurate for the known, blind to the new.

Heuristic

Static rules flag suspicious characteristics: code resembling known families, suspicious structure. Catches variants, occasionally false-positives.

Behaviour

Watches what a program does when it runs: mass encryption, injection, settings changes. Catches novel and fileless threats.

ML + cloud reputation

Models trained on malicious vs benign, plus prevalence across millions of machines. A new, rare, unsigned file is inherently suspicious.

Signatures are like a wanted-poster photo: excellent if you have the photo, useless for someone new.
HACKTHESOCLesson 75Antivirus fundamentals8 / 65

How signature matching works

  1. 1Fingerprint the fileAV computes the file's hash or looks for a distinctive byte pattern.
  2. 2Look it upIt compares that fingerprint with a huge database of known-malware signatures.
  3. 3MatchA known threat is named and acted on, fast and with near-zero false positives.
  4. 4No matchThe file is not flagged by this method. That says nothing about whether it is safe.
The database must be updated constantly. A host whose definition updates fail is weaker against even known threats.
HACKTHESOCLesson 75Antivirus fundamentals9 / 65

Why the wanted poster fails against something new

Catalogued

Known sample

Its hash is in the database, so the match is instant and certain.

Same malware, new bytes

Repacked sample

Packing or obfuscating the same code changes its bytes and hash. No signature matches, so this method misses it.

Never seen

Brand-new threat

No signature exists yet. Signatures are blind until a vendor analyses it and ships an update.

That window before a signature ships is exactly where heuristics, behaviour and ML have to do the work.
HACKTHESOCLesson 75Antivirus fundamentals10 / 65

The other three methods: what they examine and when

MethodExaminesExample of what it flags
Heuristic (static)File structure and code traits, without running itCode that resembles a known malware family
Behaviour (dynamic)What the program does while it runsMass file encryption, injecting into other processes, changing system settings
ML + cloud reputationLearned features, plus prevalence and history across millions of machinesA brand-new, rare, unsigned file
Heuristics and ML judge a file at rest. Behaviour needs the threat to execute first, which is both its power and its cost.
HACKTHESOCLesson 75Antivirus fundamentals11 / 65

Cloud reputation in practice: two files, two verdicts

Widely seen file

Present on many machines, signed, with a long history. Reputation lowers suspicion.

Rare new file

Seen on one machine, first appeared today, unsigned. Inherently more suspicious, even with no signature.

Reputation needs cloud connectivity, adds lookup latency, and can false-positive on rare legitimate software.

A niche in-house tool can look exactly like the rare new file. That is a common ML or reputation false positive.
HACKTHESOCLesson 75Antivirus fundamentals12 / 65

What a clean verdict does and does not rule out

MethodCatches wellBlind spot
SignatureKnown, catalogued malware, near-zero false positivesBrand-new threats, or ones repacked to change their bytes
Heuristic (static)Variants sharing tell-tale structure with known familiesGenuinely novel techniques resembling nothing catalogued
Behaviour (dynamic)Novel and fileless threats with clean-looking filesThreats that never run, or behave benignly while watched
ML + cloud reputationNever-before-seen files that are rare, new, unsignedFiles engineered to look statistically benign; needs connectivity
Costs: signatures need constant updates, heuristics false-positive, behaviour needs the threat to execute first, cloud lookups add latency.
HACKTHESOCLesson 75Antivirus fundamentals13 / 65
Each method has a blind spot, so AV is one layer rather than the whole defence.

Signatures miss the new, heuristics can false-positive, behaviour needs the threat to run first. That is why AV alerts need human judgement.

Section 2 of 7

Scanning modes and what AV does on a detection

A detection and a successful response are two different things.

HACKTHESOCLesson 75Antivirus fundamentals15 / 65

Two timing modes

Real-time (on-access)

Inspects files as they are created, opened, downloaded or executed, and can block a threat before it runs. The most important mode for prevention.

On-demand

A deliberate full or targeted sweep to find dormant threats missed earlier or that arrived before protection was in place. Scheduled scans are a form of this.

Real-time acts at the instant of danger, which is why it stops a malicious download the moment it lands.
HACKTHESOCLesson 75Antivirus fundamentals16 / 65

Real-time protection stopping a download

  1. 1File landsA user downloads an executable; it is written to the Downloads folder.
  2. 2Access interceptedOn creation, open or execution, the AV inspects the file before letting the action continue.
  3. 3Methods appliedSignature, heuristics, ML and reputation give a verdict.
  4. 4ActionIf malicious, AV blocks or quarantines it before it can run, and records the detection.
On-demand scans catch what was dormant before protection existed or what an update now recognises.
HACKTHESOCLesson 75Antivirus fundamentals17 / 65

The action decides whether the threat is contained

ActionContained?Analyst reads it as
QuarantineYes, but recoverableGood outcome; still check origin and whether it ran first
Remove / delete / cleanYes, nothing left to analyseContained; note you lost the sample
Block / preventYes, the action never occurredPrevention worked at the moment of danger
Allow / detect-onlyNo, may still be present and activeHigh priority; containment now falls to you
No action / failedNo, e.g. Access DeniedTreat the host as potentially compromised
The detection name, a label like Trojan:Win32/..., is vendor-specific and sometimes generic: a starting hint, not a verdict.
HACKTHESOCLesson 75Antivirus fundamentals18 / 65

What quarantine actually means

  • Moved, not deletedThe file goes to a protected store, for Defender under C:\ProgramData\Microsoft\Windows Defender\Quarantine.
  • Cannot executeOrdinary processes, including malware, cannot run it from there, so quarantined really means contained.
  • RecoverablePreserved so a false positive can be restored, or the sample analysed.
  • Not the whole storyIt may have run before it was quarantined. Check origin and execution history.
Remove or delete also contains the threat, but you lose the sample you might need to analyse.

Severity also often sets the alert's SIEM priority. Read it next to the action, never alone.
HACKTHESOCLesson 75Antivirus fundamentals20 / 65
Ask two questions: what did it find, and what did it actually do about it?

A quarantined or blocked threat is contained. A merely detected one may still be active. Reading that action is the heart of AV alert triage.

Section 3 of 7

The limits of antivirus, and AV vs EDR

What separates a novice who trusts every green checkmark from an analyst.

HACKTHESOCLesson 75Antivirus fundamentals22 / 65

Where antivirus struggles

  • Zero-day and novel malwareSignatures are blind to the unseen; heuristics and ML miss genuinely new techniques.
  • Fileless, living off the landPowerShell, WMI and LOLBins: no malicious file for file-scanning AV to grab.
  • EvasionPacking, obfuscation, encrypted payloads, testing against AV engines, disabling AV outright.
  • In-memory and injected codeCode that only runs in memory, or inside a trusted process, may never touch disk.
Fresh malware routinely evades AV for a window of time. These gaps are why the industry moved beyond classic AV.
HACKTHESOCLesson 75Antivirus fundamentals23 / 65

Each limit, and why the engine misses it

LimitWhat happensWhy AV misses it
Zero-day / novel malwareA threat nobody has catalogued yetNo signature; heuristics and ML may not recognise new techniques
Fileless, living off the landPowerShell, WMI or LOLBins (built-in binaries) do the workNo malicious file to scan; the tools are legitimate
Packing and obfuscationCode's appearance is changed, payloads encryptedBytes and hash change, breaking signatures
Pre-testing against AVMalware is tried against AV engines before useIt ships only once it already evades them
In-memory and injected codeRuns only in memory or inside a trusted processMay never touch disk where file scanning looks
AV disabledMalware or an intruder turns protection offThe engine never gets to look
Fresh malware routinely evades AV for a window of time. These gaps are why the industry moved beyond classic AV.
HACKTHESOCLesson 75Antivirus fundamentals24 / 65

How endpoint protection grew to cover the gaps

  1. 1Traditional AVKnown-bad files, mostly at the moment of access: is this file malicious?
  2. 2NGAVNext-Generation AV adds heavier behaviour analysis, ML and cloud reputation for more of the unknown.
  3. 3EDREndpoint Detection and Response records processes, connections, file and registry changes continuously.
  4. 4Analysts huntWith that record, analysts investigate and respond to what got past prevention.
EDR has its own lesson. Here it is enough to know where AV ends and EDR begins.
HACKTHESOCLesson 75Antivirus fundamentals25 / 65

AV, NGAV and EDR are layers, not competitors

Core methodsSignatures + basic heuristicsAdds behaviour, ML, cloud reputationContinuous recording + analytics

Rule of thumb: NGAV is a smarter filter, EDR is a flight recorder plus response console for everything the filter missed.
HACKTHESOCLesson 75Antivirus fundamentals26 / 65

What a clean AV result proves, and what it does not

It does tell you

None of the methods recognised anything as malicious at scan time. The odds are narrowed.

It does not tell you

That no zero-day, fileless, in-memory or obfuscated activity happened, or that AV was even running the whole time.

Bring this back whenever a student wants to close a case on a clean scan.
HACKTHESOCLesson 75Antivirus fundamentals27 / 65
Antivirus is a strong filter, not a guarantee.

A clean AV result narrows the odds but never proves a machine is safe. A mature endpoint strategy runs AV/NGAV and EDR together.

Section 4 of 7

AMSI, bypass techniques, and exclusions

The interface that lets AV see scripts, and the setting that lets it look away.

HACKTHESOCLesson 75Antivirus fundamentals29 / 65

The script problem: what is stored is not what runs

What file scanning sees

On disk

A script that is encoded, split apart or assembled at runtime. Nothing in it matches a signature.

What the engine runs

At execution

The decoded plaintext. Only at this moment does the real content exist, so this is where it has to be scanned.

This is why file scanning alone has little to say about obfuscated PowerShell, VBA or JScript.
HACKTHESOCLesson 75Antivirus fundamentals30 / 65

AMSI shows AV the script after it decodes itself

Obfuscated PowerShell, VBA or JScript on disk looks nothing like what will execute.

  1. 1Script engine prepares to runPowerShell, Windows Script Host, Office VBA, JScript or .NET.
  2. 2Engine calls AMSISubmits the fully deobfuscated, in-memory content.
  3. 3Registered AV scans itReturns clean or detected on the plaintext.
  4. 4Only clean content runsFileless and obfuscated scripts get caught after all.
The Antimalware Scan Interface is built into Windows 10 and later. By the time AMSI submits content, the obfuscation has already been undone for it.
HACKTHESOCLesson 75Antivirus fundamentals31 / 65

AMSI tampering, seen from the defender's side

Mapped to MITRE ATT&CK T1685 (formerly T1562.001), Disable or Modify Tools.

  • What it isAttackers try to stop AMSI handing scripts to the engine, instead of trying to beat the detection logic.
  • Why it mattersIf AMSI is blinded, even an excellent engine never sees the decoded script.
  • What you seePowerShell script-block logs (4104) that reference AMSI internals are a near-certain red flag.
  • What you doTreat it as a finding to escalate: something deliberately removed AV's visibility.
Keep the class on the evidence, not the method: the tell is a script that talks about AMSI itself, which legitimate scripts almost never do.
HACKTHESOCLesson 75Antivirus fundamentals32 / 65

Attack the engine, or attack the plumbing

Beat the engine

Make the content look benign to signatures, heuristics and ML. Hard, and the engine keeps improving.

Blind the plumbing

Make sure the engine is never handed the content at all. The detection logic is untouched but irrelevant.

The same idea links AMSI tampering and exclusion abuse: both remove visibility rather than defeat detection.
HACKTHESOCLesson 75Antivirus fundamentals33 / 65
An exclusion is a place antivirus has agreed never to look.

Admins exclude busy backup or database folders for performance, or a conflicting security tool for compatibility. Normal, sometimes necessary, and a known target.

The setting is legitimate. The risk is that anyone who learns the list knows where scanning never happens.
HACKTHESOCLesson 75Antivirus fundamentals34 / 65

How an exclusion turns into a blind spot

  1. 1Exclusion configuredA path, process or extension is excluded, for example a backup tool's folder.
  2. 2List discoveredThrough misconfigured Group Policy, a leaked configuration, or guessing common software paths.
  3. 3Malware staged thereFiles placed in the excluded path are never scanned, however good the engine is.
  4. 4Detection opportunityDefender logs configuration changes (5007), and the list itself can be reviewed.
From the defender's side the questions are: is this exclusion justified, who added it, and what files live there now?
HACKTHESOCLesson 75Antivirus fundamentals35 / 65

Exclusions: a place AV has agreed never to look

  • Exclusions exist for performance (backup, database dirs) or compatibility
  • An attacker who learns the list can stage malware there with zero scanning
  • Broad exclusions or AMSI-bypass patterns are findings worth escalating
Attackers find exclusion lists via misconfigured Group Policy, a leaked configuration, or guessing common software paths.
HACKTHESOCLesson 75Antivirus fundamentals36 / 65

Visibility-removal signals worth escalating

SignalWhere you see itReading
An exclusion was addedDefender event 5007, configuration changedCheck who added it and whether a change ticket exists
Very broad exclusionsGet-MpPreference on the hostWhole drives or user folders excluded is a finding

Section 5 of 7

AV telemetry: Windows Defender events and tools

The AV telemetry a SOC analyst meets most often.

HACKTHESOCLesson 75Antivirus fundamentals38 / 65

The classic pair: 1116 detects, 1117 acts

  • 1116 is the detection: name, path, severity
  • 1117 is the action, and whether it succeeded
  • Check Action Status first; a failed action arrives as a separate 1118/1119
Quarantined files go to C:\ProgramData\Microsoft\Windows Defender\Quarantine, which ordinary processes cannot execute from. A 1118/1119, or an Action of Allow, demands immediate escalation.
HACKTHESOCLesson 75Antivirus fundamentals39 / 65

Reading the 1116/1117 pair field by field

FieldValueMeaning
Threat NameTrojan:Win32/Wacatac.B!mlWhat AV thinks it found; !ml means an ML-assisted verdict
SeveritySevereTreated as active malware
Path...\d.rosen\Downloads\invoice_final.exeA Downloads executable: user-delivered
Detection TypeConcreteA detection of a specific item
Action (1117)QuarantineWhat AV did about it
Action Status (1117)SuccessRead this first: it decides contained or not
Detection Origin: Local machine means the file was found on the host's own disk.
HACKTHESOCLesson 75Antivirus fundamentals40 / 65

Success, or something that needs you now

1117 with Success

The action completed. Contained, but still find out how it arrived and whether it ran.

1118 / 1119

The action failed (1119 is a critical failure). A failure is a separate event, not a 1117 marked failed.

1008 or Action Allow

1008 when the failure follows an on-demand scan; Allow means AV did not stop it. Escalate immediately.

Build SIEM rules on the absence of a successful 1117 after a 1116, not only on the presence of 1116.
HACKTHESOCLesson 75Antivirus fundamentals41 / 65

A behaviour hit (1015) looks nothing like a file detection

The behaviour engine judges what a process does at runtime, so the fileless case shows up here, not as a hash.

  • No file hash: it names a running process, not a file on disk, the fileless case
  • Path is a signed, legitimate powershell.exe, so there is nothing to quarantine
  • Action: Allowed, No action taken: behaviour hits often warn, not block, so contain yourself
A 1015 is where living-off-the-land activity that signature scanning misses surfaces. The alert is a lead: pair it with the process tree and command line in EDR before deciding.

  2. 2Detection1116, or 1006 for the raw detection, or 1015 for behaviour.

  4. 4Protection state5000-series changes, which can themselves be the attack.

Section 6 of 7

Reading antivirus alerts as an analyst

A few fields and one critical distinction drive triage.

HACKTHESOCLesson 75Antivirus fundamentals48 / 65

What an AV alert contains

  • Detection nameWhat the AV thinks it found. A lead, not a final verdict.
  • File path and hashTemp or Downloads, or masquerading in a system directory, is more suspicious than an expected location.
  • Action takenQuarantined, blocked, removed, or only detected/allowed.
  • Host, user, timestampWho and when, for pivoting.
Never read an AV alert as simply 'AV handled it'. Read the action.
HACKTHESOCLesson 75Antivirus fundamentals49 / 65

The single most important question: was it stopped?

Quarantined or blocked

Contained. Still investigate how it arrived and whether it acted first, but the immediate danger is handled.

Detected, not remediated

Permission issue, error, or detect-only config. The file may still be present and active. Containment falls to you.

AV tells you what it managed to recognise: a lower bound on what happened, not the whole story.

Anything other than a clean quarantine or block: treat the host as potentially compromised.

The platform slot changes the investigation

Win32 / Win64

The Type slot tells you intent at a glance

  • Trojan familyTrojan, TrojanDownloader, TrojanSpy: disguised malicious programs.
  • Backdoor, Worm, RansomRemote access, self-spreading, and ransomware.
  • PWS, ExploitPassword stealers, and code that abuses a vulnerability.
  • HackTool, VirToolTools that may be legitimate admin utilities or attacker kit.
  • Grey areaPUA, Adware, BrowserModifier, SoftwareBundler: usually lower severity.
A HackTool detection on an admin's jump host may be expected; the same name on a sales laptop is not.
HACKTHESOCLesson 75Antivirus fundamentals53 / 65

Pivot outward from every AV detection

  1. 1To the endpoint / EDRWhat process dropped or launched the file? What is its process tree? What else ran then?
  2. 2To repetition and spreadIs the same detection firing on other machines, a campaign or worm?
  3. 3To what preceded itA phishing email, a suspicious download, a new scheduled task or service.
AV catches the symptom it recognised while the rest of an intrusion may be invisible to it.

A blocked detection is reassuring but still worth understanding. An unblocked detection is an active incident.

Reading the action correctly and pivoting into fuller telemetry is how a routine notification becomes a scoped investigation.

What the console label says, and what is true

Looks like

A Severe trojan with a Quarantine action: a routine, handled alert.

Actually is

A quarantine that never completed. The file is potentially still present and executable.

This is the exact trap the lesson has been building towards: reading the label instead of the status.

From alert to containment

  1. 1Read the actionA 1118, not the 1117 of a successful quarantine: this is not "AV handled it".
  2. 2Check the file nameDouble extension in Downloads: the user was socially engineered.
  3. 3Pivot to EDR nowIt executed minutes before the failed quarantine, spawning PowerShell with an outbound connection.
  4. 4Contain directlyIsolate via EDR, kill the process tree, then manual removal or reimage.
Do not wait for a scheduled scan and do not trust the console's Quarantine label. AV correctly recognised Wacatac.B; the status field showed recognition never became containment.

A strong but fallible filter: recognition and containment are separate facts, and the action status is where you read the difference.

Key takeaways

  1. 01AV layers signature, heuristic, behaviour and ML/cloud detection, and each method has a blind spot.
  2. 02On detection AV quarantines, blocks, removes, or only detects; the detection name is a lead, not a verdict.
  3. 03AV struggles with zero-days, fileless attacks, evasion and in-memory code; EDR records what prevention missed.
  4. 04AMSI lets AV see deobfuscated scripts; AMSI bypass and broad exclusions blind the engine (T1685).

Why can an intrusion that runs entirely through PowerShell and other built-in Windows tools (fileless, living off the land) often evade traditional signature-based antivirus?
