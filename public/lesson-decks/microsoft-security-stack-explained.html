Defender is not one product. It is a brand on five separate engines with separate telemetry.

An analyst who assumes they all behave the same will misread an incident the moment it spans more than one, which most serious ones do.

Also warn about renames: Azure AD is Entra ID, Microsoft 365 Defender is Defender XDR, Azure Sentinel is Microsoft Sentinel. The technology did not change; the names appear in every ticket.

Almost no real organization is purely Microsoft-centric, so most run both.

Defender XDR for deep, low-effort Microsoft coverage. Sentinel for everything else, custom detection and SOAR-style response.

There is always a third-party firewall, a line-of-business app, or AWS and GCP alongside Azure. None of that reaches Defender XDR.

KQL: the language that ties it together

Learn it once, query endpoint, email, identity and third-party logs.

HACKTHESOCLesson 15The Microsoft security stack17 / 46

Six operators cover most real queries

  • whereFilters rows by a condition. First in nearly every query.
  • projectSelects and renames the columns to display.
  • summarizeAggregates into grouped statistics: per user, host or hour.
  • countHow many rows matched everything before it.
  • joinCombines two tables on a shared key.
  • ago()Relative time window such as ago(24h) or ago(7d).
In a stack fragmented across five-plus products, one query language working identically everywhere is what makes cross-product investigation practical.
HACKTHESOCLesson 15The Microsoft security stack18 / 46

Encoded PowerShell and what it connected to

  • Each line adds one precise constraint
  • The join pairs each process with connections it made
  • Validated here, copy it into a Sentinel Analytics Rule
Advanced Hunting gives the faster feedback loop for testing; Sentinel turns the query into a standing, scheduled detection.

Section 7 of 12

Identity: Entra ID

Often the first place an account-compromise investigation touches.

HACKTHESOCLesson 15The Microsoft security stack24 / 46

Two log streams, two questions

Did they authenticate?

Sign-in logs

Every attempt by a user, service principal or managed identity: location, device, app, method, MFA, and what Conditional Access decided.

What changed?

Audit logs

Directory and configuration changes: new user, role assignment, app registration, Conditional Access edit, group membership.

Compromise needs both: how the attacker got in, and what they did with the access.

Registering a new application for persistence is an audit log event, even in the same session as the sign-in. A denial citing a Conditional Access policy is a different finding from a wrong password.
HACKTHESOCLesson 15The Microsoft security stack25 / 46

Sign-in risk is not user risk

Sign-in risk

Scores one authentication attempt, evaluated fresh each time from location, device and behavior.

User risk

Scores the account over time, e.g. leaked credentials or anomalous sign-ins. Persists until remediated or dismissed.

One risky sign-in need not raise user risk; user risk can stay high even when the latest sign-in looks fine.
HACKTHESOCLesson 15The Microsoft security stack26 / 46

MFA fatigue in the sign-in log

  • A burst of MFA pushes to one user in a short window
  • Often followed by exactly one approval
  • Treat as compromise, not login friction
The attacker already has valid stolen credentials and hopes the user approves out of irritation, habit or confusion.

Data and posture: Purview and Secure Score

What data we have, and how well-configured our controls are.

HACKTHESOCLesson 15The Microsoft security stack28 / 46

Reading a Purview DLP alert

Policies scan email, SharePoint, OneDrive, Teams and endpoints for sensitive information types.

  • Which type matchedCredit card, national ID, source code, health record identifiers.
  • Confidence levelLow-confidence matches on common patterns produce real false positives.
  • Policy and actionSilently log, warn with a policy tip, or block outright.
  • User and locationE.g. an external email of a spreadsheet with a high-confidence national ID match, blocked.
Check confidence and the specific rule before escalating. A hasty analyst escalates low-confidence matches unnecessarily.
HACKTHESOCLesson 15The Microsoft security stack29 / 46
A high Secure Score measures controls adopted, not how secure you are.

You can score well and still be breached by a zero-day, social engineering, or a system the score never evaluates.

Secure Score aggregates MFA coverage, legacy auth disabled, Conditional Access baselines and patch compliance. Useful for prioritizing and showing progress. Correct leadership when they call it proof of safety.

Intune and Conditional Access

The device-trust signal Conditional Access cannot generate alone.

HACKTHESOCLesson 15The Microsoft security stack31 / 46

MDM and MAM make different promises

Full enrollment

MDM

Manages the whole device: config profiles, encryption, passcode, remote wipe, continuous compliance. Corporate-owned devices.

App-level only

MAM

App Protection Policy wraps Outlook and Teams on a personal phone: PIN, no copy-paste out, wipe only corporate data. BYOD.

An unenrolled personal device cannot report compliance, so BYOD falls back to MAM.

Intune evaluates enrolled devices against a compliance policy and reports compliant or noncompliant to Entra ID, where Conditional Access can require it.
HACKTHESOCLesson 15The Microsoft security stack32 / 46

Require MFA and a compliant device for admins

  • Right password plus MFA on an unenrolled laptop is still blocked
  • The sign-in log says a policy blocked it
  • Intune's compliance report says which check failed
The policy applies to Global Administrator and Security Administrator roles. Pivot to Intune, not back into the sign-in log.

Just-in-time privilege with Entra PIM

Shrinking the window a compromised admin credential is actually privileged.

HACKTHESOCLesson 15The Microsoft security stack34 / 46

Eligible, active, and standing

AssignmentWhat it means
EligibleCan request the role, does not hold it until activated
Active (via PIM)Holds the role for a time-bound window set at activation
Active (standing, outside PIM)Holds the role permanently: what PIM exists to eliminate
Activation can require MFA re-confirmed at that moment, a written justification, approval from a named approver, and a maximum duration, commonly hours.
HACKTHESOCLesson 15The Microsoft security stack35 / 46

A PIM activation audit record

  • A 3am activation with no prior night-shift pattern is worth a query
  • Hunt standing assignments made outside PIM
  • A role activated every day is not time-bound in practice
Caveat: PIM shrinks the window, not the ceiling. An attacker inside an already-elevated session inherits everything it holds.

Defender for Cloud: the infrastructure itself

Not Defender for Cloud Apps. VMs, storage, containers, databases.

HACKTHESOCLesson 15The Microsoft security stack37 / 46

Two capabilities in one product

How is it configured?

CSPM

Agentless, via provider APIs, across Azure, AWS and GCP. Feeds a cloud Secure Score with the same caveat. Free foundational vs paid Defender CSPM.

Is the workload under attack?

CWPP

Defender for Servers, Containers and Storage watch running workloads. Needs an agent or runtime integration; priced separately.

Paid Defender CSPM adds attack-path analysis and agentless VM vulnerability scanning, turning a long list into exploit-path-aware priorities.
HACKTHESOCLesson 15The Microsoft security stack38 / 46

A configuration finding vs a workload alert

First record: CSPM configuration finding, with the attackPath the paid tier adds. Second: a CWPP workload alert.

An attack path to something sensitive is the detail that moves a finding from backlog to immediate escalation.

Purview Insider Risk Management

Behavior over many days, not content in one file.

What a Tier 1 reviewer actually sees

  • Pseudonymized by default: a privacy control, not a bug
  • Revealing the identity needs a separate, logged permission
  • Alert, then case, then eDiscovery hold, often with HR and Legal
Knowing this avoids a confused escalation when a case shows up under a codename. The subject is an employee, so the workflow leaves purely technical territory.

Key takeaways

  1. 01Defender is five products: Endpoint, Office 365, Identity, Cloud Apps and Cloud; Defender XDR correlates the first four.
  2. 02Defender XDR is deep and low-effort; Sentinel is broad and custom. Most organizations wire XDR into Sentinel.
  3. 03KQL works identically in Advanced Hunting and Sentinel: where, project, summarize, join, ago().
  4. 04Sign-in logs show authentication, audit logs show changes; sign-in risk is per attempt, user risk per account.
  5. 05Check DLP match confidence, and treat Secure Score as controls adopted, never proof of safety.
  6. 06Intune supplies device trust, PIM makes privilege time-bound, Insider Risk scores behavior under pseudonyms.

Check your understanding, question 1 of 3

Investigating a compromised Entra ID account, you need how the attacker authenticated and what they changed afterward, such as registering an app for persistence. Which logs do you need?

Sign-in logs record authentication; audit logs record directory changes such as a new app registration. An app registration is not a sign-in, directory changes go to the Entra audit log, not Cloud Apps, and audit logs do not show how someone signed in.

Check your understanding, question 2 of 3

An all-Microsoft organization also wants one third-party firewall's logs correlated with its Microsoft telemetry in a single view. How do Defender XDR and Sentinel fit?

Sentinel ingests third-party sources through Data Connectors and has a native connector for Defender XDR incidents. Analytics Rules run over data already ingested, Playbooks automate after an alert, and Defender custom detections query only Defender tables.

Check your understanding, question 3 of 3

A director asks whether the organization's high Secure Score means the environment is now secure against being breached. What is the technically correct response?

Secure Score reflects adoption of recommended controls such as MFA coverage and disabled legacy authentication, not resistance to zero-days or social engineering. It spans identity, device and app items, and it is a posture metric, not response speed.
