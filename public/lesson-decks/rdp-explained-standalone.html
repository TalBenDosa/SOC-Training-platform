Section 1 of 10

What RDP is and why it is used

Remote Desktop Protocol: Microsoft's protocol for full graphical control of a Windows machine.

HACKTHESOCLesson 87RDP explained6 / 42

SSH gives a prompt, RDP gives a desktop

SSH

A text command line to a remote machine, mostly Linux.

RDP

A full graphical desktop: windows and applications mirrored to you, responsive to your keyboard and mouse.

Connect with the built-in mstsc.exe or other clients, enter the address, authenticate with a Windows username and password.
HACKTHESOCLesson 87RDP explained7 / 42

Legitimate RDP is everywhere

  • Remote administrationIT staff managing Windows servers and desktops without walking to them.
  • Remote workEmployees reaching their office PC or a virtual desktop from home.
  • Servers and jump boxesAdministering Windows servers in data centres and clouds.
That high value, combined with how often RDP is carelessly exposed to the internet, makes it one of the most consequential protocols in modern intrusions.

Section 2 of 10

How RDP works and its port

Client/server on TCP 3389, and UDP 3389 for performance.

HACKTHESOCLesson 87RDP explained9 / 42

The basic RDP flow

  1. 1ConnectThe RDP client connects to the target on port 3389.
  2. 2NegotiateSession settings including encryption, which can use TLS.
  3. 3AuthenticateWindows credentials, ideally behind Network Level Authentication (NLA).
  4. 4StreamDesktop updates flow to the client, keyboard and mouse input flow back.
Optional features like shared clipboard and drive redirection carry their own security considerations, covered later.
HACKTHESOCLesson 87RDP explained10 / 42

Two settings dominate RDP's safety

Exposure

Is port 3389 reachable from the internet? An RDP port reachable from anywhere is an open invitation.

Authentication

Are NLA and strong authentication, and MFA, enforced? Without them RDP is protected only by a guessable password.

Sessions and logons are recorded in Windows event logs: the raw material for SOC detections.

RDP equals full desktop control over port 3389, gated only by Windows authentication.

Section 3 of 10

NLA and CredSSP: authenticate before the session

One of the highest-value RDP settings a SOC checks.

HACKTHESOCLesson 87RDP explained12 / 42

Without NLA versus with NLA

Without NLA

The server allocates a full session and logon screen before credentials are checked. Thousands of unauthenticated connections can exhaust resources.

With NLA

Authentication moves earlier via CredSSP. No desktop session or logon UI for a connection that never proves who it is.

The exposed logon screen is also extra surface for an attacker to explore or exploit.
HACKTHESOCLesson 87RDP explained13 / 42

How NLA authenticates

  1. 1TLS channel firstEncrypted before any Remote Desktop session logic runs.
  2. 2CredSSP passes credentialsSecurely, inside that encrypted channel.
  3. 3Server validatesAgainst local SAM or Kerberos/AD, without allocating a desktop.
  4. 4Then the sessionOnly after success is the interactive session allocated and streamed.
NLA is a specific, checkable setting: the 'Require Network Level Authentication' policy.
HACKTHESOCLesson 87RDP explained14 / 42
CVE-2018-0886: the protocol built to protect early authentication could itself be relayed.

A man-in-the-middle could relay CredSSP to gain code execution. The fix needed the patch plus AllowEncryptionOracle set to 'Force updated clients' or 'Mitigated'.

Patched March 2018. Patching alone is sometimes not enough; unpatched or misconfigured CredSSP is a scan and audit finding.

RDP's three security layers

Why 'encrypted' is not one setting.

HACKTHESOCLesson 87RDP explained16 / 42

The session security layer, negotiated at connect

LayerHow the session is securedVerdict
RDP Security Layer (native)Old RC4 encryption; server not properly authenticated to the clientLegacy and weak: avoid
TLS (SSL)Standard TLS; server certificate the client can validateStrong: preferred
NegotiateHighest layer both support, ideally TLSGood, if it lands on TLS
Native RDP is technically encrypted yet still man-in-the-middleable, because the client has no proof it is talking to the real server. The negotiated layer is visible in the RdpCoreTS/Operational log.
HACKTHESOCLesson 87RDP explained17 / 42

Two independent hardening knobs

NLA answers when authentication happens. The security layer answers how the session is protected. Both must be set.

Section 5 of 10

Why exposed RDP is so dangerous

A leading entry point for ransomware.

HACKTHESOCLesson 87RDP explained19 / 42

How attackers get in through open 3389

and credential stuffing

Brute force

Millions of guesses across the internet daily. Weak or reused passwords fall quickly. Many ransomware incidents start with brute-forced or purchased RDP credentials.

CVE-2019-0708

BlueKeep

A 'wormable' flaw allowing remote code execution against unpatched systems without any credentials.

Inside, attackers disable defences, steal credentials, move laterally, and deploy ransomware.

Attackers continuously scan the entire internet for open port 3389, then attack what they find.
HACKTHESOCLesson 87RDP explained20 / 42

The defensive lessons

  1. 1Never expose RDP directlyPut it behind a VPN, a bastion/jump host, or a Remote Desktop Gateway.
  2. 2Enforce NLA and MFASo a guessed password alone is not enough.
  3. 3Patch RDPClose known vulnerabilities like BlueKeep.
  4. 4Lock out and alertOn repeated failed logons.
Exposed RDP plus weak authentication equals ransomware's favourite front door.

Section 6 of 10

Shadowing, redirection and the RD Gateway

Legitimate admin features whose misuse blends in.

HACKTHESOCLesson 87RDP explained22 / 42

Three features, three security angles

Session shadowing

View or control another active session. Great for IT support; lets a privileged attacker silently watch or hijack a user without their credentials.

Drive and clipboard

Share local drives and clipboard. An attacker can pull files off through the RDP session itself, missed by controls watching only FTP or HTTP.

RD Gateway

Wraps RDP inside HTTPS on 443. Users authenticate to the Gateway, which relays internally. 3389 is never reachable from outside.

The shared lesson, as with SMB admin shares: compare use of these features against who is supposed to use them, and how.

Section 7 of 10

Session vs console, and the full RDP Event IDs

RDP sessions do not simply log on and log off.

HACKTHESOCLesson 87RDP explained24 / 42

Console, sessions, and the disconnect trap

  • ConsoleThe session tied to the machine's own keyboard and screen. mstsc /admin attaches to it instead of creating a new one.
  • SessionsEvery other RDP connection gets its own numbered session.
  • DisconnectedClosing the window with X leaves the session running. Reconnecting still requires authenticating again (NLA or logon screen).
Since Vista, services run in Session 0 and the first interactive logon is typically Session 1. /admin was formerly /console.
HACKTHESOCLesson 87RDP explained25 / 42

Four Security-log events that track RDP sessions

Event IDMeaningDistinct from
4624 (LogonType 10)A brand-new interactive RDP logonA reconnect is also authenticated: usually 4624 LogonType 7 (sometimes 10)
4625 (LogonType 3 with NLA; 10 only if NLA is off)A failed RDP logon attemptWith NLA the password is rejected before a session exists, so it logs as Network
4778A disconnected session was reconnected toNot a new session: written alongside the fresh 4624 (type 7 or 10)
4779A session was disconnected, left running4634/4647, which mean the session ended
A rule that only alerts on LogonType 10 logons opening a new session silently misses an attacker who disconnects and comes back later as 4778 plus a type 7 4624.
HACKTHESOCLesson 87RDP explained26 / 42

Disconnected for three days, back from a new IP

  • No new type 10 session: the return is a type 7 4624 plus 4778
  • 2 AM, from a completely different IP than the original logon
  • Correlate source IP and client name across 4624, 4779, 4778 per session
A strong hijacking indicator, visible only because the analyst tracked 4778/4779 and every 4624 logon type alongside 4625.
HACKTHESOCLesson 87RDP explained27 / 42
The truly credential-less takeover is a different technique: RDP session hijacking, T1563.002.

tscon run as SYSTEM attaches to another user's disconnected session without their password.

Contrast with the normal reconnect, which always re-authenticates. Session hijacking skips that step entirely, which is why the 4778 context matters.

The complete RDP event-log map: four channels

Each channel records a different stage of the same connection.

HACKTHESOCLesson 87RDP explained29 / 42

Which channel answers which question

ChannelKey Event IDsWhat it tells you
Security4624, 4625, 4634/4647, 4778/4779Authentication outcome and account; LogonType 10 = RemoteInteractive
RemoteConnectionManager/Operational1149Connection channel established: source IP, username. Fires very early
LocalSessionManager/Operational21, 22, 23, 24, 25Session logon, shell start, logoff, disconnect, reconnect
RdpCoreTS/Operational131, 140Connection accepted / failed bad credential; negotiated security layer
Full channel names are TerminalServices-RemoteConnectionManager, TerminalServices-LocalSessionManager and RemoteDesktopServices-RdpCoreTS.
HACKTHESOCLesson 87RDP explained30 / 42
Event 1149 says 'User authentication succeeded'. It does not mean the logon succeeded.

It fires when the channel is established and a username presented, before validation. A brute force makes one per attempt. Confirm with 4624 LogonType 10.

A classic false friend. 1149 is great for enumerating source IPs and volume, terrible as a count of who got in.
HACKTHESOCLesson 87RDP explained31 / 42

One successful logon across all four channels

1149 is the channel only; 4624 is the real authentication success. Correlate the channels by source IP and time. Reading all four together gives a minute-by-minute account of who connected and whether they got in.

Section 9 of 10

Why RDP matters to a SOC analyst

An RDP logon is someone taking interactive control of a Windows desktop.

HACKTHESOCLesson 87RDP explained33 / 42

What analysts hunt for

  • Brute forceMany 4625: type 3 with NLA, type 10 only without it. A type 10 4624 after them is a likely compromise.
  • Internet-exposed 3389A critical finding in itself, flagged as a priority to close.
  • Unusual sourcesRemoteInteractive logon from an odd country, hour or server: context is the red flag.
  • Lateral movementOne internal host RDPing to many, or between machines that never connect.
  • Related indicatorsNew local accounts, defences disabled, RDP right before ransomware.
Hunt type-3 4625 floods that coincide with inbound 3389 traffic, not just type 10. Data sources: Security logs, Terminal Services operational logs, and firewall logs on 3389.
HACKTHESOCLesson 87RDP explained34 / 42
Baseline who uses RDP, to which machines, from where. Alert on the deviations.

The brute force, the success after many failures, the foreign source, the internal fan-out.

Combined with the rule that RDP never faces the internet unprotected, this is one of the most impactful ways a SOC stops ransomware before it starts.

Worked example: RDP brute force in event logs

Forty minutes of failures, one success, then a command prompt.

HACKTHESOCLesson 87RDP explained36 / 42

From 4625 flood to cmd.exe

  • Type 3 failures (NLA on) cycling account names; confirm RDP via inbound 3389
  • Type 10 4624 from the same source: a real desktop session, Administrator fell
  • 4688 cmd.exe from explorer.exe: the attacker is actively working
With NLA the password is checked before any session exists, so failures log as type 3, which can also be SMB. Match them to inbound port-3389 connections from the same IP. Same shape as the SSH auth-log example.
HACKTHESOCLesson 87RDP explained37 / 42

Questions this sequence demands

  1. 1External or internal source?If external, RDP is internet-reachable: pull it behind a VPN or Gateway now.
  2. 2Should Administrator RDP?Best practice disables direct RDP for built-in admin accounts.
  3. 3What did cmd.exe do?Check later 4688s for credential dumping, disabled security tools, ransomware staging.
This is precisely the entry-point moment described as ransomware's favourite door.
HACKTHESOCLesson 87RDP explained38 / 42

Key takeaways

  1. 01RDP gives full Windows desktop control over TCP 3389; SSH gives a text shell, RDP an interactive desktop.
  2. 02NLA with CredSSP authenticates the user first; the TLS security layer authenticates the server. Enforce both.
  3. 03Internet-exposed 3389 is a top ransomware entry: brute force and BlueKeep. Use VPN or RD Gateway, NLA, MFA, patch.
  4. 044625 floods (type 3 under NLA) then a type 10 4624 is a brute force success; a 4778 plus type 7 4624 marks a reconnect.
  5. 05Event 1149 means a channel was established, not a successful logon; confirm with Security 4624.
  6. 06Shadowing, drive and clipboard redirection are legitimate tools that also enable hijacking and exfiltration.
