The shape of the storage decides how your software talks to the data.

HACKTHESOCLesson 109AWS storage and classes6 / 52

Object, block and file: three shapes of cloud storage

The coat check

Object (Amazon S3)

Whole files kept as objects in a flat namespace, reached over HTTPS with PUT, GET and DELETE. A ticket (the key) redeems the whole coat.

  • Replace the whole object, never edit in place
  • Objects up to 5 TB

The laptop drive

Block (Amazon EBS)

A raw virtual disk. The operating system formats it with a file system and reads or writes individual blocks.

  • Attached to an EC2 instance
  • Lives in one Availability Zone

The office file server

File (EFS and FSx)

A shared network drive. Many machines mount the same directory tree over a protocol such as NFS or SMB.

  • Edit files in place
  • Many clients at once
Stress that the shape decides how software reaches the data. A database wants a disk, a web farm wants a shared folder, a media site wants objects behind an API.

Four questions choose the type before you look at price

Ask these whenever a team requests storage.

  • How will software read it?Through an API, as a disk, or as a shared folder.
  • How many servers at once?File systems exist because several servers need the same files together.
  • Changed in place or replaced?Objects are replaced whole; block and file storage allow edits in place.
  • Outlive the server for how long?S3 is the permanent home; EBS is tied to one AZ and normally one instance.
  • Instance store: caches onlyDisk inside the host: very fast, but gone when the instance stops or the host fails.
Instance store is the fourth option and the odd one out: it is not durable. Use it for caches and scratch data, never for anything you need to keep.

S3 fundamentals: buckets, keys and the 11 nines

A regional object store with effectively unlimited capacity.

HACKTHESOCLesson 109AWS storage and classes10 / 52

Four terms carry most of the S3 vocabulary

Bucket

The top-level container. Its name is globally unique across all AWS accounts, and it lives in exactly one Region.

    Object

    The data plus its metadata, up to 5 TB each.

      Key

      The object's full name, for example images/2026/logo.png.

        Prefix

        The leading part of a key, here images/2026/. The console draws folders by splitting keys on the slash.

          Choose the Region by latency to users, price and data residency rules.

          Ask the class what a prefix is for. The answer: listing and organising keys. There are no real folders, only keys that happen to share a leading part.
          HACKTHESOCLesson 109AWS storage and classes11 / 52

          No real folders, strong consistency, simple static sites

          • Flat namespaceRenaming a folder of a million objects means copying a million objects, so key naming matters.
          • Upload limitsOne PUT uploads up to 5 GB; larger objects must use multipart upload.
          • Strong consistencySince December 2020, the next read after a successful write or delete sees the change.
          • Static website hostingEnable website hosting and name an index document. HTTP only, so put CloudFront in front. No server-side code.
          Strong read-after-write consistency means you no longer design around stale reads. The website endpoint speaks HTTP only, so production sites add CloudFront for HTTPS and caching.
          HACKTHESOCLesson 109AWS storage and classes12 / 52
          11 nines of durability is not availability, and it does not stop deletes.

          Standard is designed for 99.999999999% durability but 99.99% availability: about 52 minutes unreachable per year.

          Store 10 million objects and expect to lose one roughly every 10,000 years, thanks to copies across at least three AZs. But an overwritten or deleted object is durably gone, which is why versioning exists.

          All classes share 11 nines of design durability. The trade is price, speed, fees and minimums.

          Intelligent-Tiering moves objects for you

          The safe default when you cannot predict how data will be accessed.

          1. 1S3 watches each objectMonitoring costs about $0.0025 per 1,000 objects per month.
          2. 230 days without accessThe object drops to the Infrequent tier.
          3. 390 days without accessIt drops to Archive Instant Access. Opt-in tiers go colder still.
          4. 4Accessed againIt returns to the Frequent tier, with no retrieval fees.

          Objects under 128 KB are never tiered.

          The only cost of the convenience is the small per-object monitoring charge. That is why it fits unpredictable access and not millions of tiny objects.

          Five class pitfalls that exams and real bills reward knowing

          • One Zone-IA is one AZCheaper because there is no multi-AZ copy. Losing that AZ loses the data, so never the only copy.
          • Glacier needs a restoreFlexible and Deep Archive cannot be read directly: request a restore, wait, receive a temporary copy billed per GB and request.
          • Early deletion is billedDelete after 10 days in Standard-IA and you pay for the remaining 20 days.
          • 128 KB minimum object sizeIA classes bill at least 128 KB, so millions of tiny files can cost more than in Standard.
          • Retrieval fees punish guessingArchive data that is read weekly costs more than leaving it in Standard.

          Three questions pick the class: how often, how fast, and can it be re-created?

          Give the Standard-IA example in numbers: 30-day minimum minus 10 days stored equals 20 days still billed. Deleting early never blocks the delete, it only adds a charge.

          S3 data management: versioning, lifecycle, replication

          Protect, automate, copy and speed up your objects.

          HACKTHESOCLesson 109AWS storage and classes20 / 52

          Versioning makes overwrites and deletes recoverable

          A new version

          Overwrite

          Overwriting a key creates a new version. Every version stays under the same key.

            A delete marker

            Delete

            Deleting without a version ID removes no data. A delete marker hides the object, and removing the marker restores it.

              Every version is billed

              The price

              A file rewritten daily for a year becomes 365 stored copies unless you manage them.

                Once enabled you can suspend versioning but never fully remove it.

                Versioning is the answer to the question 'what if someone overwrites or deletes it?'. Without a lifecycle rule for old versions, though, the protection becomes a growing bill.
                HACKTHESOCLesson 109AWS storage and classes21 / 52

                Lifecycle rules walk data down a one-way waterfall

                A transition action moves objects to a cheaper class. An expiration action deletes them.

                1. 1StandardHot data. Objects normally sit at least 30 days here before an IA transition.
                2. 2Standard-IA or One Zone-IAThe first step down, once the 30 days in Standard have passed.
                3. 3Glacier Instant RetrievalArchive read about once a quarter, still in milliseconds.
                4. 4Glacier Flexible RetrievalArchive read once or twice a year, restore required.
                5. 5Glacier Deep ArchiveColdest and cheapest, for records kept for years.

                Rules filter by prefix, tag or size. Each transition is a billed request.

                Useful rule types: expire noncurrent versions after N days, remove expired delete markers, and abort incomplete multipart uploads after a few days so abandoned parts stop costing money.
                HACKTHESOCLesson 109AWS storage and classes22 / 52

                Cross-Region and Same-Region Replication compared

                AspectCross-Region (CRR)Same-Region (SRR)
                TargetA bucket in a different RegionAnother bucket in the same Region
                Useful forLower latency for distant users, disaster recovery, complianceAggregating logs, prod and analytics copies, another account
                Extra costSecond copy, requests, inter-Region transfer (about 2 cents per GB)Second copy and replication requests
                RequirementVersioning on source and destinationVersioning on source and destination

                Asynchronous, and only for objects written after the rule exists. Existing objects need S3 Batch Replication.

                Replication Time Control adds a 99.99% of objects within 15 minutes service level. The cross-region bill surprises teams replicating many terabytes.
                HACKTHESOCLesson 109AWS storage and classes23 / 52

                Faster uploads: multipart upload and Transfer Acceleration

                Parallel parts

                Multipart upload

                Splits a large object into parts of 5 MB to 5 GB (up to 10,000 parts), uploaded in parallel and stitched together at the end.

                • Recommended above 100 MB, required above 5 GB
                • A failed part is retried alone; uploads can resume

                Nearest edge location

                Transfer Acceleration

                Uploads go to the nearest CloudFront edge location, then over the AWS backbone to the bucket.

                • Helps when users are far from the Region
                • Special accelerate endpoint, extra per-GB fee

                They combine: a user in Singapore uploading 20 GB to Frankfurt benefits from both.

                Ask students which problem each solves. Multipart fixes big objects and flaky links; Transfer Acceleration fixes distance.

                EBS in depth: volume types, snapshots, encryption

                Block volumes for EC2, and how to pick the right one.

                HACKTHESOCLesson 109AWS storage and classes25 / 52

                EBS volumes live in one AZ and outlive the instance

                • One Availability ZoneA volume attaches to an instance in the same AZ.
                • PersistentData persists independently of the instance, unlike instance store.
                • Boot volumesThe root volume is deleted at termination unless you change DeleteOnTermination.
                • Multi-AttachOn io1 and io2, up to 16 Nitro instances in the same AZ share a volume. Other types attach to one.
                • You pay for provisionedCapacity and performance you provision, whether you fill the disk or not.
                Contrast with S3, where you pay for what you store. An empty 1 TiB EBS volume still bills as 1 TiB.
                HACKTHESOCLesson 109AWS storage and classes26 / 52

                Four volume types: SSD for random IO, HDD for streams

                SSD types suit random reads and writes. HDD types suit large sequential streams.

                TypeMedium and sizeMax IOPS and throughputTypical use
                gp3SSD general purpose, 1 GiB to 16 TiB16,000 IOPS, 1,000 MiB/sDefault for boot, dev/test, most databases
                io2 (Block Express)SSD provisioned IOPS, 4 GiB to 64 TiBUp to 256,000 IOPS (64,000 otherwise), 4,000 MiB/sCritical databases, sub-millisecond latency, 99.999% durability
                st1HDD throughput optimized, 125 GiB to 16 TiB500 IOPS, 500 MiB/sBig data, log processing, data warehouses
                sc1HDD cold, 125 GiB to 16 TiB250 IOPS, 250 MiB/sInfrequently accessed data, lowest EBS price

                st1 and sc1 cannot be boot volumes.

                gp3 is the default answer. Choose io2 only when latency and consistency are worth paying for, and HDD types only for big sequential workloads.
                HACKTHESOCLesson 109AWS storage and classes27 / 52

                gp3 decouples speed from size; gp2 tied them together

                IOPS follow size

                gp2 (older)

                3 IOPS per GiB, with burst credits. People bought oversized disks just to get speed.

                  The default choice

                  gp3

                  Baseline of 3,000 IOPS and 125 MiB/s at any size. Raise IOPS to 16,000 and throughput to 1,000 MiB/s independently of capacity.

                  • About 20% cheaper per GB than gp2
                  • Migrating gp2 to gp3 is a classic cost saving

                  Latency matters

                  io2

                  For workloads where latency and consistency are worth paying for. Designed for 99.999% durability, versus 99.8 to 99.9% for standard SSD.

                    Tie back to the quiz: a 200 GiB database that needs 12,000 IOPS is a gp3 job, because you buy IOPS without buying extra space.
                    HACKTHESOCLesson 109AWS storage and classes28 / 52

                    Snapshots are incremental and restore anywhere in the Region

                    A snapshot is a point-in-time backup of a volume.

                    1. 1First snapshotCopies all used blocks. Stored in S3 by the service, not in your bucket list.
                    2. 2Later snapshotsIncremental: only changed blocks are saved.
                    3. 3Delete an old snapshotRemoves only data that no newer snapshot needs.
                    4. 4Restore or copyRestore into any AZ of the Region, or copy to another Region for disaster recovery.

                    Restored volumes load blocks lazily. Fast Snapshot Restore avoids slow first reads.

                    Amazon Data Lifecycle Manager schedules snapshot creation and retention; the Snapshot Archive tier cuts cost for months-old snapshots, with restore taking 24 to 72 hours. Encryption is a per-volume KMS setting that also covers snapshots and instance-to-volume traffic.

                    Shared file systems: EFS and the FSx family

                    When several servers must read and write the same files at once.

                    HACKTHESOCLesson 109AWS storage and classes30 / 52

                    EFS is an elastic, shared NFS file system for Linux

                    The mental model: a managed office file server. You mount it, AWS handles hardware, patching and replication.

                    • ElasticGrows and shrinks automatically. You pay for GB used, with no capacity to provision.
                    • Multi-AZData is stored across AZs; each AZ has a mount target. Thousands of instances, containers and Lambda functions can mount it.
                    • Linux onlySupports NFS v4.0 and v4.1. Windows instances are not supported.
                    • Storage classesStandard, Infrequent Access and Archive, plus One Zone variants. Unread files move to cheaper classes.
                    • Throughput modesElastic, Provisioned or Bursting determine how performance scales with load.
                    Typical uses: a web farm in three AZs sharing uploaded images or a CMS, shared home directories, build and CI artifacts, container storage.
                    HACKTHESOCLesson 109AWS storage and classes31 / 52

                    FSx: pick the flavor by protocol and ecosystem

                    Each FSx flavor is a specific well-known product that AWS runs for you.

                    FSx flavorProtocolChoose it when
                    FSx for Windows File ServerSMB, Active Directory integrationWindows applications need shared folders, DFS and NTFS permissions
                    FSx for LustreLustre parallel file systemHPC, ML training, fast scratch space linked to S3
                    FSx for NetApp ONTAPNFS, SMB, iSCSIYou already run NetApp and want snapshots, cloning, multi-protocol access
                    FSx for OpenZFSNFSMigrating ZFS workloads with very low latency needs
                    The protocol is the giveaway. SMB with Active Directory points to FSx for Windows; a parallel file system for supercomputer-style work points to Lustre.
                    HACKTHESOCLesson 109AWS storage and classes32 / 52

                    Exam-style choices: which service for which job

                    EFS

                    Many Linux servers, shared files, no capacity planning.

                      FSx for Windows

                      Windows file shares with Active Directory.

                        FSx for Lustre

                        Supercomputer-style parallel processing reading huge datasets.

                          Not a file system

                          One database server needing a fast disk: EBS. Billions of web objects over HTTP: S3.

                            The last column catches the common wrong answers. Shared-folder wording signals a file system; single-server disk or HTTP objects do not.
                            HACKTHESOCLesson 109AWS storage and classes33 / 52
                            Do not use EFS as a general replacement for EBS.

                            A network file system adds protocol latency and costs more per GB than gp3, so a single-instance database belongs on a block volume.

                            The mirror-image cost trap: rarely read archives on EFS Standard when S3 or Glacier would store them for a fraction of the price.

                            Moving data in: Snowball, DataSync, Storage Gateway

                            Online or offline, one-time or continuing: the arithmetic picks the service.

                            HACKTHESOCLesson 109AWS storage and classes35 / 52
                            100 TB over a dedicated 1 Gbps link takes about 9 days at full line rate.

                            Real links rarely sustain full rate, so a poor connection can mean months. Volume, bandwidth and one-time versus permanent decide the service.

                            Always calculate days at real bandwidth first. Rule of thumb: more than about a week online pointed historically to an offline device.
                            HACKTHESOCLesson 109AWS storage and classes36 / 52

                            Snow Family, DataSync and Storage Gateway compared

                            Offline appliance

                            Snow Family

                            AWS ships a ruggedized device, you copy data locally and ship it back, and AWS loads it into S3. Encrypted and carrier-tracked.

                            • Snowball Edge holds tens to hundreds of TB
                            • Closing to new customers: check availability

                            Online transfer

                            AWS DataSync

                            An agent copies from NFS, SMB, HDFS or other object stores to S3, EFS or FSx on a schedule.

                            • Parallel transfer, throttling, retries, integrity checks
                            • Right for recurring or ongoing migrations

                            Hybrid bridge

                            Storage Gateway

                            An appliance presents local protocols while storing data in AWS, for applications that stay on premises.

                              Snow devices can also run EC2 instances and Lambda locally for edge processing. The concept still appears in the Cloud Practitioner exam, even though availability has changed.
                              HACKTHESOCLesson 109AWS storage and classes37 / 52

                              Storage Gateway types and Transfer Family

                              • S3 File GatewayNFS and SMB shares whose files are stored as S3 objects, with a local cache for hot data.
                              • Volume GatewayiSCSI block volumes backed by S3, with snapshots stored as EBS snapshots.
                              • Tape GatewayA virtual tape library for existing backup software, with tapes archived to S3 Glacier classes.
                              • Transfer FamilyManaged SFTP, FTPS and FTP endpoints in front of S3 or EFS, for partners who exchange files that way.
                              In each case the on-premises application keeps the protocol it already speaks. That is the whole point of a gateway.

                                    Durability versus availability11 nines means not lost, not always reachable, and no protection from deletes

                                        Key takeaways

                                        1. 01Object (S3), block (EBS) and file (EFS or FSx) are different shapes: pick the type from how software reads the data.
                                        2. 02S3 classes share 11 nines of durability; choose by access pattern, retrieval speed, fees and minimum duration.
                                        3. 03One Zone-IA is a single AZ, Glacier Flexible and Deep Archive need restores, and early deletion is still billed.
                                        4. 04Versioning plus lifecycle rules protect and trim data; replication needs versioning on both buckets and CRR adds transfer cost.
                                        5. 05Use gp3 for most EBS needs; EBS lives in one AZ, so shared Linux files go to EFS and Windows shares to FSx.
                                        6. 06Choose DataSync, Storage Gateway or Snow by data size, bandwidth, and whether the move is one-time or continuing.

                                        A single EC2 instance runs a database needing a steady 12,000 IOPS on only 200 GiB of data. Which is the lowest-cost storage that meets the IOPS target?

                                        A single-server database needs a block disk, and gp3 raises IOPS to 16,000 independent of size. EFS adds protocol latency and costs more per GB, sc1 tops out near 250 IOPS, and S3 cannot act as a database disk.

                                        Seven years of audit records must be retained, read about once a year, and waiting up to half a day is acceptable. Which S3 class has the lowest storage cost?

                                        Deep Archive is cheapest at about $0.00099 per GB-month, and its 12-hour retrieval and 180-day minimum suit rarely read records. The other classes pay for millisecond access or a single zone that this workload does not need.

                                        Check your understanding, question 3 of 3

                                        To save money, an engineer stores the only copy of weekly reports in S3 One Zone-IA. What is the main risk?

                                        One Zone-IA is cheaper because it drops multi-AZ redundancy, so losing that AZ can destroy data with no other copy. It returns in milliseconds, has a 30-day minimum (not 180) and the same 5 TB object limit.
