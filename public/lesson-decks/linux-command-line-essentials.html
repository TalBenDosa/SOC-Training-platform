The shell, the prompt and the shape of a command

The shell takes your typed order and asks the OS to run it. The terminal is only the window.

HACKTHESOCLesson 99Linux command line6 / 54

Read the prompt, then the shape of every command

A shell reads what you type and asks the operating system to run programs on your behalf.

  • analyst = user, web01 = hostname, ~/logs = working directory (~ is your home directory)
  • A $ at the end of the prompt means a normal user; a # means root, so slow down
  • bash is the default shell on most distributions; zsh, dash and fish also exist
Everything in this lesson works in bash. Stress that the terminal is only the window and the shell is the program running inside it.

Exit status: zero means success

  • The shell stores the exit status of the last command in the variable $?
  • Zero means success; anything else is some kind of failure
  • Exit codes are what let you chain commands safely later in this lesson
Plant this now: it pays off in the last section, where && and || decide what runs next based on this number.

Navigating the filesystem: pwd, cd and ls

Know your working directory, move with paths, and read what ls tells you.

HACKTHESOCLesson 99Linux command line11 / 54

Four symbols make relative paths fast

An absolute path starts with /. A relative path does not, and is measured from the current working directory.

SymbolMeaningExample
.The current directory./run.sh runs a script in this directory
..The parent directorycd .. goes up one level
~Your home directorycd ~/logs
-The previous directory (with cd)cd - jumps back and forth

cd with no argument takes you home. Quote names with spaces: cd 'Incident Reports 2026'.

An absolute path means the same thing wherever you are. Lose track of your working directory and you run commands against the wrong files.
HACKTHESOCLesson 99Linux command line12 / 54

Know where you are before you run anything

pwd prints the working directory; cd moves you.

  • pwd answers where you are, so you do not touch the wrong files
  • cd - prints the directory it returned to and jumps back and forth between two places
The cd - trick is a huge time saver when you bounce between two distant directories.
HACKTHESOCLesson 99Linux command line13 / 54

The ls options that matter

Plain ls hides a lot. These options reveal it.

  • -lLong format, one entry per line with details.
  • -aAll entries, including hidden ones (names starting with a dot).
  • -hHuman-readable sizes like 4.2K or 18M, combined with -l.
  • -tSort by modification time, newest first. Add -r so ls -ltr puts the newest file at the bottom.
  • -RRecurse into subdirectories.
  • -dShow a directory itself instead of its contents.
ls -ltr puts the newest file right above your next prompt, which is exactly where your eyes are.
HACKTHESOCLesson 99Linux command line14 / 54

Reading one ls -l line, left to right

  • First character is the type (- file, d directory, l symlink); then nine permission bits
  • Modification time is a first stop: a file changed at 03:00 on a Sunday deserves a question
  • Use ls -la on home directories: .bash_history and .ssh are hidden from plain ls
After the type and permissions come link count, owner, group, size, modification time and name. Attackers know defenders forget hidden files, so make ls -la a reflex.

HACKTHESOCLesson 99Linux command line17 / 54

rm has no undo: where rm -rf goes wrong

How it goes wrong

There is no recycle bin. rm -r deletes directories and everything inside; -f hides prompts and errors.

  • Stray space: rm -rf /tmp/work /* starts at the filesystem root
  • Empty variable: rm -rf $DIR/ becomes rm -rf / when DIR is unset
  • A glob that matches more than you expected

Defensive habits

Preview, prompt by hand, and let Tab complete paths instead of typing them in full.

  • Run ls with the same arguments first to preview matches
  • rm -i, or rm -I for one prompt on bulk deletes
  • rmdir removes only empty directories
These are real incident patterns, all from the same few mistakes. The ls preview trick costs five seconds and catches the glob that matched too much.
HACKTHESOCLesson 99Linux command line18 / 54

One listing shows hard and symbolic links

Same number in the first column means the same inode: one set of data, two names.

A file's name and its data are separate things. The data lives at an inode and a directory entry is a name pointing at it; ln creates extra names. Note the link count of 2 on the first two lines.
HACKTHESOCLesson 99Linux command line19 / 54

Hard links share data; symbolic links store a path

Second name, same inode

Hard link

Delete one name and the data survives until the last name is gone.

  • Cannot cross filesystems
  • Cannot point at directories

A small file holding a path

Symbolic link

Works like a shortcut. If the target is deleted or moved, the symlink dangles and points at nothing.

  • Created with ln -s
  • ls -l shows the arrow to the target

Why analysts care: attackers use symlinks to redirect where a program reads or writes, and a quick ls -l shows the arrow that gives it away.

Ask: what happens to soft.log if you delete auth_sample.log? It dangles. And hard.log? Still holds the data.

Keys to memorize in less

less opens a file one screen at a time without loading it all. Its keys are the same ones man uses.

  • space / bPage down / page up.
  • g / GJump to the start / end of the file.
  • /patternSearch forward; n next match, N previous match.
  • FFollow the end of the file as it grows; Ctrl-C stops following.
  • qQuit.

Start with less -S to stop long lines wrapping and keep columnar logs readable.

Because the keys are shared with man, learning them once pays off twice.

Watch a log live with tail -f

head shows the start, tail the end, 10 lines by default. tail -F keeps going across log rotation.

tail -f keeps the file open and prints new lines as they arrive: how you watch a log live while you reproduce a problem or wait for an attacker's next move. Ctrl-C stops it.

Wildcards, globbing and quoting

Describe sets of files with patterns, and know who expands them.

HACKTHESOCLesson 99Linux command line26 / 54

Globs: the shell expands the pattern, not the command

When you type ls *.log, bash swaps in the matching names before ls starts. ls never sees the asterisk.

PatternMatchesExample
*Any run of characters, including none*.log matches auth.log and syslog.log
?Exactly one characterlog?.txt matches log1.txt, not log10.txt
[abc]One character from the setlog[123].txt
[a-c]One character from a range[a-c]*.txt
[!abc]One character not in the set[!0-9]*.txt
[[:digit:]]A character class (digit, alpha, upper)access-[[:digit:]].log

skips hidden files unless you ask with .. With no match, bash passes the pattern through literally.

This is why ls .xyz in an empty directory complains about a file literally named .xyz: the command received the unexpanded pattern.
HACKTHESOCLesson 99Linux command line27 / 54

Braces generate names, even for files that do not exist

  • Braces generate strings and never look at the filesystem
  • The last line expands to cp auth_sample.log auth_sample.log.bak, a handy backup idiom
Zero-padded ranges such as {01..12} produce 01, 02 and so on up to 12. The fourth line is output of the echo, not a command.
HACKTHESOCLesson 99Linux command line28 / 54

Globs and regex look alike but are different languages

Globs match filenames and the shell expands them. Regex matches text inside data and is read by grep, sed and awk.

IdeaGlobRegex
Any characters*.*
One character?.
Starts with errerr*^err
Ends with .log*.log[.]log$

The star is the classic trap: in a glob it means anything, in regex it repeats the previous item zero or more times.

Ask which language find -name uses (glob) and which grep uses (regex). Mixing them up is one of the most common beginner mistakes.
HACKTHESOCLesson 99Linux command line29 / 54

Quotes decide what the shell touches

The shell acts on special characters before the command runs, so quotes pass them through untouched.

Single quotes

Keep everything literal.

  • echo '$HOME *' prints exactly that

Double quotes

Stop globbing and word splitting, but still expand variables.

  • echo "$HOME" prints /home/analyst

Unquoted

Expanded, glob-matched and split on spaces.

  • rm 'old notes.txt' needs quotes for the space

Quote grep patterns and find -name globs. A file named -rf looks like an option to rm : use rm -- or ./*.

Examples to type live: grep 'Failed.root' auth_sample.log and find . -name '.log'. Without the quotes the shell would try to glob them first.

Section 6 of 9

Streams, pipes and redirection

Rewire stdin, stdout and stderr, and connect small tools together.

HACKTHESOCLesson 99Linux command line31 / 54

Three streams, two of them on your screen

Every Linux program is born with three open streams.

Input

stdin (descriptor 0)

Input to the program, normally your keyboard. cmd < file reads it from a file instead.

    Normal output

    stdout (descriptor 1)

    Normal output, normally your screen. > redirects it and a pipe sends it to the next program.

      Errors

      stderr (descriptor 2)

      Error and diagnostic messages, also normally your screen. 2> redirects them separately.

        Splitting results from errors is deliberate: save the data in a file while errors still reach your eyes, or discard the noise without losing data.

        Redirection rewires these streams. A pipe connects the stdout of one program to the stdin of the next.
        HACKTHESOCLesson 99Linux command line32 / 54

        Redirection operators rewire the streams

        OperatorWhat it doesExample
        cmd > fileSend stdout to file, overwriting itls > listing.txt
        cmd >> fileAppend stdout to filedate >> timeline.txt
        cmd < fileRead stdin from filesort < ips.txt
        cmd 2> fileSend stderr to filefind / -name x 2> errors.txt
        cmd > out 2>&1Send stdout and stderr to the same filemake > build.log 2>&1
        cmd &> fileBash shorthand for both streamsmake &> build.log
        cmd 2> /dev/nullDiscard error messagesfind / -name '*.conf' 2> /dev/null

        A pipe cmd1 | cmd2 sends the stdout of cmd1 into the stdin of cmd2.

        The highlighted row is the one you will use most and the one students get backwards. Next slide shows why the order matters.
        HACKTHESOCLesson 99Linux command line33 / 54

        Order matters in 2>&1, and > can destroy your data

        • Redirections run left to right: 2>&1 points stderr wherever stdout points at that moment
        • > truncates the target to zero length before the command starts, so sort reads an empty file
        Write the file redirect first, then 2>&1. For the overwrite trap, write to a different file and rename it, or use sort -o.
        HACKTHESOCLesson 99Linux command line34 / 54

        Pipes, tee and /dev/null keep pipelines clean

        • /dev/null accepts everything and stores nothing: the standard way to silence noise
        • tee copies to the screen and a file without breaking the pipeline; -a appends
        • A pipe carries only stdout; errors from the left-hand command still reach the terminal
        The second command saved all 287 failed lines to failed.txt and printed the count. Each program does one job and passes text along.

        HACKTHESOCLesson 99Linux command line36 / 54

        grep: filter rows with a handful of flags

        FlagMeaningExample
        -iIgnore casegrep -i failed auth.log
        -vInvert: lines that do NOT matchgrep -v CRON syslog
        -rRecurse through a directorygrep -r 'password' /srv/app

        The -o example pulls every IPv4 address out of a log, a one-liner worth memorizing.
        HACKTHESOCLesson 99Linux command line37 / 54

        Basic regex building blocks for grep

        The pattern is a regular expression, though plain words work too.

        • ^ and $Anchor the start and the end of a line.
        • .Matches any one character.
        • *Repeats the previous item zero or more times.
        • [0-9]A set of characters.
        • [.]A literal dot: inside brackets the dot loses its special meaning.
        • + and | (with -E)One or more, and alternation.

        Always single-quote your patterns so the shell leaves them alone.

        This is the same star trap from the globbing section: in regex it repeats, it does not mean anything.

        cut, awk, sort, uniq, sed, tr: one job each

        ToolWhat it doesKey detail
        cutSlices columns: -d sets the delimiter, -f picks fieldsTreats every single delimiter as a separator
        awkSplits on runs of whitespace into $1, $2; $NF is the last field$(NF-3) counts back from the end

        Worked example: who is hammering the web server?

        Build a grep, cut, sort and uniq pipeline one stage at a time to find the offending IPs.

        HACKTHESOCLesson 99Linux command line41 / 54

        Start with the data and measure the problem

        access.log has one request per line: timestamp, client IP, method, path, status code, single-space separated.

        • The pattern ' 401$' is a space, then 401, at the end of the line
        • Anchoring avoids matching a 401 elsewhere in the line, such as in a path
        Step 1 is how big the problem is: 1431 failures out of 18204 requests. Always size the problem before you dig.
        HACKTHESOCLesson 99Linux command line42 / 54

        Build the pipeline one stage at a time

        Run the first stage, look at the output, then add the next. You always know which stage broke something.

        1. 1grep ' 401$'Keeps only the 401 lines: filter rows.
        2. 2cut -d' ' -f2Extracts field 2, the client IP: slice a column.
        3. 3sortPuts identical IPs next to each other so none are miscounted.
        4. 4uniq -cCollapses duplicates and prefixes each IP with its count.
        5. 5sort -rnOrders numerically (-n) with the biggest first (-r).
        6. 6head -n 5Keeps the top five.

        Filter rows, then slice columns: that is the whole mental model.

        Show the intermediate result after each stage on screen. Without the first sort, uniq would count only adjacent repeats and produce misleading numbers.
        HACKTHESOCLesson 99Linux command line43 / 54

        The full pipeline ranks every source IP

        • Without sort, uniq counts only adjacent repeats and gives misleading numbers
        • Without -n, 9 would sort after 10: text order compares character by character
        One address with 1212 failures stands out immediately. That is the payoff of the pipeline.
        HACKTHESOCLesson 99Linux command line44 / 54

        Same template, new questions, and a lead not a verdict

        Change one stage to answer a new question. Then check scanner, VPN exit or misconfigured client before blocking.

        The SSH log needs awk and a count from the end because invalid user adds two words. One IP with 1212 failures in minutes looks like brute force or credential stuffing, but the pipeline gives you a lead, not a verdict.

        Finding files, history, completion and chaining

        Search by attributes, work faster at the prompt, and chain commands safely.

        HACKTHESOCLesson 99Linux command line46 / 54

        find: search by attributes, not just by name

        Syntax: find where tests actions. Quote the glob so the shell does not expand it first.

        • -name takes a quoted glob, -iname ignores case, -type f/d/l picks files, dirs or symlinks
        • -mtime -1 is the last 24 hours, +7 is over 7 days; -mmin -30 counts minutes
        • -size +50M is larger than 50 MB; add 2>/dev/null on broad searches to hide errors
        By default find prints matches; -exec command {} + runs a command on the results. Use -mmin when something happened half an hour ago.
        HACKTHESOCLesson 99Linux command line47 / 54

        find gives current truth; locate is fast but can be stale

        Current truth

        find

        Walks a directory tree and tests each entry. Use it when you need attribute filters or an answer that is up to date.

        • Tests: name, type, time, size, depth
        • Actions: print, or run a command with -exec

        Fast but stale

        locate

        Searches a prebuilt database refreshed by updatedb, usually daily. A file created ten minutes ago will not appear.

        • Answers instantly
        In an investigation, a stale answer is worse than a slow one. Reach for find when freshness matters.
        HACKTHESOCLesson 99Linux command line48 / 54

        History and Tab completion save time and prevent typos

        ShortcutWhat it does
        Up / DownStep through earlier commands
        Ctrl-RReverse search: type part of a command, press again to cycle
        !!Repeat the last command; sudo !! when you forgot sudo
        !$The last argument of the previous command
        Ctrl-A / Ctrl-EJump to the start / end of the line
        Ctrl-U / Ctrl-L / Ctrl-CClear to line start / clear the screen / abort a running command
        TabOne Tab completes when unambiguous; two Tabs list the candidates

        History is written to ~/.bash_history when the shell exits: a useful but incomplete timeline.

        Tab completion is also a safety tool: it prevents typos in paths before they reach rm.
        HACKTHESOCLesson 99Linux command line49 / 54

        && chains on success, ; chains no matter what

        OperatorRuns the next commandExample
        ;Always, regardless of the resultdate ; uptime
        &&Only if the previous succeeded (exit status 0)mkdir out && cd out
        ||Only if the previous failedgrep -q root /etc/passwd || echo missing

        cp -r data backup && rm -rf data deletes the original only if the copy worked. With ; you could lose both.

        This is where exit status pays off. A common idiom is test && success-action || failure-action, but if the success action itself fails, the failure branch also runs.

        Key takeaways

        1. 01The shell reads your text and runs programs for you. Every command is a command, options and arguments, and ends with an exit status.
        2. 02Check man, --help and type before an unfamiliar option, and use ls -la so hidden files never escape you.
        3. 03cp, mv and rm act silently with no undo: preview with ls, prompt with -i, and keep the original evidence untouched.
        4. 04The shell expands globs, not the command: quote grep patterns and find -name globs, and remember a glob is not a regex.
        5. 05> empties the target before the command runs, the order in > file 2>&1 matters, and && chains only on success.
        6. 06Build pipelines one stage at a time: grep, cut, sort, uniq -c, sort -rn. The output is a lead, not a verdict.
        HACKTHESOCLesson 99Linux command line51 / 54

        Check your understanding, question 1 of 3

        A teammate's pipeline counts failed-login IPs: grep ' 401$' access.log | cut -d' ' -f2 | uniq -c | sort -rn. The same IP appears several times. What is the fix?

        uniq merges only adjacent identical lines, so unsorted input repeats IPs with partial counts; sorting first groups them. cut works fine here, grep -i is irrelevant, and the final sort cannot undo earlier duplicates.

        You want all output of a build script, including error messages, saved into build.log. Which command does that?

        Redirections run left to right: stdout goes to build.log, then 2>&1 points stderr there too. The reversed order aims stderr at the screen first, so errors still print. A pipe would try to run build.log, and < reads it as input.

        Check your understanding, question 3 of 3

        You want to remove the original directory data only after a successful copy to backup. Which command line is the safest?

        && runs rm only if cp exits with status 0, so a failed copy leaves the original intact. With ; the rm -rf runs regardless and can destroy both copies. || deletes precisely when the copy failed. The last form deletes while the copy is still reading.
