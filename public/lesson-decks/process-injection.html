Every process is a private apartment that only its own residents can normally enter.

Process injection breaks into someone else's apartment on purpose and runs attacker code there.

Section 1 of 9

Address space, handles, and remote threads

The OS mechanics injection sits on. If these are fuzzy, the topic reads as magic.

HACKTHESOCLesson 43Process injection6 / 41

The four building blocks

  • Address spaceA process's private memory. The OS normally stops one process reading or writing another's. Injection breaks that isolation.
  • HandleOpenProcess(desiredAccess, ..., targetPID) returns a ticket scoped to exactly the rights requested.
  • Remote threadCreated by process A, running inside process B. CreateRemoteThread does it, and has legitimate uses.
  • DLL and LoadLibraryA DLL is reusable code loaded at runtime. LoadLibrary maps it by file path into the caller.
These APIs exist for debuggers and security tools, which is exactly why they are not blocked outright and why attackers can reuse them.
HACKTHESOCLesson 43Process injection7 / 41
GrantedAccess states exactly what the requester was allowed to do with the handle.

Every injection technique is a chain of ordinary Windows API calls aimed at one dishonest goal: attacker code in someone else's apartment.

Plant GrantedAccess now. Sections 7 and 9 decode it in real telemetry.

Section 2 of 9

What process injection is and why attackers use it

MITRE ATT&CK T1055, under both Stealth and Privilege Escalation.

HACKTHESOCLesson 43Process injection9 / 41

Hiding in plain sight

Without injection

Malware runs as evil.exe: an unsigned binary in a temp folder making network connections. Trivial to spot.

With injection

The same code runs inside explorer.exe, svchost.exe or notepad.exe. The beacon now appears to come from a signed, trusted process.

Process injection is executing arbitrary code within the address space of a separate, live process.
HACKTHESOCLesson 43Process injection10 / 41

What injection buys the attacker

  • Evades process detectionAllowlists, reputation checks and unknown-binary alerts pass the signed host.
  • Masquerades trafficThe proxy or firewall sees svchost.exe reaching out, which looks normal.
  • Victim's contextMemory, tokens and handles of the target, for data theft or privilege escalation.
  • StealthNo malicious file needs to stay on disk if code lives only in memory (fileless).

Indicator APIs: OpenProcess, VirtualAllocEx, WriteProcessMemory, CreateRemoteThread, QueueUserAPC, SetThreadContext.

Detection differs subtly between techniques, which is why we learn the family by name.

Section 3 of 9

Classic DLL injection and APC injection

The textbook method, and two quieter relatives.

HACKTHESOCLesson 43Process injection12 / 41

Classic remote-thread DLL injection (T1055.001)

  1. 1OpenProcessGet a handle to the target with sufficient access rights.
  2. 2VirtualAllocExAllocate memory inside the target.
  3. 3WriteProcessMemoryWrite the malicious DLL path (or shellcode) into that memory.
  4. 4CreateRemoteThreadStart a thread in the target that calls LoadLibrary on the path.
CreateRemoteThread is the loud, observable moment: one process starting a thread in another is abnormal for most software.
HACKTHESOCLesson 43Process injection13 / 41

Two ways to be quieter

T1055.004

APC injection

QueueUserAPC queues the attacker's function to an existing thread; it runs when that thread enters an alertable wait. Early Bird queues it to a suspended process, before security products hook it.

T1620, closely related

Reflective DLL loading

The loader maps the DLL manually and resolves imports itself. The OS loader never runs, so the module is missing from normal module lists.

That is why memory-based EDR inspection, not just image-load logging, is needed.

APC avoids an obvious remote thread; reflective loading avoids leaving a registered module.

Section 4 of 9

Process hollowing and other variants

Looks like svchost.exe on disk and in the process list, runs attacker code.

HACKTHESOCLesson 43Process injection15 / 41

Process hollowing (T1055.012)

  1. 1Create suspendedStart a legitimate process, e.g. svchost.exe, suspended.
  2. 2UnmapHollow out its code with NtUnmapViewOfSection / ZwUnmapViewOfSection.
  3. 3Write the imageAllocate memory and write the malicious image in.
  4. 4Redirect entrySetThreadContext points the entry point at the malicious code.
  5. 5ResumeThe thread runs attacker code under a legitimate name.
Telltale: the image file on disk differs from executing memory, and the process often has an unexpected parent.

Common to all of them: attacker-controlled memory marked RWX.

Legitimate code is normally RX. A large private, unbacked RWX region holding shellcode is one of the strongest injection indicators.

Memory scanners and EDR lean heavily on this signal, which is why attackers invented ways to avoid it next.

Section 5 of 9

PE injection, thread hijacking, stomping, AtomBombing

Each technique exists because defenders learned to catch the previous one.

HACKTHESOCLesson 43Process injection19 / 41

Two techniques that skip a loud step

T1055.002

PE injection

Writes a complete PE image into target memory, resolves relocations and imports by hand, then jumps to the entry point. No LoadLibrary, no DLL on disk.

T1055.003

Thread hijacking

OpenThread, SuspendThread, GetThreadContext / SetThreadContext to rewrite the instruction pointer, ResumeThread. No new thread, so no Event ID 8.

Relying on Event ID 8 alone misses thread hijacking entirely because only an existing thread was redirected.
HACKTHESOCLesson 43Process injection20 / 41

Two techniques that hide the write

DLL hollowing

Module stomping

Load a real DLL with LoadLibraryEx and DONT_RESOLVE_DLL_REFERENCES, overwrite its memory and AddressOfEntryPoint with shellcode, start a thread there. No unbacked RWX region.

No WriteProcessMemory

AtomBombing

GlobalAddAtom stores shellcode in the global atom table. NtQueueApcThread makes the target call GlobalGetAtomName, copying it in, with a ROP chain for the extra arguments.

Cobalt Strike has shipped module stomping since version 3.11, so it appears across many unrelated intrusions.

AtomBombing tricks the target process itself into copying the shellcode, so the most watched injection API never fires.
HACKTHESOCLesson 43Process injection21 / 41

The fingerprint module stomping leaves

  • A real, functioning DLL never has a NULL entry point
  • Loaded and flagged as an EXE, not a DLL
  • The entry-point region was overwritten after loading
Reconstructed from memory-inspection tooling such as Process Hacker or EDR API telemetry.

Worked example: an injection chain in telemetry

updater32.exe, PID 5188, arrived as an email attachment minutes earlier. Four events, two seconds.

HACKTHESOCLesson 43Process injection27 / 41

Event ID 1: Word spawns a Temp-folder binary

  • Already one anomaly: a Temp-folder executable whose parent is Word
Windows Security 4688 records the same launch (NewProcessName, SubjectUserName d.rosen, CreatorProcessName WINWORD.EXE), useful even without Sysmon.
HACKTHESOCLesson 43Process injection28 / 41

Event ID 10, then 8: the handle and the remote thread

  • 0x1FFF includes VM_WRITE, VM_OPERATION and CREATE_THREAD
  • StartAddress matches no DLL svchost.exe normally loads: raw shellcode
Event 10 is the ticket into svchost.exe's apartment; Event 8 is the remote thread starting 121 ms later.
HACKTHESOCLesson 43Process injection29 / 41
Read the chain as a sentence: phishing document to classic remote-thread injection (T1055.001) in under two seconds.

Word spawned an unsigned Temp binary, which opened svchost.exe with write and create-thread rights, then started a thread at an address matching no module.

Confirm live with Process Hacker or Process Explorer (unbacked RWX block), Moneta or Hollows Hunter, or by attaching x64dbg at that start address.

What EDR adds, and how to defend

EDR adds

What Sysmon cannot see.

  • Memory scans for RWX and unbacked executable memory
  • API sequences: VirtualAllocEx, WriteProcessMemory, CreateRemoteThread
  • In-memory image differing from disk

Defensive measures

Reduce the attack surface and the blind spots.

  • Tune EID 8 and 10 (SwiftOnSecurity / Olaf Hartong)
  • Memory-aware EDR plus ASR rules
  • LSASS as PPL and Credential Guard
  • Least privilege; hunt write handles
Access to lsass.exe with these rights also overlaps with credential dumping, which is the next lesson's territory.

Decoding GrantedAccess in Event ID 10

The fine print on the handle ticket, and the difference between noise and an injection attempt.

HACKTHESOCLesson 43Process injection34 / 41

GrantedAccess is a bitmask of rights

RightValueWhy an injector wants it
PROCESS_CREATE_THREAD0x0002Start a remote thread (CreateRemoteThread)
PROCESS_VM_OPERATION0x0008Allocate or change protections (VirtualAllocEx, VirtualProtectEx)
PROCESS_VM_READ0x0010Read target memory; also credential dumping of lsass.exe
PROCESS_VM_WRITE0x0020Write shellcode in (WriteProcessMemory)
PROCESS_QUERY_INFORMATION0x0400Query target details; often benign alone
PROCESS_SUSPEND_RESUME0x0800Suspend and resume threads (hijacking, hollowing)
Badge analogy: a cleaner needs only the lobby bit. Someone asking for the safe and new-staff bits together is doing something a cleaner never would. PROCESS_SET_INFORMATION is 0x0200.
HACKTHESOCLesson 43Process injection35 / 41

Composite values you will actually see

GrantedAccessDecodes toInterpretation
0x1FFFFFPROCESS_ALL_ACCESSMaximum rights; loud against a system process
0x1F0FFFLegacy PROCESS_ALL_ACCESS (pre-Vista)Same story; many tools still request it
0x1438VM_OPERATION + VM_WRITE + VM_READ + QUERYThe classic injection combination
0x143AAbove plus CREATE_THREADInjection and the right to launch the thread
0x1410VM_READ + QUERY_LIMITED_INFORMATIONRead-only; benign monitoring, but on lsass.exe possible dumping
0x1000QUERY_LIMITED_INFORMATION onlyAlmost always benign enumeration
No single right convicts. The write-plus-execute combination against a process the source has no reason to touch does.
HACKTHESOCLesson 43Process injection36 / 41

Same field, opposite verdicts

Smoking gun

0x143A from an Office application opening svchost.exe.

Background noise

0x1410 from a legitimate EDR agent reading many processes.

Decode the mask, check the source-target pair, and the false-positive rate collapses.

This is the analyst reflex to drill: rights first, then who is touching whom.

Key takeaways

  1. 01Injection breaks process isolation on purpose: a handle, a write into memory, then code running there.
  2. 02T1055 hides code inside signed processes to beat process-based detection and masquerade traffic.
  3. 03Each variant avoids something: a new thread, RWX allocation, WriteProcessMemory, or the OS loader.
  4. 04The OS narrows the list: .008, .009 and .014 are Linux only, the rest are Windows.
  5. 05Read telemetry as a sentence: EID 1 odd parent, EID 10 write rights, EID 8 thread at no module.
  6. 06Decode GrantedAccess: write plus create-thread against an unrelated target is the signal.

A memory scan flags a large private RWX region inside svchost.exe that matches no DLL on disk, and the process was started suspended. Which technique does this best describe?

A suspended-start process whose in-memory image differs from disk, plus an unbacked RWX region, is the signature of process hollowing (T1055.012). Legitimate software does not run from unbacked RWX memory that mismatches disk.

Check your understanding, question 2 of 3

Reflective DLL loading maps a malicious DLL into memory manually instead of using the Windows loader. Which telemetry gap does this create for a defender relying only on Sysmon?

Reflective loading bypasses LoadLibrary and the OS loader, so no Event ID 7 or module-list entry is produced. That is why memory-based EDR scanning, not just image-load logging, is needed.

Check your understanding, question 3 of 3

Sysmon Event ID 10 shows winword.exe opening a handle to svchost.exe with GrantedAccess 0x143A. Why is this a strong injection indicator?

GrantedAccess is a bitmask. 0x143A holds write, operate, read and create-thread rights, precisely the injection toolkit, and winword.exe requesting them against svchost.exe has no benign explanation.
