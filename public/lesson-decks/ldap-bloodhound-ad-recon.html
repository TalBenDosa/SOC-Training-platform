The openness LDAP recon exploits

Assumes domain, DC and SID are known; the one protocol fact it turns on.

HACKTHESOCLesson 41LDAP and BloodHound6 / 40
By design, most of the directory is readable by any authenticated domain user.

The same rule that lets a helpdesk app look up your manager lets an attacker list Domain Admins, SPN-carrying accounts, and who holds dangerous rights, exploiting nothing.

LDAP (Lightweight Directory Access Protocol) is the language programs use to query the directory, over TCP 389 (cleartext/STARTTLS) or 636 (LDAPS). Detection cannot rely on a single query looking bad, because reading all of this is cheap and permitted.
HACKTHESOCLesson 41LDAP and BloodHound7 / 40

SID and ACL: the two things recon reads

SID

A unique identifier like S-1-5-21-...-512. The trailing RID names well-known accounts: 500 is Administrator, 512 is Domain Admins.

ACL

A per-object list of who may read it, modify it, reset its password, or add members. Where unintended privilege hides.

A right granted once for one legitimate reason is rarely revisited, which is exactly where non-obvious escalation lives.

The deeper wire-level mechanics (ports, binds, search scopes) come in a later section. Here the point is only that reading all of this is cheap and permitted.

Why recon comes first

AD compromise is relationship-driven, and relationships are readable.

HACKTHESOCLesson 41LDAP and BloodHound9 / 40

Each attack needs a fact recon provides

  • KerberoastingWhich accounts have SPNs.
  • AS-REP RoastingWhich accounts lack preauth.
  • DCSyncWho holds replication rights.
  • Privilege escalationWhich low-privilege account can reset a high-privilege account's password.

All discoverable by reading AD, not attacking it.

MITRE maps these: T1087 Account Discovery, T1069 Permission Groups Discovery, T1482 Domain Trust Discovery, T1018 Remote System Discovery.
HACKTHESOCLesson 41LDAP and BloodHound10 / 40
The attacker's mental model is a graph: principals are nodes, rights are edges.

Edges like MemberOf, AdminTo, GenericAll, ForceChangePassword. The job is a path from a low-privilege node to Domain Admins.

The graph, not brute force, is what makes modern AD compromise fast and reliable. Understanding recon is the foundation for detecting the whole kill chain early.

LDAP under the hood

Ports, binds, scopes, and the Global Catalog, so you can hunt the traffic.

HACKTHESOCLesson 41LDAP and BloodHound15 / 40

The four LDAP ports

PortProtocolScope
389LDAP (cleartext or STARTTLS)This domain partition; creds sniffable if unencrypted
636LDAPS (over TLS)This domain partition, encrypted from the first byte
3268Global CatalogWhole forest (partial attributes): an attacker favourite
3269Global Catalog over SSLWhole forest, encrypted
A single GC query on 3268 returns a partial view of every object in the entire forest, so one foothold enumerates across domain boundaries without touching each DC.
HACKTHESOCLesson 41LDAP and BloodHound16 / 40

Binds and scopes: how you prove who you are, and how much you ask

Bind types

Simple binds on 389 leak the password to a sniffer, a reason to prefer LDAPS.

  • Anonymous: no creds; often restricted
  • Simple: user+password, cleartext on 389
  • SASL (Kerberos/NTLM): the legitimate path

Search scope

SharpHound and PowerView use subtree searches from the domain root, reading thousands of objects at once.

  • base: that one object only
  • one: its immediate children
  • sub: the base and everything beneath

Cleartext simple binds, anonymous binds, GC subtree sweeps, and wildcard filters are all rare for apps, constant for a collector.

A subtree search of (objectClass=*) from the root, visible in Event ID 1644, is a recon red flag.

BloodHound and SharpHound: the graph

Ingest AD data, render it as a graph, run shortest-path queries.

HACKTHESOCLesson 41LDAP and BloodHound18 / 40

Collect with SharpHound, query with Cypher

  • DCOnly is quiet (LDAP only); Default adds host-based SMB/RPC collection; All adds more
  • The query finds the shortest chain of edges of any type to Domain Admins
BloodHound is the graph database (Neo4j); SharpHound is the collector. Knowing which method was used tells a SOC how aggressively the environment was swept.
HACKTHESOCLesson 41LDAP and BloodHound19 / 40

What SharpHound collects

  • Domain objectsUsers, groups, computers, OUs, GPOs, trusts.
  • Group membershipsIncluding nested chains.
  • ACLs and object rightsGenericAll, WriteDACL, AddMember: the escalation edges.
  • SessionsWhich users are logged on where, revealing exposed credentials.
  • AccessAdminTo, CanRDP, ExecuteDCOM.
  • DelegationConstrained and unconstrained delegation settings.
Transitive pathfinding is the power: chaining ForceChangePassword, MemberOf, AdminTo walks a helpdesk account to a DC in seconds. Defenders should run it proactively to cut the same paths.

Worked example: a path to Domain Admins

Four ordinary facts strung into a devastating outcome.

HACKTHESOCLesson 41LDAP and BloodHound24 / 40

Reading the shortest path edge by edge

  1. 1The pathsvc-helpdesk02 -[ForceChangePassword]-> it-support-lead -[MemberOf]-> IT-ADMINS -[AdminTo]-> DC01.
  2. 2ForceChangePasswordHelpdesk was delegated the right to reset it-support-lead's password without the old one.
  3. 3MemberOfit-support-lead belongs to the IT-ADMINS group.
  4. 4AdminToIT-ADMINS has local admin on DC01, a Domain Controller.
No step is alarming alone: helpdesk resets passwords, memberships are normal, admin groups administer servers. The chain is the attack.
HACKTHESOCLesson 41LDAP and BloodHound25 / 40
The attacker resets the password, logs in, and lands with local admin on a Domain Controller.

A direct route to dumping LSASS or running DCSync as a fully privileged identity. Cut it by removing one edge: helpdesk's ForceChangePassword right.

Any path an attacker's graph finds, a defender's graph finds first. This is exactly what the 'Shortest Paths to Domain Admins' query surfaces automatically.

Detection: volume, breadth, rights-focused reads

Reading the directory is normal, so hunt the shape, not any single query.

HACKTHESOCLesson 41LDAP and BloodHound27 / 40

Event 4662: a security-descriptor read burst

  • One account touching thousands of objects, reading security descriptors, is strong enumeration
  • 4662 requires SACL auditing on the objects, or it never fires
Event 4661 (handle requested) can spike similarly. DCs can log expensive LDAP searches; broad filters from a workstation are suspicious.
HACKTHESOCLesson 41LDAP and BloodHound28 / 40

Behavioural tells and the best tripwire

  • SharpHound burstsConnections from one host to many machines (Session collection), and rapid sequential LDAP binds.
  • Defender for IdentityFlags LDAP reconnaissance and SharpHound-style enumeration patterns directly.
  • Honeytoken accountsA decoy like svc_backup_admin with no legitimate use. Any read, Kerberos request, or edge touching it is almost certainly malicious.

A honeytoken appears prominently in SharpHound output, catching the collection itself, not only later exploitation.

It is the highest-value tripwire because nothing legitimate ever queries it.
HACKTHESOCLesson 41LDAP and BloodHound29 / 40

Two channels a DC-only LDAP hunt misses

Host-based collection

Default/All reach over SMB/RPC to every host for sessions (srvsvc, NetSessionEnum) and local groups (samr). Watch Event 5145 for repeated IPC$ + \PIPE\srvsvc/\PIPE\samr.

AD Web Services (9389)

The AD PowerShell module and SOAPHound query ADWS on TCP 9389, not raw 389. A hunt on 389/636 alone misses it.

The host tell is one source opening short-lived SMB sessions to dozens or hundreds of hosts in minutes, plus a 4624 Type 3 fan-out from one account.

ADWS proxies to LDAP, so 1644 LDAP-search logging still captures the resulting searches on the DC. Monitor 9389 connections from non-admin hosts too.

Defence: reducing exposure and payoff

Shrink what an attacker can find, and what a found path is worth.

HACKTHESOCLesson 41LDAP and BloodHound34 / 40

Four defensive levers

ACL hygiene

Remove dangerous delegated rights like GenericAll and WriteDACL. Run BloodHound defensively on a schedule and remediate the shortest paths first.

Administrative tiering

Tier the model so enumerating a workstation never reveals Tier 0 sessions, and a lower-tier ACL mistake cannot chain up to Domain Admin.

Reduce readable surface

Clear secrets from description fields, retire stale accounts flagged by old lastLogonTimestamp, constrain sensitive attribute visibility.

Behavioural monitoring

Deploy Defender for Identity on DCs and baseline normal LDAP volume per account so bulk enumeration stands out from app traffic.

Defence reduces both exposure (what is findable) and payoff (what a path is worth).

Running BloodHound against your own domain, the same way an attacker would, finds the paths first.
HACKTHESOCLesson 41LDAP and BloodHound35 / 40

Blind the host half, and cover the cloud graph

Restrict remote SAM

The GPO 'Network access: Restrict clients allowed to make remote calls to SAM' (RestrictRemoteSam), scoped to admins only, blinds the host-based AdminTo/local-group half of a collection.

Cover Entra ID

BloodHound ingests AzureHound data, modelling AZGlobalAdmin, AZOwner, AZResetPassword and app-control edges. Run it on your tenant and watch MicrosoftGraphActivityLogs for bulk reads.

The Graph-activity burst is the Entra parallel to the on-prem 4662 burst.

A cloud escalation path is often an app owner who can add credentials to a privileged service principal, the exact attack-path thinking extended to the cloud.

Key takeaways

  1. 01AD is a directory service queryable over LDAP, and most of it is readable by any authenticated user by design.
  2. 02Recon precedes every attack: enumerate users, groups, trusts, SPNs, and especially ACLs where escalation edges hide.
  3. 03BloodHound and SharpHound graph AD and ACL data, chaining ordinary rights into a path from low-privilege to Domain Admins.
  4. 04No single edge looks alarming; it is the chain, which is why defenders must run BloodHound and cut edges, not just monitor.
  5. 05Detect by volume and breadth: 4662 read bursts, Defender for Identity LDAP recon alerts, and honeytokens being touched.
