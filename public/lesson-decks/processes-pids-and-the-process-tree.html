What is a process?

A program is a file on disk; a process is that program actually running.

HACKTHESOCLesson 69Processes and the tree6 / 38

Every process gets its own private resources

  • Memory spaceIts own RAM for code and data, isolated so one crash does not corrupt another.
  • ThreadsOne or more streams of execution. A process always has at least one.
  • HandlesReferences to open files, network connections or registry keys it is using.
  • Security context (token)Who the process runs as, which sets its permissions.
The same program can run as several processes at once: three browser windows may be several separate instances of one file.
HACKTHESOCLesson 69Processes and the tree7 / 38
A process acts with the privileges of whatever account it runs under.

When attacker code runs inside a process, especially a privileged one, it inherits those privileges.

Shift the class from thinking about programs to thinking about running processes: that is what Task Manager, ps, top and the EDR actually show.

PIDs: how the OS names every process

A unique number per process at a given moment.

HACKTHESOCLesson 69Processes and the tree9 / 38

Four facts about PIDs to internalise

  • Unique, but reusedA freed PID goes to a new, unrelated process. PID 4728 this morning and this afternoon may be different programs.
  • How tools target a processKill or inspect by PID: on Linux, kill 4728 targets that process.
  • Some are specialLinux PID 1 is always init or systemd; on Windows, low PIDs belong to core system processes.
  • The thread you pullFrom a PID you find the file path, command line, connections and its parent.
Never identify a process by PID alone across time. Pair it with name, path, start time and machine; good telemetry also records hashes.

Section 3 of 10

Parent and child processes

Every process is created by another. The PPID records who.

HACKTHESOCLesson 69Processes and the tree11 / 38

The child is normal, the parent makes it suspicious

winword.exe > powershell.exe

Word has no reason to spawn a scripting engine: the classic malicious macro in a phishing document.

w3wp.exe > cmd.exe

A web server launching a command shell strongly suggests a web shell.

Odd parent > PowerShell

PowerShell spawned by an unusual parent, then reaching out, is a common malware-execution chain.

Sysmon Event ID 1 records the image, command line, and the parent image and parent command line.

PowerShell and cmd are useful tools. They become suspicious because of who launched them: process lineage.

The legitimate Windows process tree

Know normal ancestry from boot to desktop so the abnormal jumps out.

HACKTHESOCLesson 69Processes and the tree13 / 38

The startup chain on a healthy machine

userinit.exe exits after starting explorer.exe, so a healthy explorer.exe has no live parent moments after logon. Benign, and malware authors know it.
HACKTHESOCLesson 69Processes and the tree14 / 38

Two high-value genealogy checks

Generic service host

svchost.exe

Many instances, each hosting a service group (-k netsvcs). Parent must be services.exe, path C:\Windows\System32.

Credential-theft target

lsass.exe

Exactly one, in System32, parent wininit.exe (a sibling of services.exe), and it should never spawn children.

A second lsass, a wrong parent, a path outside System32, or a child process is a red flag for masquerading or credential dumping.

Access tokens and integrity levels

Why two identical-looking processes can have different power.

HACKTHESOCLesson 69Processes and the tree17 / 38

The access token decides every security check

  • User SIDThe account the process runs as.
  • Group SIDsEvery group it belongs to, such as Domain Admins with RID -512.
  • PrivilegesE.g. SeDebugPrivilege, which allows reading another process's memory, exactly what credential dumpers need.

Can this process open that file? Windows consults the token, not the process's name.

Same image name, same path, very different power: the token is the difference.

Section 7 of 10

Reading the process tree in an investigation

Turn a pile of individual events into the narrative of an attack.

HACKTHESOCLesson 69Processes and the tree23 / 38

Walk backward for root cause, forward for impact

  1. 1The alert: PowerShellA suspicious PowerShell process is the child you start from.
  2. 2Its parent: winword.exeA macro in a Word document launched it.
  3. 3Word's parent: explorer.exeThe user opened the document themselves, likely phishing.
  4. 4Walk forwardIts children and connections: did it download a payload, spawn cmd.exe, contact C2?
Three steps back tell the whole initial-access story. The tree is the crime-scene reconstruction: patient zero, the execution chain, the blast radius.
HACKTHESOCLesson 69Processes and the tree24 / 38

Two habits that make tree reading reliable

  • Watch for impersonationsvch0st.exe, or a real-looking svchost.exe from the wrong folder or under the wrong parent.
  • The relationship is the signalSuspicious child with an innocent parent, or innocent child with a suspicious parent: both deserve scrutiny.
On a healthy tree, services.exe launches svchost.exe and explorer.exe is the parent of what a user launches. Attackers must insert themselves somewhere.

Event ID 4688 versus Sysmon Event ID 1

Process details must be logged somewhere before anyone can see them.

HACKTHESOCLesson 69Processes and the tree26 / 38

Native 4688: built in, limited by default

  • Needs Audit Process Creation, plus a second policy to include the command line
  • %%1936 full token (no split), %%1937 elevated, %%1938 limited; none means UAC bypassed
Without the command-line policy, 4688 tells you what ran but not with what arguments, hiding an encoded PowerShell payload. An elevated process with no consent prompt has to be judged from its parent chain, not this field.
HACKTHESOCLesson 69Processes and the tree27 / 38

Most mature SOCs run both

Event ID 4688Sysmon Event ID 1

Parent command line?No, only parent's PIDYes, in full

ProcessGuid is never recycled, which solves the PID-reuse problem from section 2. The hash lets you pivot to threat intel even after a file is renamed or deleted.

Section 9 of 10

Parent PID spoofing (T1134.004)

When the recorded parent is a lie.

HACKTHESOCLesson 69Processes and the tree29 / 38

The PPID field itself is forged

  • CreateProcess accepts PROC_THREAD_ATTRIBUTE_PARENT_PROCESS to choose the parent
  • Defeats a check looking for winword.exe -> powershell.exe
A sub-technique of Access Token Manipulation. It abuses a legitimate OS feature, so it cannot be prevented outright.
HACKTHESOCLesson 69Processes and the tree30 / 38

Why attackers spoof, and how it is caught

Stealth

Tools flagging scripting engines spawned by Office never see that relationship.

Privilege escalation

Spoof a SYSTEM parent such as lsass.exe and the child can inherit an elevated token.

Detection

Kernel callbacks (PsSetCreateProcessNotifyRoutine) see the real caller. A mismatch with the reported PPID is a strong signal.

A clean-looking tree is a starting point for investigation, not a verdict.

Injection, hollowing and masquerading

Hiding code inside a process the tree already trusts.

HACKTHESOCLesson 69Processes and the tree32 / 38

Three ways the tree is made to lie

T1055

Injection

Write code into a running process and execute it. No new process: it inherits that PID, privileges and reputation.

  • OpenProcess
  • VirtualAllocEx
  • WriteProcessMemory
  • CreateRemoteThread

T1055.012

Hollowing

Start a legitimate binary suspended, replace its memory, then run. Path and parent look normal; in-memory code differs from disk.

T1036

Masquerading

Look trusted: svch0st.exe, or svchost.exe running from C:\Users\Public instead of System32.

These defeat a shallow reading of the tree, not the tree itself. Correlate path, parent, memory versus disk, and remote threads.

Key takeaways

  1. 01A process is a running program with memory, threads, handles and a token that sets its privileges.
  2. 02PIDs are unique at a moment but reused, so pair them with name, path and start time.
  3. 03Abnormal parent-child pairs like winword.exe to powershell.exe are among the strongest attack signals.
  4. 04Validate core processes by path, parent and count: one lsass.exe, parent wininit.exe, no children.
  5. 05Sysmon Event ID 1 beats 4688 by default: command line, hashes, parent command line, ProcessGuid.
  6. 06PPID spoofing, injection, hollowing and masquerading make a clean tree lie; check memory and Events 8, 10, 25.

Check your understanding, question 1 of 3

svchost.exe was launched normally by services.exe from System32, and nothing looks unusual in the tree. Yet EDR flags it for 'suspicious image in memory'. What technique is most likely, and why does the tree alone miss it?

Hollowing starts a legitimate executable and replaces its in-memory code, so path and parent look normal while memory no longer matches disk. DLL hijacking loads a module, masquerading's memory matches its file, and PID reuse says nothing about memory.

Check your understanding, question 2 of 3

Sysmon shows a powershell.exe whose reported parent is explorer.exe, but the EDR's kernel-level record shows it was created by winword.exe, seconds after the user opened an emailed document. Which technique explains the mismatch?

PPID spoofing sets a false parent at creation; kernel creation callbacks still see the real caller, and the mismatch is the signal. Hollowing, DLL hijacking and masquerading do not alter the recorded parent.

Check your understanding, question 3 of 3

A 4688 event shows New Process Name ...\powershell.exe and a Creator Process ID, but the Process Command Line field is blank. What is the most likely explanation?

The field stays empty unless "Include command line in process creation events" is enabled. It is not populated by default, a blank field is a configuration gap, not tampering, and 4688 can capture it once the policy is on.
