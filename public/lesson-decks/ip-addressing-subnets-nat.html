What an IP address is and why it exists

Routers move traffic using fixed-length numbers, not names, because numbers are fast to compare billions of times a second.

HACKTHESOCLesson 46IP, subnets, and NAT6 / 51

32 bits become the dotted decimal you see

  • Each octet is 8 bits: 0 to 255, since 2^8 = 256 values
  • Four octets give about 4.3 billion addresses (256^4)
IPv4 is a 32-bit number. Subnetting is just deciding where in those 32 bits the network part ends and the host part begins.
HACKTHESOCLesson 46IP, subnets, and NAT7 / 51

Network portion and host portion

Network portion

The left-hand bits identify which network a device is on, the neighbourhood. Every device on the same segment shares it.

Host portion

The right-hand bits identify the one device within that network, the house number. Unique inside the network.

Where the split falls is set by the subnet mask, which the next sections make precise.

This split is the single idea behind subnetting. Plant it here so CIDR lands as a rule with a model behind it, not a formula.

Public vs private: the first call you always make

Classifying an address tells you the direction of a connection before you know anything else.

HACKTHESOCLesson 46IP, subnets, and NAT9 / 51

The RFC 1918 private ranges to memorise

RangeCIDRTypical use
10.0.0.0 - 10.255.255.25510.0.0.0/8Large enterprises
172.16.0.0 - 172.31.255.255172.16.0.0/12Medium networks
192.168.0.0 - 192.168.255.255192.168.0.0/16Home and small office

Public addresses are globally unique and routable; private addresses are not routed on the internet and are reused everywhere.

Note 172 only covers 16 to 31, not all of 172.x. You will see these thousands of times.
HACKTHESOCLesson 46IP, subnets, and NAT10 / 51

Direction falls out of the classification

Private to private

Internal, east-west traffic between two inside hosts.

Private to public

Outbound, egress: an inside host reaching out.

Public to private

Inbound: the internet reaching your public-facing host.

Watch for TEST-NET docs ranges (192.0.2.x, 198.51.100.x, 203.0.113.x) in real traffic: they should never appear.

IANA's Special-Purpose registry is larger: 127/8 loopback, 169.254/16 APIPA, 100.64/10 CGNAT. Direction shapes every hypothesis you form.

Direction is the first thing a verdict hangs on.

A server making an outbound connection to a public IP is suspicious; the same connection inbound to a web server is routine. Same bytes, opposite meaning.

This is why classify-first is not busywork: it sets the entire frame for what counts as normal.

Section 3 of 10

How a host gets its address: DHCP

Most devices lease an address from DHCP (Dynamic Host Configuration Protocol); its logs are often the only IP-to-device record.

HACKTHESOCLesson 46IP, subnets, and NAT14 / 51

The DORA handshake

  1. 1DiscoverClient broadcasts: I just joined and have no address, is a DHCP server out there?
  2. 2OfferServer: you can have 192.168.1.20, here are the terms.
  3. 3RequestClient broadcasts: I accept that offer, so other servers know.
  4. 4AcknowledgementServer: confirmed, the lease is yours for N hours.

Runs over UDP, client on port 68, server on port 67. Hands over the gateway, DNS servers and lease time.

If no server answers, the host self-assigns a 169.254.x.x APIPA address, which means DHCP was unreachable, not an attack.
HACKTHESOCLesson 46IP, subnets, and NAT15 / 51

A DHCP lease is your IP-to-device ledger

  • Who was 10.5.20.14 at 02:00? This line, for this window, answers it
  • The MAC and hostname pivot you to the physical device
  • The lease window bounds how long the mapping is valid
Addresses are reused, so attribution needs the lease that covered the exact timestamp, not the current owner of the address.
HACKTHESOCLesson 46IP, subnets, and NAT16 / 51

DHCP: normal lease vs a rogue server

Legitimate

The offer comes from the approved DHCP server on its trusted switch port, handing out the real gateway and DNS.

T1557.003

Rogue DHCP

An attacker's DHCP server answers first and hands victims a malicious gateway or DNS, putting itself on-path. DHCP Spoofing, a sub-technique of Adversary-in-the-Middle (T1557).

DHCP snooping on managed switches trusts offers only from an approved port, the standard defence.

The tell is an unexpected server source, or clients suddenly pointed at an unfamiliar gateway or DNS server.

Subnets and CIDR: carving the network

The number after the slash is how many bits, from the left, belong to the network portion.

HACKTHESOCLesson 46IP, subnets, and NAT18 / 51

Is a host inside this subnet?

CIDR (Classless Inter-Domain Routing): the number after the slash counts network bits from the left.

  • /24 = 256 addresses, 254 usable (network + broadcast reserved)
  • Host bits = 32 minus the prefix; usable = total minus 2
A /31 (RFC 3021) is the exception: 2 usable, for point-to-point links. A /32 is a single host. Walk the magic-number shortcut on the board.
HACKTHESOCLesson 46IP, subnets, and NAT19 / 51

Prefix to size, at a glance

CIDRTotal addressesUsable hosts
/24256254
/266462
/3042 (point-to-point)
/3122 (RFC 3021 link)
/3211 (single host)
Usable is total minus 2 (network and broadcast reserved), except /31 and /32 which are special cases. These are the prefixes you meet most.
HACKTHESOCLesson 46IP, subnets, and NAT20 / 51
Subnets are the backbone of network segmentation.

Finance, workstations, guest Wi-Fi and the DMZ sit on separate subnets, so traffic between them must cross a firewall that can control and log it.

A well-segmented network limits lateral movement: a foothold on one workstation cannot freely reach the domain controllers.
HACKTHESOCLesson 46IP, subnets, and NAT21 / 51

Knowing your subnet map is a superpower

Within a segment

10.5.20.14 reaching 10.5.20.9: two workstations on the user VLAN talking. Usually unremarkable.

Across a boundary

10.5.20.14 (user VLAN) reaching 10.5.99.3 (server VLAN): a workstation touched a server. Is that crossing approved?

Segment boundaries are where the interesting alerts live. Guest subnet talking to the database subnet should raise eyebrows.

If .20.x is users and .99.x is servers, the subnet map turns a pair of numbers into a sentence about trust zones.

NAT and the translation problem

Many private hosts, few public IPv4 addresses: NAT (Network Address Translation) lets a whole organisation share one.

HACKTHESOCLesson 46IP, subnets, and NAT23 / 51

How PAT multiplexes many hosts onto one IP

PAT (Port Address Translation), also called NAT overload, is the common office case.

  1. 1An inside host connects out192.168.1.20 opens a session from its own source port.
  2. 2The NAT device rewrites the sourceIt swaps the private IP for the one public IP and assigns a unique translated port.
  3. 3It records the mappingAn xlate entry ties private IP:port to public IP:port, with a timestamp.
  4. 4Replies are reversedReturn traffic to that public port is mapped back to the original inside host.
The unique translated port per session is what lets one public IP carry thousands of hosts and still be untangled afterwards.
HACKTHESOCLesson 46IP, subnets, and NAT24 / 51

The xlate translation table, worked

  • The same host appears twice with different translated ports
  • Two different hosts share one public IP, told apart by port and time
Check Point exposes xlatesrc and xlatedst next to src and dst. The table is the key to undoing the translation later.
HACKTHESOCLesson 46IP, subnets, and NAT25 / 51
The xlate problem: the internet sees only 203.0.113.10, mapping to thousands of internal machines over time.

To answer which of my machines did this, correlate the public IP and translated port against xlate logs at the exact timestamp.

A one-minute clock skew points at the wrong workstation, which is why NTP time sync matters for attribution.
HACKTHESOCLesson 46IP, subnets, and NAT26 / 51

The NAT family, split by direction

NAT typeMappingDirection / use
Static NATOne private to one public, fixedBoth ways; a server always reachable at one public IP
Dynamic NATPrivate IPs to a pool, first-comeOutbound; no ports rewritten
PAT / overloadMany private to one public, per portOutbound; the common office case
Static PAT / forwardingOne fixed public IP:port to one private IP:portInbound; a single fixed rule for one service
Destination NAT (DNAT)The general destination-rewrite classInbound; static PAT is one fixed case of it
Hairpin / loopbackInside host reaches inside server by public IPInternal
Static PAT is a single fixed IP:port rule; DNAT is the broader class it belongs to. Static NAT and port-forwarding are inbound exposure: each is a hole punched through the perimeter.
HACKTHESOCLesson 46IP, subnets, and NAT27 / 51
An undocumented port-forward is how a backdoor stays reachable.

Any inbound static NAT or forwarding rule is an opening in the perimeter, so an unexplained one deserves the same scrutiny as an open firewall port.

When reviewing NAT config, every inbound rule should map to a known, sanctioned service. The unexplained rule is the finding.

IPv6: when the world ran out of addresses

A 128-bit address, about 3.4x10^38 of them, replacing the exhausted 32-bit IPv4 pool.

HACKTHESOCLesson 46IP, subnets, and NAT29 / 51

An IPv6 address, full and shortened

  • Eight groups of four hex digits, colon-separated
  • :: may appear only once, or the zero count is ambiguous
340 undecillion addresses: enough for every grain of sand on Earth many times over.
HACKTHESOCLesson 46IP, subnets, and NAT30 / 51

IPv6 announces its own type in its prefix

PrefixTypeIPv4 analogue
2000::/3Global unicastPublic IP
fc00::/7 (fd00::/8)Unique localRFC 1918 private
fe80::/10Link-local169.254.0.0/16 (APIPA)
ff00::/8Multicast224.0.0.0/4 (no broadcast in IPv6)
::1/128Loopback127.0.0.1
2001:db8::/32Documentation192.0.2.0/24

A single interface routinely holds several addresses at once: a link-local fe80:: plus one or more global 2000::.

Scanning a 2^64 subnet by brute force is impractical, which changes the reconnaissance picture versus IPv4.
HACKTHESOCLesson 46IP, subnets, and NAT31 / 51

The dual-stack pitfall for an analyst

What happens

A dual-stack host runs IPv4 and IPv6 at once, so the same machine appears under an IPv4 address in one log and an IPv6 address in another.

Why it bites

Correlate only on the IPv4 address and you miss half the host's activity. Tie both addresses to the device before scoping.

The prefix tells you the type at a glance, so you can recognise an IPv6 host's role even when IPv4 is quiet.

This is an easy correlation to miss and a common reason an investigation under-scopes a compromised host.

Address resolution: IP to MAC (ARP and NDP)

IP routes across networks (Layer 3); a MAC address delivers a frame on the local segment (Layer 2).

HACKTHESOCLesson 46IP, subnets, and NAT33 / 51

The ARP exchange, step by step

  1. 1A needs a local MACHost A has an IP to reach on its own subnet but not the hardware address for it.
  2. 2A broadcasts a requestWho has 192.168.1.20? Tell 192.168.1.5. Every host on the segment hears it.
  3. 3The owner replies192.168.1.20 is at 00:1a:2b:3c:4d:5e. Only the owner should answer.
  4. 4A caches the mappingThe pair is stored for a short timeout, so A need not ask again for every packet.

A MAC address is a 48-bit hardware address, six hex pairs. ARP is IPv4; IPv6 uses NDP.

The cache timeout is why ARP traffic is constant but low. NDP does the same job over ICMPv6 multicast in IPv6.
HACKTHESOCLesson 46IP, subnets, and NAT34 / 51

The ARP cache, read

  • Each line ties an IP on this segment to the MAC that claimed it
  • The gateway's entry is the one an on-path attacker most wants to forge
If two IPs suddenly share one MAC, or the gateway's MAC changes, that is the shape of ARP poisoning.
HACKTHESOCLesson 46IP, subnets, and NAT35 / 51

No authentication, so ARP is poisoned

T1557.002

ARP spoofing

Any host can claim any IP. Forged replies say the attacker's MAC owns the gateway IP; victims send traffic to the attacker. On-path position.

RFC 4861

NDP in IPv6

Neighbor Solicitation and Advertisement replace ARP over ICMPv6 multicast. Router Advertisements enable SLAAC. Same missing authentication, same spoofing risk.

Works only within one broadcast segment, which is why segmentation also limits an ARP attacker's reach.

Detect with arpwatch-style monitoring or Dynamic ARP Inspection: a MAC suddenly claiming an IP it never held, or one MAC claiming many IPs.

Wildcard masks, VLSM, and CGNAT

Three advanced pieces you will meet in configs, diagrams and threat-intel reports.

HACKTHESOCLesson 46IP, subnets, and NAT37 / 51

A wildcard mask is the inverse of a subnet mask

  • Cisco ACLs and OSPF use the wildcard, marking host bits with 1s
  • A 0.0.0.255 wildcard covers the same 256 addresses as a /24
Easy to misread as a subnet mask and get the range backwards. VLSM applies the same CIDR math recursively to size each subnet to its need.
HACKTHESOCLesson 46IP, subnets, and NAT38 / 51

VLSM: right-size each subnet

Variable Length Subnet Masking carves one block into subnets of different sizes.

  • The problemA point-to-point link needs 2 hosts; a user VLAN needs 200. One fixed size wastes addresses.
  • The fixGive the link a /30 and the VLAN a /24 out of the same parent block, sized to need.
  • Why it matters hereReading a design means every segment has its own prefix; the mask tells you the segment's role and size.
VLSM is why a real network has many different prefixes side by side. Recognise it so a subnet diagram is not a wall of numbers.
HACKTHESOCLesson 46IP, subnets, and NAT39 / 51

CGNAT makes a source IP weaker evidence

What it is

CGNAT (RFC 6598) is NAT one level up: an ISP shares one public pool across many customers. 100.64.0.0/10 is reserved for it.

Why it matters

A malicious IP in that range may be shared by dozens of unrelated subscribers at once. Only the ISP holds the subscriber mapping, so attribution needs a legal request.

Treat a CGNAT source IP as weaker evidence than an enterprise-NAT public IP.

Recognising 100.64/10 stops you from over-trusting a shared carrier address as if it were one subscriber.

The sentence: at 14:32:05 internal host .20 reached public host .34 on HTTPS, accepted under rule 17, unless reputation, time or volume say otherwise.
HACKTHESOCLesson 46IP, subnets, and NAT42 / 51

Four reflexes on every log line

  • Classify the addressesPrivate to public is egress; public to private is inbound.
  • Check direction vs expectationA server making an outbound connection to a public IP is a beaconing or exfiltration tell.
  • Watch segment crossingsSource and destination in different internal subnets crossed a boundary; is it approved?
  • Use xlate for attributionMap the public IP and translated port back to the real internal src.
Everything downstream, pivoting, scoping and escalating, depends on getting that sentence right. NAT is the twist that trips analysts up most.

How attackers abuse this layer

Reconnaissance, spoofing, proxies, and segment-hopping.

HACKTHESOCLesson 46IP, subnets, and NAT44 / 51

Three abuse patterns

T1046 / T1018

Discovery

Ping sweeps and port scans map subnets. In logs: one source touching many destination IPs or many ports in a short window.

T1498-style floods

IP spoofing

Forging the source address. Replies go to the forged address, so the TCP handshake cannot complete and no real session forms; seen in floods and DoS, not stateful sessions.

T1090

Proxies and NAT

Routing through NAT, VPNs and proxy chains so your logs see a false source, blending C2 traffic in.

Normal user traffic talks to a small, repetitive set of destinations, which is why the scan shape stands out.
HACKTHESOCLesson 46IP, subnets, and NAT45 / 51

The scan shape in firewall logs

  • One source to many destinations on one port: a host/port sweep
  • The crossing from .20 (users) into .99 (servers) compounds the concern
This one-to-many fan-out is the signature of discovery (T1046/T1018). A user host normally talks to a few repeated destinations.
HACKTHESOCLesson 46IP, subnets, and NAT46 / 51
Segment-hopping from a low-trust subnet into a high-trust one is among the highest-value alerts a segmented network produces.

It usually means a misconfiguration or lateral movement in progress.

The three questions for any IP in an alert: private or public? which subnet, and should it talk to the destination subnet? translated, and if so what real host or user is behind it?

Key takeaways

  1. 01An IPv4 address is 32 bits in four octets; classify private vs public first to learn direction.
  2. 02CIDR marks where network bits end; subnetting underpins segmentation, and boundary crossings are high-value signals.
  3. 03NAT/PAT shares one public IP across many hosts by port; attribution needs the IP plus port plus exact time.
  4. 04IPv6's 128-bit space makes NAT rare and brute scanning impractical, but dual-stack hosts hide behind two addresses.
  5. 05ARP and NDP map IP to MAC and have no authentication, enabling on-path spoofing within a segment.
  6. 06Attackers scan (T1046/T1018) as one-to-many traffic and route through proxies (T1090) to hide their source.

A workstation that normally uses DHCP suddenly appears as 169.254.87.3 and can reach only hosts on its own segment. What most likely happened?

169.254.0.0/16 (RFC 3927) is the APIPA link-local range a host self-assigns when no DHCP server answers. It gives local-segment connectivity only, with no default gateway, so it signals a DHCP failure rather than an attack or internet access.
