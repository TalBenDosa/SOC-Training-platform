What the OWASP Top 10 is and why it exists

A data-driven consensus list of web risk categories, and a shared vocabulary.

HACKTHESOCLesson 50OWASP Top 10 tour6 / 68

A list built from data, not fear

  • OWASPThe Open Worldwide Application Security Project, a non-profit publishing free security guidance.
  • Data-drivenRebuilt from data contributed by dozens of firms plus a community survey, so ranks reflect prevalence.
  • Root causes in 2021Categories merged and renamed: Sensitive Data Exposure became A02 Cryptographic Failures.
  • Categories, not bugsEach entry holds many CWE (Common Weakness Enumeration) IDs, so one alert logic covers a family.
Three 2021 categories were entirely new, added partly from the survey because tooling struggles to detect them automatically.
HACKTHESOCLesson 50OWASP Top 10 tour7 / 68

One category, many CWEs: A03 as an example

A CWE is a catalog number for one weakness type. An OWASP category is a family of them.

CWEWeaknessLog signal
CWE-89SQL injectionSQL keywords (UNION SELECT, OR 1=1, --) in parameters; clustered 500s
CWE-79Cross-site scripting (XSS)<script>, onerror=, javascript: in parameters and bodies
CWE-78OS command injectionShell metacharacters in parameters; the web-server user spawning a process

One alert logic per category covers the whole family, instead of one signature per exploit variant.

Show that the three signals differ but share the root cause: input treated as code. That shared cause is what the category names.
HACKTHESOCLesson 50OWASP Top 10 tour8 / 68

Why a developer list matters to the SOC

Hypotheses from logs

../../etc/passwd in a path is path traversal, A01. ' OR 1=1-- in a query string is A03 Injection.

Shared ATT&CK language

Most of the lesson falls under T1190, Exploit Public-Facing Application. Cite it in tickets and detections.

The Top 10 is the common vocabulary between developers, pen testers and incident responders.

When an alert fires, everyone should understand both the technique and the fix being discussed.
HACKTHESOCLesson 50OWASP Top 10 tour9 / 68

From a raw request to a named category

Every attack in this lesson is just an HTTP request. Read it in a fixed order.

  1. 1Find the odd fieldMethod, path, query, headers or body: the field holding the odd value narrows the category.
  2. 2Decode before judgingValues usually arrive URL-encoded in logs. Decode them before you read or search.
  3. 3Form a category hypothesisAnother user's ID or a ../ path: A01. SQL keywords: A03. An internal URL: A10.
  4. 4Read the responseStatus code and size say whether it worked. Later sections show how.
  5. 5Cite the shared IDsOWASP category, CWE and ATT&CK T1190 make the ticket readable by every team and tool.
Because each category holds many CWEs, one detection per category covers a whole family instead of one signature per exploit variant.

Section 2 of 9

A01 to A05: access, crypto, injection, design, misconfig

The five categories that drive most noisy, high-volume web attack traffic.

HACKTHESOCLesson 50OWASP Top 10 tour11 / 68

A01 Broken Access Control: one digit changed

  • Same session cookie, different id: account 124's data comes back anyway
  • This is IDOR, Insecure Direct Object Reference: the server trusted the URL, not the session
  • In logs: users reaching others' resources, or 403 bursts on sequential IDs
A01 rose to number one in 2021. The attack lives entirely in the query string, and it needs no stolen credentials, only curiosity.
HACKTHESOCLesson 50OWASP Top 10 tour12 / 68

What A01 looks like in your logs

Walking through IDs

Probing

A burst of 403 Forbidden responses as one session requests sequential IDs it does not own.

  • Same session, many IDs
  • Mostly 403s

The check never happened

Success

An authenticated user receiving 200 for a record they never created. Quieter, and the one that matters.

  • 200 on another user's record
  • No error to warn you

Root cause: the server trusted the id in the URL instead of checking whether this session may see it.

The successful case produces no error at all. Only comparing the session's owner with the record's owner reveals it, which is why application logs need the user ID.
HACKTHESOCLesson 50OWASP Top 10 tour13 / 68

A03 Injection: input interpreted as code

  • The WHERE clause always evaluates true, so every row comes back
  • A03 groups SQL injection, command injection and XSS (Cross-Site Scripting)
Access logs and WAF alerts often show the payload in plain sight inside the query string, exactly where the primer told you to look.
HACKTHESOCLesson 50OWASP Top 10 tour14 / 68

What you checkIn this requestWhat it tells you

Encoding%27, %20, %3D in the raw logDecode first, or keyword searches miss it

Stress the habit, not the payload: identify the field, decode, classify, then go to the response fields before deciding anything.
HACKTHESOCLesson 50OWASP Top 10 tour15 / 68

A02, A04 and A05: weak protection, bad design, bad config

A02 Cryptographic

Weak, missing or misused encryption, in transit or at rest. Plain HTTP login leaks the Cookie; passwords kept unsalted or with a broken hash (CWE-327, CWE-916) all fall in one database dump.

A04 Insecure Design

Flaws in the architecture, like a password reset with no rate limiting. You cannot patch it; re-think it with threat modelling.

A05 Misconfiguration

GET /.env returns 200 OK with database credentials, because the server serves dotfiles. Nothing was hacked.

A05 is the one that surprises students: a misconfigured server simply answered a request it should have refused.
HACKTHESOCLesson 50OWASP Top 10 tour16 / 68

A01Broken Access ControlSpikes of 403s, sequential-ID IDOR patterns
A02Cryptographic FailuresPlain HTTP logins, weak TLS

These five drive the majority of the noisy, high-volume web attack traffic analysts triage day to day.

Section 3 of 9

A06 to A10: components, auth, integrity, logging, SSRF

Lower volume, often higher impact.

HACKTHESOCLesson 50OWASP Top 10 tour18 / 68

A06 Outdated components: Log4Shell in one header

  • Vulnerable Log4j evaluates the ${jndi:...} lookup in any logged field
  • It reaches attacker infrastructure and can run attacker-supplied code
  • CVE-2021-44228: no special endpoint needed, just a value that gets logged
If you cannot inventory your dependencies, you cannot know your exposure. Threat intel feeds and vulnerability scanners feed this category.
HACKTHESOCLesson 50OWASP Top 10 tour19 / 68

Where an A06 exposure shows up for the SOC

SourceWhat to look for
Web and WAF logs${jndi: strings in headers or any field the app might log
Network and firewall logsUnexpected outbound connections from app servers to external hosts
Asset inventory / SBOMWhich systems run the affected library version at all
Scanners and threat intelNew CVEs mapped to components you actually run

A probe string proves someone tried. Exposure depends on whether the component is present and vulnerable.

If you cannot inventory dependencies, you cannot answer 'are we affected?'. That is the real lesson of A06 for a SOC.
HACKTHESOCLesson 50OWASP Top 10 tour20 / 68

A07, A08, A09: logins, trust, and visibility

A07 Auth failures

Credential stuffing, brute force, non-expiring sessions, no MFA (multi-factor auth). POST /login returning 401 repeatedly, or one account failing from many countries.

A08 Integrity failures

Code or data trusted without verification: unsigned auto-updates, a compromised CI/CD pipeline. Headline example: SolarWinds.

A09 Logging failures

Auth, denials and server errors not logged or never reviewed. Most breaches are found by outsiders; dwell time grows.

A07 is prime SOC hunting ground. A09 is the category analysts feel most personally.
HACKTHESOCLesson 50OWASP Top 10 tour21 / 68

A07 in sign-in logs: four patterns

PatternWhat you seeLikely meaning
Many accounts, many failuresPOST /login returning 401 across many usernamesCredential stuffing or spraying
One account, many failuresRepeated 401s for a single userBrute force against that account
One account, many countriesFailures for one user from widely spread locationsDistributed attack on one identity
Sessions that never endOld session tokens still acceptedWeak session control, a design gap
A07 maps to T1110 Brute Force and, once a guess succeeds, T1078 Valid Accounts. The success after many failures is the event to hunt for.
HACKTHESOCLesson 50OWASP Top 10 tour22 / 68

A10 SSRF: the server fetches what the attacker chose

  • SSRF = Server-Side Request Forgery: the attacker picks the URL the server fetches
  • 169.254.169.254 is the cloud metadata service, reachable only from on the instance
  • That path returns the server's own temporary cloud credentials for the attacker to use
A link-preview feature meant for public URLs is aimed at the metadata service instead. Watch for outbound connections from web servers to internal or link-local IPs.
HACKTHESOCLesson 50OWASP Top 10 tour23 / 68

SSRF in telemetry: normal vs suspicious outbound

Expected

A link-preview feature fetching public internet sites, the destination it was built for.

  • Public destinations
  • Volumes match feature use

Suspicious

The same web server connecting to internal or link-local addresses it has no business reaching.

  • 169.254.169.254 (cloud metadata)
  • Internal subnets from a web tier
  • Parameter holding an internal URL

Detection pairs the request parameter in the web log with the server's own outbound connection.

The danger is credential exposure: the metadata service returns the instance's temporary cloud credentials. Treat any confirmed hit as a cloud credential incident.
HACKTHESOCLesson 50OWASP Top 10 tour24 / 68
Without good logging and an analyst reading it, the quieter categories succeed silently.

One exploited outdated component or one SSRF into cloud metadata can hand over a foothold or credentials that no firewall tuning will catch.

This is why A09 matters so much: it decides whether any of the other nine can be detected.

Root causes A01 to A05, in plain words

  • A01 Access controlThe server trusts a client-supplied identifier or path instead of re-checking whether this session is allowed.
  • A02 CryptographicSensitive data protected weakly or not at all: plaintext transport, unhashed passwords, broken ciphers.
  • A03 InjectionUntrusted input is parsed as code (SQL, shell, HTML/JavaScript) instead of data.
  • A04 Insecure designA control missing from the architecture itself: no rate limit, no anti-automation, wrong trust boundary.
  • A05 MisconfigurationInsecure defaults, verbose errors, exposed files or features, or an over-permissive XML parser (XXE).
The root cause is what you write in the ticket's recommendation. It tells developers what to change, not just what was seen.

Root causes A06 to A10, in plain words

  • A06 ComponentsRunning a library, framework or server with a known, published vulnerability.
  • A07 AuthenticationLogin and session controls that allow guessing, replay or session abuse.
  • A08 IntegrityCode or data accepted without checking it was not tampered with: unsigned updates, insecure deserialization, compromised CI/CD.
  • A09 LoggingSecurity events not logged, or logged but never reviewed or alerted on.
  • A10 SSRFThe server fetches a URL the attacker chose because the destination is never validated.
A09 is the odd one out: it is about the defender, which is why it has no ATT&CK technique.

A01 has four shapes, one root cause

The server trusts the client instead of re-checking.

ShapeWhat the request doesLog signal
IDORChanges id=123 to id=124One session touching many sequential IDs, or a record it never created
Path traversal (CWE-22)Uses ../ to leave the intended folder../, ..%2f, %2e%2e%2f in a file, path or page parameter
Forced browsingGuesses unlinked URLs like /admin, /backup.zip401/403 bursts, then a 200 on a sensitive path
Parameter tamperingSubmits role=admin or is_admin=trueRole changes in app logs that no admin action explains
Broken Access Control is number one in both editions, so these four shapes are worth memorising as log signals.
HACKTHESOCLesson 50OWASP Top 10 tour31 / 68

A03 is three attacks: SQLi, XSS, command injection

  • Stored XSS (CWE-79): script runs in the next visitor's session, ships the cookie
  • Command injection (CWE-78): ping runs, then cat /etc/passwd
  • Hunt <script>, onerror=, javascript:; shell ; | & $()
XSS has three flavours: stored, reflected, DOM-based. Fixes: output-encode plus Content-Security-Policy for XSS; avoid shelling out, or strict allow-lists, for command injection.
HACKTHESOCLesson 50OWASP Top 10 tour32 / 68

Three XSS flavours, and where the evidence lives

FlavourWhere the script comes fromWhere you see it
StoredSaved on the server, e.g. a comment or profile fieldThe POST that saved it, in web/WAF logs; hits every viewer
ReflectedBounced straight back from a crafted link the victim clicksThe GET with the script in a parameter
DOM-basedUnsafe handling in the browser's own JavaScriptOften little or nothing in server logs

Signals: <script>, onerror=, onload=, javascript: in parameters and bodies; WAF XSS rule hits.

DOM-based XSS is the reminder that server logs do not see everything that happens in the browser.
HACKTHESOCLesson 50OWASP Top 10 tour33 / 68

Three one-liners worth a log signal

  • XXE (A05, CWE-611)XML External Entity. Signal: a body with <!DOCTYPE and <!ENTITY ... SYSTEM, or an XML upload then unexpected outbound HTTP/DNS. Fix: disable DTDs.
  • Deserialization (A08, CWE-502)Signal: a serialized object where one is not normal (Java base64 starts rO0AB), then the web process spawning a shell in EDR.
  • CSRF (A01, CWE-352)Cross-Site Request Forgery. Signal: a state-changing request with a foreign Origin or Referer, or token-403 bursts. Fix: anti-CSRF tokens, SameSite.
These three got only a passing mention in the tour. The strongest deserialization corroboration is EDR: java, w3wp.exe or php-fpm spawning cmd.exe or /bin/sh seconds after the request.

HACKTHESOCLesson 50OWASP Top 10 tour36 / 68

Why the shifts happened

SSRF folded into A01

Most SSRF bugs are a server trusting a request it should have restricted: the access-control root cause.

Supply chain at #3

Formalizes vulnerable dependencies and poisoned build pipelines like SolarWinds into a top-level risk.

Injection down to #5

Not rarer. Access control and misconfiguration are now measured as even more prevalent in CVE data.

Exceptional conditions

A stack trace in a 500 leaking paths, or a payment flow that fails open when validation times out.

Misconfiguration's climb reflects cloud and container mistakes: open buckets, default credentials, exposed services.
HACKTHESOCLesson 50OWASP Top 10 tour37 / 68
The version number is a label for your report, not a change to how you read evidence.

An IDOR is an IDOR as A01:2021 or A01:2025. A UNION SELECT is injection whether ranked A03 or A05.

The detection signals from the 2021 tour apply directly.

Reading web logs through the OWASP lens

Sort each anomaly by the request's method, path, query string, headers, body and status code.

HACKTHESOCLesson 50OWASP Top 10 tour40 / 68

One Combined Log Format line, read left to right

  • The query string carries a URL-encoded UNION SELECT on /search: A03 Injection
  • Status 500 and only 512 bytes: the backend choked, so this probe got an error, not data
  • python-requests user agent: a scripted client on a search box meant for humans
%27 is an encoded single quote, %20 a space. Request plus status plus tiny body together read as attempted but failed, not a successful extraction.

HACKTHESOCLesson 50OWASP Top 10 tour42 / 68

Status codes are your fast filter

  • 200, wrong userOn a sensitive resource: possible A01 access-control break that succeeded.
  • 403 in burstsSomeone probing authorization boundaries.
  • 500 clustersAround odd input: the backend choking on an injection attempt.
  • Unexpected outboundFrom a server to internal or metadata IPs: A10 SSRF.
These are filters to prioritise, not verdicts on their own.
HACKTHESOCLesson 50OWASP Top 10 tour43 / 68

Correlation beats any single line

One SQL-looking string

Might be a false positive from a security scanner.

100 variations, then a 200

Suggests successful data extraction. Pivot to database or identity logs to confirm impact.

Remember A09: all of this depends on apps logging auth events, denials and server errors to the SIEM with accurate timestamps.

Requesting a new log source or richer field directly reduces dwell time. OWASP gives you the language to justify it.
HACKTHESOCLesson 50OWASP Top 10 tour44 / 68

A09 in practice: the fields your hunts depend on

  • Authentication eventsEvery success and failure, with user, source IP and time. Without them A07 is invisible.
  • Access-control denialsThe 403s that reveal A01 probing. Many apps never log them.
  • Server-side errorsThe 500s and exceptions that show injection reaching the backend.
  • Accurate time and sourceSynchronised timestamps and the real client IP, so lines correlate across systems.
Asking for one of these fields is a concrete A09 fix, and it directly reduces dwell time.

Section 7 of 9

Did it work? Proving success from the log fields

Most web attack traffic fails. The evidence for the fraction that did not lives in the response fields.

HACKTHESOCLesson 50OWASP Top 10 tour46 / 68
The payload tells you what was attempted. The response fields tell you whether it worked.

Size, status, error text and latency on the same log line separate a blocked probe from a real breach.

This is the shift from 'an attack was tried' to 'an attack succeeded'. Analysts who stop at the payload miss the few requests that mattered.
HACKTHESOCLesson 50OWASP Top 10 tour47 / 68

Four outcome tells: failed attempt vs success

TellFailed attemptLikely success
Size vs the path's normalStandard 1.2 KB error page380 KB where 4 to 6 KB is normal, or bytes matching the target file
Status in context403s or WAF blocksOne 200 on the same path and parameter after the blocks
Error text in the bodyGeneric error pageSQL syntax error or stack trace leaking internals
LatencyNormal response timeDurations matching the delay the suspicious request asked for

A 500 is ambiguous: it proves input reached the backend, not that data came out.

A leaked error message is a partial success for the attacker even without data: it helps refine the next request.
HACKTHESOCLesson 50OWASP Top 10 tour48 / 68

Where to find each tell

  • SizeThe bytes field of the access log, compared with a per-path baseline such as the median.
  • StatusAccess and WAF logs for the same source, path and parameter, in time order.
  • Error textOnly visible where application or WAF response logging is enabled.
  • DurationIIS time-taken, Apache %D, nginx $request_time, if the format records it.
If a field is missing from your logs, that tell is unavailable. Note the gap in the verdict and request the field.
HACKTHESOCLesson 50OWASP Top 10 tour49 / 68

Hunt by outcome, not by payload keyword

  • Join a suspicious request to an abnormal outcome, not a keyword alone
  • Bytes far above the path's median suggest a data-returning injection
  • A duration near the delay the probe asked for means the DB executed it
Payload-keyword searches return every scanner on the internet. Joining a suspicious request to an abnormal outcome returns the few that matter.
HACKTHESOCLesson 50OWASP Top 10 tour50 / 68

Three questions to judge a WAF block

  1. 1Who is the source?A real customer with a normal session history, or a new address with no history?
  2. 2What is the 'payload'?Ordinary prose in a free-text field (review, comment, ticket) that happens to contain SQL-like words?
  3. 3What happened next?Did the same user retry the same action, as a frustrated customer would?

Three yes answers point to a false positive.

Free-text fields are where WAF false positives cluster. Judge the block by the person and the field, not only the rule name.
HACKTHESOCLesson 50OWASP Top 10 tour51 / 68

Was the WAF block a real attack?

Likely false positive

A real customer with normal session history, ordinary prose in a free-text field (a review, comment, ticket), who retried the same action.

Fix it narrowly

Set the one managed rule to Count for that path, or exclude just the argument from the rule ID that fired. Never disable the whole rule.

Record why each exclusion exists: an over-broad exclusion is a hole you created yourself.

WAFs block legitimate requests when a free-text field contains SQL-like words or punctuation. Judge the block by the source, the field, and whether a normal user retried.
HACKTHESOCLesson 50OWASP Top 10 tour52 / 68

A WAF record, a five-step checklist, and why the order matters.

HACKTHESOCLesson 50OWASP Top 10 tour56 / 68

The triage checklist

  1. 1Blocked or allowed?BLOCK means it never reached the app. Lower urgency; still log the source IP.
  2. 2Volume from this sourcePivot on clientIp for the last hour. One is noise; two hundred variations is a scanner.
  3. 3Did anything get through?Look for allowed 200s on the same path. A large body after BLOCKs means a bypass.
  4. 4Correlate downstreamDatabase logs: unusual query at that time? Returned data volume spike?
  5. 5DecideAll blocked, low volume: close as routine scan. Allowed payload or spike: escalate.
On escalation, consider a temporary IP block or rate limit while you confirm impact.
HACKTHESOCLesson 50OWASP Top 10 tour57 / 68

Two endings for the same alert

Close as routine scan

Everything blocked, low volume, a single source, no allowed requests with suspicious content.

  • Log the source IP
  • No downstream anomalies

Escalate

Any allowed request carrying a suspicious payload, or a volume spike from one source.

  • Check database logs for that time
  • Temporary IP block or rate limit
  • Widen into identity logs
The evidence, not the alert's severity label, decides which ending applies.

Detection and defence in practice

Where attacks are caught, where they are fixed, and the SOC's role in between.

HACKTHESOCLesson 50OWASP Top 10 tour60 / 68

Where detection lives

WAF

Inspects method, path, query, headers and body. Managed groups cover A03 and A07 patterns; custom rules can block a url resolving to 169.254.169.254.

Rate limiting

Caps requests per IP or account per minute. Blunts A04 unthrottled reset endpoints and A07 credential stuffing.

The custom SSRF rule is a direct, cheap defence against A10.
HACKTHESOCLesson 50OWASP Top 10 tour61 / 68

Where prevention lives: mostly in code

CategoryThe fix
A01 / A03Server-side access checks on every request; parameterized queries treat input as data
A02TLS everywhere, modern password hashing, disable outdated ciphers
A05Remove default creds, disable directory listing and dotfiles, config scanners in CI/CD
A06Keep an SBOM (software bill of materials); patch on a schedule, not just after Log4Shell
A09Log auth events, denials and server errors with timestamps and source IPs, ship to SIEM
Parameterized queries alone eliminate classic SQL injection. Knowing the fix makes your ticket to developers more useful.

A ticket that gets the fix prioritised

  • Name the categoryThe shared OWASP vocabulary developers already understand.
  • Show the evidenceThe raw request or log line.
  • State the outcomeWas the attempt blocked or did it succeed?
  • Recommend the fixRate limit, patch, code fix, or logging gap.
You rarely write the parameterized query, but you are often the first to prove the gap exists.
HACKTHESOCLesson 50OWASP Top 10 tour63 / 68

The worked example as a ticket

  • Names the category with CWE and ATT&CK IDs
  • States the outcome and the evidence behind it
  • Recommends a concrete fix category for developers
Category plus evidence plus outcome plus fix is what gets a ticket acted on by a team that does not read logs daily.

Key takeaways

  1. 01Every attack is an HTTP request: method, URL, headers, body, answered by a status code.
  2. 02The 2021 Top 10 ranks risk by prevalence and maps mostly to T1190; A01 Broken Access Control is number one.
  3. 03A01 to A05 are noisy and high volume; A06 to A10 are quieter, and A09 decides if anything is detected.
  4. 04Triage order: classify, measure volume and block/allow, correlate downstream, then decide.
  5. 052025 moved SSRF into A01, raised Misconfiguration to #2, and added two new categories; signals are unchanged.
  6. 06A good ticket names the category, shows the evidence, states the outcome and recommends the fix.
