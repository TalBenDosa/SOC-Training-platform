What the OWASP Top 10 is and why it exists

A data-driven consensus list of web risk categories, and a shared vocabulary.

HACKTHESOCLesson 50OWASP Top 10 tour6 / 49

A list built from data, not fear

  • OWASPThe Open Worldwide Application Security Project, a non-profit publishing free security guidance.
  • Data-drivenRebuilt from data contributed by dozens of firms plus a community survey, so ranks reflect prevalence.
  • Root causes in 2021Categories merged and renamed: Sensitive Data Exposure became A02 Cryptographic Failures.
  • Categories, not bugsEach entry holds many CWE (Common Weakness Enumeration) IDs, so one alert logic covers a family.
Three 2021 categories were entirely new, added partly from the survey because tooling struggles to detect them automatically.
HACKTHESOCLesson 50OWASP Top 10 tour7 / 49

Why a developer list matters to the SOC

Hypotheses from logs

../../etc/passwd in a path is path traversal, A01. ' OR 1=1-- in a query string is A03 Injection.

Shared ATT&CK language

Most of the lesson falls under T1190, Exploit Public-Facing Application. Cite it in tickets and detections.

The Top 10 is the common vocabulary between developers, pen testers and incident responders.

When an alert fires, everyone should understand both the technique and the fix being discussed.

Section 2 of 9

A01 to A05: access, crypto, injection, design, misconfig

The five categories that drive most noisy, high-volume web attack traffic.

HACKTHESOCLesson 50OWASP Top 10 tour9 / 49

A01 Broken Access Control: one digit changed

  • Same session cookie, different id: account 124's data comes back anyway
  • This is IDOR: the server trusted the URL instead of checking the session
  • In logs: users reaching others' resources, or 403 bursts on sequential IDs
A01 rose to number one in 2021. The attack lives entirely in the query string, and it needs no stolen credentials, only curiosity.
HACKTHESOCLesson 50OWASP Top 10 tour10 / 49

A03 Injection: input interpreted as code

  • The WHERE clause always evaluates true, so every row comes back
  • A03 groups SQL injection, command injection and XSS
Access logs and WAF alerts often show the payload in plain sight inside the query string, exactly where the primer told you to look.
HACKTHESOCLesson 50OWASP Top 10 tour11 / 49

A02, A04 and A05: weak protection, bad design, bad config

A02 Cryptographic

Weak, missing or misused encryption. A login form served over plain HTTP lets a network attacker read the Cookie and body in transit.

A04 Insecure Design

Flaws in the architecture, like a password reset with no rate limiting. You cannot patch it; re-think it with threat modelling.

A05 Misconfiguration

GET /.env returns 200 OK with database credentials, because the server serves dotfiles. Nothing was hacked.

A05 is the one that surprises students: a misconfigured server simply answered a request it should have refused.
HACKTHESOCLesson 50OWASP Top 10 tour12 / 49

One quick signal per category

RankCategoryOne quick signal
A01Broken Access ControlSpikes of 403s, sequential-ID IDOR patterns
A02Cryptographic FailuresPlain HTTP logins, weak TLS
A03InjectionSQL/script payloads in the query string or body
A04Insecure DesignMissing rate limits by design
A05Security MisconfigurationDefault creds, exposed files, open panels
These five drive the majority of the noisy, high-volume web attack traffic analysts triage day to day.

Section 3 of 9

A06 to A10: components, auth, integrity, logging, SSRF

Lower volume, often higher impact.

HACKTHESOCLesson 50OWASP Top 10 tour14 / 49

A06 Outdated components: Log4Shell in one header

  • Vulnerable Log4j evaluates the ${jndi:...} lookup in any logged field
  • It reaches attacker infrastructure and can run attacker-supplied code
  • CVE-2021-44228: no special endpoint needed, just a value that gets logged
If you cannot inventory your dependencies, you cannot know your exposure. Threat intel feeds and vulnerability scanners feed this category.
HACKTHESOCLesson 50OWASP Top 10 tour15 / 49

A07, A08, A09: logins, trust, and visibility

A07 Auth failures

Credential stuffing, brute force, non-expiring sessions, no MFA. POST /login returning 401 repeatedly, or one account failing from many countries.

A08 Integrity failures

Code or data trusted without verification: unsigned auto-updates, a compromised CI/CD pipeline. Headline example: SolarWinds.

A09 Logging failures

Auth, denials and server errors not logged or never reviewed. Most breaches are found by outsiders; dwell time grows.

A07 is prime SOC hunting ground. A09 is the category analysts feel most personally.
HACKTHESOCLesson 50OWASP Top 10 tour16 / 49

A10 SSRF: the server fetches what the attacker chose

A link-preview feature meant for the public internet is pointed at the cloud metadata service and returns the server's own temporary credentials. Watch for outbound connections from web servers to internal or link-local IPs.
HACKTHESOCLesson 50OWASP Top 10 tour17 / 49
Without good logging and an analyst reading it, the quieter categories succeed silently.

One exploited outdated component or one SSRF into cloud metadata can hand over a foothold or credentials that no firewall tuning will catch.

This is why A09 matters so much: it decides whether any of the other nine can be detected.

HACKTHESOCLesson 50OWASP Top 10 tour21 / 49

A01 has four shapes, one root cause

The server trusts the client instead of re-checking.

  • IDORid=123 becomes id=124. Signal: one session touching many sequential IDs.
  • Path traversalfile=../../../../etc/passwd (CWE-22). Signal: ../, ..%2f, %2e%2e%2f in file or path params.
  • Forced browsingGuessing /admin, /backup.zip. Signal: 401/403 bursts, then a 200 on a sensitive path.
  • Parameter tamperingSubmitting role=admin or is_admin=true. Signal: role changes no admin action explains.
Broken Access Control is number one in both editions, so these four shapes are worth memorising.
HACKTHESOCLesson 50OWASP Top 10 tour22 / 49

A03 is three attacks: SQLi, XSS, command injection

  • Stored XSS (CWE-79): script runs in the next visitor's session, ships the cookie
  • Command injection (CWE-78): ping runs, then cat /etc/passwd
  • Hunt <script>, onerror=, javascript:; shell ; | & $()
XSS has three flavours: stored, reflected, DOM-based. Fixes: output-encode plus Content-Security-Policy for XSS; avoid shelling out, or strict allow-lists, for command injection.
HACKTHESOCLesson 50OWASP Top 10 tour23 / 49

Three one-liners worth a log signal

  • XXE (A05, CWE-611)Signal: a body declaring <!DOCTYPE with <!ENTITY ... SYSTEM, or an XML upload followed by unexpected outbound HTTP/DNS. Fix: disable DTDs.
  • Deserialization (A08, CWE-502)Signal: a serialized object where one is not normal (Java base64 starts rO0AB), then the web process spawning a shell in EDR.
  • CSRF (A01, CWE-352)Signal: a state-changing request whose Origin or Referer is a foreign domain, or a burst of CSRF-token 403s. Fix: anti-CSRF tokens, SameSite.
These three got only a passing mention in the tour. The strongest deserialization corroboration is EDR: java, w3wp.exe or php-fpm spawning cmd.exe or /bin/sh seconds after the request.

The OWASP Top 10:2025 update

Unveiled November 2025, built from over 175,000 CVE records across 589 CWEs.

HACKTHESOCLesson 50OWASP Top 10 tour25 / 49

The 2025 lineup and where each came from

2025 rankCategory2021 equivalent
A01Broken Access ControlSame as 2021 A01, now absorbs SSRF
A02Security MisconfigurationJumped from #5
A03Software Supply Chain FailuresNew category
A04 to A06Cryptographic Failures, Injection, Insecure DesignWere A02, A03 (down two places), A04
A07 to A09Authentication, Integrity, Logging and Alerting FailuresSame ranks as 2021
A10Mishandling of Exceptional ConditionsNew category
Most documentation, WAF rule names and training will keep referencing 2021 for some time, but analysts should recognise the new numbering in tooling and reports.
HACKTHESOCLesson 50OWASP Top 10 tour26 / 49

Why the shifts happened

SSRF folded into A01

Most SSRF bugs are a server trusting a request it should have restricted: the access-control root cause.

Supply chain at #3

Formalizes vulnerable dependencies and poisoned build pipelines like SolarWinds into a top-level risk.

Injection down to #5

Not rarer. Access control and misconfiguration are now measured as even more prevalent in CVE data.

Exceptional conditions

A stack trace in a 500 leaking paths, or a payment flow that fails open when validation times out.

Misconfiguration's climb reflects cloud and container mistakes: open buckets, default credentials, exposed services.
HACKTHESOCLesson 50OWASP Top 10 tour27 / 49
The version number is a label for your report, not a change to how you read evidence.

An IDOR is an IDOR as A01:2021 or A01:2025. A UNION SELECT is injection whether ranked A03 or A05.

The detection signals from the 2021 tour apply directly.

Reading web logs through the OWASP lens

Sort each anomaly by the request's method, path, query string, headers, body and status code.

HACKTHESOCLesson 50OWASP Top 10 tour29 / 49

One Combined Log Format line, read left to right

Source IP, timestamp, a URL-encoded UNION SELECT against /search (A03), a 500 because the backend choked, 512 bytes, no referrer, and python-requests: a scripted client on a search box meant for humans.
HACKTHESOCLesson 50OWASP Top 10 tour30 / 49

Status codes are your fast filter

  • 200, wrong userOn a sensitive resource: possible A01 access-control break that succeeded.
  • 403 in burstsSomeone probing authorization boundaries.
  • 500 clustersAround odd input: the backend choking on an injection attempt.
  • Unexpected outboundFrom a server to internal or metadata IPs: A10 SSRF.
These are filters to prioritise, not verdicts on their own.
HACKTHESOCLesson 50OWASP Top 10 tour31 / 49

Correlation beats any single line

One SQL-looking string

Might be a false positive from a security scanner.

100 variations, then a 200

Suggests successful data extraction. Pivot to database or identity logs to confirm impact.

Remember A09: all of this depends on apps logging auth events, denials and server errors to the SIEM with accurate timestamps.

Requesting a new log source or richer field directly reduces dwell time. OWASP gives you the language to justify it.

Section 7 of 9

Did it work? Proving success from the log fields

Most web attack traffic fails. The evidence for the fraction that did not lives in the response fields.

HACKTHESOCLesson 50OWASP Top 10 tour33 / 49
The payload tells you what was attempted. The response fields tell you whether it worked.

Size, status, error text and latency on the same log line separate a blocked probe from a real breach.

This is the shift from 'an attack was tried' to 'an attack succeeded'. Analysts who stop at the payload miss the few requests that mattered.
HACKTHESOCLesson 50OWASP Top 10 tour34 / 49

Four outcome tells in the response

  • Response size vs normalA search page that normally returns 4 to 6 KB answering one request with 380 KB signals a data-returning injection.
  • Status in contextA run of 403s or WAF blocks then one 200 on the same path and parameter means something got through. A 500 is ambiguous.
  • Error text in the bodyA SQL syntax error naming the engine, or a Java stack trace with internal paths, means the app is leaking internals.
  • LatencyIf the log records duration, responses taking almost exactly the delay a probe asked for mean the database executed the input.
A path-traversal 200 whose byte count matches the target file is a hit; the same request returning the standard 1.2 KB error page is not.
HACKTHESOCLesson 50OWASP Top 10 tour35 / 49

Hunt by outcome, not by payload keyword

  • Join a suspicious request to an abnormal outcome, not a keyword alone
  • Bytes far above the path's median suggest a data-returning injection
  • A duration near the delay the probe asked for means the DB executed it
Payload-keyword searches return every scanner on the internet. Joining a suspicious request to an abnormal outcome returns the few that matter.
HACKTHESOCLesson 50OWASP Top 10 tour36 / 49

Was the WAF block a real attack?

Likely false positive

A real customer with normal session history, ordinary prose in a free-text field (a review, comment, ticket), who retried the same action.

Fix it narrowly

Set the one managed rule to Count for that path, or exclude just the argument from the rule ID that fired. Never disable the whole rule.

Record why each exclusion exists: an over-broad exclusion is a hole you created yourself.

WAFs block legitimate requests when a free-text field contains SQL-like words or punctuation. Judge the block by the source, the field, and whether a normal user retried.

A worked investigation: from alert to verdict

A WAF record, a five-step checklist, and why the order matters.

HACKTHESOCLesson 50OWASP Top 10 tour38 / 49

The WAF fires: SQLi blocked by a managed rule

  • args is the query string: a UNION SELECT payload, so A03 Injection
  • action: BLOCK changes the triage path completely
Walk it like the raw request in section one: method, uri, args.
HACKTHESOCLesson 50OWASP Top 10 tour39 / 49

The triage checklist

  1. 1Blocked or allowed?BLOCK means it never reached the app. Lower urgency; still log the source IP.
  2. 2Volume from this sourcePivot on clientIp for the last hour. One is noise; two hundred variations is a scanner.
  3. 3Did anything get through?Look for allowed 200s on the same path. A large body after BLOCKs means a bypass.
  4. 4Correlate downstreamDatabase logs: unusual query at that time? Returned data volume spike?
  5. 5DecideAll blocked, low volume: close as routine scan. Allowed payload or spike: escalate.
On escalation, consider a temporary IP block or rate limit while you confirm impact.
HACKTHESOCLesson 50OWASP Top 10 tour40 / 49
Classify, then measure volume and outcome, then correlate downstream.

Jumping straight to 'block the IP' without checking whether the attack already succeeded is a common beginner mistake.

Containment matters, but so does knowing whether you are already too late and must widen into the database and identity layers.

Section 9 of 9

Detection and defence in practice

Where attacks are caught, where they are fixed, and the SOC's role in between.

HACKTHESOCLesson 50OWASP Top 10 tour42 / 49

Where detection lives

WAF

Inspects method, path, query, headers and body. Managed groups cover A03 and A07 patterns; custom rules can block a url resolving to 169.254.169.254.

Rate limiting

Caps requests per IP or account per minute. Blunts A04 unthrottled reset endpoints and A07 credential stuffing.

The custom SSRF rule is a direct, cheap defence against A10.
HACKTHESOCLesson 50OWASP Top 10 tour43 / 49

Where prevention lives: mostly in code

CategoryThe fix
A01 / A03Server-side access checks on every request; parameterized queries treat input as data
A02TLS everywhere, modern password hashing, disable outdated ciphers
A05Remove default creds, disable directory listing and dotfiles, config scanners in CI/CD
A06Maintain an SBOM and patch on a schedule, not only after Log4Shell
A09Log auth events, denials and server errors with timestamps and source IPs, ship to SIEM
Parameterized queries alone eliminate classic SQL injection. Knowing the fix makes your ticket to developers more useful.
HACKTHESOCLesson 50OWASP Top 10 tour44 / 49

A ticket that gets the fix prioritised

  • Name the categoryThe shared OWASP vocabulary developers already understand.
  • Show the evidenceThe raw request or log line.
  • State the outcomeWas the attempt blocked or did it succeed?
  • Recommend the fixRate limit, patch, code fix, or logging gap.
You rarely write the parameterized query, but you are often the first to prove the gap exists.
HACKTHESOCLesson 50OWASP Top 10 tour45 / 49

Key takeaways

  1. 01Every attack is an HTTP request: method, URL, headers, body, answered by a status code.
  2. 02The 2021 Top 10 ranks risk by prevalence and maps mostly to T1190; A01 Broken Access Control is number one.
  3. 03A01 to A05 are noisy and high volume; A06 to A10 are quieter, and A09 decides if anything is detected.
  4. 04Triage order: classify, measure volume and block/allow, correlate downstream, then decide.
  5. 052025 moved SSRF into A01, raised Misconfiguration to #2, and added two new categories; signals are unchanged.
  6. 06A good ticket names the category, shows the evidence, states the outcome and recommends the fix.

Check your understanding, question 1 of 3

One external IP sends dozens of requests whose query strings contain ' OR '1'='1 and UNION SELECT, several returning HTTP 500. Which OWASP 2021 category fits best?

These are classic SQL injection payloads: untrusted input interpreted as database code, A03. The 500s suggest the backend is choking on malformed queries. Nothing targets TLS, guesses passwords, or makes the server fetch a URL.

Check your understanding, question 2 of 3

After a POST to a public 'link preview' feature with url=http://169.254.169.254/..., the web server starts making outbound requests to that address. Which category and consequence fit?

Forcing a server-side feature to request 169.254.169.254 so it returns the server's own credentials is textbook A10 SSRF. The issue is an attacker-chosen request, not rate limiting, TLS, or an unsigned update.

Check your understanding, question 3 of 3

A server receives GET /download?file=../../../../etc/passwd and returns 200 with the file contents. Which category matches, and what should you hunt for?

The ../ sequence climbs out of the intended folder to read an arbitrary file: path traversal, one of A01's four shapes. It is not directory listing, not an outbound fetch, and reading /etc/passwd is not a login.
