What SMB is and why Windows networks rely on it

Server Message Block: sharing files and printers so a distant folder feels local.

HACKTHESOCLesson 83SMB explained6 / 56

The machinery behind everyday collaboration

  • Network drives and sharesThe \\FILESERVER\HR folders teams collaborate in.
  • Shared printersSending a document to a printer across the network.
  • Server file accessMuch of what Windows domains do for collaboration.
  • Shares and permissionsA server offers named shares; permissions decide who may read or write.
  • UNC path\\server\share, Universal Naming Convention, is how SMB names a shared resource.
SMB is enabled on essentially every Windows network. That ubiquity is why it is indispensable to users and irresistible to attackers: sharing is also a ready-made way to move files and reach machines.
HACKTHESOCLesson 83SMB explained7 / 56

Share, permission, and who connects

A server offers named shares; permissions decide who may read or write each one.

Share (UNC path)HoldsWho should reach it
\\FILESERVER\HRHR team documentsThe HR group, read and write
\\FILESERVER\PublicCompany-wide read-only filesAll staff, read only
\\PRINT01\Printer3A shared printer queueAnyone who may print

\\server\share is the Universal Naming Convention (UNC): how SMB names a shared resource.

Permissions are the control that turns open sharing into something governed. An over-permissive share is a finding before any attacker shows up.
HACKTHESOCLesson 83SMB explained8 / 56

The same feature, seen two ways

To the business

A folder on a distant server behaves like a local one. Teams collaborate, print, and share without thinking about it.

To an intruder

A ready-made way to move files onto other machines and reach them. Sharing and lateral movement use the same machinery.

SMB is enabled on essentially every Windows network, which is exactly why it is both indispensable and irresistible.

Hold this dual-use idea the whole lesson: nothing about malicious SMB is a different protocol, only a different pattern of the same operations.

Section 2 of 10

How SMB works: shares, permissions and port 445

A client/server protocol running directly over TCP 445.

HACKTHESOCLesson 83SMB explained10 / 56

The basic SMB exchange

Modern SMB uses TCP 445. Older SMB used 137–139 with NetBIOS.

  1. 1Server advertises sharesA file server or even an ordinary PC exposes named shares and enforces permissions.
  2. 2Client connectsOn port 445, requesting a specific share by its UNC path.
  3. 3Server checks permissionsIf allowed: browse, open, read, write, delete, print.
  4. 4Session continuesAs the user works with the shared resource.
You may still see 139 referenced, but 445 is the modern standard.
HACKTHESOCLesson 83SMB explained11 / 56

Which ports carry SMB, and when

Port(s)EraWhat you should see today
TCP 445Modern SMBThe normal, expected path for all current SMB
TCP 139NetBIOS Session ServiceLegacy; occasional, worth noting on a modern net
UDP 137 / 138NetBIOS name / datagramOld name resolution; should be rare and scoped

You may still see 139 referenced, but 445 is the standard; heavy 137-139 on a modern LAN is itself a flag.

Attackers also abuse NetBIOS name service (LLMNR/NBT-NS) for poisoning, which is why unexpected 137-139 is worth a glance.
HACKTHESOCLesson 83SMB explained12 / 56

Two things behind the scenes that matter for security

Authentication

SMB access is tied to a user the server recognises, so it is deeply intertwined with Kerberos/NTLM and Active Directory.

Versions

SMBv1, v2, v3. The ancient SMBv1 is dangerous and should be disabled; SMBv3 adds encryption and stronger protections.

Users open \\server\share, map Z:, or print. Admins use net share and net use.

On the wire, SMB is just constant connections on 445. That normality is what lets malicious SMB blend in until you know what abnormal looks like.

Section 3 of 10

Inside an SMB message: headers, commands, trees

The small set of building blocks every SMB2/3 conversation is made of.

HACKTHESOCLesson 83SMB explained14 / 56

Header fields an analyst relies on

Each message is a PDU: a fixed header plus a command-specific body.

  • CommandWhich operation this message is.
  • MessageIdA counter pairing each request with its response.
  • TreeIdWhich connected share this refers to.
  • SessionIdWhich authenticated session.
  • StatusOn responses, e.g. STATUS_SUCCESS, STATUS_ACCESS_DENIED.
PDU means Protocol Data Unit, a single self-contained chunk of protocol data.
HACKTHESOCLesson 83SMB explained15 / 56

How request and response pair up

MessageId

A counter: the response carries the same id as its request, so you can follow a conversation even when many are interleaved.

TreeId / SessionId

Which connected share, and which authenticated session, this message belongs to.

Status

On responses: STATUS_SUCCESS, or STATUS_ACCESS_DENIED when permissions refused the operation.

A run of ACCESS_DENIED followed by a SUCCESS on the same object is the SMB-level shape of a permission being found or a right being gained.
HACKTHESOCLesson 83SMB explained16 / 56

The SMB2 commands that tell the story

CommandWhat it doesAnalyst relevance
NEGOTIATEAgree on the dialectReveals SMB version; SMB1 here is a red flag
SESSION_SETUPAuthentication handshake (NTLM/Kerberos via SPNEGO)Where the logon happens; ties to Event ID 4624
TREE_CONNECTConnect to a share, e.g. \\srv\ADMIN$The 'connected to a share' moment; Event ID 5140
CREATEOpen a file, directory or named pipeOpening \PIPE\svcctl shows here; Event ID 5145
READ / WRITETransfer file or pipe dataBulk WRITEs across many files = possible ransomware
IOCTLDevice/pipe control, RPC-over-pipeCarries the actual remote-admin RPC calls

TREE_DISCONNECT, LOGOFF and CLOSE are the orderly teardown of the tree, session and handle.
HACKTHESOCLesson 83SMB explained17 / 56

Same skeleton, benign then malicious

Every Windows share access, legitimate or malicious, is built from exactly these pieces. 4624 rides on SESSION_SETUP, 5140 on TREE_CONNECT, 5145 on the object accesses inside the tree.
HACKTHESOCLesson 83SMB explained18 / 56

Reading the two halves of that capture

Benign half

A named user opens one business file on a normal share: Finance, Kerberos, a single READ. Narrow and expected.

Malicious half

The same commands aimed at ADMIN$ to drop a file, then IPC$ and the svcctl pipe: copy a tool, then run it remotely.

Identical SMB2 commands. Only the target shares and the sequence differ.

This is the lesson in one slide: you do not look for exotic commands, you look for ordinary commands aimed at admin shares and pipes.

Section 4 of 10

SMB in the real world: files, drives, admin shares

Know normal so the abnormal jumps out.

HACKTHESOCLesson 83SMB explained20 / 56

Everyday SMB versus built-in admin shares

Everyday SMB

A workstation reaching a handful of known file servers on 445 for team folders and printers. Stable and predictable.

C$ and ADMIN$

Hidden shares Windows creates on every machine: C$ is the whole C: drive, ADMIN$ the Windows folder. Meant for remote admin.

Mapped drives

The Z: that is really \\FILESERVER\Finance. LNK files and Jump Lists record these UNC paths.

Access to C$ or ADMIN$ across many machines from one source is a strong lateral-movement signal.
HACKTHESOCLesson 83SMB explained21 / 56

The three hidden shares every Windows host exposes

ShareWhat it maps toLegitimate use / abuse
C$The whole C: driveRemote admin of files; or reading and writing a victim's disk
ADMIN$The Windows directoryPatch and tool deployment; or dropping a payload to run
IPC$Named pipes, not filesRemote administration over RPC; or recon and remote execution

Hidden means the trailing $ keeps them out of share listings, not that they are protected.

These are created automatically on every machine. Access to them across many hosts from one source is the single strongest lateral-movement tell.
HACKTHESOCLesson 83SMB explained22 / 56
PsExec connects to an admin share, copies a program, and starts it as a service.

Legitimate for admins, a favourite for attackers. That is why so much lateral movement shows up as SMB activity.

Normal SMB is narrow: a user reaching a few known shares. Abuse is broad: one machine suddenly touching admin shares on dozens of others.

Section 5 of 10

SMB versions and signing: SMBv1 to SMBv3

Where a network stands on these settings decides how much SMB can be used against it.

HACKTHESOCLesson 83SMB explained24 / 56

Three eras of SMB

1980s/90s

SMBv1

Old, inefficient, and holds the flaws exploited by EternalBlue and WannaCry. Disable everywhere; re-enabling it for legacy devices is worth flagging.

Windows Vista

SMBv2

A major rewrite that improved performance and dropped some SMBv1 weaknesses.

Windows 8 / Server 2012

SMBv3

Adds end-to-end encryption and further hardening. What a well-secured network should run exclusively.

Modern Windows disables SMBv1 by default and only re-enables it for compatibility.
HACKTHESOCLesson 83SMB explained25 / 56

How an SMB relay attack works without signing

  1. 1CaptureAttacker intercepts an auth attempt, often via LLMNR/NBT-NS poisoning elsewhere on the network.
  2. 2RelayForwards it unmodified to a different server.
  3. 3Log in as the victimWithout ever knowing the password.
  4. 4Signing stops itEach message is signed, so a relayed, unsigned message is rejected.
Require signing on servers, especially domain controllers. Microsoft moved toward signing by default because relay remained common in real intrusions for years.
HACKTHESOCLesson 83SMB explained26 / 56

The three-question SMB hardening check

  • SMBv1 disabled?Removes the EternalBlue-era attack surface.
  • Signing enforced?Particularly toward domain controllers; defeats relay.
  • Null sessions blocked?A null session authenticates as nobody yet can enumerate usernames or share names.

These three facts, more than almost anything else, decide how far SMB can be turned against the network.

Modern Windows restricts null sessions by default, but older or misconfigured systems still allow anonymous enumeration as early recon.
HACKTHESOCLesson 83SMB explained27 / 56

What each hardening control actually stops

ControlCloses offIf missing
Disable SMBv1The EternalBlue / WannaCry class (MS17-010)A wormable remote exploit on the segment
Enforce SMB signingSMB relay of captured authenticationA login as the victim with no password known
Block null sessionsAnonymous enumeration of users and sharesFree reconnaissance before any credential
These three facts, more than almost anything else, decide how far SMB itself can be turned against the network.

Section 6 of 10

The SMB dialect table and how negotiation works

Tools report dialects as raw hex like 0x0311. Read them at a glance.

HACKTHESOCLesson 83SMB explained29 / 56

Negotiation in three moves

  1. 1Client offersNEGOTIATE request lists every dialect it will speak, oldest to newest.
  2. 2Server picksThe highest dialect it also supports.
  3. 3Session runsEntirely in the chosen dialect.
Modern Windows negotiates 2.0.2 up to 3.1.1 and will not negotiate SMB1 unless the legacy feature is re-enabled. A successful SMB1 negotiation is itself worth an alert.
HACKTHESOCLesson 83SMB explained30 / 56

Every dialect and what it added

DialectCodeFirst releaseWhat it added
SMB 1.0 (CIFS)pre-SMB2NT / 2000 eraThe original; EternalBlue's target. Disable.
SMB 2.0.20x0202Vista / Server 2008Full rewrite, fewer commands, larger reads/writes
SMB 2.10x0210Windows 7 / 2008 R2Oplock improvements, large MTU support
SMB 3.00x0300Windows 8 / 2012Encryption, SMB Direct, Multichannel, failover
SMB 3.0.20x0302Windows 8.1 / 2012 R2Ability to disable SMB1, encryption improvements
SMB 3.1.10x0311Windows 10 / 2016Pre-auth integrity (SHA-512), AES-GCM/CCM, downgrade protection
3.1.1 is modern and downgrade-resistant, 2.x is functional but older, SMB1 at all is a finding.
HACKTHESOCLesson 83SMB explained31 / 56

Reading a negotiated dialect at a glance

0x0311 (3.1.1)

Modern and downgrade-resistant: pre-auth integrity and AES encryption negotiation.

0x02xx / 0x03xx

Functional but older. Expected on mixed estates; note where encryption is not in use.

SMB1 (NT LM 0.12)

A finding on a hardened network: either a genuinely ancient device or a downgrade.

You do not memorise the hex to use it. Green for 3.1.1, caution for 2.x, alarm for any SMB1 negotiation at all.
HACKTHESOCLesson 83SMB explained32 / 56

Dialect negotiation in a packet capture

  • Wireshark smb2 filter shows the offered and selected dialects
  • 3.1.1 hashes the negotiate exchange, so tampering mid-negotiation is detected
Earlier SMB had no pre-authentication integrity, which is what made silent downgrade attacks feasible.

Named pipes and the IPC$ share

The hidden share that carries Windows remote administration.

HACKTHESOCLesson 83SMB explained34 / 56

Each pipe name maps to a service

IPC$ exposes named pipes, not files: a two-way tube to one specific process.

PipeBacking serviceUsed for
\PIPE\svcctlService Control ManagerCreate/start/stop a service: the PsExec mechanism
\PIPE\srvsvcServer ServiceEnumerate shares on a remote host
\PIPE\samrSecurity Account ManagerEnumerate local users and groups (classic recon)
\PIPE\lsarpcLocal Security AuthorityEnumerate SIDs, security policy, trust information
\PIPE\netlogonNetlogonDomain authentication (CVE-2020-1472, Zerologon)
\PIPE\winregRemote RegistryRead or modify a remote registry
IPC$ carries Remote Procedure Calls (RPC) to specific Windows services. Knowing the pipe turns a cryptic log entry into a clear story.
HACKTHESOCLesson 83SMB explained35 / 56
IPC$ carries conversations with processes, not files: a labelled tube to one specific Windows service.

Opening a pipe like svcctl or samr is remote administration or reconnaissance happening over SMB.

This reframes IPC$ from a mysterious hidden share into exactly what it is: the transport for Windows remote-management RPC.
HACKTHESOCLesson 83SMB explained36 / 56

What PsExec-style execution does over SMB

  • Steps 2-5 from a host with no admin role for that server is a strong signal
  • Impacket psexec.py/wmiexec.py, NetExec, BloodHound collectors ride this path
The legacy null session was dangerous because it let anyone enumerate users and shares over lsarpc and samr without authenticating.
HACKTHESOCLesson 83SMB explained37 / 56

Why the null session was so dangerous

The feature

An anonymous connection to IPC$ that authenticated as nobody, yet could still open pipes like samr and lsarpc.

The abuse

Enumerate users, groups and shares with no credential at all: free reconnaissance before an attack even begins.

Today

Modern Windows restricts null-session access to IPC$ by default; finding it allowed on a host is a finding.

Null-session recon is why blocking anonymous IPC$ access is one of the three hardening facts from the versions section.

Section 8 of 10

Authentication over SMB: NTLM, Kerberos, 5145

SMB wraps one of two Windows protocols, negotiated via SPNEGO.

HACKTHESOCLesson 83SMB explained39 / 56

Kerberos first, NTLM as fallback

Kerberos

Preferred default in AD. Ticket-based, signed by a domain controller, mutual authentication, resistant to simple replay.

NTLM

Older hash-based challenge-response, no mutual auth. Enables pass-the-hash and SMB relay. Used when connecting by IP, to non-domain systems, or by legacy tools.

In a Kerberos-everywhere environment, a spike of NTLM network logons is itself a signal.

Causes: misconfiguration, legacy software nobody hardened, or a relay or downgrade attack deliberately avoiding Kerberos.
HACKTHESOCLesson 83SMB explained40 / 56

Why an NTLM spike is worth chasing

In an AD domain Kerberos is the default; NTLM is the fallback.

  • When NTLM is normalConnecting by IP not hostname, reaching a non-domain host, or legacy tooling.
  • When it is a signalA sudden rise in NTLM network logons where Kerberos is expected everywhere.
  • What it can meanMisconfiguration, unhardened legacy software, or a relay or downgrade deliberately avoiding Kerberos.
The Authentication Package field on Event 4624 is where you read Kerberos versus NTLM for each network logon.
HACKTHESOCLesson 83SMB explained41 / 56

From logon to share to the exact object

  • 4624 Logon Type 3: the Authentication Package says Kerberos or NTLM
  • 5140 fires once, the first time a session connects to a share
  • 5145 fires per object: here it proves svcctl was opened
5145 fires so often that most environments enable it selectively via the Audit Detailed File Share policy on high-value shares.
HACKTHESOCLesson 83SMB explained42 / 56

Drilling from logon to the exact object touched

  1. 14624, Logon Type 3A network logon happened; the package says Kerberos or NTLM, with a source address.
  2. 25140, share connectThat session connected to a share, e.g. \\SRV-DB01\IPC$. Fires once per share.
  3. 35145, object accessInside the share it opened a specific object, e.g. the svcctl pipe. Fires per object.
  4. 4CorrelateOne account, one source, admin shares and svcctl: the remote-execution story in three event IDs.
5145 is noisy, so it is usually enabled selectively via Audit Detailed File Share on high-value shares. 5140 plus 4624 is the baseline.

Section 9 of 10

Why SMB matters to a SOC analyst

Much of an intrusion actually happens here: moving, spreading, encrypting.

HACKTHESOCLesson 83SMB explained44 / 56

The major SMB abuses

Lateral movement

Admin shares, copied tools, PsExec pattern. One machine rapidly connecting to many on 445.

Ransomware spread

Reaches and encrypts shared drives across the organisation at once. Mass file modification is a hallmark.

EternalBlue

WannaCry spread machine to machine through MS17-010 in SMBv1.

Credentials and recon

Enumerating shares; harvesting or relaying NTLM credentials.

EternalBlue is the headline reason SMBv1 must be disabled and SMB patched.
HACKTHESOCLesson 83SMB explained45 / 56

Each abuse and the telemetry that reveals it

AbuseWhat you watchThe tell
Lateral movementPort 445 connection graphOne host to many on 445, admin shares, one account
Ransomware spreadFile operations on sharesMass WRITE and rename across many files at once
EternalBlue (SMBv1)Dialect negotiatedAny SMB1 on a modern segment
Recon and relayAuth package and IPC$ pipesNTLM spike; samr or lsarpc from odd sources
Each row maps back to an earlier section: the connection graph, the dialect table, the auth events, the pipes.
HACKTHESOCLesson 83SMB explained46 / 56

What the SOC watches on port 445

  • Zone crossingA workstation reaching servers or workstations it never normally touches.
  • Fan-outOne host connecting to many hosts on 445.
  • Admin sharesC$ and ADMIN$ access from unexpected sources.
  • Mass file operationsBulk changes on shares: possible ransomware.
  • Any SMBv1Should not exist in a hardened environment.
Normal SMB is quiet and predictable. Malicious SMB is a machine reaching where it should not.

Worked example: lateral movement in SMB logs

Five Event ID 5140 lines from one source in under fifteen seconds.

HACKTHESOCLesson 83SMB explained48 / 56

One source, four machines, one account

  • Hidden ADMIN$ on three workstations then a database server
  • Ends at C$ on SRV-DB01 moments after touching ordinary workstations
  • Backup jobs run on a schedule against a fixed list, not ad hoc like this
One source, many admin-share destinations, a tight time window, one set of credentials: the fan-out signature made concrete.

The account name svc-backup is designed to look routine. Judge the behaviour, not the name, against how backup actually runs here.

The questions an analyst asks next

  1. 1Is the account doing its job?Does svc-backup normally use WKS-041 as the source? Backup usually flows server to target.
  2. 2Which process started it?A scripting engine or remote-admin tool on WKS-041 around 14:02?
  3. 3Was a file written?A copy into ADMIN$ or C$ is the next step of a PsExec-style spread.
