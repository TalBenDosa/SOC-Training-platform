Section 1 of 5

Excessive Agency (OWASP LLM06)

When the agency granted to an AI agent exceeds what its task requires.

HACKTHESOCLesson 92AI attacks, part 26 / 36
Handing a confused intern a master key 'just in case' makes the whole building the blast radius.

Hallucination, injection or a compromised peer agent triggers the misbehaviour. Unneeded permissions amplify the damage.

Excessive Agency is the amplifier, not the trigger. That framing is what this section is about.
HACKTHESOCLesson 92AI attacks, part 27 / 36

OWASP names three root causes precisely

Root causeWhat it meansWorked example
Excessive FunctionalityA tool bundles more capability than the task needsA 'read customer record' tool that also supports delete and update
Excessive PermissionsThe tool has broader downstream access than neededA read-only agent connected with INSERT, UPDATE and DELETE rights
Excessive AutonomyHigh-impact actions with no verification or approvalA refund agent that completes a transaction the moment it decides to
Knowing which root cause applies changes what you actually fix.
HACKTHESOCLesson 92AI attacks, part 28 / 36

Part 1's ticket agent, revisited

  • The capability sat there unused until the injection triggered it
  • Excessive Functionality plus Excessive Autonomy acting together
The injection was not especially clever. The agent's own permission footprint turned an attempt into an incident.
HACKTHESOCLesson 92AI attacks, part 29 / 36

Never use the LLM's judgment as the security boundary

  • Enforce downstreamAuthorization lives in the system the agent calls, as you would never trust a user's own claim of access.
  • Tool-invocation audit logsCorrelate to agent identity and its task profile; flag any call outside the expected set.
  • Least privilege per toolA 'check order status' tool is architecturally incapable of cancelling or refunding.
  • Logged human approvalMandatory for high-impact actions: financial transactions, data deletion, external communications.
This is the same least-privilege discipline taught for human and service accounts, applied one layer further.
HACKTHESOCLesson 92AI attacks, part 210 / 36

The tool-call audit record is the evidence

  • Written by the application that executes tools, not by the model
  • An order-status bot issued a refund, with no approval required
Teach students to read agent identity, tool, parameters, approval and result together. The record is what lets you reconstruct who drove the action.
HACKTHESOCLesson 92AI attacks, part 211 / 36

Flag any tool call outside the agent's task profile

  • The refund is returned: not in the profile, no approval, and it succeeded
  • Incident (who drove it?) and design defect (why could it call issue_refund?)
The left-anti join keeps only calls that do not match a documented profile entry. Both questions in the second callout need an owner.

Section 2 of 5

Improper Output Handling (OWASP LLM05)

Treat model output as untrusted input to the rest of the application.

HACKTHESOCLesson 92AI attacks, part 213 / 36
If an attacker can influence a model's input, they can influence its output.

Rendering, executing or forwarding that output without validation hands the attacker whatever the downstream system can do.

Engineers distrust user input but not 'our own AI system'. That gap is the whole category.
HACKTHESOCLesson 92AI attacks, part 214 / 36

Four exploitation shapes that recur

XSS

Reply rendered as raw HTML; an image tag with an onerror handler runs JavaScript in the viewer's browser.

RCE

A coding assistant wired to execute the shell commands it proposes.

SQL injection

Model output concatenated into a query instead of parameterized.

SSRF

Output builds a URL the server fetches, reaching internal infrastructure.

Each is a classic web vulnerability. The only new part is the source of the untrusted string.
HACKTHESOCLesson 92AI attacks, part 215 / 36

WAF alert plus gateway log: the payload came from the bot

Read together: the 'attack' request came from an internal admin's browser because the payload was inside the bot's stored reply. Root cause is unescaped rendering of model output, so the ticket goes to the console's developers, not the network team.
HACKTHESOCLesson 92AI attacks, part 216 / 36

The fix lives entirely on the output side

  • Encoding and CSPContext-aware output encoding before rendering, plus a Content-Security-Policy on any interface showing model output.
  • Parameterized queriesModel text can never be concatenated directly into SQL.
  • Sandboxed executionPermission-scoped execution for any pipeline that runs model-suggested code.
  • Classifiers are not enoughA safety classifier reduces what the model produces, not whether the app handles it safely.
  • CorrelateMatch WAF and database-audit findings to LLM gateway logs to prove the payload came from a model response.
That correlation turns 'we got an XSS alert' into 'our AI wrapper trusts its own output', which gets the right team assigned.

Section 3 of 5

Unbounded Consumption (OWASP LLM10)

No meaningful limit on one identity's query volume, input size or cost.

HACKTHESOCLesson 92AI attacks, part 218 / 36

OWASP's seven scenarios group into four shapes

ShapeMechanism
Denial of ServiceVariable-length input flood, context-window overflow, resource-intensive queries
Denial of WalletDriving pay-per-token billing into a real, unsustainable bill
Extraction & functional replicationSynthetic Q&A from outputs to fine-tune a cheaper substitute offline
Side-channel attacksTiming or filtering behaviour used to infer weights or architecture
Functional replication evades defenses built for direct query-sweep extraction (AML.T0024.002, covered in Part 1).
HACKTHESOCLesson 92AI attacks, part 219 / 36

A Denial-of-Wallet weekend

  1. 1Exposed endpointPublic support chatbot, no authentication, no per-user rate limits, billed per token.
  2. 2Scripted floodThousands of maximum-length requests padded with filler to maximize tokens per call.
  3. 3Nothing looks like an attackNo injection, nothing sensitive asked, no single request suspicious.
  4. 4Real impactAn unbudgeted invoice, and slower responses for every legitimate customer.
The source could even be a buggy, abused legitimate integration with no malicious intent at all.
HACKTHESOCLesson 92AI attacks, part 220 / 36

Count tokens and cost, not requests

Request-count limits

A few maximally padded requests can cost as much as thousands of small ones. Count alone misses it.

What works

Per-identity token and cost quotas, input-length caps at the gateway, real-time cost anomaly monitoring against billing, WAF or bot mitigation.

An unauthenticated, unlimited chat endpoint is as exposed as an unauthenticated, unlimited login form.

Treat a cost anomaly with the urgency of a security alert, not as something found when the invoice arrives.
HACKTHESOCLesson 92AI attacks, part 221 / 36

Token-cost anomaly per API key against its own baseline

  • 14-day hourly baseline per key; replace 5.0 with your per-million-token price
  • High AvgPrompt with modest Requests: the padded Denial-of-Wallet shape
  • Huge Requests with varied, short prompts points to extraction instead
LLMGateway_CL is the gateway's own log table and its column names are that gateway's. Adapt them, but keep the logic: tokens and cost, per identity, against its own history.

Section 4 of 5

Adversarial ML evasion (ATLAS AML.T0015)

Fooling the SOC's own detection models: next-gen AV, EDR, spam filters, NIDS.

HACKTHESOCLesson 92AI attacks, part 223 / 36

Evade AI Model maps to three tactics at once

AML.TA0004

Initial Access

Evading the detector meant to keep the attacker out is how they get in.

AML.TA0007

Defense Evasion

Hides the attacker's activity from the AI-enabled defense.

AML.TA0011

Impact

A security product silently failing disrupts the defense you believed you had.

NIST AI 100-2 calls it an evasion attack: weights untouched, input crafted to land on the wrong side of the decision boundary.

Contrast with poisoning from Part 1, which does change the weights during training.
HACKTHESOCLesson 92AI attacks, part 224 / 36

The 2019 Cylance bypass in three lines

  • A secondary 'override' model could outvote the core classifier
  • Worked on WannaCry, SamSam, Mimikatz and hundreds of others
Adi Ashkenazy and Shahar Zini of Skylight Cyber found the override model from Cylance's talks, patents and verbose product logging.
HACKTHESOCLesson 92AI attacks, part 225 / 36

How well it worked, and where it is documented

ItemDetail

Not one byte of the malware's functional code changed. Only the classifier's view of the file did.
HACKTHESOCLesson 92AI attacks, part 226 / 36
No single ML or AI-based engine should ever be the sole gate.

Combine ML with signature and heuristic engines, sandboxing and EDR behaviour: process ancestry, LSASS access, C2 beaconing.

Evading detection does not stop malicious code behaving maliciously once it runs. Also red-team your own ML products and correlate verdicts across vendors.
HACKTHESOCLesson 92AI attacks, part 227 / 36

Files the static engine passed but behaviour caught

  • Each row: the prevention layer let it through, only behaviour caught it
  • Next, look the hash up in a multi-engine service
  • A few malicious verdicts, most clean, on a misbehaving file: the Cylance pattern
Wide disagreement between engines on a file that is behaving badly on your hosts is exactly the evasion signature to escalate.

Section 5 of 5

Jailbreak vs prompt injection (ATLAS AML.T0054)

Two different rules defeated, two different ATLAS tactic mappings.

HACKTHESOCLesson 92AI attacks, part 229 / 36

The question is whose rule is defeated

Prompt injection (AML.T0051)Jailbreak (AML.T0054)
What it overridesThe application's system prompt, written by a developerThe model provider's built-in safety and alignment training
ATLAS tacticsExecution (AML.TA0005), Privilege Escalation (AML.TA0012)Defense Evasion (AML.TA0007), Privilege Escalation (AML.TA0012)
AnalogyToday's supervisor instruction doesn't apply right nowSet aside your own ethics training, whatever store you work in
Both carry Privilege Escalation: either is often the step that turns a permission an agent holds into an action it is willing to take. That links back to Excessive Agency.
HACKTHESOCLesson 92AI attacks, part 230 / 36

Recurring jailbreak strategies MITRE ATLAS documents

  • Instruction override'Ignore your prior training'.
  • Roleplay or persona'Respond as an unfiltered security researcher'; DAN is the canonical example.
  • FictionalizationDisallowed content requested as a story or 'purely educational' scenario.
  • Separating intentAsking for an 'example' or 'template' that implicitly contains it.
  • Multi-turn escalationCrescendo-style: starts benign and escalates gradually across many turns.
A single real attempt often combines more than one strategy.
HACKTHESOCLesson 92AI attacks, part 231 / 36

Per-turn scores stay low while the session score climbs

  • No turn crosses the 0.5 per-message threshold; session_risk does by turn 4
  • Alert on session_risk, then review the turn 4 'partial' response
  • The incident is disallowed content actually produced, not the attempt
A Crescendo-style escalation starts benign and drifts across turns, so a per-message classifier is blind to it. Also re-test known jailbreaks after every major model update, as providers patch them continuously.
HACKTHESOCLesson 92AI attacks, part 232 / 36

Key takeaways

  1. 01Excessive Agency: Functionality, Permissions, Autonomy. Check tool-call audit logs against each agent's profile.
  2. 02Improper Output Handling: a WAF or DB alert traced to a stored model response routes the fix to the right team.
  3. 03Unbounded Consumption covers DoS, Denial of Wallet, extraction and side channels; baseline tokens and cost per key.
  4. 04AML.T0015 beat Cylance in 2019: hunt files the static engine passed that later raise behavioural EDR alerts.
  5. 05Injection defeats the app's system prompt; jailbreak (AML.T0054) defeats the provider's safety training.
  6. 06Catch multi-turn jailbreaks with session-level risk; the incident is disallowed content produced, not the attempt.
