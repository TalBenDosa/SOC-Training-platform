Section 1 of 9

What a script is and how it runs

A plain text file of commands, read from top to bottom by the interpreter.

HACKTHESOCLesson 100Bash scripting basics6 / 59

The shebang tells the kernel which interpreter to use

The first line is the two characters #! followed by the interpreter path.

  • The kernel reads line 1, starts that program and hands it the script path
  • /usr/bin/env bash finds Bash on PATH wherever it lives
  • A hard-coded #!/bin/bash is also fine when you control every target host
Using env works whether Bash lives in /bin, /usr/bin or /usr/local/bin. Ask students why a script is more reviewable than a typed procedure.
HACKTHESOCLesson 100Bash scripting basics7 / 59

Three shebang pitfalls that break scripts

  • Not on line 1, byte 1A blank line or a leading space before it makes it just a comment.
  • Windows CRLF line endingsThe kernel looks for an interpreter named 'bash' plus a carriage return and fails with 'bad interpreter'. Fix with dos2unix.
  • No shebang at allThe launching shell guesses. On Debian and Ubuntu that is often dash: no [[, no arrays, no (( )).

A script that 'worked on my machine' then breaks in cron.

The missing-shebang case is the classic cron surprise: the interactive shell was Bash, the scheduled one was dash.
HACKTHESOCLesson 100Bash scripting basics8 / 59

Three ways to run a script

Set the execute bit first with chmod +x hello.sh.

MethodNeeds +xUses shebangRuns in
./hello.shYesYesA child process
bash hello.shNoNo, you named BashA child process
source hello.shNoNoYour current shell

A cd or variable assignment in a child process disappears when it ends. Sourcing loads helpers into your own session.

source hello.sh is the same as . hello.sh. Use it to load helper functions or environment settings, not to run a normal script.
HACKTHESOCLesson 100Bash scripting basics9 / 59

PATH decides which command runs

A name containing a slash means use exactly this path. A bare name is searched.

  • Bare names are searched left to right in PATH; the first match wins
  • Never add . or an empty element to PATH; a writable early directory can hijack ls
  • Cron and sudo use a minimal PATH: call tools by full path or set PATH at the top
The current directory is deliberately not on PATH, which is why typing hello.sh alone gives 'command not found'. A file named ls dropped early in PATH runs instead of the real one.

Variables and quoting

Quoting is the source of most script bugs and many injection flaws.

HACKTHESOCLesson 100Bash scripting basics11 / 59

Assign without spaces, expand with braces

  • No spaces around the equals sign: host = web01 runs a command named host
  • Use $(...) rather than old backticks: it nests cleanly and reads well
  • Without braces, $host_$today would look for variables named host_ and today
Walk the parameter expansions one at a time; students rarely know :? exists, and it is the guard used later against rm -rf.
HACKTHESOCLesson 100Bash scripting basics12 / 59

Three quoting forms, and only one is the default

After an unquoted expansion, the shell splits the result on whitespace and then expands wildcards.

FormVariables and $( )Splits and globsTypical use
"double quotes"YesNo, stays one wordAlmost everything
'single quotes'NoNoLiteral text, regexes, awk programs
UnquotedYesYesAlmost never

Rule: quote every expansion unless you can name the reason you need splitting.

Single quotes are what you want around a regex or an awk program so the shell leaves it alone.
HACKTHESOCLesson 100Bash scripting basics13 / 59

Unquoted expansion splits one filename into two

  • rm -rf $dir/ with an empty $dir becomes rm -rf /
  • ShellCheck reports the omission as SC2086
This is the classic disaster. The guard ${dir:?} aborts instead of expanding to nothing; this is also quiz question one.
HACKTHESOCLesson 100Bash scripting basics14 / 59

Shell variables stay home; exported ones are inherited

A plain assignment is visible only to the current shell.

level=high

Shell variable

Visible only to the current shell. A child process does not see it.

  • A child shell prints: child sees: []

export level

Environment variable

export marks the variable for inheritance by child processes.

  • A child shell prints: child sees: [high]
  • API_TIMEOUT=5 ./enrich.sh sets it for one command
  • printenv | sort lists the environment

The risk

Exported variables are visible to every child process and to /proc/PID/environ. Never export secrets you do not need to share.

    Single quotes around the bash -c program stop the parent shell from expanding $level.

    Demonstrate with bash -c 'echo "child sees: [$level]"' before and after export.

    Three ways to loop over arguments, one is correct

    Run as ./args.sh "alpha beta" gamma. Which loop sees two arguments?

    Use this

    "$@" quoted

    Each argument stays its own word. The loop prints [alpha beta] and [gamma].

      One string

      "$*" quoted

      Joins everything into a single string, so the loop prints one line: [alpha beta gamma].

        Splits again

        $@ or $* unquoted

        Splits 'alpha beta' into two words, so the loop prints three lines: [alpha], [beta], [gamma].

          Rule: use "$@" to pass arguments along intact.

          HACKTHESOCLesson 100Bash scripting basics18 / 59

          Validate the count, default the optional, shift the rest

          • >&2 sends the usage message to stderr; exit 2 is the convention for usage errors
          • shift drops $1, moves the rest down by one and decrements $#
          • shift 2 removes -f file pairs; the getopts builtin parses real flags
          Ask: what happens if the argument is missing, empty, or contains a space? A script with an answer to all three is one you can trust.
          HACKTHESOCLesson 100Bash scripting basics19 / 59

          read: the flags that matter

          read takes a line from standard input and stores it in variables.

          • read -rAlways use it. Without it, backslashes are eaten, which corrupts Windows paths and regexes.
          • -p "prompt"Prints a prompt, then waits for input.
          • -sHides typing, for input such as an API key.
          • -t 10Gives up after 10 seconds, so ans=${ans:-N} can supply a default.
          • Prefer arguments in cronA prompt in an automated script waits forever. read also works on piped data.

          Piped input works too: echo 198.51.100.7 | ./lookup.sh.

          Always -r, no exceptions. In automated scripts prefer arguments over prompts.

          Section 4 of 9

          Exit codes and testing conditions

          Status 0 means success; every test and control operator builds on it.

          HACKTHESOCLesson 100Bash scripting basics21 / 59

          Exit codes: 0 is success, everything else is failure

          Every command ends with a number from 0 to 255, stored in $?. Copy it at once: the next command overwrites it.

          CodeMeaning
          0Success (grep: found a match)
          1General failure (grep: not found)
          2Misuse of a command or builtin (grep: error such as a missing file)
          126Found but not executable
          127Command not found
          130Stopped by Ctrl-C
          128+NKilled by signal N (137 is SIGKILL)

          cmd1 && cmd2 runs the second only on success; cmd1 || cmd2 runs it only on failure.

          Your script ends with the status of its last command unless you call exit N. Cron, CI pipelines and SOAR playbooks decide whether it worked from that number, so choose codes deliberately.
          HACKTHESOCLesson 100Bash scripting basics22 / 59

          [ ] is a command; [[ ]] is Bash syntax

          A command, POSIX

          [ ] and test

          test EXPR and [ EXPR ] are the same thing. The spaces inside are mandatory, and unquoted variables break it.

          • [ $name = "admin" ] with an empty name: unary operator expected
          • [ "$name" = "admin" ] is the correct form
          • Use a single = in [ ], not ==

          A Bash keyword

          [[ ]]

          Does not word-split variables, allows && and || inside, and adds glob and regex matching. Not in POSIX sh.

          • [[ $name == "admin" ]] works; quotes optional on the left
          • Unquoted right side of == is a glob, quoted is literal
          • For a regex, store it in a variable: [[ $line =~ $re ]]
          Because [ is a command, an empty unquoted variable simply disappears and the expression becomes malformed.
          HACKTHESOCLesson 100Bash scripting basics23 / 59

          The test operators worth memorising

          CategoryOperatorTrue when
          String= or ==Strings are equal; != when they differ
          String-z STR and -n STRString is empty / string is not empty
          String, [[ ]] only== patternMatches a glob, e.g. [[ $f == *.log ]]
          String, [[ ]] only=~ regexMatches an extended regex
          Numeric-eq -ne -lt -le -gt -geInteger comparison
          File-e -f -dPath exists / is a regular file / is a directory
          File-r -w -x -sReadable, writable, executable by you / exists and is not empty

          -f is false for directories: pick the file test that matches what you mean.

          Use -z and -n with a quoted variable to test emptiness safely.
          HACKTHESOCLesson 100Bash scripting basics24 / 59

          String and numeric operators are not interchangeable

          • < inside [[ ]] compares text, and "1" sorts before "9"; use -lt or (( a < b ))
          • The wrong operator family gives wrong answers, often with no error at all
          • -z "$var" and -n "$var" are the safe emptiness tests
          This is quiz question three. The scary part is that nothing complains: the test is simply true.

          Section 5 of 9

          Conditionals: if/elif/else and case

          Branch on a command's exit status, or match one value against many patterns.

          HACKTHESOCLesson 100Bash scripting basics26 / 59

          if, elif, else: the first success wins

          • The first branch whose condition succeeds runs; the rest are skipped
          • Validate digits first: it prevents 'integer expression expected'
          • Every if ends with fi; then sits on its own line or follows a semicolon
          The validation line is the habit to teach: odd input should never reach the later commands.
          HACKTHESOCLesson 100Bash scripting basics27 / 59

          Branch directly on a program's result

          The test brackets are just one possible command: any program can follow if.

          • if grep -q ...Runs grep -q "Failed password" "$logfile" and branches on its exit status.
          • if ! command -v jqNegates with ! to check a tool exists, then prints an error to stderr and exits 1.
          • > /dev/null 2>&1Discards normal output and errors, because only the exit status matters.
          • [[ -f && -r && -s ]]Combine tests with && and || inside [[ ]]: exists, readable and not empty.
          Show the tool-check pattern; it belongs at the top of any script that depends on jq or similar.
          HACKTHESOCLesson 100Bash scripting basics28 / 59

          case: one value, many patterns

          • Each branch: a glob pattern, ), the commands, then ;;
          • A bar separates alternatives; *) is the catch-all default
          • case uses globs, not regexes
          A second realistic use is dispatching on file type: .gz to zcat, .bz2 to bzcat, *.log to cat, anything else an error.
          HACKTHESOCLesson 100Bash scripting basics29 / 59

          if for different conditions, case for one value

          Use if

          Different kinds of conditions: tests, file checks, a program's result, combined with && and ||.

            Use case

            One value with many possibilities: a port number, or a file extension such as .gz, .bz2 or *.log.

              Common case mistakes

              Three slips break a case block.

              • Forgetting a ;;
              • Forgetting the closing esac
              • Putting the catch-all *) first

              A catch-all placed first swallows every value, so the later branches never run.

              Remember that the pattern .*\.gz$ does not work in case: it is a glob, not a regex.

              Section 6 of 9

              Loops: for, while, until and reading files

              Iterate safely over files and lines, and avoid the pipe subshell trap.

              HACKTHESOCLesson 100Bash scripting basics31 / 59

              for: loop over a glob, never over ls output

              • Loop over a glob, never over ls output: it keeps names with spaces intact
              • If nothing matched, f is the literal pattern, so test -e and continue
              • Counted loops: for (( i=1; i<=3; i++ ))
              for f in $(ls) splits on whitespace; the glob does not. Brace expansion {01..07} gives zero-padded values.
              HACKTHESOCLesson 100Bash scripting basics32 / 59

              while repeats on success, until repeats on failure

              Repeats while it succeeds

              while

              Runs the body for as long as the command succeeds. A natural fit for counters.

              • while [[ $attempts -lt 3 ]]; do ... done
              • attempts=$((attempts + 1)) advances the counter

              Repeats until it succeeds

              until

              Runs the body until the command succeeds. A natural fit for waiting on something.

              • until ping -c1 -W1 "$host" > /dev/null 2>&1; do
              • sleep 5 between attempts
              Both forms test the exit status of a command, exactly like if.
              HACKTHESOCLesson 100Bash scripting basics33 / 59

              Read a file line by line: the backbone of log processing

              • IFS= keeps leading and trailing whitespace; -r stops backslash handling
              • < "$file" after done feeds the loop; read fails at end of input, ending it
              • IFS=, for one read splits each line into fields; continue skips, break leaves
              A file whose final line lacks a newline loses that line; add || [[ -n $line ]] to the while condition if that matters.
              HACKTHESOCLesson 100Bash scripting basics34 / 59

              The pipe subshell trap: why the count stays 0

              ips.txt has 40 lines. Only a loop that runs in the current shell keeps its changes.

              Prints 0

              cat file | while read

              The pipe runs the loop in a subshell, so the increment changes a copy that vanishes when the loop ends.

                Correct count

                done < ips.txt

                Redirection feeds the loop from the file, so it runs in the current shell and its changes stay.

                  Filter first

                  done < <(grep ...)

                  Process substitution lets you filter, such as grep -v '^#' ips.txt, and still keep the loop in the main shell.

                    Ask of every loop: what am I iterating over, and could an item contain a space or start with a dash?

                    This is quiz question four. Each side of a pipe is its own subshell, so the parent never sees the increment.

                    Section 7 of 9

                    Functions

                    Name a block of commands once and call it many times.

                    HACKTHESOCLesson 100Bash scripting basics36 / 59

                    A function names a block you write once

                    • Define a function before the line that calls it
                    • Inside it, $1, $@ and $# are its own arguments; $0 is still the script name
                    • Arguments are passed by position, with no parentheses at the call site
                    The logger writes to stderr so it never pollutes output that another command may be capturing.
                    HACKTHESOCLesson 100Bash scripting basics37 / 59

                    Variables are global unless you declare them local

                    Without local

                    A function that assigns to a name used elsewhere silently overwrites it.

                    • bad() { total=0; } clobbers the caller's variable
                    • After bad, echo "$total" prints 0

                    With local

                    local keeps a function-internal variable private to the function.

                    • good() { local total=0; } is private
                    • After good, echo "$total" still prints 100
                    Declare function-internal variables with local, every time.
                    HACKTHESOCLesson 100Bash scripting basics38 / 59

                    return carries a status; echo carries data

                    • No explicit return: a function returns the status of its last command
                    • return N is for yes/no answers if can test; return "yes" is an error
                    • Print data with echo and capture it with $(...)
                    Only integers 0 to 255 are allowed after return. A string result has to be printed and captured.
                    HACKTHESOCLesson 100Bash scripting basics39 / 59

                    Four function pitfalls

                    • Logging inside captured functionsAnything printed to stdout becomes part of $(...). Send diagnostics to stderr with >&2.
                    • local hides failuresIn local out=$(cmd) the status is that of local, always 0. Split it in two lines (ShellCheck SC2155).
                    • exit versus returnreturn leaves the function; exit ends the whole script. Inside $(...) it ends only the capturing subshell.
                    • Trailing newlines$(...) strips trailing newlines from captured text, which is normally helpful.

                    One job per function, validate arguments at the top, report errors to stderr, return a meaningful status.

                    A small library of functions such as is_private_ip, log and require_tool can be sourced from many scripts.

                    Arithmetic, arrays and here-documents

                    Integer math, lists without splitting bugs, and multi-line input.

                    HACKTHESOCLesson 100Bash scripting basics41 / 59

                    Integer math with $(( )) and (( ))

                    • $(( )) yields a value; (( )) sets an exit status; no $ needed inside
                    • Division truncates and there are no floats: use bc or awk
                    • ((count++)) returns 1 at 0 and aborts under set -e: use count=$((count + 1))
                    The ((count++)) trap is subtle: the expression evaluates to 0, so the exit status is 1, and set -e kills the script.
                    HACKTHESOCLesson 100Bash scripting basics42 / 59

                    Two kinds of array: indexed and associative

                    Indexes start at 0

                    Indexed

                    A list without the splitting problems of a space-separated string.

                    • hosts=(web01 web02 "db 01") keeps db 01 whole
                    • Quote "${hosts[@]}", as you quote "$@"
                    • mapfile -t lines < file reads one line per element

                    Bash 4 and newer

                    Associative

                    Maps string keys to values, which is ideal for counting. The Bash 3.2 that macOS ships does not have them.

                    • declare -A seen creates it
                    • seen[$ip] reads or sets one key
                    • ${!seen[@]} lists the keys
                    • Check bash --version first
                    The associative array is exactly the structure the SSH script uses to count failures per IP.
                    HACKTHESOCLesson 100Bash scripting basics43 / 59

                    Arrays in practice: a list and a counter

                    • Quote "${hosts[@]}" so db 01 stays a single element
                    • ${!seen[@]} lists the keys; read each value with ${seen[$k]}
                    Slices work too: ${hosts[@]:1:2} gives two elements starting at index 1.
                    HACKTHESOCLesson 100Bash scripting basics44 / 59

                    Here-documents and here-strings feed input without a pipe

                    A here-document ends at the closing delimiter alone on a line.

                    FormWhat it doesUse it for
                    <<EOFUnquoted delimiter: variables and substitutions are expandedReports with $(hostname) or $(date -u +%FT%TZ)
                    <<'EOF'Quoted delimiter: the text is taken literallyRegexes, and generating other scripts
                    <<-EOFStrips leading tab charactersIndenting the block inside a script
                    <<<Here-string: supplies a single string as inputread -r user ip <<< "alice 203.0.113.9"

                    A here-string splits a value into variables without a pipe, so it avoids the subshell trap.

                    Example of a literal here-doc: write Failed password and Invalid user to a patterns file, then run grep -F -f on the auth log.

                            A cleanup script sets file="Incident Report.txt" and then runs: rm $file. The directory also holds an unrelated file named "Report.txt". What happens?
