Section 1 of 8

What Defender for Office 365 protects against

Exchange Online email plus SharePoint, OneDrive and Teams, against what basic anti-spam misses.

HACKTHESOCLesson 64Defender for Office 3656 / 58

Four threats, mapped to how attacks arrive

Malicious attachments

Malware or a downloading macro. Zero-day files have no signature, so MDO detonates them.

Malicious URLs

Benign at send time, weaponised later, so MDO checks links at click time.

Phishing and impersonation

Pretending to be a brand, your domain, or an executive: the lead-in to business email compromise (BEC).

Post-delivery threats

Clean on arrival, later found malicious. MDO can retroactively remove it.

Safe Attachments and Safe Links close exactly the gap signature filtering leaves: the unknown attachment and the time-delayed link.
HACKTHESOCLesson 64Defender for Office 3657 / 58

The path of one inbound message through EOP and MDO

  1. 1Sender reputation (EOP)Known-bad sending IPs and domains are refused early.
  2. 2Signature checks (EOP)Known spam and known malware are caught by signature.
  3. 3Anti-phishing (MDO)Impersonation and spoofing checks on sender name and domain.
  4. 4Safe Attachments (MDO)Unknown files are detonated in a sandbox.
  5. 5Safe Links (MDO)URLs are rewritten so every later click is re-checked.
  6. 6VerdictInbox, Junk or quarantine; ZAP can still act after delivery.
EOP does the cheap, known-bad work first; MDO spends effort only on what remains. Every stage leaves a verdict you can later see in EmailEvents.

Section 2 of 8

Safe Attachments: detonating the unknown

Open the file in an isolated sandbox and judge it by what it does, not by its signature.

HACKTHESOCLesson 64Defender for Office 36512 / 58

How a file gets detonated

  1. 1EOP scans firstOrdinary anti-malware scanning catches known threats.
  2. 2Unknown file is detonatedOpened in a disposable, isolated VM. Does it download code, modify the system, reach a suspicious server?
  3. 3Verdict decides deliveryDelivered, blocked, or the attachment stripped.

Same protection covers files in SharePoint, OneDrive and Teams, not just email.

The administrator configures policies once; MDO detonates every unknown attachment before, or with Dynamic Delivery in parallel with, delivery.
HACKTHESOCLesson 64Defender for Office 36513 / 58

Signature scanning vs detonation

EOP anti-malware

Signature scan

Answers: have we seen this file before?

  • Compares the file to known-bad patterns
  • Instant and cheap
  • Misses a file nobody has seen before

Safe Attachments

Detonation

Answers: what does this file do when opened?

  • Opens the file in a disposable VM
  • Watches downloads, system changes, connections
  • Takes time; judges new files
A brand-new malicious document has no signature yet, so only behaviour can condemn it. That is the zero-day gap Safe Attachments exists to close.
HACKTHESOCLesson 64Defender for Office 36514 / 58

Safe Attachments policy actions

ActionWhat happens to the messageUser experienceStatus
BlockMalicious attachment's message quarantinedNo mail until verdictCurrent default / recommended
Dynamic DeliveryBody now with a placeholder; file released once safeNo inbox delayCurrent, best user experience
MonitorDelivers even if malicious, only records behaviourMail arrives regardlessRetired: auto-converted to Block
ReplaceDelivers but swaps the attachment for a .txt noticeAttachment removedRetired
OffNo scan (EOP anti-malware still runs)Zero-day files can slip throughNot recommended

Only Off, Block and Dynamic Delivery still exist. For audit-only testing, use Evaluation mode, not the retired Monitor.

The live protective choices are Block and Dynamic Delivery. Both withhold a malicious file; they differ only on whether the harmless body waits. Monitor and Replace were auto-converted to Block.
HACKTHESOCLesson 64Defender for Office 36515 / 58

Dynamic Delivery, as the recipient experiences it

  1. 1Body arrives at onceThe user can read the message; the attachment shows a placeholder.
  2. 2File detonatesSafe Attachments opens it in the sandbox in the background.
  3. 3Safe verdictThe real attachment is reattached to the message.
  4. 4Malicious verdictThe file is withheld, so the user never gets it.
Block gives the same protection but holds the whole message. Dynamic Delivery trades nothing in safety for a better user experience, which is why it is so common.

A detonation verdict also tells you what the file tried to do, which helps gauge intent and scope.

Hunt for the hash, and purge everywhere it landed if needed.

Section 3 of 8

Safe Links: checking the link at click time

Attackers swap a harmless page for a malicious one after delivery. Safe Links checks again on every click.

HACKTHESOCLesson 64Defender for Office 36519 / 58

Rewrite, re-check, then allow or block

  1. 1Rewrite on deliveryURLs are routed via safelinks.protection.outlook.com, with the original destination preserved inside.
  2. 2Check at the clickMicrosoft evaluates the current reputation of the real destination, not its reputation at arrival.
  3. 3Warn, block or forwardKnown-malicious now: a warning or block page. Safe: forwarded transparently.

Also covers Teams messages and Office apps; a link to a file can trigger Safe Attachments detonation.

Administrators decide whether users may click through a warning page or are blocked outright.
HACKTHESOCLesson 64Defender for Office 36520 / 58

Why a delivery-time check is not enough for links

At delivery

The link points to a harmless page. Every scanner agrees it is clean, so the mail is delivered.

Hours later

The attacker swaps the page for a credential-harvesting site. The email in the inbox has not changed at all.

At the click

Safe Links checks the destination as it is now, so the swap is caught.

This is the time-of-click trick in three frames. A one-time scan only ever sees the first frame.
HACKTHESOCLesson 64Defender for Office 36521 / 58

What a rewritten link looks like

  • Originalhttps://contoso-invoices.example/pay
  • Rewrittenhttps://nam01.safelinks.protection.outlook.com/?url=https%3A%2F%2Fcontoso-invoices.example%2Fpay&data=...&sdata=...
  • Inside url=The real destination, URL-encoded.
  • The hostMicrosoft's checking service, reached before the real site, so it can re-check live reputation.
Students will see these wrapped URLs in reported phishing. Decode the url= parameter to find the real destination.
HACKTHESOCLesson 64Defender for Office 36522 / 58

Decoding the url= parameter by hand

  • Percent-encoding replaces reserved characters with %XX codes
  • The decoded value is the real destination to investigate
  • Use it as the indicator in UrlClickEvents and proxy searches
Never click the wrapped link during an investigation; decode it and look the destination up in your tools.

Anti-phishing and impersonation protection

For phishing with no malware and no bad link: pure social engineering.

HACKTHESOCLesson 64Defender for Office 36526 / 58

Three impersonation tricks, three checks

TypeThe trickExampleWhat MDO checks
User impersonationFakes a named high-value person'Jane Smith, CFO' from a non-Jane mailboxProtected-user list vs actual sender
Domain impersonationRegisters a look-alike domainc0ntoso.com, contoso-invoices.comProtected-domain list vs lookalike
SpoofingForges your real domain in FromFrom you@contoso.com, unauthorisedSPF/DKIM/DMARC + spoof intelligence
The first two rely on lists you configure. A CEO-fraud email that slipped through may simply mean the CEO was never on the protected list.
HACKTHESOCLesson 64Defender for Office 36527 / 58

How a receiver checks that mail really came from a domain

  1. 1SPFLook up the sending domain's SPF record; is the sending IP listed?
  2. 2DKIMVerify the signature with the public key published in DNS.
  3. 3Alignment (DMARC)Does a passing SPF or DKIM domain match the visible From domain?
  4. 4Policy (DMARC)On failure, apply the owner's policy: none, quarantine or reject.
  5. 5Composite verdictSpoof intelligence combines these into the final spoof decision.
Alignment is the step students miss: SPF can pass for the attacker's own domain while the From line shows yours. DMARC is what ties the check to what the user sees.
HACKTHESOCLesson 64Defender for Office 36528 / 58

The email-authentication standards behind spoof intelligence

StandardWhat it checksPublished as
SPF (Sender Policy Framework)Is the sending server's IP on the domain's authorised list?DNS TXT record listing allowed IPs
DKIM (DomainKeys Identified Mail)Was the message signed by the domain and unaltered in transit?DNS record with the public key
DMARCDo SPF/DKIM align with the visible From, and what to do on failure?DNS TXT policy: none, quarantine, reject
A message failing DMARC while claiming your own domain is a strong forgery signal. Spoof intelligence separates it from an authorised newsletter service sending on your behalf.
HACKTHESOCLesson 64Defender for Office 36529 / 58

Reading the authentication verdict in a message header

  • spf=fail: the sending IP is not authorised for the envelope domain
  • dkim=none: no signature, so nothing proves the content is untampered
  • dmarc=fail with header.from=contoso.com: someone forged your own domain
Fictional header in the format Exchange Online writes. compauth is Microsoft's composite verdict; fail here is the spoof finding in one word.
HACKTHESOCLesson 64Defender for Office 36530 / 58

Intelligence and presets

  • Spoof intelligenceDistinguishes legitimate spoofing (an authorised service) from malicious forgery of your domain.
  • Mailbox intelligenceLearns each user's normal contacts and flags a familiar sender breaking pattern, e.g. a sudden bank-account change.
  • Preset policiesStandard and Strict bundle recommended defaults for Safe Attachments, Safe Links and anti-phishing.

Impersonation detections are often the first sign of BEC, before any malware or link is in play.

Most organisations start from a preset and customise only for specific needs, which reduces the chance of a misconfigured gap.
HACKTHESOCLesson 64Defender for Office 36531 / 58

A business email compromise message carries no payload

What the email contains

Nothing for Safe Attachments or Safe Links to inspect.

  • Display name of the real CFO
  • An urgent request to change a supplier's bank account
  • No attachment, no link

What can still catch it

Identity-based checks, not payload checks.

  • User impersonation: CFO on the protected list
  • Mailbox intelligence: unusual sender for this user
  • Spoof checks if your own domain is forged
If such a message got through, first check whether the CFO was on the protected-user list. Often the answer explains the miss.

Reading MDO alerts and logs

Alerts and incidents in the Defender portal, queryable events in Advanced Hunting.

HACKTHESOCLesson 64Defender for Office 36533 / 58

A simplified MDO alert

  • Read first: severity, entities (who and what), status
  • You set the classification: true positive, false positive, benign
Alerts flow into the unified Defender portal (security.microsoft.com) and correlate into incidents with endpoint and identity signals. With Plan 2, Threat Explorer scopes a campaign without a query.
HACKTHESOCLesson 64Defender for Office 36534 / 58

Reading the alert in a fixed order

  • 1. severity and titleHigh, "Malicious URL clicked": a user may already be exposed.
  • 2. categoryInitialAccess: the attacker is trying to get in, not yet established.
  • 3. entitiesThe user, the URL (defanged as hxxps) and the mailbox: your pivots.
  • 4. first and last activityThe time window to search around in the hunting tables.
  • 5. statusNew: nobody owns it yet. Assign, investigate, then classify.
The defanged hxxps form stops the URL being clickable in tickets and chats. Keep it that way when you copy it.
HACKTHESOCLesson 64Defender for Office 36535 / 58

Received is not engaged: one campaign, three groups

Most recipients

Received, no click

Purge the copies. No credential action needed unless other evidence appears.

ClickBlocked, no click-through

Clicked, blocked

Protected by Safe Links. Note it, lower priority.

ClickAllowed or clicked past

Reached the page

Treat as exposed: password reset, revoke sessions, review sign-ins.

This split is the reason click tracking must stay on. Without it, every recipient has to be treated as the red column.

Section 7 of 8

ZAP, quarantine and Submissions

Verdicts change after delivery, so detection does not stop at the inbox door.

HACKTHESOCLesson 64Defender for Office 36545 / 58

Acting on mail already delivered

Zero-hour Auto Purge

Re-evaluates delivered mail as new intelligence arrives and moves or deletes every copy later found malicious, with no manual hunt.

Quarantine

Where blocked mail lands for review, release or deletion. Too permissive: users release real phishing. Too strict: legitimate mail is stuck.

Submissions

User reports via Report Message appear here; analysts also submit files, URLs or email to Microsoft for reanalysis.

Many user reports for the same sender or subject usually mean the campaign is bigger than one report suggested. Correlate with Threat Explorer and EmailEvents.
HACKTHESOCLesson 64Defender for Office 36546 / 58

How ZAP acts on a message after delivery

  1. 1Delivered cleanAt arrival nothing was known against the message.
  2. 2Verdict changesNew intelligence marks its sender, URL or file as malicious.
  3. 3ZAP moves the copiesEvery copy is moved out of inboxes, per the policy action.
  4. 4The action is recordedEmailPostDeliveryEvents logs Phish ZAP or Malware ZAP.
ZAP is the message-level twin of the time-of-click check. Always confirm it ran: the table records where each copy was when it acted.
HACKTHESOCLesson 64Defender for Office 36547 / 58

Triage of a user-reported message

Verdict after reviewWhat you do
Phish confirmedScope the campaign, purge all copies, find who clicked
Malware confirmedPurge, then check endpoints of anyone who opened the file
Spam, not maliciousNo security action; tune filtering if it recurs
Legitimate mailRelease or reply to the reporter; submit as not junk

Thank the reporter in every case. Users who are told their reports matter keep reporting, and reports are an early sensor.

The full email-threat lifecycle

  1. 1PreventSafe Attachments, Safe Links and anti-phishing stop most of it before delivery.
  2. 2DetectAlerts, user reports, Threat Explorer and Advanced Hunting catch what got through.
  3. 3Retroactively correctZAP and manual purge remove what is now known bad.
  4. 4Feed backSubmissions improve future detection.
Every phishing incident ends at the same question: is this email still in anyone's inbox right now, and how do we get it out?

Threat Explorer, Campaign Views, post-delivery

Point-and-click scoping, automatic campaign clustering, and the record of what happened after delivery.

HACKTHESOCLesson 64Defender for Office 36550 / 58

Two Plan 2 views for scoping

Threat Explorer

Filter mail by sender, recipient, subject, URL, attachment or detection technology; see delivery location and verdict per message. No KQL needed. Plan 1 gets Real-time detections (malware and high-confidence phish only).

Campaign Views

Clusters near-identical variants across many recipients into one view: who was targeted, what was delivered vs blocked, which variants were used.

Attackers tweak sender addresses and subjects slightly to dodge simple filters. Campaign Views saves you grouping scattered alerts by hand.
HACKTHESOCLesson 64Defender for Office 36551 / 58

Which tool for which question

QuestionBest toolWhy
Where did this one message go, and why?Threat ExplorerPoint and click, per-message delivery location and verdict
How big is this whole campaign?Campaign ViewsClusters variants with tweaked senders and subjects
Who clicked, and what happened next?Advanced Hunting (KQL)Joins email, clicks and other Defender data
Was it purged from every mailbox?EmailPostDeliveryEventsRecords actions taken after delivery
Experienced analysts move between all four in one case. Start with the view that answers your current question fastest.
HACKTHESOCLesson 64Defender for Office 36552 / 58

Was it actually purged, and from where?

  • ActionType: Manual remediation, Phish ZAP, or Malware ZAP
  • DeliveryLocation: Inbox/Folder, Quarantine, Junk, Deleted Items
  • ActionTrigger: an admin or an automated mechanism like ZAP
EmailEvents only records the original delivery decision. This table, not EmailEvents, answers whether the phishing email was removed from every inbox.
HACKTHESOCLesson 64Defender for Office 36553 / 58
EmailEvents records the decision at delivery. EmailPostDeliveryEvents records what happened after.

A message delivered to the Inbox at 09:01 and removed by ZAP at 10:30 shows as Delivered in one table and Phish ZAP in the other. Read both before you close.

A common reporting mistake is to say a phish is still in inboxes because EmailEvents says Delivered. The post-delivery table settles it.

Key takeaways

  1. 01MDO sits above EOP and covers email, SharePoint, OneDrive and Teams; Plan 1 prevents, Plan 2 adds hunting and AIR.
  2. 02Safe Attachments detonates unknown files in a sandbox; Dynamic Delivery sends the body while the file is judged.
  3. 03Safe Links rewrites URLs and checks them at click time, producing the UrlClickEvents record of who clicked.
  4. 04Anti-phishing adds user and domain impersonation, spoof intelligence on SPF/DKIM/DMARC, and mailbox intelligence.
  5. 05Hunt by question: EmailEvents for scope, EmailUrlInfo/AttachmentInfo for payload, UrlClickEvents for engagement.
  6. 06Contain with purge, ZAP and quarantine review, confirm in EmailPostDeliveryEvents, and feed back via Submissions.
