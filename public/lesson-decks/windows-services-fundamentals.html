Much of what Windows does happens without any window on screen.

Updates, network listeners, antivirus, printing. These background workers start before anyone logs in, and their strengths are exactly what attackers want.

Services are a double-sided topic: essential machinery, and one of the most reliable ways to gain boot-surviving, privileged persistence.

Section 1 of 7

What a Windows service is

A background program with no UI, usually started at boot, run by a service account.

HACKTHESOCLesson 72Windows services6 / 46

An application versus a service

Application

You launch it, it shows a window, it runs as your account, and it closes when you log off.

Service

Starts on its own, often at boot. No window. Runs under a service account independent of any logged-in user.

A mail server or antivirus cannot depend on someone being logged in. That independence is the point.

Autostart, privilege, invisibility: an almost ideal vehicle for an attacker.

Install a malicious service and your code runs automatically, early, and powerfully, every time the machine starts.

Which account the service runs as is the security-critical detail: LocalSystem, LocalService, NetworkService, or a custom account.

Service accounts in depth

The account a service runs as is the biggest factor in its danger if compromised.

HACKTHESOCLesson 72Windows services10 / 46

Four accounts, four blast radii

AccountSIDOn the networkRisk if compromised
LocalSystemS-1-5-18As the computer accountTotal host compromise
LocalServiceS-1-5-19Anonymous credentialsLower local blast radius, still runs code
NetworkServiceS-1-5-20As the computer accountLimited locally; usable in network chains
gMSAUnique domain SIDAs a real AD identityHost-bound use; password cannot be cracked

SID = Security Identifier: the unique value Windows uses to name an account. Well-known SIDs like S-1-5-18 are identical on every Windows machine.

LocalSystem has near-total control, can even load kernel drivers. It is the account most persistence techniques try to reach.
HACKTHESOCLesson 72Windows services11 / 46
LocalSystem can even load kernel drivers.

It authenticates on the network as the computer account and has near-total control of the host, which is why most persistence techniques try to reach it.

Contrast with LocalService and NetworkService: minimal local privilege, so a lower local blast radius even though they still run code at boot.
HACKTHESOCLesson 72Windows services12 / 46

Why gMSAs exist

gMSA stands for Group Managed Service Account, Active Directory fix for the static service-account password problem.

Legacy custom account

An ordinary domain user with broad permissions and a password rarely rotated. The weakness behind Kerberoasting.

Windows Server 2012+

gMSA

A 240-byte random password generated by the Key Distribution Service (KDS) on the domain controllers, rotated every 30 days by default. No human ever handles it.

A new service under a legacy custom account, especially one newly added to a privileged group, is the pattern worth chasing.
HACKTHESOCLesson 72Windows services13 / 46

Spot a gMSA by its trailing $

  • The $ suffix is the same convention Windows uses for computer accounts
  • A service under a gMSA is a good sign: no crackable static password
CORP\svc-web$ is a gMSA, not a regular user account impersonating a service.
HACKTHESOCLesson 72Windows services14 / 46

What a gMSA changes for the attacker

Legacy custom account

A static password set once; an attacker can request its ticket and crack it offline (Kerberoasting).

gMSA

A 240-byte random password the KDS rotates roughly monthly. Nothing to crack; host-bound use only.

KDS = Key Distribution Service, running on the domain controllers.

So a service on a gMSA is reassuring; a new service on a legacy custom account, freshly added to a privileged group, is the pattern to chase.

Section 3 of 7

How Windows manages and runs services

The SCM, start types, svchost.exe, and the Registry behind them.

HACKTHESOCLesson 72Windows services16 / 46

The moving parts

  • Service Control ManagerStarts, stops and tracks services, and can restart failed ones. Config in HKLM\System\CurrentControlSet\Services.
  • Start typesAutomatic, Automatic (Delayed Start), Manual, Disabled. Attacker persistence wants Automatic.
  • svchost.exeGroups many services, each packaged as a DLL, into one process to save resources. Real copies live in System32, launched by services.exe.
  • Toolsservices.msc for a graphical list, sc.exe for sc query, sc create, sc config.
Many svchost.exe processes are normal, which is why malware imitates it. Wrong folder or wrong parent is the tell.
HACKTHESOCLesson 72Windows services17 / 46

From boot to a running service

  1. 1SCM reads the configAt boot the Service Control Manager reads each service's key under ...\Services.
  2. 2Automatic services startThe SCM launches everything set to start automatically.
  3. 3svchost groups the DLLsMany services are DLLs hosted together in svchost.exe to save resources.
  4. 4The SCM keeps watchIt tracks state and can restart a service that fails.
Because many svchost.exe processes are normal, malware imitates it. The tells are the wrong folder or a parent other than services.exe.
HACKTHESOCLesson 72Windows services18 / 46

The Start value as it appears in the Registry

A REG_DWORD named Start inside the service's key.

StartConstantWhen it runs
0SERVICE_BOOT_STARTLoaded by the boot loader. Kernel drivers only
1SERVICE_SYSTEM_STARTDuring kernel initialisation. Kernel drivers only
2SERVICE_AUTO_STARTAt startup by the SCM; attacker persistence's usual pick
3SERVICE_DEMAND_STARTOnly when requested; PsExec's PSEXESVC is created this way
4SERVICE_DISABLEDNever; attackers set security services to 4
Flipping WinDefend from 2 to 4 does not stop it now, but guarantees it never starts after reboot. That is why Event 7040 (start type changed) is a separate alert.
HACKTHESOCLesson 72Windows services19 / 46

Two Registry values decide how a service behaves

Start

When it runs: 2 Automatic is persistence's usual pick, 4 Disabled is how a defence is silenced for every future boot.

Type

What it is: 0x20 shared svchost service is ordinary, 0x1 kernel driver runs at the highest privilege and deserves 7045-level scrutiny.

Reading these two REG_DWORDs from a raw export or a Sysmon Event 13 tells you instantly what an attacker configured.
HACKTHESOCLesson 72Windows services20 / 46

The Type value: service or kernel driver?

TypeConstantMeaning
0x1SERVICE_KERNEL_DRIVERA kernel-mode device driver
0x2SERVICE_FILE_SYSTEM_DRIVERFile-system or top-level network driver
0x10SERVICE_WIN32_OWN_PROCESSWin32 service in its own process
0x20SERVICE_WIN32_SHARE_PROCESSShares a process: the svchost.exe model
0x100SERVICE_INTERACTIVE_PROCESSDesktop interaction flag; rare, restricted

A new Type 0x1 service runs a kernel driver at highest privilege, able to blind EDR (endpoint detection and response) from below: the BYOVD trick.

BYOVD = Bring Your Own Vulnerable Driver: load a legitimately signed but vulnerable driver, then exploit it to run kernel code and disable security tooling.

Section 4 of 7

How attackers abuse services

Automatic startup, high privilege, and legitimate-looking cover.

HACKTHESOCLesson 72Windows services22 / 46

Four abuse patterns

MITRE ATT&CK T1543.003, Create or Modify System Process: Windows Service.

Malicious service

Register a new auto-start service pointing at malware, typically as LocalSystem. Survives reboots and logoffs.

Hijack a service

Change an existing service's binary path, or replace its executable. Normal name, different code.

PsExec execution

Connect remotely, copy a program, create a service to run it: a hallmark of lateral movement.

Service accounts

Powerful accounts with rarely changed passwords are targets in their own right.

Hijacking is quieter than creating. 'A service' sounds inherently legitimate, which is exactly why it is easy to overlook.
HACKTHESOCLesson 72Windows services23 / 46

Create versus hijack: which is noisier?

Create a new serviceHijack an existing one
DurabilityAuto-start survives rebootsInherits the existing start type
Headline eventRaises a 7045: a new name appearsNo new service; only config changes
What to watchA new service where they are rareA changed binary path on a known name
"A service" sounds inherently legitimate, which is exactly why hijacking an existing one is easy to overlook.
HACKTHESOCLesson 72Windows services24 / 46
A service is a trusted, privileged, automatic execution slot.

An attacker who controls one has a foothold that is hard to dislodge and easy to overlook. That is why the SOC watches service activity closely.

All four abuse patterns map to MITRE T1543.003, Create or Modify System Process: Windows Service.

Section 5 of 7

Detecting malicious service activity

Installing or changing a service generates well-known events.

HACKTHESOCLesson 72Windows services26 / 46
Event ID 7045: a new service was installed.

It captures the service name and binary. A Temp or Downloads path, a random-looking name, or timing during suspected lateral movement is a strong indicator.

Many real intrusions are caught precisely at the 7045. Legitimate new services are rare and usually tied to software installs.
HACKTHESOCLesson 72Windows services27 / 46

Reading a 7045: benign install or intrusion?

Likely benign

Legitimate new services are rare and usually tied to installs.

  • Binary under Program Files
  • Signed by a known vendor
  • Alongside a software install

Worth chasing

The 7045 is where many real intrusions are first caught.

  • Binary in Temp, Downloads, Public
  • Random-looking name
  • No install context, lateral-movement timing
Judge the 7045 by the binary path, the name and the surrounding context, not by the word "service" in the event.
HACKTHESOCLesson 72Windows services28 / 46

The service event reference

Event IDSourceAnalyst relevance
7045System (SCM)Name, binary path, start type, account of a new service
4697Security (audit)Same install, auditable and user-attributed
7040System (SCM)Start type change: Automatic to Disabled silences a defense
7036 / 7034System (SCM)State change or crash of a security service
7009 / 7000System (SCM)Timeout or failed start: failed malware or sabotage
Sysmon 13Sysmon registryImagePath hijacking and Start/Type changes

704x events come from the SCM with no special audit policy; 46xx need audit policy but tie the action to a user. 7040 also catches Disabled to Automatic arming dormant persistence.
HACKTHESOCLesson 72Windows services29 / 46

How to hunt service abuse

  • New services (7045)Suspicious paths, odd names, or created around other signs of intrusion.
  • Binary path changesThe fingerprint of hijacking an existing service.
  • svchost.exe anomaliesWrong folder, or a parent other than services.exe.
  • Security services stoppingUnexpected stops or start-type changes on defensive services.

A 4624 type 3 then a 7045 on the same target is the remote-service-creation fingerprint. Neither alone is conclusive; the ordered pair is.

Combine the service event with the creating process, the file it points to, and whether the host already showed attacker activity.

HACKTHESOCLesson 72Windows services32 / 46

sc query inspects, sc create plants persistence

  • UpdSvc: a generic, unremarkable chosen name
  • binPath in world-writable C:\Users\Public
  • start= auto survives every reboot
sc create, or sc config changing an existing binPath, with a suspicious path is a near-direct signal in command-line telemetry.
HACKTHESOCLesson 72Windows services33 / 46

The same two verbs in sc.exe and PowerShell

Read side

sc query and Get-Service show a service's current state: the investigator's commands for confirming a hypothesis.

Write side

sc create and New-Service perform the identical creation. Seen in command-line telemetry with a suspect path, close to a direct signal.

Attackers and admins use identical syntax, so the path and the parent process, not the verb, carry the signal.
HACKTHESOCLesson 72Windows services34 / 46

The same actions from PowerShell

Get-Service reads; New-Service performs the same creation as sc create. Script-block logging, Event ID 4104, complements service telemetry.
HACKTHESOCLesson 72Windows services35 / 46

Current state versus how it got there

Live queries

sc query, Get-Service, services.msc: what a service looks like right now. Good for confirming a hypothesis.

Event logs

7045 and related events: when it appeared and what created it.

With PsExec, the 7045 may land on a machine where no interactive attacker session ever appears, only a 4624 type 3.

An analyst who reads both moves fluidly between what is on this box today and how it got there.

Key takeaways

  1. 01A service runs in the background, usually from boot, under a service account often as powerful as LocalSystem.
  2. 02gMSAs have auto-rotated 240-byte passwords; a new service on a legacy custom account is worth chasing.
  3. 03Start 2 is Automatic and 4 is Disabled; Type 0x1 is a kernel driver worth the scrutiny of a 7045.
  4. 04Attackers create auto-start services, hijack binary paths, and use PsExec-style service creation to move.
  5. 05Event 7045 is the headline signal, backed by 4697, 7040, 7036/7034, Sysmon 13 and sc.exe telemetry.
  6. 06A 4624 type 3 followed by a 7045 on the same target, plus the source host's history, confirms lateral movement.

Event ID 7045 on a server shows a new service with a random-looking name whose binary is in C:\Users\Public\temp. Why is this significant?

7045 fires when a service is installed, and a random name with a binary in a user-writable temp folder strongly indicates malicious persistence or lateral movement. It does not record deletions or firewall changes.

Check your understanding, question 2 of 3

A 7045 shows PSEXESVC installed on a file server right after a Logon Type 3 from a workstation using a service account. Why is the name alone not enough to call it malicious?

PSEXESVC is PsExec's default service name, so it does not distinguish admin use from lateral movement. Logon type, account and source-host context do. 7045 records the name, nothing is encrypted, and type 3 is a network logon.

Check your understanding, question 3 of 3

A security service's Start value changed from REG_DWORD 0x2 to 0x4 and Windows logged Event 7040. What did the attacker likely do, and why is it worse than a stop?

0x2 is Automatic and 0x4 is Disabled, so the security service stays off on every subsequent boot. That durable disabling is why 7040 is alerted on separately. Start is not the Type value.
