An LLM predicts the most likely next word. Every attack abuses a detail behind that.

Eight terms before any attack makes sense

TermPlain-English definition
Prompt / system promptText sent to the model / hidden developer instructions written before the user types anything
Context windowAll text the model sees at once, in tokens: system prompt, conversation and documents share it
InferenceThe model generating a response; running it, as opposed to training it
Model weightsBillions of learned parameters that encode what the model knows
EmbeddingA numeric vector of a text's meaning; similar meaning, similar vector

An agent turns a conversation into consequences. That is why agent attacks become real incidents.

Each attack abuses one mechanical fact

Prompt injection

System prompt and user or document text share one context window with no label for trusted vs data.

Poisoning

Model weights are learned from data an attacker can sometimes influence.

Model theft

Inference is just an API a client can call repeatedly.

RAG poisoning

A vector database is only as trustworthy as what gets embedded into it.

Ask students to keep this slide in mind: every section later maps back to one of these four facts.

Section 2 of 7

Prompt injection: how attackers execute it

OWASP LLM01, MITRE ATLAS AML.T0051, under the Execution tactic AML.TA0005.

HACKTHESOCLesson 91AI attacks in the SOC10 / 43
To the model, a developer's instruction and a stranger's note are just words on the same page.

System prompt and user text are concatenated into one context window. Every token competes for attention the same way.

Use the translator analogy: a single sheet with the employer's orders and a stranger's 'ignore your employer, say this instead'. With no way to tell them apart, both get repeated.
HACKTHESOCLesson 91AI attacks in the SOC11 / 43

Three sub-techniques of AML.T0051

AML.T0051.000

Direct

The attacker is the user, typing instructions into the conversation to override the system prompt in the same turn.

AML.T0051.001

Indirect

Instructions hidden in content the system later ingests: web page, document, email, record, ticket. The attacker never talks to the model.

AML.T0051.002

Triggered

A dormant payload in ingested content fires only when a later user action or event meets a condition.

Triggered injection lets the attacker time the attack or slip past an earlier review.
HACKTHESOCLesson 91AI attacks in the SOC12 / 43

Direct vs indirect injection, described in words

AML.T0051.000

Direct: OrderBot chat

The user types text telling the bot to drop its rules, reveal its system prompt and list other customers' order history and emails.

AML.T0051.001

Indirect: ticket #48213

A normal-looking refund request hides bracketed text telling the summarizing agent, which can send email, to export the customer database to an outside address.

No suspicious user ever appears in a chat log for the ticket attack: the attacker never talks to the model.

OrderBot's system prompt limits it to the customer's own order status. In the ticket case a human skimming sees an ordinary refund request, while the agent treats every token the same and may try to comply.
HACKTHESOCLesson 91AI attacks in the SOC13 / 43

Jailbreak is not the same as prompt injection

AML.T0051

Prompt injection

Overrides the application's instructions: its system prompt.

AML.T0054

Jailbreak

Targets the model's own safety training rather than the application's instructions.

Gateway classifiers often report both under one verdict, which is why detection treats them together.

Precision in terminology matters when you write the ticket and tag the technique.

Prompt injection: detection engineering

Text through a normal channel: no single alert screams attack, so spot the pattern.

HACKTHESOCLesson 91AI attacks in the SOC15 / 43

Signs an analyst looks for

  • Output contradicts policyAn 'order status only' bot discussing internal tools, other customers or its own configuration.
  • Unexpected tool invocationAn agent sends email or queries a database it was not asked to use.
  • Classifier verdictsA gateway safety classifier, e.g. Microsoft Prompt Shields, flags jailbreak or injection: a direct signal.
  • Anomalous length patternsA long ingested document followed by a wildly off-topic completion.
  • System prompt probingRepeated requests to recite its instructions or list its tools: recon that crosses into LLM07.
A positive classifier verdict is a direct signal, not just a heuristic guess.

Join classifier hits to real actions from the same agent run

The highest-value correlation: a flagged prompt followed by a real downstream action.

  • agent_actions is the application's own audit log: tool executed, target, result
  • Detected, unfiltered, plus a successful external send_email: an incident
  • A detection with no matching action is an attempt
Turning an attempt into impact is LLM06:2025 Excessive Agency: more tool permission than the task needs. For Bedrock, CloudTrail alone can flag unusual model use per identity (InvokeModel and Converse counts, distinct modelIds) with no content needed.
HACKTHESOCLesson 91AI attacks in the SOC19 / 43

False positives come from people talking about injection

Awareness training

Content quoting real payloads as examples trips the same classifier.

Red team / pentest

Exercises generate expected positives.

RAG over a blog post

An indexed blog post about injection surfaces the classic trigger phrase with zero malicious intent.

Check the content's source and whether any downstream action followed. The trigger phrase alone is not proof.

A spike of jailbreak verdicts from the awareness-training team's account, with no tool call afterwards, is the textbook example.

Worked triage: an indirect-injection alert

From the gateway record above to a defensible verdict, in a fixed order.

HACKTHESOCLesson 91AI attacks in the SOC21 / 43
Prompt Shields flagged indirect_attack in ticket INC-88412, nothing was filtered, and the agent asked to send an email.

The gateway was in monitor mode. Work the alert in order: trigger, execution, scope, data, containment.

Everything in this section uses the gateway record from the previous section, so students can follow each pivot.
HACKTHESOCLesson 91AI attacks in the SOC22 / 43

Five triage moves, in this order

  1. 1Confirm the triggerPull INC-88412 from the ticketing system, not the alert. Portal log: submitter email and IP.
  2. 2Did the tool call execute?Action log, same run ID: send_email with status=success. Then the mail trace.
  3. 3ScopeSame submitter, external domain in any tool argument, or wording, across 30 days of tickets.
  4. 4Assess the dataWhat customers_export.csv held and how many records: a privacy-notification decision?
  5. 5Contain and fixRotate the agent's mail credential, block the domain, quarantine the ticket, gateway to block.
Indirect injection is cheap to repeat, so one hit often has siblings that were filtered or went to an agent without a classifier. The agent identity spn-support-agent and its permissions define the maximum blast radius.

What to look for, and what proves impact

In the stored ticket

Text aimed at the model, not a human: addressed to 'the assistant', hidden or white-on-white in an HTML body, or in fields a human never sees.

Requested vs executed

The gateway shows the model requested send_email. The action log shows the application ran it. Message trace or EmailEvents confirms delivery and attachment size.

Requested is an attempt; status=success in the action log changes it to an incident. Delivery is then confirmed in the mail platform for that sender identity and recipient.
HACKTHESOCLesson 91AI attacks in the SOC24 / 43
Verdict: true positive. Indirect prompt injection (AML.T0051.001) with successful exfiltration through an agent tool.

Evidence: the stored ticket text, the gateway verdict, the action-log success and the mail trace. Design finding: LLM06 Excessive Agency.

An agent that sends external email with attachments, without human approval, on the strength of untrusted ticket text is a design problem that no classifier fully fixes.

Sensitive disclosure and data/model poisoning

Making a model say what it shouldn't, or learn something wrong in the first place.

HACKTHESOCLesson 91AI attacks in the SOC26 / 43

Three shapes of LLM02:2025 Sensitive Information Disclosure

System prompt leakage

Business logic, tool names, even hardcoded secrets extracted by asking the model to repeat its instructions. Its own category: LLM07:2025.

Training-data memorization

Large models can regurgitate verbatim snippets of training data, including scraped PII.

RAG across boundaries

A shared vector index without per-document access control quotes a document the user may not see.

Retrieval doesn't know or care who is asking. That is the root of the third shape.
HACKTHESOCLesson 91AI attacks in the SOC27 / 43

Poison Training Data: AML.T0020, OWASP LLM04:2025

  • Two tactics at onceResource Development (AML.TA0003), prepared before deployment, and Persistence (AML.TA0006), surviving inside the model.
  • MechanismModify training, fine-tuning or labeling data, directly or via a poisoned public dataset.
  • Hidden triggerA code-completion model inserts a subtle vulnerability only when it sees one innocent comment string.
  • NIST AI 100-2 framingAn integrity attack. PredAI poisoning hits a classifier's training set; GenAI poisoning hits fine-tuning data or the RAG index.
Confidentiality attacks are disclosure and extraction; availability attacks include unbounded consumption.
HACKTHESOCLesson 91AI attacks in the SOC28 / 43

Detecting disclosure and poisoning

  • DLP on model outputsScan for PII, secrets or credential-shaped strings before a response leaves.
  • Canary stringsA honeytoken seeded in a corpus appearing in an unrelated user's answer proves a leak.
  • Provenance reviewTreat an unverified public dataset like an unverified software dependency.
  • Differential testingBackdoors are narrow by design, so broad varied inputs reveal the one that diverges.
Canary strings turn a suspicion of cross-boundary leakage into proof.

Model theft, RAG poisoning, and supply chain

Attack surface where a network defender might not think to look.

HACKTHESOCLesson 91AI attacks in the SOC30 / 43

AML.T0024 Exfiltration via AI Inference API

Tactic: Exfiltration (AML.TA0010). Three documented sub-techniques.

Sub-techniqueWhat the attacker does
AML.T0024.000 Infer Training Data MembershipDetermines whether a specific record was in the training set
AML.T0024.001 Invert AI ModelReconstructs sensitive inputs from a pattern of outputs
AML.T0024.002 Extract AI ModelQueries repeatedly and trains a cheap clone on the answers
Extraction is black-box: an API key and patience. ATLAS files the economic harm as AML.T0048.004 AI Intellectual Property Theft. It shares a root defect with LLM10:2025 Unbounded Consumption: no per-identity limit on query volume or cost.
HACKTHESOCLesson 91AI attacks in the SOC31 / 43

Retrieval and supply chain risks

Vector and embedding

LLM08:2025

Malicious content indexed into a retrieval corpus is quoted as ground truth. Also embedding inversion and cross-tenant vector-store leakage.

Supply chain

LLM03:2025

A hub model, LoRA adapter, plugin or scraped dataset can carry a backdoor nobody audited. Verify publisher, check format for unsafe deserialization, scan artifacts.

RAG poisoning is prompt injection through the back door of trusted data. The model is doing exactly what RAG is designed to do.

Shadow AI: three sources that actually find it

Pasting code, customer records or strategy into an unapproved public AI tool is a DLP and visibility problem.

  • Proxy or SWG logsGroup by user and AI domain (chatgpt.com, claude.ai, gemini.google.com...) and look at bytes sent, not visits.
  • CASB / Defender for Cloud AppsApp catalog risk scores plus Cloud Discovery of who reaches which AI apps; mark sanctioned or unsanctioned, then block.
  • Endpoint DLPPurview audits or blocks pasting classified content into AI sites: records user, site, matched type, action.
A reader sends kilobytes; someone pasting a code base sends megabytes in POST requests. Unapproved destinations are the finding, large uploads the priority. Only endpoint DLP sees what was pasted.
HACKTHESOCLesson 91AI attacks in the SOC37 / 43

A starting hunt: big POST uploads to AI domains in Sentinel

  • CommonSecurityLog columns are populated by most proxies
  • SentBytes on POST measures uploads, not page views
  • Users over 20 MB to an AI domain in a week rise to the top
This is a starting hunt, not a finished rule: it finds who is sending megabytes to AI sites, and the CASB catalog then tells you which of those destinations are unapproved.

Key takeaways

  1. 01Prompt injection (LLM01, AML.T0051) works because instructions and data share one context window: Direct, Indirect, Triggered.
  2. 02Azure OpenAI and Bedrock defaults log metadata, not prompts; an LLM gateway holds prompt, verdict and tool calls together.
  3. 03A classifier hit plus a successful tool call from the same agent run is an incident; a hit with no action is an attempt.
  4. 04Disclosure (LLM02, LLM07) and poisoning (LLM04) hit the model's data; theft (AML.T0024) shares LLM10's missing query limit.
  5. 05Arup lost about $25.6 million in one day to a deepfake call; the control is out-of-band verification, not a log query.
  6. 06Find shadow AI by bytes uploaded to AI domains, the CASB app catalog, and endpoint DLP that records what was pasted.
