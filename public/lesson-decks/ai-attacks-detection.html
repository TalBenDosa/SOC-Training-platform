Chatbot, RAG app, agent: what each can do, and what can go wrong

Answers only

Chatbot

Takes a prompt, returns text. Worst case: it says something it should not, such as its system prompt or memorized data.

Reads your documents

RAG application

Pulls documents from a vector database into the prompt. Worst case: it quotes a poisoned or off-limits document as if it were fact.

Acts with tools

AI agent

Can call tools: send email, query a database, change a record. Worst case: a manipulated answer becomes a real action with real consequences.

The more an AI system can do, the more an attack on it can do. Always check what the system is permitted to touch.

This ladder explains why most real AI incidents in this lesson involve agents: a chatbot can only embarrass you, an agent can move your data.
HACKTHESOCLesson 91AI attacks in the SOC8 / 66

How one request reaches the model: a single shared context window

  1. 1Developer writes the system promptHidden rules, e.g. 'only discuss the customer's own order status'.
  2. 2User text is addedThe question or message typed into the app.
  3. 3Documents and tool output are addedRAG results, an ingested ticket, an email: whatever the app retrieved.
  4. 4All of it becomes one block of tokensConcatenated into the context window, with no built-in trusted / untrusted label.
  5. 5Inference produces the answerThe model predicts the next words. An agent's answer can include a tool call the app then runs.
Pause on step 4: this is the root cause of prompt injection. Nothing in the window says which words came from the developer and which from a stranger.
HACKTHESOCLesson 91AI attacks in the SOC9 / 66

Each attack abuses one mechanical fact

Prompt injection

System prompt and user or document text share one context window with no label for trusted vs data.

Poisoning

Model weights are learned from data an attacker can sometimes influence.

Model theft

Inference is just an API a client can call repeatedly.

RAG poisoning

A vector database is only as trustworthy as what gets embedded into it.

Prompt injection: how attackers execute it

OWASP LLM01, MITRE ATLAS AML.T0051, under the Execution tactic AML.TA0005.

HACKTHESOCLesson 91AI attacks in the SOC13 / 66
To the model, a developer's instruction and a stranger's note are just words on the same page.

System prompt and user text are concatenated into one context window. Every token competes for attention the same way.

Use the translator analogy: a single sheet with the employer's orders and a stranger's 'ignore your employer, say this instead'. With no way to tell them apart, both get repeated.
HACKTHESOCLesson 91AI attacks in the SOC14 / 66

Why an injected instruction can win over the system prompt

  1. 1App builds the promptSystem prompt, then untrusted text: a chat message or an ingested document.
  2. 2No separation survivesBoth arrive as plain tokens in one window; the model sees no 'trusted' marker.
  3. 3Model weighs all instructionsIt may follow the attacker's sentence instead of the developer's rule.
  4. 4Output carries the intentA policy-breaking reply, a leaked prompt, or a requested tool call.
  5. 5App acts on the outputIf the app executes tool calls without a check, the attack becomes an action.
The defensive takeaway: classifiers and Spotlighting reduce step 3, but limiting what the app does at step 5 is what caps the damage.
HACKTHESOCLesson 91AI attacks in the SOC15 / 66

Three sub-techniques of AML.T0051

AML.T0051.000

Direct

The attacker is the user, typing instructions into the conversation to override the system prompt in the same turn.

AML.T0051.001

Indirect

Instructions hidden in content the system later ingests: web page, document, email, record, ticket. The attacker never talks to the model.

AML.T0051.002

Triggered

A dormant payload in ingested content fires only when a later user action or event meets a condition.

Triggered injection lets the attacker time the attack or slip past an earlier review.

Direct vs indirect injection, read side by side

Direct: OrderBot chatIndirect: ticket #48213
Who writes the textThe attacker, as the chat userThe attacker, as an ordinary-looking customer
Where it entersThe chat box, in the same turnA ticket body the summarizing agent ingests later
What it asks forDrop the rules, reveal the system prompt, list other customers' orders and emailsExport the customer database and email it to an outside address
What a human seesAn odd chat messageAn ordinary refund request; the instruction is bracketed or hidden

OrderBot's system prompt limits it to the customer's own order status. The ticket agent can send email, which is what turns the indirect case from embarrassing into dangerous.
HACKTHESOCLesson 91AI attacks in the SOC17 / 66

Jailbreak is not the same as prompt injection

AML.T0051

Prompt injection

Overrides the application's instructions: its system prompt.

AML.T0054

Jailbreak

Targets the model's own safety training rather than the application's instructions.

Gateway classifiers often report both under one verdict, which is why detection treats them together.

Precision in terminology matters when you write the ticket and tag the technique.

Prompt injection: detection engineering

Text through a normal channel: no single alert screams attack, so spot the pattern.

HACKTHESOCLesson 91AI attacks in the SOC19 / 66

Signs an analyst looks for

  • Output contradicts policyAn 'order status only' bot discussing internal tools, other customers or its own configuration.
  • Unexpected tool invocationAn agent sends email or queries a database it was not asked to use.
  • Classifier verdictsA gateway safety classifier, e.g. Microsoft Prompt Shields, flags jailbreak or injection: a direct signal.
  • Anomalous length patternsA long ingested document followed by a wildly off-topic completion.
  • System prompt probingRepeated requests to recite its instructions or list its tools: recon that crosses into LLM07.
A positive classifier verdict is a direct signal, not just a heuristic guess.

HACKTHESOCLesson 91AI attacks in the SOC21 / 66

Where the gateway sits: the path of one agent turn

  1. 1Content arrivesA user turn, a retrieved document or a ticket enters the app.
  2. 2Gateway checks itA classifier such as Prompt Shields scores it for jailbreak and indirect attack.
  3. 3Policy decidesblock filters the turn; monitor records the verdict and lets it through.
  4. 4Model answersThe completion may include tool calls the model requests.
  5. 5App executesThe application runs the tool and writes its own action log: what was executed.
Two different logs for two different facts: the gateway knows what the model asked for, the application knows what actually happened. Correlating them is the core skill of this section.

Join classifier hits to real actions from the same agent run

The highest-value correlation: a flagged prompt followed by a real downstream action.

  • agent_actions is the application's own audit log: tool executed, target, result
  • Detected, unfiltered, plus a successful external send_email: an incident
  • A detection with no matching action is an attempt
Turning an attempt into impact is LLM06:2025 Excessive Agency: more tool permission than the task needs. For Bedrock, CloudTrail alone can flag unusual model use per identity (InvokeModel and Converse counts, distinct modelIds) with no content needed.
HACKTHESOCLesson 91AI attacks in the SOC26 / 66

What the join does, one line at a time

  1. 1Find classifier hitsGateway records where indirect_attack or jailbreak was detected.
  2. 2Name the runRename session_id to run so both sources share one key.
  3. 3Find successful actionsAgent action log rows with action_status=success, renamed agent_run_id to run.
  4. 4Inner join on runOnly runs present in both survive: a flag followed by a real action.
  5. 5Table the evidenceTime, app, identity, trigger, action and target: ready for the ticket.
The inner join is the whole point: it discards flagged prompts that did nothing and successful actions that were never flagged, leaving the overlap that is an incident.

False positives come from people talking about injection

Awareness training

Content quoting real payloads as examples trips the same classifier.

Red team / pentest

Exercises generate expected positives.

RAG over a blog post

An indexed blog post about injection surfaces the classic trigger phrase with zero malicious intent.

Check the content's source and whether any downstream action followed. The trigger phrase alone is not proof.

A spike of jailbreak verdicts from the awareness-training team's account, with no tool call afterwards, is the textbook example.

Worked triage: an indirect-injection alert

From the gateway record above to a defensible verdict, in a fixed order.

HACKTHESOCLesson 91AI attacks in the SOC29 / 66
Prompt Shields flagged indirect_attack in ticket INC-88412, nothing was filtered, and the agent asked to send an email.

The gateway was in monitor mode. Work the alert in order: trigger, execution, scope, data, containment.

Everything in this section uses the gateway record from the previous section, so students can follow each pivot.
HACKTHESOCLesson 91AI attacks in the SOC30 / 66

Five triage moves, in this order

  1. 1Confirm the triggerPull INC-88412 from the ticketing system, not the alert. Portal log: submitter email and IP.
  2. 2Did the tool call execute?Action log, same run ID: send_email with status=success. Then the mail trace.
  3. 3ScopeSame submitter, external domain in any tool argument, or wording, across 30 days of tickets.
  4. 4Assess the dataWhat customers_export.csv held and how many records: a privacy-notification decision?
  5. 5Contain and fixRotate the agent's mail credential, block the domain, quarantine the ticket, gateway to block.
Indirect injection is cheap to repeat, so one hit often has siblings that were filtered or went to an agent without a classifier. The agent identity spn-support-agent and its permissions define the maximum blast radius.

What to look for, and what proves impact

In the stored ticket

Text aimed at the model, not a human: addressed to 'the assistant', hidden or white-on-white in an HTML body, or in fields a human never sees.

Requested vs executed

The gateway shows the model requested send_email. The action log shows the application ran it. Message trace or EmailEvents confirms delivery and attachment size.

Requested is an attempt; status=success in the action log changes it to an incident. Delivery is then confirmed in the mail platform for that sender identity and recipient.

Containment and the design fix

  • Rotate the agent's mail accessRevoke or rotate whatever spn-support-agent used to send mail, if it is reusable.
  • Block the destinationBlock the external domain that received the export.
  • Quarantine the ticketSo the agent cannot re-ingest the same instructions on its next run.
  • Gateway to blockSwitch indirect_attack from monitor to block for this app: the immediate control.
  • Raise the design findingExternal email with attachments, no human approval, on untrusted text: LLM06 Excessive Agency.
The first four stop this incident. Only the fifth stops the next one: no classifier fully fixes an agent that holds more permission than its task needs.

Sensitive disclosure and data/model poisoning

Making a model say what it shouldn't, or learn something wrong in the first place.

HACKTHESOCLesson 91AI attacks in the SOC36 / 66

Three shapes of LLM02:2025 Sensitive Information Disclosure

System prompt leakage

Business logic, tool names, even hardcoded secrets extracted by asking the model to repeat its instructions. Its own category: LLM07:2025.

Training-data memorization

Large models can regurgitate verbatim snippets of training data, including scraped PII.

RAG across boundaries

A shared vector index without per-document access control quotes a document the user may not see.

Retrieval doesn't know or care who is asking. That is the root of the third shape.
HACKTHESOCLesson 91AI attacks in the SOC37 / 66

How RAG leaks a document across a permission boundary

  1. 1One shared indexDocuments from many teams, with different access rights, are embedded into one vector store.
  2. 2A user asks a questionTheir words are turned into an embedding.
  3. 3Retrieval finds the closest vectorsBy meaning only. It does not check who is asking.
  4. 4The model quotes the matchEven an HR or finance document the user could never open directly.

The fix is per-document access control in retrieval, not a better model.

Ask students where the access check should have happened: at retrieval time, using the asking user's permissions, before the text ever enters the context window.
HACKTHESOCLesson 91AI attacks in the SOC38 / 66

Three disclosure shapes: what you see and what stops it

ShapeWhat the analyst seesControl
System prompt leakage (LLM07)Repeated 'repeat your instructions' prompts; replies listing tool namesKeep secrets out of system prompts; output filtering

The canary string is the strongest evidence of the three: it turns 'I think the index leaks' into proof.
HACKTHESOCLesson 91AI attacks in the SOC39 / 66

Poison Training Data: AML.T0020, OWASP LLM04:2025

  • Two tactics at onceResource Development (AML.TA0003), prepared before deployment, and Persistence (AML.TA0006), surviving inside the model.
  • MechanismModify training, fine-tuning or labeling data, directly or via a poisoned public dataset.
  • Hidden triggerA code-completion model inserts a subtle vulnerability only when it sees one innocent comment string.
  • NIST AI 100-2 framingAn integrity attack. PredAI poisoning hits a classifier's training set; GenAI poisoning hits fine-tuning data or the RAG index.
Confidentiality attacks are disclosure and extraction; availability attacks include unbounded consumption.
HACKTHESOCLesson 91AI attacks in the SOC40 / 66

Where a poisoning backdoor can be caught, stage by stage

Poisoning hides a trigger-activated behavior in training data. Each stage of the pipeline is a checkpoint.

  1. 1Data intakeProvenance review: is this public dataset verified, like any third-party dependency?
  2. 2Before trainingIntegrity checks on fine-tuning and labeling data: who changed what, and when.
  3. 3After trainingDifferential testing on broad, varied inputs: a narrow backdoor shows as one divergent case.
  4. 4At deploymentModel-artifact provenance: the weights you ship are the ones you tested.
  5. 5In productionOutput review and DLP: unexpected content, such as insecure code suggestions, gets flagged.
ATLAS maps AML.T0020 to two tactics: Resource Development, because the data is prepared before deployment, and Persistence, because the behavior then lives in the weights. Normal testing misses it, which is why broad differential testing matters.
HACKTHESOCLesson 91AI attacks in the SOC41 / 66

NIST AI 100-2: three things an attacker can want

Corrupt it

Integrity

Change what the model learns or believes: poisoning of training data, fine-tuning data or the RAG index.

Steal from it

Confidentiality

Get out what it should keep in: disclosure and extraction of data or the model itself.

Exhaust it

Availability

Make it too costly or slow to use: unbounded consumption, covered in the next section.

The same split exists for PredAI and GenAI: classic poisoning corrupts a classifier's training set, GenAI poisoning targets fine-tuning data or RAG documents.
HACKTHESOCLesson 91AI attacks in the SOC42 / 66

Detecting disclosure and poisoning

  • DLP on model outputsScan for PII, secrets or credential-shaped strings before a response leaves.
  • Canary stringsA honeytoken seeded in a corpus appearing in an unrelated user's answer proves a leak.
  • Provenance reviewTreat an unverified public dataset like an unverified software dependency.
  • Differential testingBackdoors are narrow by design, so broad varied inputs reveal the one that diverges.
Canary strings turn a suspicion of cross-boundary leakage into proof.

Model theft, RAG poisoning, and supply chain

Attack surface where a network defender might not think to look.

HACKTHESOCLesson 91AI attacks in the SOC44 / 66

AML.T0024 Exfiltration via AI Inference API

Tactic: Exfiltration (AML.TA0010). Three documented sub-techniques.

Sub-techniqueWhat the attacker does
AML.T0024.000 Infer Training Data MembershipDetermines whether a specific record was in the training set
AML.T0024.001 Invert AI ModelReconstructs sensitive inputs from a pattern of outputs
AML.T0024.002 Extract AI ModelQueries repeatedly and trains a cheap clone on the answers
Extraction is black-box: an API key and patience. ATLAS files the economic harm as AML.T0048.004 AI Intellectual Property Theft. It shares a root defect with LLM10:2025 Unbounded Consumption: no per-identity limit on query volume or cost.
HACKTHESOCLesson 91AI attacks in the SOC45 / 66

What model extraction looks like in the telemetry

Extraction (AML.T0024.002) clones a model from its answers through the normal API, so only the usage pattern gives it away.

  1. 1One identity's volume jumpsAPI-gateway or CloudTrail counts per key rise far above that key's own baseline.
  2. 2Query diversity widensTopics sweep the input space instead of matching the tool's real purpose.
  3. 3Breadth across modelsIn Bedrock, distinct modelId values per identity climb.
  4. 4Cost followsToken spend for that key rises: the same signal LLM10 monitoring watches.
  5. 5Classify the harmThe economic loss is AML.T0048.004 AI Intellectual Property Theft.
Every call is a valid API call. There is no exploit to detect, only a usage pattern, which is why per-identity baselines are the detection.
HACKTHESOCLesson 91AI attacks in the SOC46 / 66

Bedrock: unusual model use per identity, from CloudTrail alone

  • Default CloudTrail management events: no prompt content needed
  • count per identity catches volume; dc(modelId) catches breadth
  • Tune the 5000 and 3 thresholds to your own baseline
This query works on day one because CloudTrail records InvokeModel and Converse by default. It cannot see what was asked, only who asked how much of which model.
HACKTHESOCLesson 91AI attacks in the SOC47 / 66

High volume: batch job or extraction?

Benign batch job

Volume rises after a known change, but queries look like the tool's real work: actual tickets, one model, a predictable schedule.

Extraction pattern

One key sweeping unrelated topics, inputs varied systematically rather than serving the tool's purpose, sometimes several models at once.

Volume alone is not the verdict. Diversity of queries relative to the tool's purpose is.

Ask the owner of the key what the tool does, then compare a sample of its queries to that purpose. A reporting tool has no reason to ask about everything.
HACKTHESOCLesson 91AI attacks in the SOC48 / 66
Extraction and denial-of-wallet share one root defect: no limit on a single identity's query volume or cost.

That is OWASP LLM10:2025 Unbounded Consumption. Per-key rate and spend limits blunt both attacks at once.

Availability and confidentiality attacks meet here: the same missing limit lets one key drain the budget or clone the model.
HACKTHESOCLesson 91AI attacks in the SOC49 / 66

Retrieval and supply chain risks

Vector and embedding

LLM08:2025

Malicious content indexed into a retrieval corpus is quoted as ground truth. Also embedding inversion and cross-tenant vector-store leakage.

Supply chain

LLM03:2025

A hub model, LoRA adapter, plugin or scraped dataset can carry a backdoor nobody audited. Verify publisher, check format for unsafe deserialization, scan artifacts.

RAG poisoning is prompt injection through the back door of trusted data. The model is doing exactly what RAG is designed to do.
HACKTHESOCLesson 91AI attacks in the SOC50 / 66

Tracing RAG poisoning back through the logs

RAG poisoning gets malicious content indexed so the model later quotes it as fact. Work backwards from the answer.

  1. 1The suspect answerGateway record: which documents were retrieved into that turn's context.
  2. 2The source documentIs it a wiki page, an uploaded PDF, or a crawled public page?
  3. 3Who changed itWiki edit history, upload log or crawl record: account, time, source.
  4. 4Who indexed itThe vector store's ingestion and access-control audit for that document.

The chat looks normal, because RAG is working as designed. The evidence sits in ingestion and access audit.

This is indirect prompt injection with a better disguise: the instructions or false facts arrive through the trusted data path, not the conversation.

Three points where the Arup fraud could have been stopped

Days before

The email

A message impersonating the CFO asks for a confidential transaction. Secrecy plus money is the warning sign.

Key takeaways

  1. 01Prompt injection (LLM01, AML.T0051) works because instructions and data share one context window: Direct, Indirect, Triggered.
