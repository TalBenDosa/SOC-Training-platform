Why Infrastructure as Code, and the tool landscape

Describe infrastructure in text files so it can be repeated, reviewed and rebuilt.

HACKTHESOCLesson 113AWS IaC, monitoring, billing6 / 52

IaC gives four operational properties

Infrastructure as Code (IaC) turns text files into servers, networks, databases and permissions.

Repeatable

The same template creates identical dev, test and production environments, in any Region or account.

    Versioned

    The template lives in Git, so every change has an author, a timestamp and a diff.

      Reviewable

      A teammate approves a pull request before the change reaches the account: a control point console clicks never have.

        Recoverable

        A destroyed environment can be rebuilt from the repository: the base of disaster recovery for infrastructure.

          The alternative, clicking in the console, gives environments nobody can reproduce exactly, review before they change, or roll back with confidence.

          Out-of-band change is the pitfall that unites every IaC tool.

          Someone fixes an incident in the console, the code still says otherwise, and the next deployment reverts the fix or fails. Treat the console as read-only in production.

          Mature teams use IaC for every change, including emergency ones. The next section shows how CloudFormation detects exactly this situation.

          CloudFormation: templates, stacks, change sets, drift

          A template becomes a stack; change sets preview an update and drift detection finds out-of-band edits.

          HACKTHESOCLesson 113AWS IaC, monitoring, billing10 / 52

          A template has four top-level sections

          A stack is the unit of deployment: created, updated and deleted together, and rolled back whole if any resource fails.

          • ParametersInputs such as environment name or instance size, so one template serves many environments.
          • Mappings and ConditionsLookup tables and if-logic, e.g. a larger instance only when the environment is prod.
          • ResourcesThe only required section: a logical ID, a Type such as AWS::S3::Bucket, and Properties.
          • OutputsValues other stacks can import, such as a VPC ID.
          Because failed creations roll back the whole stack, you never keep a half-built environment.
          HACKTHESOCLesson 113AWS IaC, monitoring, billing11 / 52

          A minimal template, and the line that protects your data

          • Without DeletionPolicy: Retain, deleting the stack deletes the bucket
          • Use Retain or Snapshot for databases and buckets holding real data
          The Env parameter lets one template serve dev and prod. The full example also has an Outputs section exposing the bucket name.
          HACKTHESOCLesson 113AWS IaC, monitoring, billing12 / 52

          Read the change set before you execute

          A change set asks CloudFormation what it would do, instead of updating the stack directly.

          1. 1Create the change setaws cloudformation create-change-set with the template and parameters.
          2. 2Read each actionEvery resource shows Add, Modify or Remove.
          3. 3Check Replacement on ModifyTrue, False or Conditional. True means delete and recreate with a new physical ID.
          4. 4Stop and ask whyOn RDS or EC2, True means data or an address may be lost. Check backups first.
          Use describe-change-set to read the result. Replacement is not an error indicator: it is the line that tells you a resource will be rebuilt.
          HACKTHESOCLesson 113AWS IaC, monitoring, billing13 / 52

          Change sets look ahead; drift detection checks the present

          Before the update

          Change set

          Answers: what would this update do to each resource?

          • Action: Add, Modify, Remove
          • Replacement: True, False, Conditional

          After someone edits

          Drift detection

          Answers: does the real resource still match the template?

          • Reports IN_SYNC, MODIFIED, DELETED, NOT_CHECKED
          • Not every resource type supports it

          Ask: who ran the update, was there a change set, and does the production stack have a stack policy or termination protection?

          Drift is the signal that someone changed infrastructure out-of-band. Remember the stack's service role defines the blast radius of any template.

          Deployment strategies trade speed for safe rollback

          In-place

          Replaces the application on the existing servers.

            Blue/green

            Launches a new fleet, shifts traffic, and keeps the old fleet for instant rollback.

              Canary and linear

              Shift a percentage of traffic over time.

                CodeDeploy can be wired to a CloudWatch alarm, so a rising error rate triggers automatic rollback.

                Whoever can edit the pipeline or the buildspec holds the pipeline's permissions.

                CloudWatch monitoring, and how it differs from CloudTrail

                CloudWatch collects numbers and text so you can see performance, set thresholds and react.

                HACKTHESOCLesson 113AWS IaC, monitoring, billing20 / 52

                Five parts of CloudWatch

                • MetricsTime series by namespace, name and dimensions, e.g. AWS/EC2, CPUUtilization, InstanceId=i-0abc.
                • AlarmsWatch one metric: OK, ALARM or INSUFFICIENT_DATA. Trigger SNS, Auto Scaling or EC2 recover.
                • LogsLog groups and streams. Logs Insights queries them; metric filters turn lines into metrics.
                • DashboardsShared graphs of metrics and alarms for an at-a-glance view.
                • EventBridgeFormerly CloudWatch Events: routes events such as instance state changes to targets like Lambda.

                EC2 basic monitoring uses 5-minute periods, detailed uses 1-minute. Memory and disk need the CloudWatch agent.

                An alarm example: average CPU above 80 percent for 3 out of 3 periods of 5 minutes. Logs Insights can also count errors with a stats query over 5-minute bins.
                HACKTHESOCLesson 113AWS IaC, monitoring, billing21 / 52

                CloudWatch asks how it is performing; CloudTrail asks who

                AspectCloudWatchCloudTrail
                Question answeredHow is it performing right now, and is it healthy?Who called which API, from where, and when?
                Data typeMetrics, application and system logs, eventsAPI call records (management and data events)
                Typical exampleCPU at 95 percent for 15 minutesUser alice called DeleteBucket from IP 203.0.113.9 at 02:14
                Action on dataAlarms, auto scaling, dashboardsInvestigation, audit, compliance, detection
                Time orientationNear real time operational viewForensic record of actions
                The classic confusion. If the question is about performance, reach for CloudWatch; if it is about who did what, reach for CloudTrail.
                HACKTHESOCLesson 113AWS IaC, monitoring, billing22 / 52

                They work together: root logins become an alarm

                1. 1CloudTrail records itThe source of truth for who did what.
                2. 2Delivered to a Logs groupCloudTrail can deliver events to a CloudWatch Logs group.
                3. 3A metric filter countsIt counts matching lines, e.g. root console logins.
                4. 4An alarm notifies youA CloudWatch alarm on that metric sends the notification.
                CloudTrail event fields are covered in the cloud audit logs lesson. Here CloudTrail is only the source for this pattern, and the worked example at the end builds it.
                HACKTHESOCLesson 113AWS IaC, monitoring, billing23 / 52

                Four monitoring pitfalls that stay silent

                No action attached

                The alarm turns red and nobody hears it.

                  INSUFFICIENT_DATA

                  A crashed instance simply stops sending metrics. For critical alarms, treat missing data as breaching.

                    Retention forgotten

                    Log groups keep data forever by default, so cost grows quietly.

                      Dashboards over alarms

                      Dashboards nobody reviews wake nobody. Build alarms that do.

                        Do not read INSUFFICIENT_DATA as healthy. A silent instance is often a dead instance.

                        Health and operations: AWS Health and Systems Manager

                        CloudWatch watches your workloads. These two cover the platform beneath them and safe ways to operate fleets.

                        HACKTHESOCLesson 113AWS IaC, monitoring, billing25 / 52

                        AWS Health: notices that exist to prevent the breakage

                        Service health

                        The public status of AWS services by Region, for everyone.

                          Your account health

                          Events for your resources: scheduled host retirement for EC2, RDS maintenance, an expiring certificate, a deprecated Lambda runtime.

                            Route it into alerting

                            Health publishes to EventBridge, so a rule can send events to SNS or chat. With Organizations, one view aggregates all member accounts.

                              Ask: is any resource in an open event, what is the deadline, and does it sit behind redundancy?

                              Teams that only look at the dashboard when something is already broken miss the notices meant to prevent the breakage.
                              HACKTHESOCLesson 113AWS IaC, monitoring, billing26 / 52

                              Systems Manager operates fleets without SSH

                              It acts on managed nodes: EC2 instances and on-premises servers running the SSM Agent.

                              CapabilityPurpose
                              Session ManagerShell with no open inbound port, bastion host or SSH key; can log to S3 or CloudWatch Logs
                              Run CommandRun a script across many instances at once, with output collection
                              Patch ManagerPatch baselines and maintenance windows, plus compliance reporting
                              Parameter StoreHierarchical configuration values and secrets, versioned and under IAM control
                              AutomationRunbooks, e.g. restart a service or snapshot a volume, triggered by a person or an alarm
                              Inventory and State ManagerCollect software inventory and enforce a desired configuration
                              The security win: replacing SSH with Session Manager removes an inbound attack surface and moves access control into IAM, where it is auditable.
                              HACKTHESOCLesson 113AWS IaC, monitoring, billing27 / 52

                              What Session Manager needs, and where it goes wrong

                              • SSM AgentMust be running on the instance.
                              • Instance profileNeeds AmazonSSMManagedInstanceCore. Without it the instance never appears in Fleet Manager.
                              • Network pathInternet egress or VPC endpoints to the Systems Manager endpoints.
                              • Patch baselinesA baseline never attached to a maintenance window does nothing.
                              • SecretsStore them as SecureString, not plain String parameters.
                              These are the usual reasons a fleet looks managed on paper but is not.
                              HACKTHESOCLesson 113AWS IaC, monitoring, billing28 / 52

                              The operations loop: notice, fix, record

                              1. 1A notice or alarm firesAn AWS Health event or a CloudWatch alarm.
                              2. 2An automation runsA Systems Manager runbook applies a documented fix.
                              3. 3The action is recordedSo the next person can see what happened and why.
                              Together, Health, CloudWatch and Systems Manager form this loop.

                              Cost and billing: pricing and the tools to watch spend

                              Know the pricing rules, then the tools that show where the money went.

                              HACKTHESOCLesson 113AWS IaC, monitoring, billing30 / 52

                              Three pricing principles drive every bill

                              Pay as you go

                              You pay for what you use, with no upfront contract for on-demand resources.

                                Pay less when you reserve

                                Commit to usage for one or three years in exchange for a discount.

                                  Pay less as you use more

                                  Tiered pricing: S3 storage, for example, becomes cheaper per GB at higher volumes.

                                    Data transfer into AWS is generally free; transfer out to the internet and between Regions is charged.

                                    Data transfer out is a frequent source of surprise bills. The free tier is limited by time or quota, so a forgotten resource becomes a bill once the allowance is gone.
                                    HACKTHESOCLesson 113AWS IaC, monitoring, billing31 / 52

                                    Four tools for seeing and steering spend

                                    • Cost ExplorerGraphs historical cost by service, account, Region or tag; forecasts; recommends rightsizing and Savings Plans.
                                    • AWS BudgetsAlerts on actual or forecasted spend by email or SNS. Budget actions can apply a restrictive policy.
                                    • Cost allocation tagsLabels like team=payments. Visible in billing only after activation, and not retroactive.
                                    • Consolidated billingOne payer account, one invoice. Usage is combined for volume discounts; commitments can be shared.
                                    Cost Explorer is where you ask why the bill rose in March. Spend before a tag is activated stays unattributed, so activate early.
                                    HACKTHESOCLesson 113AWS IaC, monitoring, billing32 / 52

                                    Commitment options trade flexibility for discount

                                    OptionWhat you commit toFlexibility
                                    On-DemandNothingFull flexibility, highest unit price
                                    Savings PlansA dollar-per-hour spend for 1 or 3 yearsCompute: EC2, Fargate, Lambda. EC2 Instance: one family and Region, bigger discount
                                    Reserved InstancesA specific instance configuration for 1 or 3 yearsLess flexible; Standard and Convertible types
                                    SpotNothing, but capacity can be reclaimed with a two-minute warningDeep discount for interruptible work such as batch jobs
                                    Do not buy commitments before usage is stable. Spot suits batch jobs that can be interrupted.
                                    HACKTHESOCLesson 113AWS IaC, monitoring, billing33 / 52

                                    Pitfalls that cost real money

                                    No budget at all

                                    The first alert is the invoice.

                                      Untagged resources

                                      A cost review turns into archaeology.

                                        Unmodeled charges

                                        Data transfer and NAT gateway charges nobody planned for.

                                          Idle or premature

                                          Unattached EBS volumes, unused Elastic IPs, commitments bought too early.

                                            Routine: enforce tags through IaC, review Cost Explorer weekly by tag, send Budgets to a monitored mailbox.

                                            A monitored shared mailbox beats one person's inbox, because that person goes on holiday.

                                            The Well-Architected Framework and Trusted Advisor

                                            Six pillars to judge a design, and an automated checker that reports on your account.

                                            HACKTHESOCLesson 113AWS IaC, monitoring, billing35 / 52

                                            Six pillars, six questions to ask of a workload

                                            PillarCore questionExample practices
                                            Operational excellenceCan we run, monitor and improve this?IaC, small reversible changes, runbooks, post-incident learning
                                            SecurityIs data and access protected?Least privilege, MFA, encryption, logging, incident response plan
                                            ReliabilityDoes it recover from failure and meet demand?Multi-AZ design, backups, tested recovery, health checks
                                            Performance efficiencyAre we using the right resources for the job?Right instance or serverless choice, caching, measuring before tuning
                                            Cost optimizationAre we avoiding unnecessary spend?Rightsizing, tags, Savings Plans, deleting idle resources
                                            SustainabilityAre we minimizing environmental impact?Efficient utilization, managed services, reducing waste
                                            Quota awareness also sits under reliability. Have students find the pillar behind each earlier section: IaC is operational excellence, tags are cost optimization.
                                            HACKTHESOCLesson 113AWS IaC, monitoring, billing36 / 52

                                            Pillars pull against each other, so decide on purpose

                                            Reliability up

                                            A multi-Region active-active design lifts reliability but raises cost and operational complexity.

                                              Cost down

                                              Aggressive cost cutting on a single instance lowers reliability.

                                                A deliberate choice

                                                The framework gives no single correct answer. It makes the trade-off explicit so the decision is deliberate.

                                                  Read every pillar question through the Shared Responsibility Model: which tasks are AWS's, which are yours.

                                                  This is the reasoning behind the quiz-style question about active-active for a tool that can tolerate hours of downtime.
                                                  HACKTHESOCLesson 113AWS IaC, monitoring, billing37 / 52

                                                  Trusted Advisor checks map closely to the pillars

                                                  Each check shows status (green, yellow, red), the affected resources and a recommended action: a prioritized to-do list.

                                                  • Cost optimizationIdle load balancers, underutilized instances.
                                                  • SecurityOpen security groups on risky ports, public S3 buckets or snapshots, no MFA on root, exposed access keys.
                                                  • Fault toleranceNo backups, single-AZ resources.
                                                  • PerformanceOverutilized instances, large number of rules.
                                                  • Service quotasUsage approaching a limit.
                                                  • Operational excellenceAppears in newer check sets.

                                                  Full checks need Business, Enterprise On-Ramp or Enterprise support; Basic and Developer see a limited core set.

                                                  Trusted Advisor is the automated counterpart to the Well-Architected Tool, which walks a team through the questions and flags high-risk and medium-risk items.
                                                  HACKTHESOCLesson 113AWS IaC, monitoring, billing38 / 52
                                                  Map the question to the pillar: rebuilding points to operations or reliability, idle resources to cost, who reaches the database to security.

                                                  Run Well-Architected reviews before launch and after major changes, not as paperwork.

                                                  A short mapping habit that helps in exams and in practice. The Well-Architected Tool records answers and tracks improvement through milestones.

                                                  Governance at a glance: Organizations, Control Tower, SCPs

                                                  Past a handful of accounts, monitoring and billing practices need a structure around them.

                                                  HACKTHESOCLesson 113AWS IaC, monitoring, billing40 / 52

                                                  Three services give the estate its structure

                                                  The hierarchy

                                                  AWS Organizations

                                                  Groups accounts under a management account into OUs. Gives consolidated billing, API account creation and a place to attach policies.

                                                    The landing zone

                                                    AWS Control Tower

                                                    Builds on Organizations: log archive and audit accounts, org-wide logging, Account Factory, and preventive and detective controls.

                                                      The ceiling

                                                      Service control policies

                                                      Set the maximum permissions in the accounts they attach to. They never grant permission and do not apply to the management account.

                                                        Separate accounts are the strongest isolation boundary AWS offers.

                                                        Preventive controls are implemented as SCPs, detective controls as AWS Config rules. SCP mechanics live in the existing cloud security lesson.

                                                        An empty account gets a baseline before anything is deployed: a budget, a root-login alarm and one template.

                                                        Three guardrails before the first deployment

                                                        GuardrailBuilt withPurpose
                                                        Cost visibilityAWS BudgetKnow about unexpected cost
                                                        Security detectionCloudWatch alarm on root loginKnow about unexpected root access
                                                        ConsistencyOne CloudFormation templateEverything defined in one place

                                                        CloudTrail already writes to a CloudWatch Logs group, whose name is passed in as a parameter.

                                                        The parameters are AlertEmail, MonthlyLimit (default 500) and TrailLogGroup. These guardrails cover the two events that hurt most in a new account.

                                                        Notification channel and the root-login metric filter

                                                        The filter matches CloudTrail records where the identity is Root and the event is ConsoleLogin, and counts each as 1 in the Guardrails namespace.
                                                        HACKTHESOCLesson 113AWS IaC, monitoring, billing46 / 52

                                                        What each guardrail does and how to read it

                                                        SNS topic

                                                        The single notification channel. The email subscriber must confirm, or alarm messages go nowhere. In production use a shared mailbox or chat.

                                                          Filter plus alarm

                                                          CloudTrail proves the login happened; the filter counts it; the alarm sums over 300 seconds with threshold 1. TreatMissingData notBreaching fits: no logins, no data points.

                                                            Budget

                                                            80 percent actual says you are close. 100 percent forecasted fires earlier in the month, when the trend says you will exceed. Forecasts need a few days of history.

                                                              The alarm uses Statistic Sum, Period 300, EvaluationPeriods 1 and GreaterThanOrEqualToThreshold. The budget is a COST budget, MONTHLY, in USD.

                                                              Deploy the baseline, then keep it honest

                                                              1. 1Commit the templateIt lives in Git like any other change.
                                                              2. 2Lint in CodeBuildRun cfn-lint before the template goes anywhere.
                                                              3. 3Create a change setReview it, then execute it.
                                                              4. 4Run drift detection weeklyIt catches out-of-band edits to the guardrails.
                                                              5. 5Enable termination protectionOn the stack, so it is not deleted by mistake.
                                                              6. 6Activate the team tagAs a cost allocation tag in the Billing console.

                                                              Not covered: Budgets only alert unless a budget action is set, root use is not prevented, and this is no Well-Architected review.

                                                              Preventing root use takes an SCP or simply protecting the root credentials with MFA. Tag activation lets the Budget and Cost Explorer group by team.
