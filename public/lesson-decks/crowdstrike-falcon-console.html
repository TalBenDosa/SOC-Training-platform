A lightweight sensor and a heavyweight cloud

Keep the endpoint piece small; put the intelligence where the attacker cannot reach it.

HACKTHESOCLesson 12CrowdStrike Falcon6 / 84

Falcon's architectural bet

On the endpoint

Falcon Sensor

Commonly cited under 5 MB, runs in kernel mode. Observes process, file, registry and network activity and streams it to the cloud continuously.

In the cloud

Threat Graph

Holds telemetry from every Falcon customer. New patterns learned at one customer benefit all. Scoring, grouping and MITRE mapping happen here.

You are not the first layer of analysis. You review a conclusion the cloud already reached.

A local admin cannot simply kill a kernel-mode sensor like a user-mode agent. But a host offline from the cloud loses real-time correlation and live RTR access, so note that gap.

Sensor light, cloud heavy

SensorKernel-mode, under 5 MB, streams telemetryHard to kill from inside a compromised host
Threat GraphCloud store of every customer's eventsOne customer's new pattern protects all, fast
Your roleReview a conclusion the cloud reachedYou are not the first layer of analysis
The architectural bet: keep the endpoint dumb and fast, and put the intelligence where the attacker cannot touch it.

Check Host Management before trusting protection

Host Groups get Sensor Policies; a DC and a marketing laptop should not share one.

  1. 1Is the sensor version current?Outdated sensors can mean outdated capability.
  2. 2When was the last check-in?A stale timestamp during an investigation may mean the sensor was disabled or evaded.
  3. 3Which Host Group?The global settings page can hide different configurations.
  4. 4Which Sensor Policy is applied?A policy mismatch is a common reason something was only logged.
When a detection looks softer than expected or prevention did not block, these four checks come first.
HACKTHESOCLesson 12CrowdStrike Falcon9 / 84

Host Groups and policies are not one size fits all

The setup

Hosts sit in Host Groups, each assigned Sensor and Prevention policies that decide which features are active and at what sensitivity.

The triage habit

When a detection is softer than expected, or prevention should have blocked and did not, ask which Host Group the machine is in and what policy applies.

A domain controller and a marketing laptop should almost never share one policy. The global-looking settings page can hide very different configs.

Detection vs Incident: read the tree

Confusing the two is the fastest way to under-triage a serious attack.

HACKTHESOCLesson 12CrowdStrike Falcon11 / 84

One event, or one attack chain

Detection

One suspicious event, such as LSASS memory access or an encoded PowerShell launch. Has its own severity, ATT&CK tags, confidence and process tree.

Incident

Related Detections grouped by shared lineage, hosts, timing and indicators. One view of the full chain, one combined severity: the worst thing anywhere in it.

A phishing-to-lateral-movement attack can produce four or more Detections. Reviewed separately, three might get closed as low severity without anyone seeing the whole.
HACKTHESOCLesson 12CrowdStrike Falcon12 / 84

Detection versus Incident

DetectionIncident
ScopeOne suspicious eventA group of related Detections
CarriesIts own severity, tags and treeOne combined severity for the chain
Risk of misreadingClosing a serious one as lowTrusting the grouping as a verdict
A real attack generates several Detections. Reviewing each in isolation risks closing three of four without seeing they are one chain.
HACKTHESOCLesson 12CrowdStrike Falcon13 / 84

How two Detections become one Incident

  1. 1WINWORD.EXE opens Q3_Invoice.docmThe initial access point.
  2. 2powershell.exe -EncodedCommandDetection 1: suspicious Office child process.
  3. 3rundll32.exe loads comsvcs.dllAgainst lsass.exe. Detection 2: Credential Access, LSASS Memory.
  4. 4Cloud correlation engineGroups both into one Incident with combined severity and full tree.
Triage order: start from the earliest event in the tree and read forward. A Critical buried in a Medium chain still sets the urgency.
HACKTHESOCLesson 12CrowdStrike Falcon14 / 84

Read the tree from the earliest event

The method

Start at the earliest process in the tree, almost always initial access, and read forward, asking if each step is a plausible continuation of the last.

The urgency rule

A Critical Detection buried in an otherwise Medium chain still deserves the highest severity present: the chain is one attack, not four coincidences.

The shape of the tree carries meaning. A Word document spawning PowerShell is a shape normal editing never produces.
HACKTHESOCLesson 12CrowdStrike Falcon15 / 84

Working a detection in the console

Status, assignee and comments are part of the job, not admin.

  1. 1Assign it to yourselfBefore you start, so two analysts do not work the same chain.
  2. 2Set it to In progressCurrent consoles: New, In progress, Closed (Reopened if it comes back).
  3. 3Comment as you goWhat you checked, what you found, what you did: the record the next shift reads.
  4. 4Pivot to the hostInvestigation views show activity outside the tree: a second persistence, an odd logon.
  5. 5Contain if needed'Network contain' is a host action here, released later with 'Lift containment'.
Older consoles and the legacy detections API closed detections as True positive, False positive or Ignored, and those values still show up in exports and integrations.

IOA vs IOC: behavior over artifacts

Not marketing language: it changes how you read every detection.

HACKTHESOCLesson 12CrowdStrike Falcon20 / 84

Artifact matching vs behavior matching

A hash, IP or domain

IOC

Asks whether this exact artifact has been seen before. Goes blind the moment an attacker recompiles a tool or moves to new infrastructure.

Falcon's signature detections

IOA

Matches the behaviour a technique requires, such as an unexpected process requesting broad access to lsass.exe memory soon after an unusual parent spawned it, whichever binary does it.

Defeating an IOA means abandoning the technique, not just swapping the file.

This is why Falcon can catch custom or newly compiled tooling with no reputation anywhere. Your own behavioural rules are custom IOAs, covered later in the lesson.
HACKTHESOCLesson 12CrowdStrike Falcon21 / 84

IOC versus IOA

IOC (artifact)IOA (behavior)
AsksHas this exact hash or IP been seen?Is this the behavior a technique requires?
Defeated byRecompiling, or new infrastructureAbandoning the technique itself
Catches new toolingNo, it needs prior reputationYes, the behavior gives it away
Falcon bets on IOAs. The ATT&CK technique tag on a detection usually reflects an IOA match, not a hash.
HACKTHESOCLesson 12CrowdStrike Falcon22 / 84
GrantedAccess 0x1FFFFF against lsass.exe is the access pattern credential theft requires.

That is PROCESS_ALL_ACCESS, usually tagged T1003.001. Falcon is not claiming to know the tool, only that the behavior is suspicious.

A clean or unknown hash with a suspicious access pattern is not reassurance. It is often what a competent, freshly built attacker tool looks like.
HACKTHESOCLesson 12CrowdStrike Falcon23 / 84

Reading an LSASS-access detection

What Falcon asserts

GrantedAccess 0x1FFFFF (PROCESS_ALL_ACCESS) against lsass.exe is the access pattern credential theft requires, whichever binary requests it (T1003.001).

Why the hash is quiet

A clean or unknown hash with a suspicious access pattern is often exactly what a freshly built tool looks like, because it has no reputation yet.

Resist dismissing an IOA detection because nothing came back on the hash. The behavior is the signal, not the file.
HACKTHESOCLesson 12CrowdStrike Falcon24 / 84

Why a clean hash is not reassurance

  1. 1Check the behavior firstAn IOA fired on what the process did, not on what it is. Read the access pattern and the parent.
  2. 2Weigh the lineageAn unusual parent spawning a process that opens lsass.exe is the shape, regardless of the file.
  3. 3Decide on the patternModerate confidence plus a genuinely suspicious pattern is a lead, not a false alarm.
A clean or unknown hash paired with a suspicious access pattern is not reassurance; it is often what a competent, freshly built tool looks like.

A remote shell over the sensor's existing encrypted channel. No VPN, no RDP.

RTR tiers: read, respond, administer

Read-only

ps, netstat, ls, reg query, filehash: informational commands that change nothing on the host.

Active responder

get and memdump to collect evidence, kill and rm for narrow containment of a process or dropped file.

Administrator

put, run, runscript: the ability to push and execute code on production endpoints.

The tiers exist because RTR can do real damage if misused, or if an attacker gained access to an analyst's own Falcon account.

A real RTR session on a contained host

WKS-FIN-014, after network containment. Output trimmed to the lines that matter.

HACKTHESOCLesson 12CrowdStrike Falcon29 / 84

Shared libraries and an audit log for every session

  • Custom-script libraryPowerShell, bash and zsh scripts uploaded once, each shared privately, to a group, or to everyone with the right RTR role.
  • Put files libraryTools such as a collector or cleanup binary, pushed to a host with put.
  • At scaleThe same scripts run through the API across many hosts: one remediation, dozens of machines.
  • RTR audit logAnalyst, host, start and end time, every command. Read it before touching a host someone else worked.
Sharing permissions are how a team keeps a vetted triage script available to everyone while a destructive cleanup script stays with its author. The log protects the organization and protects you when a command has a side effect.
HACKTHESOCLesson 12CrowdStrike Falcon30 / 84

RTR is not network containment

RTR alone

Kill and rm stop what you can see. They do nothing about persistence you have not found, or an attacker who simply relaunches.

Network Containment first

Isolates the host but keeps the CrowdStrike cloud channel alive, so RTR still works on the contained host.

In a serious incident: contain first to stop the bleeding, then investigate with RTR.

Leaving a live host connected while you poke around inside it is the mistake this sequence avoids.
HACKTHESOCLesson 12CrowdStrike Falcon31 / 84

Contain first, then investigate with RTR

  1. 1Network containIsolate the host from the network while keeping its channel to CrowdStrike's cloud alive.
  2. 2Then open RTRYou can still run RTR against the contained host, now cut off from the attacker's infrastructure.
  3. 3Collect and remediateInvestigate, pull evidence, and only then kill, delete or run remediation.
RTR alone is not containment: killing a process does nothing about persistence you have not found, or an attacker who simply relaunches.

Section 5 of 13

Prevention policies: detect-only is not protection

The setting that decides whether Falcon is allowed to stop anything.

HACKTHESOCLesson 12CrowdStrike Falcon33 / 84

What happens after Falcon scores a process malicious

  1. 1Check the Host Group's modeThe Prevention Policy decides Detect-only or Prevent.
  2. 2Detect-onlyDetection logged, process runs to completion. A perfect record, too late.
  3. 3Prevent, above thresholdProcess blocked automatically before impact.
  4. 4Prevent, below thresholdDetection logged for analyst review only.
Detect-only and Prevent produce the same Detections at the same severity. The console gives no loud signal that protection was absent.
HACKTHESOCLesson 12CrowdStrike Falcon34 / 84

Prevent versus Detect-only

ModeWhat the sensor doesConsequence
PreventBlocks the scored process automaticallyThe malicious process never completes
Detect-onlySame scoring, same card, no blockThe malicious process runs to completion
The scoring is identical; only the response differs. Detect-only is one of the most common and most dangerous gaps a SOC inherits.
HACKTHESOCLesson 12CrowdStrike Falcon35 / 84

Legitimate mode, dangerous default

Why it exists

A calibration period before trusting automatic blocking, or fragile legacy environments where a false block is judged worse than the residual risk.

Why it becomes dangerous

Left on by oversight while everyone assumes 'EDR deployed' means 'protected'. Ransomware can encrypt while Falcon logs every step.

ML sensitivity in Prevent: Cautious, Moderate, Aggressive, Extra Aggressive. Different Host Groups, different settings.

When an attack you expected Falcon to stop completed, check the Prevention Policy before questioning the engine. Full ATT&CK mapping says Falcon understood; not that it was allowed to act.
HACKTHESOCLesson 12CrowdStrike Falcon36 / 84
A policy mismatch is the usual reason something you expected to be blocked was only ever logged.

When prevention should have fired and did not, check which Host Group the host is in and whether its policy is Prevent or Detect-only before anything else.

The console's global-looking settings can hide a Detect-only group. Make the policy check a reflex on any prevention gap.

Hunting in Falcon: Event Search

A detection is Falcon's opinion. Raw events are the ground truth.

HACKTHESOCLesson 12CrowdStrike Falcon38 / 84
A detection is Falcon's opinion. The raw events are the record you check it against.

Event Search (Advanced Event Search, LogScale query language) queries everything the sensor streams: hunt where no rule exists, count one host or forty.

Detections are a small slice of what the sensor sends. Every managed host streams raw events whether or not anything fires.
HACKTHESOCLesson 12CrowdStrike Falcon39 / 84

Build a hunt query stage by stage

  1. 1Scope the event typeFilter on event_simpleName, e.g. ProcessRollup2, and include SyntheticProcessRollup2 for already-running processes.
  2. 2Narrow the fieldsKeep only the few columns triage needs, not the entire raw event.
  3. 3Aggregate, then sort raregroupBy with count, sorted by host count ascending, floats the rare values to the top.
A detection is Falcon's opinion; the raw events are the record you check it against, hunt in when no rule exists, and count with.
HACKTHESOCLesson 12CrowdStrike Falcon40 / 84

HACKTHESOCLesson 12CrowdStrike Falcon41 / 84

How Falcon events join, and two pitfalls

The process IDs

In ProcessRollup2 the process is TargetProcessId and its parent is ParentProcessId. Later events it causes carry the same value as ContextProcessId.

The join

Which process made this connection? NetworkConnectIP4.ContextProcessId to ProcessRollup2.TargetProcessId, always paired with aid: IDs are unique only per host.

The pitfalls

RawProcessId is the Windows PID, which Windows reuses: never join on it. A short window misses a process that started earlier, so widen the process side.

The same join answers which process made a DNS lookup or injected a thread, since those events also carry ContextProcessId.
HACKTHESOCLesson 12CrowdStrike Falcon42 / 84

Aggregate before you read: stack, then sort rare first

groupBy with count turns ten thousand launches into a short table; sorting by host count ascending puts the rare values, where an intruder usually sits, on top. A hunt that keeps paying off becomes a custom IOA or scheduled search.
HACKTHESOCLesson 12CrowdStrike Falcon43 / 84

Reading a rarity stack

Common, likely benign

The values seen on hundreds of hosts: normal software behaving normally. You scroll straight past these.

Rare, worth a look

The one or two hosts where a value appears once. Sorting by host count ascending floats them to the top, which is where an intruder usually sits.

At fleet scale you stack rather than scroll. Rarity, not raw volume, is the signal you are mining for.
HACKTHESOCLesson 12CrowdStrike Falcon44 / 84

Join: where did PowerShell connect to?

  • case {} maps both event types to one falconPID key (process launch, network event)
  • selfJoinFilter keeps only falconPID values present in BOTH event types: the intersection
  • So each output row is one PowerShell process that actually opened a connection
The case block gives both event types a common falconPID, and the join key is that ID plus aid. The result is one row per PowerShell process that made a connection.

Custom IOAs and indicator management

Moving from consumer of detections to author of them.

HACKTHESOCLesson 12CrowdStrike Falcon51 / 84

Two authoring tools, two targets

Behavior

Custom IOA rules

Rule sets scoped to host groups: alert or block when this process, from this path, does this. Durable across disposable files.

Artifacts

IOC management

Lists of hashes, IPs and domains, each with an action: detect, prevent/block or allow. Operationalises intel and tunes noise.

Custom IOAs codify a validated hunt or catch activity specific to your environment that no generic rule covers.
HACKTHESOCLesson 12CrowdStrike Falcon52 / 84

Custom IOA versus IOC management

ToolTargetsUse it to
Custom IOA ruleBehaviorCodify a validated hunt, or catch environment-specific activity
IOC managementArtifacts: hash, IP, domainBlock intel indicators, or allow a known-good noisy tool
Custom IOAs are durable across an attacker's disposable files; an IOC goes blind the moment they recompile or move infrastructure.
HACKTHESOCLesson 12CrowdStrike Falcon53 / 84

The tuning discipline both demand

Detect before prevent

A sloppy custom IOA floods the console or, set to block, breaks legitimate work. Test in detect mode first.

Allowlisting is a loaded gun

An allow IOC silences future detections on that indicator forever. Right for a confirmed false positive, dangerous if it later turns malicious.

Every allow entry is a deliberate, documented decision, not a reflex to make an alert go away.

Falcon is a platform you configure, not just alarms you answer.
HACKTHESOCLesson 12CrowdStrike Falcon54 / 84

Exclusions: tuning without turning off protection

Three types, each silencing a different layer.

HACKTHESOCLesson 12CrowdStrike Falcon60 / 84

Three exclusion types, three levels of risk

TypeWhat it silencesTypical useRisk
Machine LearningStatic ML verdicts for a path; optionally cloud uploadKnown-clean installer trips an ML verdictLow-to-moderate
IOABehavioral detections for one IOA patternLegit app behavior matches a built-in IOAModerate
Sensor VisibilityRecording, detection AND prevention for the pathExtreme, narrow cases onlyHigh: activity there is invisible

HACKTHESOCLesson 12CrowdStrike Falcon61 / 84

Sensor Visibility is the dangerous exclusion

ML and IOA: scoped

Machine Learning stops static verdicts for a path; IOA stops one behavioral pattern for a process. Narrow, and IOA cannot silence OverWatch or custom IOAs.

Sensor Visibility: broad

Minimizes what the sensor even records for a path and stops all detection and prevention. Attacker activity inside that path becomes invisible, not just unblocked.

The three are not interchangeable. The wrong one either fails to fix the noise or opens a hole far larger than the problem required.
HACKTHESOCLesson 12CrowdStrike Falcon62 / 84

One noisy backup agent, scoped three ways

Falcon Fusion SOAR

Automating the response that follows a well-understood detection.

HACKTHESOCLesson 12CrowdStrike Falcon66 / 84

Trigger, condition, action

Trigger

What starts it: a new detection matching criteria, a schedule, or a manual run.

Condition

If / else-if / else branching on severity, host criticality or tag.

Action

Enrich, notify, open a ticket via HTTP action, or take a Falcon response like Network Containment.

Steps can run sequentially or in parallel, and HTTP actions reach any external tool with an API.

Policy over what a device may connect to, physically and over the network.

Two modules that never raise a Detection card

Device Control

  • Read-only
  • Full read-write

Central host firewall rules instead of local Windows Filtering Platform config. Rules into rule groups, into policies, onto Host Groups.

Why these never raise a Detection card

The gap

Device Control and Firewall Management govern what a device connects to, not what a process does, so neither produces the kind of Detection the IOA engine would.

Where to look

Why was this outbound not blocked, or how did a file leave on USB with no Detection, sends you to these modules' own policy and audit pages.

Firewall rules evaluate in precedence order and the first match wins, so a broad allow above a narrow block silently defeats it.

Key takeaways

  1. 01A tiny kernel-mode sensor streams telemetry; scoring, correlation and MITRE mapping happen in the cloud.
  2. 02An Incident groups related Detections into one chain; assign it, read the tree from the earliest event, and comment as you go.

Sensor Visibility stops recording, detecting and preventing in the path, so the whole folder becomes a blind spot. An ML Exclusion scoped to the installer clears the ML verdict while everything else stays on. IOA Exclusions cover IOA patterns, not ML verdicts.
