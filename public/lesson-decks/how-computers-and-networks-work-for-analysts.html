Section 1 of 13

Hosts, IP addresses, and ports

Three ideas that make half of networking suddenly make sense.

HACKTHESOCLesson 02Computers and networks6 / 81

A host has an address and many numbered doors

Host

Any device that sends or receives data: laptop, server, printer, firewall, cloud VM. The thing you isolate, inspect and remediate.

The street address

IP address

Identifies the host so data knows where to go. IPv4 looks like 192.168.1.50. Every packet carries a source IP and a destination IP.

The apartment number

Port

0 to 65535. Keeps one host's many conversations apart. Services live on well-known ports by convention.

Source IP plus destination IP answers 'who was talking to whom', the backbone of almost every investigation.

In logs a host often appears both by name (FIN-PC7, DC01) and by address. 'Which host' is one of the first questions you answer.
HACKTHESOCLesson 02Computers and networks7 / 81

How one host keeps many conversations apart

A laptop runs a browser, an email client and file sharing at once. Ports keep each line separate.

  1. 1A service listens on a known portThe web server waits on 443, the file server on 445, by convention.
  2. 2The client picks a temporary portYour browser grabs a high source port, e.g. 51244, just for this one conversation.
  3. 3The four-tuple names the conversationSource IP, source port, destination IP, destination port: unique for this exchange.
  4. 4Replies come back to that portThe server answers to 51244, so the right program on the laptop gets the data.
This is why the low port in a log tells you the service and the high port tells you almost nothing: it is a temporary return address.
HACKTHESOCLesson 02Computers and networks8 / 81

A connection is a four-tuple; the dest port is your first hint

  • Firewall logs often name the four fields src, spt, dst, dpt
  • Always ask: what service normally lives on that destination port?
A workstation going out to 443 is ordinary browsing. The same workstation connecting to another workstation on 3389 is worth a second look. The number is not proof, but it is the first question, every time.
HACKTHESOCLesson 02Computers and networks9 / 81

Same laptop, two connections, two very different questions

Ordinary

Workstation out to 443

10.4.2.15 -> 93.184.216.34:443. A PC reaching a public web server over HTTPS: what every browser does all day.

Worth a second look

Workstation to PC on 3389

One user PC opening remote desktop to another user PC. Workstations rarely need to log into each other.

The port is not proof of anything. It is the first question you ask, every time.

Ask the class: which of these would you expect hundreds of times an hour? Which would you expect almost never? That gut sense is a baseline.

Public vs private IP, and NAT

Why the same laptop appears with two completely different addresses in two logs.

HACKTHESOCLesson 02Computers and networks11 / 81

Memorize the three RFC 1918 private ranges

RangeBlockTypical use
10.0.0.0 to 10.255.255.255/8A huge block, common in enterprises
172.16.0.0 to 172.31.255.255/12Note: only .16 to .31
192.168.0.0 to 192.168.255.255/16Common in homes and small networks
Anything else, e.g. 8.8.8.8PublicGlobally unique, routable across the internet: external
Private addresses are not unique in the world, like an internal office extension. Glancing at an address and calling it internal or external is a core reflex you use on every connection.
HACKTHESOCLesson 02Computers and networks12 / 81

Classify these at a glance: internal or external?

'Internal or external?' is a question you answer on every connection. Practise the reflex.

  • 10.4.2.15Internal: inside 10.0.0.0/8.
  • 172.20.1.9Internal: 172.20 is inside the .16 to .31 block.
  • 172.40.1.9External. The trap: 172.x is only private from .16 to .31.
  • 192.168.1.1Internal: millions of home routers use this exact address at the same time.
  • 185.220.101.4External: outside every RFC 1918 range, so ask about its reputation.
The 172 range is where students slip. Drill it until 172.40 sounds wrong instantly.
HACKTHESOCLesson 02Computers and networks13 / 81

How NAT works, one packet at a time

Network Address Translation lets a thousand private hosts share a handful of public IPs.

  1. 1Laptop sends from its private IP10.4.2.15 opens a connection to a website on the internet.
  2. 2Firewall rewrites the sourceOn the way out, 10.4.2.15 becomes the shared public 203.0.113.7. The mapping is remembered.
  3. 3The server replies to the public IPThe website only ever sees 203.0.113.7. The 10.x address is invisible to it.
  4. 4Firewall translates backIt looks up the mapping and forwards the reply to 10.4.2.15.
The hotel switchboard: outside callers only see the hotel's one number; the switchboard remembers which room to ring.
HACKTHESOCLesson 02Computers and networks14 / 81

NAT gives one host two faces

Use the hotel switchboard analogy: every room has an internal extension, but outside calls all show the hotel's one public number, and the switchboard remembers which room to route the answer to.
HACKTHESOCLesson 02Computers and networks15 / 81

Trace a public IP back to a person through the NAT log

  • Nothing is wrong: you see the connection before and after translation
  • Find the firewall log that shows both src and xlatesrc at that time
  • Always ask: is this address pre-NAT or post-NAT?
If you forget NAT when correlating an external log with an internal one, you will never connect the public IP back to the real internal host.

TCP vs UDP and the life of a connection

Which transport an event used tells you a surprising amount about what happened.

HACKTHESOCLesson 02Computers and networks17 / 81

A phone call versus a postcard

PropertyTCPUDP
ConnectionConnection-oriented: three-way handshake firstConnectionless: no handshake
ReliabilityReliable and ordered; re-sends anything lostNo guarantee of delivery or order
AnalogyA phone callA postcard in the mail
Typical usesWeb, email, file sharing, remote desktop, databaseDNS, DHCP, streaming, VoIP, logging protocols
UDP trades reliability for speed and low overhead, which is also why some malware favors it for lightweight beaconing.
HACKTHESOCLesson 02Computers and networks18 / 81

What TCP flags in a log tell you

  • Only a completed handshake proves the two hosts really talked
  • UDP has no handshake, so there is no equivalent proof
Students do not need to memorise flags beyond these three patterns. The handshake gets a full section later.
HACKTHESOCLesson 02Computers and networks19 / 81

What the analyst infers from the transport

  • Full handshake + dataThe two hosts genuinely connected. A real two-way conversation took place.
  • Many SYN, no SYN-ACKThe classic signature of a port scan: knocking on doors, never completing a call.
  • Burst of RSTConnections are being refused or torn down.
  • A single UDP packetDoes not prove anyone was listening, so you weigh it differently.
  • Transport vs portDNS on UDP/53 is expected. DNS on TCP/53 with a large payload is worth a look.
Note the proto=tcp or proto=udp field every time. A burst of UDP to 53 may be normal DNS or tunneling; the transport does not decide, but it shapes the questions.
HACKTHESOCLesson 02Computers and networks20 / 81

Is this transport normal for this port?

ServiceExpected transportWorth a look when
DNS (53)UDP; TCP for big answers or zone transfersTCP/53 with a large payload, or bursts of UDP/53 from one host
DHCP (67/68), NTP (123)UDPSeen from a host that should not be serving them
Web (80/443), SMB (445)TCPThe traffic shape does not fit the service (see section 5)
RDP (3389), SSH (22), SMTP (25)TCPInitiated between hosts that never normally talk

The transport does not decide the verdict, but it shapes the questions you ask.

Some malware favours UDP for lightweight beaconing because it is cheap and stateless. A UDP burst to 53 may be normal DNS or tunnelling.

The network layers in plain language

Knowing the layer tells you what a log can and cannot tell you.

HACKTHESOCLesson 02Computers and networks22 / 81

Four practical layers: lower ones move the envelope

LayerWhat it handlesExamples
Link (layer 2)The physical local networkEthernet, Wi-Fi, MAC addresses
Internet (layer 3)IP addresses and routing between networksSource IP, destination IP
Transport (layer 4)TCP and UDP and the port numbersReliability, port (apartment-number) addressing
Application (layer 7)The actual services users recognizeHTTP, DNS, SMB, email
The memory hook: the lower layers move the envelope; the top layer is the letter inside.
HACKTHESOCLesson 02Computers and networks23 / 81

Same event, two depths

Firewall, NetFlow

Layer 3/4 view

Sees IPs, ports, protocol and byte counts. Host A talked to host B on 443 and moved 2 MB. Cannot see which page.

  • 10.4.2.15 -> 93.184.216.34 : 443, 2 MB out

Proxy, Zeek, DNS, EDR

Layer 7 view

Sees the domain, URL, DNS query name, SMB filename. EDR adds which process opened the connection.

  • 10.4.2.15 -> https://files.example.ru/upload

Thin alert? Ask which layer produced it and pivot to a source at the layer that holds the answer.

Firewall shows a suspicious 443 connection but no domain: pivot up to proxy or DNS. Only a DNS log: pivot down to flow data to learn how much moved. The layer is a map of which questions each source can answer.
HACKTHESOCLesson 02Computers and networks24 / 81

Which tool sees which layer, and what it cannot show you

SourceLayerSeesCannot show you
Firewall, NetFlow3/4IPs, ports, protocol, byte countsThe domain, URL or file involved
Web proxy7The domain and URL requestedTraffic that bypasses the proxy
DNS logs7The name a host asked forHow much data then moved
Zeek sensor7DNS names, TLS details, SMB filenamesWhat happened inside the host
EDR7 + hostWhich process opened the connectionHosts without the agent
Knowing the layer keeps you from demanding information a log physically cannot contain, and points you to the source that does.
HACKTHESOCLesson 02Computers and networks25 / 81

Pivoting between layers when an alert is thin

  1. 1Name the layer of the alertA firewall alert is layer 3/4; a DNS alert is layer 7.
  2. 2Name the missing answerWhere did it really go? Or: how much actually moved?
  3. 3Pivot up for WHEREFirewall shows 443 to a public IP: query the proxy or DNS logs for the domain.
  4. 4Pivot down for HOW MUCHDNS shows a suspicious name: query flow data for bytes and duration.
The layer is a map of which questions each data source can answer. Pivot by time window and source IP.

Section 5 of 13

Reading a connection log

Not admiring the fields: interrogating them.

HACKTHESOCLesson 02Computers and networks27 / 81

Attach a question to every field

  1. 1Destination portIs this port normal for this application and this host?
  2. 2Destination IPInternal (RFC 1918) or public? The two tell very different stories.
  3. 3Direction and bytesWhich way is data flowing, and does the volume make sense?
  4. 4ActionAllowed or denied? A denied connection still shows something tried.
  5. 5ProtocolDoes the transport fit the port?
  6. 6Widen outWho is the source, is this normal for that host, what else did it do?
Normal browsing pulls far more data IN than it sends OUT. A workstation sending hundreds of MB OUT to an unfamiliar IP is a classic exfiltration shape, even on 443.
HACKTHESOCLesson 02Computers and networks28 / 81

One line, read as questions

  • 443 looks like web, but ~480 MB OUT vs 2 KB IN is inverted
  • 185.220.101.4 is not RFC 1918: external. What is its reputation?
  • action=allow: data actually left a finance user's workstation
Individually each field is innocent; together they suggest exfiltration disguised as HTTPS. Verdict at least suspicious. Next: pivot to proxy or DNS and check what FIN-PC7 did in the 30 minutes before.

The browsing shape versus the exfiltration shape

Normal browsing

Small request out, large page in. A workstation pulls far more data IN than it sends OUT.

  • bytes_in much larger than bytes_out
  • Known, reputable destinations

Possible exfiltration

Hundreds of MB OUT to an unfamiliar external IP, even on 443. The direction is inverted.

  • bytes_out much larger than bytes_in
  • Unfamiliar or new destination
  • Large volume in one session

Next step on the suspicious shape: pivot to proxy or DNS for where it went, and to the 30 minutes before on that host.

Some legitimate jobs upload (backups, cloud sync). That is why destination and host context complete the picture, not bytes alone.
HACKTHESOCLesson 02Computers and networks31 / 81
No single field convicts. The combination, read with the right questions, produces the verdict.

Read every connection log as a set of questions whose combined answers tell you to close, dig, or escalate.

This is the whole job in miniature.

The server side sits on a stable low number (443, 22, 445). The client side is a high number like 51844.

The low port tells you the service; the high port is just this client's temporary return address.
HACKTHESOCLesson 02Computers and networks34 / 81

Server side versus client side of every connection

Stable, low

Server side

Sits on a well-known port: 443, 22, 445. This number tells you the service.

Temporary, high

Client side

A random ephemeral port like 51844, chosen for one conversation. It tells you almost nothing.

Reading spt=51244 dpt=443: the client is on the left, the HTTPS server on the right.

HACKTHESOCLesson 02Computers and networks36 / 81

Three more services, and the vocabulary the table assumes

  • IMAP / POP3143 / 110 (TLS 993 / 995): reading mail. Abuse looks like mailbox theft after an account compromise.
  • FTP20 to 21/TCP: legacy file transfer. Credentials in cleartext; a favourite for staging stolen data.
  • C2 (command and control)The attacker's remote channel to a compromised host, often hidden on 443 to blend in.
  • BeaconingThe compromised host checking in to its C2 on a schedule, like a heartbeat.
  • DGA (domain generation)Malware that computes throwaway domain names by algorithm, seen as floods of odd DNS lookups.
These terms recur in every network lesson. The C2 lesson goes deep; here students only need to recognise them.
HACKTHESOCLesson 02Computers and networks37 / 81

Two habits that make the port table pay off

Direction plus port

An internal host initiating to 445 on many internal hosts is lateral movement. The same host receiving on 445 is a file server doing its job.

Wrong port is a signal

Attackers run C2 on 443 to blend in, or move SSH to 2222 to dodge lazy rules. When behaviour does not match the port's hint, start digging.

A workstation outbound on 443 is the whole internet. The same workstation listening on 3389, reachable from outside, is a remote-desktop server you probably did not mean to expose.

Section 7 of 13

DNS, DHCP, and ARP: the quiet plumbing

Invisible until they break, or until an attacker turns them into a weapon.

HACKTHESOCLesson 02Computers and networks39 / 81

Three protocols behind every single connection

Port 53, the phone book

DNS

Turns names into IPs. Records intent even when the connection is encrypted, so it is the first place an investigation looks.

  • Tunnelling: stolen data hidden in query names
  • DGA: algorithm-made throwaway C2 domains
  • Beaconing: malware calling home on a timer

Ports 67 and 68

DHCP

Leases a host its IP for a time. An IP is not a permanent identity: check the lease before blaming a machine.

  • Confirm by lease, hostname or MAC

Layer 2, local LAN

ARP

Asks who on this LAN has an IP and maps it to a MAC. No authentication, so it is abused for ARP spoofing.

  • Classic man-in-the-middle on the segment

DHCP gave the address, DNS turned the name into an IP, ARP delivered the first packet to the right box.

Attackers abuse each for a different purpose: exfiltration, evasion, interception. Accusing the wrong device after skipping the DHCP check is one of the most common beginner mistakes.
HACKTHESOCLesson 02Computers and networks40 / 81

DNS records intent before any connection happens

  1. 1Something wants a nameA user, or malware, needs mail.company.com or a C2 domain.
  2. 2It asks DNS on port 53The query names exactly what it wants to reach.
  3. 3The resolver answers with an IPE.g. 93.184.216.34. Only now can the connection start.
  4. 4The DNS log keeps the nameEven if the connection that follows is encrypted, the intent is recorded.

This is why DNS is the first place an investigation looks.

DNS tunnelling hides stolen data in the subdomain of queries the attacker's server answers, slipping past firewalls that never block 53.

DHCP: the same IP can be two different laptops

DHCP (ports 67 and 68) leases an address for a time, e.g. 'you are 10.0.4.51 for eight hours'.

Laptop A holds the lease

02:00

10.0.4.51 beacons to a bad domain. This is the machine you want.

Lease reassigned

10:00

10.0.4.51 is now laptop B, which did nothing wrong.

Anchor the identity

The fix

Check the DHCP lease for that IP at that time, or anchor on hostname or MAC address.

Accusing the wrong device after skipping the lease check is one of the most common beginner mistakes. The worked example in section 9 shows the check.
HACKTHESOCLesson 02Computers and networks43 / 81

ARP: the last local hop, and how spoofing hijacks it

Across the LAN, delivery is by MAC address. ARP asks 'who has this IP? Tell me your MAC.'

  1. 1A host asks for the gateway'Who on this LAN has 10.0.4.1?'
  2. 2The real gateway answersWith its MAC address. Frames for the internet now go to it.
  3. 3No answer is authenticatedARP was designed for a trusting era: any host can reply.
  4. 4Spoofing: 'I am 10.0.4.1'A machine on the same segment claims the gateway's IP. Traffic flows through it first: man-in-the-middle.
ARP rarely reaches a SIEM. When an investigation involves one machine impersonating another on the local segment, ARP is the mechanism.

The TCP handshake and what a scan looks like

A real connection means all three packets happened. Scans abuse exactly that.

HACKTHESOCLesson 02Computers and networks45 / 81

A real connection completes; a SYN scan finishes nothing

SYN, SYN-ACK, ACK, then ESTABLISHED and data flows. Closing is a similar exchange using FIN packets. Students do not need sequence numbers.
HACKTHESOCLesson 02Computers and networks46 / 81

How a half-open SYN scan reads each port

Network Service Discovery, MITRE ATT&CK T1046.

  1. 1Attacker sends SYNTo one port, deliberately never planning to finish the handshake.
  2. 2SYN-ACK comes backPort is open. The scanner abandons the connection instead of sending ACK.
  3. 3RST comes backPort is closed.
  4. 4Nothing comes backPort is filtered by a firewall.

In logs: one source, many ports or hosts, a short burst, lots of SYNs and very few established connections.

A port scan is usually the first thing done after a foothold. When one internal host fans out like this, it is often the host the attacker already controls.
HACKTHESOCLesson 02Computers and networks47 / 81

A normal client versus a scanner, as the logs see them

Normal client

Opens a few connections to expected ports and completes them.

  • Few destinations
  • Expected services
  • Handshakes complete

Scanner

One source sprays SYNs across many ports or hosts in a short burst and finishes almost none.

  • Many ports or hosts
  • Short burst
  • Lots of SYN, few established
Count distinct destination ports per source per minute: that is the simplest scan detection, and students will build it in the SIEM lessons.
HACKTHESOCLesson 02Computers and networks48 / 81
When an internal host fans out like a scanner, look at that host first.

Scanning is usually the first thing done after a foothold. The host doing the knocking is often the one the attacker already controls.

Ties back to Network Service Discovery, T1046. The scan is reconnaissance; the question is how that host got compromised.

HACKTHESOCLesson 02Computers and networks56 / 81

Two maps of one stack: OSI and TCP/IP

What analysts use daily

TCP/IP: four layers

Link, Internet, Transport, Application. Simple, practical, enough for most investigations.

What vendors and exams use

OSI: seven layers

Splits Link into Physical (1) and Data Link (2), and Application into Session (5), Presentation (6) and Application (7).

'Layer 3' and 'layer 4' mean the same thing in both. 'Layer 7' is the top of both.

When a vendor says 'Layer 7 firewall', translate: it can read the application data, like a proxy, not just IPs and ports.

Encapsulation: each layer wraps the one above

Every header is metadata a downstream tool might inspect. A layer 3/4 firewall reads the IP and TCP headers but never unwraps down to the HTTP request inside them.

What OSI vocabulary tells you in practice

  • The PDU names the layerFrame = layer 2, packet = layer 3, segment or datagram = layer 4. Docs use these words precisely.
  • Layer 6 holds encryptionConceptually where TLS and character encoding sit, which is why payloads are opaque to lower layers.
  • Headers are metadataEach wrapper adds fields a downstream tool might inspect: MAC, IP, ports.
  • Depth sets visibilityA layer 3/4 firewall reads IP and TCP headers; a layer 7 proxy unwraps down to the request.
Students do not need to recite all seven. They need to hear 'layer N' and know which questions that tool can answer.

Subnetting, CIDR, and routing decisions

The slash number behind every routing decision on any network.

HACKTHESOCLesson 02Computers and networks60 / 81

How a subnet mask splits an IPv4 address

  1. 1An IPv4 address is 32 bitsFour numbers of 8 bits each, e.g. 10.4.2.15.
  2. 2The mask splits it in twoA network portion that names the subnet, and a host portion for one device.
  3. 3The slash counts network bits/24 = first 24 bits are network, same as mask 255.255.255.0.
  4. 4Host bits give the size8 host bits = 256 addresses, minus network and broadcast = 254 usable.
The fewer network bits, the bigger the block. That is why 10.0.0.0/8 is enormous and 192.168.0.0/16 is much smaller.
HACKTHESOCLesson 02Computers and networks61 / 81

The slash number counts the network bits

Two addresses are subtracted for network and broadcast. 10.4.2.0/24 is 10.4.2.1 to 10.4.2.254, likely one floor, VLAN or department. Traffic from it reaching 10.9.0.0/24 is a segmentation question: was it supposed to cross subnets at all?

The router always picks the most specific match

  • Longest prefix wins: a /32 beats a /24 when both apply
  • Default gateway: 'if you don't know a better path, ask this router'
  • VLANs keep finance and guest Wi-Fi apart even on one physical switch
Overlapping routes at different specificities are normal; longest-prefix matching is what resolves them.

Segmentation: the questions the routing table raises

VLANs separate on purpose

Finance and guest Wi-Fi can share one physical switch and still never route to each other directly.

Crossings are a question

A workstation subnet reaching a server or finance subnet it never normally touches is a segmentation finding.

Default gateway traffic

Anything matching no specific route goes to 0.0.0.0/0, usually the internet edge.

Longest prefix wins, so a /32 host route can quietly redirect one host's traffic. Overlapping routes are normal; know which one applies.

IPv6: the address space behind modern networks

IPv4's 4.3 billion addresses ran out. Recognize the successor on sight.

HACKTHESOCLesson 02Computers and networks66 / 81

Shortening an IPv6 address in two rules

128 bits, written as eight groups of four hexadecimal digits.

  1. 1Start from the full form2001:0db8:85a3:0000:0000:8a2e:0370:7334
  2. 2Drop leading zeros0db8 becomes db8, 0370 becomes 370.
  3. 3Collapse one zero run to ::0000:0000 becomes ::, giving 2001:db8:85a3::8a2e:370:7334.
  4. 4Only once per addressUsing :: twice would make the length ambiguous, so it is not allowed.
When correlating, normalise addresses to one form first: the same host can be written several ways.
HACKTHESOCLesson 02Computers and networks67 / 81

Read an IPv6 address and spot the special ones

128 bits, eight groups of four hex digits. The :: collapse can be used only once per address so it stays unambiguous.

What IPv6 changes for the analyst

  • Often no NATA host can have its own stable public address, which can make attribution easier.
  • Directly reachableA misconfigured host with a public IPv6 address may be exposed in a way its IPv4/NAT twin never was.
  • RFC 1918 blind spotMonitoring that only watches private IPv4 ranges can miss that segmentation mistake.
  • Dual-stackOne host logs both families. Check both before declaring an investigation complete.
An investigation that only checks IPv4 may miss an entire IPv6 conversation the same attacker used.

Attribution flips between IPv4 and IPv6

IPv4 behind NAT

Many hosts share one public IP. To attribute, you need the NAT log showing src and xlatesrc.

IPv6 end to end

A host often keeps its own public address. Attribution is easier, but the host may be directly reachable from the internet.

Dual-stack hosts produce both kinds of logs: check both address families before you call an investigation complete.

TLS: what actually makes HTTPS secure

'It's just encrypted, move on' is not enough when attackers hide inside it.

HACKTHESOCLesson 02Computers and networks71 / 81

The TLS handshake at a working level

  1. 1ClientHelloTLS versions and cipher suites offered, plus SNI: the hostname it wants.
  2. 2ServerHello + certificateServer picks version and cipher, then proves identity with a cert chained to a trusted CA.
  3. 3Key exchangeClient validates the chain; both derive a shared session key (Diffie-Hellman in TLS 1.3).
  4. 4Encrypted dataEverything after, the HTTP request, headers, cookies, is encrypted.
TLS 1.3 finishes in one round trip and encrypts more of the handshake than 1.2, which also means less is visible to a passive observer.
HACKTHESOCLesson 02Computers and networks72 / 81

What TLS hides, and what stays readable

Visible in the handshake

Sent before encryption starts, so sensors can log it without decrypting.

  • SNI: the hostname requested
  • Offered TLS versions and ciphers
  • Certificate (TLS 1.2)

Encrypted after it

Everything carried with the session key once the handshake ends.

  • The HTTP request and URL path
  • Headers and cookies
  • Certificate (TLS 1.3)
'It is just encrypted, move on' is wrong: the visible half is where the signal lives.
HACKTHESOCLesson 02Computers and networks73 / 81

What a sensor logs without decrypting anything

  • SNI reveals the destination hostname over an encrypted connection
  • Lookalike domain plus a 6-day-old cert: suspicious infrastructure
  • JA3 does not match this host's normal browser: non-browser TLS client
The certificate is visible in TLS 1.2; in 1.3 it is encrypted, though earlier handshake fields stay visible. Self-signed, newly issued or mismatched certs are strong signals on their own.
HACKTHESOCLesson 02Computers and networks74 / 81

How a JA3 fingerprint is made

  1. 1Take the ClientHello fieldsTLS version, offered cipher suites, extensions, elliptic curves.
  2. 2Keep them in sent orderConcatenate the values exactly as the client listed them.
  3. 3Hash with MD5One 32-character value, e.g. e7d705a3286e19ea42f587b344ee6865.
  4. 4CompareDoes it match this host's normal browser, or a Python, Go or known malware TLS stack?
Different applications build their ClientHello differently, so the hash separates 'looks like Chrome' from 'looks like a script', without decrypting anything.
HACKTHESOCLesson 02Computers and networks75 / 81

JA3 broke for browsers; JA4+ is the current standard

JA3

MD5 of ClientHello fields in order. Since Chrome 110 (early 2023) Chromium randomises extension order every connection, so one Chrome yields many JA3s.

  • Still stable for Python, Go and custom implants

JA4+

Sorts cipher and extension lists before hashing, so randomisation no longer changes it. Readable structured fingerprint. Supported in Suricata and Zeek.

  • JA4S server, JA4H HTTP, JA4X certificates

A JA3 allow/block list for browser traffic falls apart, and 'no JA3 match' proves nothing.

Many malware and C2 defaults never randomise, so JA3/JA3S remains useful against fixed-order or legacy TLS stacks.

Key takeaways

  1. 01A connection is a four-tuple; the destination port is your first hint about what the traffic should be.
  2. 02RFC 1918 means internal; NAT is why one laptop shows a private address inside and a public one outside.
  3. 03A full SYN / SYN-ACK / ACK proves a real session; many SYNs with few completions is a port scan.
  4. 04Firewalls and NetFlow see layer 3/4; proxies, DNS, Zeek and EDR see layer 7. Pivot to the layer you need.
  5. 05DNS records intent, and DHCP leases mean an IP is not an identity: confirm the host before you name it.
  6. 06TLS hides the payload, not the handshake: SNI, certificates and JA4+/JA3 still give signal.
