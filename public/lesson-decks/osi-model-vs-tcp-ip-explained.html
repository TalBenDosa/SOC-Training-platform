Why networking is built in layers

Divide the work so each layer handles one job and relies on the layer below.

HACKTHESOCLesson 88OSI vs TCP/IP6 / 48
You never think about the trucks; the trucks never read your letter.

Like the postal system, each layer wraps the data with what its job needs and hands it down. On the other side, each layer unwraps its part.

Use the letter, envelope, mailbag, truck chain. It maps directly onto encapsulation.
HACKTHESOCLesson 88OSI vs TCP/IP7 / 48

Encapsulation: each layer adds its own header

The data gets a new name at each layer on the way down.

  1. 1Transport: segmentTransport header added around the application data.
  2. 2Network: packetNetwork header with addressing added.
  3. 3Data link: frameLocal delivery header added.
  4. 4Physical: bitsSent as signals on the wire or radio.
On the receiving side each layer removes its header and passes the rest up.
HACKTHESOCLesson 88OSI vs TCP/IP8 / 48

Two big benefits of layering

Modularity

Each layer can change independently. Wi-Fi replaced Ethernet cables without rewriting the web.

Shared vocabulary

'A Layer 3 problem' or 'a Layer 7 attack' is understood precisely by engineers and analysts.

Two standard layer models exist, OSI and TCP/IP. The rest of the lesson covers both.
HACKTHESOCLesson 88OSI vs TCP/IP9 / 48

Where you will hear layer talk in a SOC

  • 'Layer 3/4 block'A firewall denied traffic by IP or port, without ever reading the application data.
  • 'Layer 7 attack'Something in the application content itself, like SQL injection in an HTTP request.
  • 'Layer 2 problem'A local issue with MAC addresses or switching, confined to one segment.
Students meet these phrases on day one. Grounding them in the model now means the alerts read as plain language later.

The seven layers of the OSI model

Open Systems Interconnection: ISO's conceptual reference model.

HACKTHESOCLesson 88OSI vs TCP/IP11 / 48

OSI from the bottom up

LayerJobExample
1 PhysicalRaw bits as signals: cables, radio, voltages, lightEthernet cabling, Wi-Fi radio
2 Data LinkBetween directly connected devices via MAC addresses, as framesEthernet switches, NIC MAC
3 NetworkAddressing and routing across networks; IP addresses live hereIP, routers
4 TransportEnd-to-end delivery between programs, reliability, portsTCP 443, UDP 53
5 SessionOpens, keeps alive and ends a conversation between two appsA login session held across requests
6 PresentationAgrees the data's format: encryption, compression, encodingTLS encrypts; UTF-8 vs ASCII text
7 ApplicationClosest to the user: applications and their protocolsHTTP, DNS, SMTP, SSH
Mnemonic for 1 to 7: Please Do Not Throw Sausage Pizza Away. Session = keep one logical conversation going; Presentation = make both ends agree on format before the app reads it. OSI is not what the internet runs on, but its layer numbers are used everywhere in security.
HACKTHESOCLesson 88OSI vs TCP/IP12 / 48
The lower layers move the data to the machine; the upper layers make it meaningful to the app.

Layers 1 to 3 get bits to the right host across networks. Layers 4 to 7 deliver them to the right program in a form it understands.

This split is the mental hinge of the model: 'getting there' versus 'making sense once there'. It explains why routers care about L3 and a WAF cares about L7.

MAC versus IP: two kinds of address

AddressLayerScope and example
MAC2Local segment only, never crosses a router: 00:11:22:aa:bb:cc
IP3Routable across networks, gets a packet host to host: 10.14.22.108
The single most common beginner confusion. MAC is the local hop, IP is the journey. Each router hop rewrites the MAC but keeps the IP.

Layer 4: TCP versus UDP, reliability versus speed

Two transport protocols sit at Layer 4, and which one a service uses shapes its whole traffic pattern.

Connection-oriented

TCP

Sets up a connection first with a three-way handshake (SYN, SYN-ACK, ACK), numbers every byte, acknowledges and retransmits what is lost, and delivers in order. Reliable but slower. HTTP, SSH, SMB, RDP, FTP control.

Connectionless

UDP

Just fires off independent datagrams: no handshake, no ordering, no retransmission. Fast and lightweight; if something matters, the application handles loss itself. DNS, DHCP, syslog, VoIP.

Reliable-and-ordered versus fast-and-fire-and-forget is the core trade-off; it also explains why a SYN flood is a TCP attack.

This distinction is assumed constantly in SOC work: a SYN flood abuses TCP's handshake, DNS tunneling rides UDP. Define it once here so the later investigation checklist makes sense.
HACKTHESOCLesson 88OSI vs TCP/IP15 / 48

The TCP three-way handshake, step by step

  1. 1SYNThe client asks to connect and proposes a starting sequence number.
  2. 2SYN-ACKThe server agrees, acknowledges the client, and sends its own sequence number.
  3. 3ACKThe client acknowledges the server. The connection is now established.
  4. 4Why it mattersA SYN flood sends step 1 endlessly and never finishes, exhausting the server's connection table.
UDP skips all of this: no handshake at all. Knowing the handshake is what makes a half-open SYN flood legible as a Layer 4 attack later.

Layer-by-layer reference: PDU, protocols, attacks

The table you should be able to rebuild from memory.

HACKTHESOCLesson 88OSI vs TCP/IP19 / 48

Function, PDU and protocols per layer

A PDU (Protocol Data Unit) is the data's name at a layer once that layer's header is added.

OSI layerPDUExample protocols
7 ApplicationDataHTTP, DNS, SMTP, SSH
6 PresentationDataTLS/SSL, JPEG/MIME encoding
5 SessionDataNetBIOS, RPC, PPTP
4 TransportSegment (TCP) / Datagram (UDP)TCP, UDP
3 NetworkPacketIP, ICMP
2 Data LinkFrameEthernet, Wi-Fi (802.11), ARP
1 PhysicalBitEthernet cabling, fibre, Wi-Fi radio
The PDU names are the vocabulary behind encapsulation: the same data, named by the layer you look at it from. Quick glosses: ICMP = ping and error messages (L3); RPC = remote procedure call; PPTP = an old VPN protocol (both L5).
HACKTHESOCLesson 88OSI vs TCP/IP20 / 48
The same data has a different name, and a different protocol speaking it, at each layer.

That is why one capture can be described seven ways: bits, frame, packet, segment, then the application's own words.

Bridge from the function table to the attack table: each layer's PDU and protocol is exactly what the matching attack forges or abuses.

One representative attack per layer

OSI layerExample attack
7 ApplicationSQL injection, XSS, phishing email content
6 PresentationTLS downgrade attack
5 SessionSession hijacking
4 TransportSYN flood, port scanning
3 NetworkIP spoofing
2 Data LinkARP spoofing / poisoning

L5 session hijacking = steal a valid session token to take over a live session; L6 TLS downgrade = force weaker, breakable crypto.

The attack's name almost always tells you which header is forged or which layer's process is exploited. XSS = injecting script into a page other users then load; phishing is social, not technical, but is carried in L7 content.
HACKTHESOCLesson 88OSI vs TCP/IP22 / 48

Each attack abuses its own layer's header or handshake

Layer 2

ARP spoofing

Forged ARP replies tie the attacker's MAC to another host's IP to intercept local traffic. Pure MAC, never leaves the segment.

Layer 3

IP spoofing

Forges the source IP in the packet header to hide origin or impersonate a trusted host.

Layer 4

SYN flood

Floods TCP connection requests without completing them, exhausting the target's capacity to track new connections.

This is the whole point of thinking in layers: the attack lines up with the layer it abuses.
HACKTHESOCLesson 88OSI vs TCP/IP23 / 48

Upper-layer attacks ride the session and the app

  • Session hijacking (L5)Steal a valid session token to take over a conversation already authenticated, no password needed.
  • TLS downgrade (L6)Force the two ends onto weaker, breakable encryption by stripping the stronger options.
  • SQL injection, XSS (L7)Smuggle commands or scripts inside the application data itself, where only an app-aware control sees them.
Lower-layer attacks forge a header; upper-layer attacks abuse state or content. Both line up with exactly one layer, the whole payoff of the model.
HACKTHESOCLesson 88OSI vs TCP/IP24 / 48

Decapsulation: one frame walking up the stack

  1. 1L1 to L2NIC receives bits, rebuilds a frame; checks destination MAC, strips header.
  2. 2L3Reads the IP header, confirms destination IP, strips it, hands up a segment.
  3. 3L4Reads TCP/UDP header; the destination port picks which application.
  4. 4L7The application reads the data as the HTTP request, DNS query or email it is.
Every header added on the way out is read once, for exactly its purpose, and removed on the way back up. The jump from L4 to L7 is expected: TCP/IP folds OSI's L5 and L6 into the application, as the next section shows.

The TCP/IP model and how it maps to OSI

Four layers, named after TCP and IP: what the internet actually runs on.

HACKTHESOCLesson 88OSI vs TCP/IP26 / 48

TCP/IP layers mapped onto OSI

TCP/IP layerOSI layer(s)Examples
Application5 Session + 6 Presentation + 7 ApplicationHTTP, DNS, SMTP, SSH, TLS
Transport4 TransportTCP, UDP (ports)
Internet3 NetworkIP, routing
Link (Network Access)1 Physical + 2 Data LinkEthernet, Wi-Fi, MAC
TCP/IP bundles OSI's top three into one Application layer and the bottom two into one Link layer.
HACKTHESOCLesson 88OSI vs TCP/IP27 / 48

What each TCP/IP layer is responsible for

  1. 1LinkMove a frame across one physical hop using MAC addresses: Ethernet, Wi-Fi.
  2. 2InternetRoute a packet host to host across networks using IP addresses.
  3. 3TransportDeliver to the right program with ports, reliably (TCP) or not (UDP).
  4. 4ApplicationEverything the program needs: the protocol, any encryption, the data itself.
Four responsibilities, same journey as the seven OSI layers. The Application layer here quietly does OSI's session, presentation and application jobs at once.
HACKTHESOCLesson 88OSI vs TCP/IP28 / 48

Reference model versus implemented reality

7 layers

OSI

A conceptual reference model for teaching, designing and troubleshooting. Won in the classroom as the clearer map.

4 layers

TCP/IP

The practical, implemented protocol suite the internet uses. Won in practice: deployed first, and it worked.

Speak in OSI layer numbers, but know the internet runs on TCP/IP.

'A Layer 7 firewall' uses OSI numbers to describe TCP/IP reality. Both models describe the same journey.

Analysts speak in OSI numbers but the traffic is TCP/IP. Both describe the same journey.

'A Layer 7 firewall' uses OSI's number to describe a TCP/IP Application-layer control. The number is the shared language.

Resolve the apparent contradiction head on: you will hear OSI layer numbers every day for a network that runs on TCP/IP.

Different tools see different depths

Firewall

Looks as deep as the IP and TCP headers: enough to allow or block by address and port, never unwrapping HTTP.

Web server log / WAF

Built to unwrap all the way to Layer 7 and record the request itself.

Neither is better. Each control is looking at a different envelope in the same stack.

This is why defence in depth places controls at multiple layers.

Why layered thinking matters to a SOC analyst

A mental map for every protocol, attack, control and log source.

HACKTHESOCLesson 88OSI vs TCP/IP36 / 48

Attacks and controls, placed by layer

Layer 3/4

IP-based attacks, port scanning, volumetric DDoS floods. Network firewalls allow or deny by IP and port.

Layer 7

SQL injection, XSS, application exploits, 'Layer 7 DDoS'. Needs a Layer 7 firewall / WAF to inspect HTTP content.

Defence in depth

Network firewall at 3/4, WAF at 7, encryption at 6, endpoint controls above. One layer's failure is caught at another.

Protocols snap onto the model: MAC and switches L2, IP and IP-filtering firewalls L3, TCP/UDP and port filtering L4, HTTP, DNS, SMTP, SSH, RDP at L7.

Two alerts, two layers, two sources

Layer 3/4

Connection blocked to port 445

An address-and-port fact. The firewall log answers it: who, to where, on which port.

Layer 7

An application-content fact. Only the web or WAF log, which unwraps to L7, can show it.

Placing the alert in the stack tells you which log to open before you open anything. Wrong layer, wrong source, wasted time.

A layered investigation checklist

Bottom-up, one layer-specific question at a time instead of guessing.

HACKTHESOCLesson 88OSI vs TCP/IP41 / 48

Questions to ask at each layer

  • Layer 1/2Is the link up? Does the device's MAC show on the switch? Matters when reachability is in doubt.
  • Layer 3Valid IP and route? A DHCP lease log answers this. Blocked or routed somewhere unexpected?
  • Layer 4Is the port open and listening? Blocked by port? TCP (HTTP/SSH/SMB/RDP/FTP control) or UDP (DHCP/DNS)?
  • Layer 7What did the application actually say: method, command, content. Where intent lives.
Layer 7 dominates SOC work: HTTP methods and codes, SMTP headers, SSH auth method, RDP logon type.
HACKTHESOCLesson 88OSI vs TCP/IP42 / 48

Same incident, a fact at each layer

Lower layers

These confirm the traffic could and did reach the server.

  • Link up, MAC on the switch
  • Valid IP and route
  • Port 443 open and allowed

Layer 7

This is where intent lives, and where most SOC findings actually are.

  • The HTTP request body
  • A malicious parameter
  • The method and status code
Walking up the stack turns 'something is wrong' into a specific, answerable question at the layer that owns it.
HACKTHESOCLesson 88OSI vs TCP/IP43 / 48

The checklist for any confusing event

  1. 1Place it in the stackPhysical connectivity, addressing, ports, or application content?
  2. 2Pick the right sourceFirewall log for Layer 3/4 questions; application or endpoint log for Layer 7.
  3. 3Ask the layer's questionA specific, layer-appropriate question rather than a vague one.

'Blocked connection' is a Layer 3/4 fact. 'SQL injection attempt' is a Layer 7 fact.

Knowing that difference instantly turns the diagram from quiz material into a working diagnostic habit.

Key takeaways

  1. 01Layers give each job its own place; encapsulation wraps data as segment, packet, frame, then bits.
  2. 02OSI's seven layers: Physical, Data Link (MAC), Network (IP), Transport (ports), Session, Presentation, Application.
  3. 03TCP/IP's four layers: Link (OSI 1-2), Internet (3), Transport (4), Application (5-7). The internet runs on it.
  4. 04Attacks line up with the layer they abuse: ARP spoofing L2, IP spoofing L3, SYN flood L4, SQL injection L7.
  5. 05Firewalls see Layer 3/4; WAFs and app logs see Layer 7. Defence in depth puts controls at several layers.
  6. 06Investigate bottom-up: place the event in the stack, pick the log that sees that layer, ask its question.

An analyst says a WAF is needed because a network firewall filtering only by IP and port cannot stop SQL injection. Using the layer model, why is this correct?

A port-based firewall decides at Layer 3/4, but the SQL injection payload is Layer 7 application data in the HTTP request, not an encoding issue, not in the TCP or IP header. Only a Layer 7 WAF parses it.
