A router is a regional sorting office: it reads only the postcode, looks up the outbound truck, and hands the letter over.

The postcode is the destination IP address and the list of trucks is the routing table. Everything in this lesson builds on that picture.

Open with the postal analogy. The router does not care who the letter is for, only which network the address belongs to.

What a router does and what the routing table holds

A Layer 3 device moves packets between IP networks by looking up the destination in its table.

HACKTHESOCLesson 103Routing: static and inter-VLAN6 / 54

Every packet gets the same six-step treatment

A router is like a sorting office: it reads the postcode, not the name.

  1. 1Receive the frameConfirm the destination MAC is the router's own.
  2. 2Strip the Layer 2 headerThe old frame is discarded; only the IP packet continues.
  3. 3Read the destination IPThe router looks only at the address, like a postcode.
  4. 4Find the best matching routeSearch the routing table for the best matching entry.
  5. 5Decrement the TTLAt zero, drop the packet and send ICMP time exceeded.
  6. 6Build a new frameNew Layer 2 frame to the next hop; MACs are rewritten each hop.

IP addresses stay the same end to end (ignoring NAT); MAC addresses change at every hop.

This rewriting is also why a router separates broadcast domains: a broadcast frame dies at the router interface. Come back to the MAC rewrite when we reach the default gateway.

            Administrative distance: lower means more trusted

            AD only matters when two different sources offer the exact same prefix and mask.

            Prefix length is decided first. AD and metric only choose among routes to the same prefix.

            A /25 learned from RIP (AD 120) beats a /16 static route (AD 1) for a destination inside the /25.

            The frequent misconception is that AD is compared before prefix length. When reading a table, ask: is the most specific route the one I intended, is its next hop reachable, and is a lower-AD source overriding a route I expected?

            Static routing with ip route

            A manual instruction: to reach this network, send traffic here.

            HACKTHESOCLesson 103Routing: static and inter-VLAN16 / 54

            Configuring and verifying a static route on R1

            R1 (10.0.0.1) and R2 (10.0.0.2) share 10.0.0.0/30. R2 has a LAN, 172.16.20.0/24, that R1 does not know.

            Show the syntax line first, then the one concrete command. The static route is installed only if its next hop is resolvable through an up connected route.
            HACKTHESOCLesson 103Routing: static and inter-VLAN17 / 54

            Three flavors of static route

            Names the neighbor IP

            Next-hop

            IOS does a recursive lookup to find which interface reaches the next hop, resolved from the connected route.

            • ip route 172.16.20.0 255.255.255.0 10.0.0.2

            Fine on point-to-point

            Exit-interface

            Names only the local interface. On Ethernet the router ARPs for every destination and relies on proxy ARP from the neighbor.

            • ip route 172.16.20.0 255.255.255.0 Serial0/0/0

            Names both

            Fully specified

            Names the interface and the next hop. A safe form on Ethernet, along with the plain next-hop route.

            • ip route 172.16.20.0 255.255.255.0 GigabitEthernet0/1 10.0.0.2
            The Ethernet exit-interface pitfall works sometimes, bloats the ARP table, and breaks when proxy ARP is off. On serial links or tunnels an exit interface alone is fine.
            HACKTHESOCLesson 103Routing: static and inter-VLAN18 / 54
            Routing is a two-way street: R1 reaching R2's LAN is only half the job.

            If R2 has no return route, the echo request arrives, the reply is dropped or goes elsewhere, and the ping fails even though the forward path is perfect.

            This is the pitfall that costs the most hours. Always check both directions, and remember we will meet it again in the final troubleshooting scenario.
            HACKTHESOCLesson 103Routing: static and inter-VLAN19 / 54

            Static route pitfalls, and when static is the right tool

            • Wrong maskA /24 route where the real network is /23 leaves half the hosts unreachable.
            • Mistyped next hopA next hop not on a connected subnet means the route never installs.
            • Unsaved configurationForgetting copy running-config startup-config.
            • Asymmetric routingRequest and reply take different paths. Legitimate, but stateful firewalls see only half the conversation.
            • The right toolStubs with one way out, small stable topologies, ISP defaults, deliberate overrides.

            Static is the wrong tool where topology changes often: nobody updates the routes when a link fails.

            If the interface goes down the static route is withdrawn automatically. That behavior is what makes floating statics possible in the next section.

            Default routes and floating static routes

            The route of last resort, and a backup route that waits out of sight.

            HACKTHESOCLesson 103Routing: static and inter-VLAN21 / 54

            A default route is the route of last resort

            ip route 0.0.0.0 0.0.0.0 203.0.113.1: if you do not know where it goes, give it to the ISP.

            S* in the table

            Default route present

            show ip route prints Gateway of last resort is 203.0.113.1 to network 0.0.0.0. Unknown destinations go to the ISP.

              Unknown means dropped

              Gateway of last resort not set

              Any destination missing from the table is dropped. Internal networks work but the internet does not, or traceroute dies at the first router.

                A stub site with one uplink needs only a default route; the upstream router needs specific routes back.

                Missing default routes are among the most common causes of lost connectivity at branch sites. The return-path rule applies here too.
                HACKTHESOCLesson 103Routing: static and inter-VLAN22 / 54

                A floating static route is a backup with a worse AD

                R1 has a primary ISP link and a cheaper backup ISP link.

                • The primary carries the default AD of 1
                • AD 250 keeps the backup out of the table
                • Same prefix, lower AD wins: only the primary is installed
                The word floating comes from the route hovering above the table until it is needed. The empty output of the include command is the proof it is waiting.
                HACKTHESOCLesson 103Routing: static and inter-VLAN23 / 54

                How the backup takes over and hands back

                1. 1Primary is upThe primary default (AD 1) is installed; the AD 250 backup stays out of the table.
                2. 2Primary interface goes downIts connected route disappears, so the primary static is withdrawn.
                3. 3Backup is promotedThe AD 250 route enters the table and traffic uses the second ISP.
                4. 4Primary returnsThe better route preempts the backup again.
                Everything here depends on the primary next hop becoming unresolvable. Keep that in mind for the limit on the next slide.
                HACKTHESOCLesson 103Routing: static and inter-VLAN24 / 54

                Two traps with floating statics

                Above all that should win

                Pick the backup AD carefully

                Higher than the primary and higher than any dynamic protocol that should win, for example above 110 if OSPF should win. The same AD of 1 installs both routes and load balances.

                  The ISP can fail silently

                  It reacts to local state only

                  If the primary link stays up/up but the ISP beyond it fails, the primary route stays in the table and traffic black holes.

                    The remedy: tie the primary route to an IP SLA probe with the track keyword, so it is withdrawn when a remote target stops answering.

                    A common example of the second trap is an Ethernet handoff to a provider modem. The interface is fine, the service is not.

                    Inter-VLAN routing: the problem and three solutions

                    Each VLAN is its own subnet, so crossing between them needs a Layer 3 hop.

                    HACKTHESOCLesson 103Routing: static and inter-VLAN26 / 54

                    Three ways to route between VLANs

                    A Layer 2 switch never forwards between VLANs, so a router function is needed somewhere.

                    MethodWhere routing happensStrengthsWeaknesses
                    Router-on-a-stickOne router, one trunk, a subinterface per VLANCheap, basic router, simple to readSingle trunk is a bottleneck and single point of failure
                    Layer 3 switch with SVIsThe switch, one SVI per VLANWire-speed forwarding, no external link, usual campus designNeeds a multilayer switch and ip routing enabled
                    Routed portPhysical switch port set to no switchportClean point-to-point L3 link to a router or L3 switchNo VLANs, only one subnet per port

                    The legacy method of one physical router interface per VLAN does not scale and is not used now.

                    Example subnets: VLAN 10 is 192.168.10.0/24 and VLAN 20 is 192.168.20.0/24. All inter-VLAN traffic in router-on-a-stick hairpins through the single trunk.
                    HACKTHESOCLesson 103Routing: static and inter-VLAN27 / 54

                    Router-on-a-stick: one trunk, many subinterfaces

                    802.1Q trunk

                    Switch side

                    One physical link is configured as a trunk toward the router.

                    • Allowed VLANs 10, 20 and 99
                    • Native VLAN 99

                    Logical subinterfaces

                    Router side

                    The physical interface is split into subinterfaces. Each is tied to one VLAN tag and holds that VLAN's default gateway address.

                    • Gi0/0.10 for VLAN 10
                    • Gi0/0.20 for VLAN 20
                    • Gi0/0.99 for native VLAN 99
                    The VLAN's hosts point their default gateway at the subinterface address. The physical interface itself carries no IP address.
                    HACKTHESOCLesson 103Routing: static and inter-VLAN28 / 54

                    Router-on-a-stick configuration, router and switch

                    • The tag in encapsulation dot1q tells the subinterface which VLAN it serves
                    • Each subinterface address is that VLAN's default gateway
                    • Allowed list and native VLAN on the switch must agree with the router
                    Trimmed for the slide: description and exit lines are omitted. Some switches also need switchport trunk encapsulation dot1q first, but omit it if the switch rejects it.
                    HACKTHESOCLesson 103Routing: static and inter-VLAN29 / 54

                    Router-on-a-stick: the classic mistakes

                    • IP on the physical interfaceThe gateway addresses belong on the subinterfaces.
                    • Physical port left shut downWithout no shutdown on it, every subinterface stays down.
                    • Wrong tag in the commandThe subinterface number is a label; the tag in encapsulation dot1q is what counts.
                    • VLAN missing from allowed listTagged frames for that VLAN never reach the router.
                    • Native VLAN mismatchThe two ends of the trunk disagree about the native VLAN.
                    The quiz question on VLAN 20 failing while VLAN 10 works is the fourth mistake. VLAN 10 still working proves the router interface itself is fine.

                    Layer 3 switches: SVIs and routed ports

                    Routing inside the switch at wire speed, with a routed link up to the edge.

                    HACKTHESOCLesson 103Routing: static and inter-VLAN31 / 54

                    SVIs: the switch holds a gateway for every VLAN

                    Each SVI address is the default gateway for the hosts in that VLAN.

                    • Global ip routing: many Catalyst switches ship with it disabled
                    • Each SVI address is the gateway for its VLAN
                    • Without ip routing, show ip route says: IP routing not enabled
                    Forgetting ip routing is the classic pitfall. The SVIs can hold addresses and even show up/up, so hosts can ping their own gateway, yet the switch will not forward between them.
                    HACKTHESOCLesson 103Routing: static and inter-VLAN32 / 54

                    An SVI is up/up only when three things hold

                    1. 1The VLAN existsIt must be in the VLAN database.
                    2. 2An active port carries the VLANAt least one access port in the VLAN is up, or a trunk allowing it is up.
                    3. 3The SVI is not shut downno shutdown has been issued on the interface.

                    Up/down usually means no active port or a VLAN never created. Administratively down means a forgotten no shutdown.

                    Use this as a checklist when an SVI refuses to come up. The two failure states point to different fixes, so read the status column carefully.
                    HACKTHESOCLesson 103Routing: static and inter-VLAN33 / 54

                    A routed port gives a clean Layer 3 uplink

                    no switchport turns a physical port into a router-style interface: no VLAN, one IP address.

                    • The routed port carries no VLAN and holds a single address
                    • The default route points up the routed link
                    • Each addressed, up/up SVI creates a C route automatically
                    Those C routes are the networks the switch can route between with no static routes needed. Verify with show ip interface brief first.
                    HACKTHESOCLesson 103Routing: static and inter-VLAN34 / 54

                    The standard campus design

                    Face the user VLANs

                    SVIs

                    Traffic between VLANs is routed inside the switch at wire speed and never leaves through a cable.

                      Faces the edge

                      Routed port

                      A point-to-point link to the edge router or firewall, with no VLAN or SVI created just for the uplink.

                        Points up the link

                        Default route

                        A static default sends everything else to the upstream device, here 10.255.0.1.

                          A routed uplink also keeps spanning tree loops out of the uplink.

                          This is the design you will see most often on a campus. It is also the topology of the troubleshooting scenario at the end of the lesson.

                          The default gateway and DHCP relay

                          How a host decides to leave its subnet, and why broadcasts need help to cross.

                          HACKTHESOCLesson 103Routing: static and inter-VLAN36 / 54

                          How a host decides to leave its subnet

                          The default gateway is an address on the host's own subnet that belongs to a router interface, subinterface or SVI.

                          1. 1AND with the maskBitwise AND of its own IP and mask with the destination address.
                          2. 2Compare to own networkIf the result matches its own network, the destination is local.
                          3. 3Local: ARP for the destinationThe frame goes directly to the destination's MAC.
                          4. 4Remote: ARP for the gatewayThe frame goes to the gateway's MAC; the destination IP is unchanged.
                          The host makes one decision per packet. The gateway is its only exit door, so a wrong gateway or mask breaks everything beyond the subnet.
                          HACKTHESOCLesson 103Routing: static and inter-VLAN37 / 54

                          PC1 to PC2: IPs stay, MACs change at each routed hop

                          PC1 (192.168.10.50/24) pings PC2 (192.168.20.60/24) through an SVI switch.

                          HopSource and dest IPSource MACDest MAC
                          PC1 to switch192.168.10.50 to 192.168.20.60PC1SVI Vlan10
                          Switch to PC2192.168.10.50 to 192.168.20.60SVI Vlan20PC2

                          A packet capture on PC1 shows the gateway's MAC, not PC2's.

                          This is exactly the rewriting from section 1. The IP addresses never change, only the MACs do.
                          HACKTHESOCLesson 103Routing: static and inter-VLAN38 / 54

                          Common host-side faults

                          • No gateway configuredLocal traffic works, everything else fails.
                          • Wrong gateway addressOutside the host's subnet, on the wrong interface, or an address no device owns.
                          • Wrong host maskThe host thinks a remote host is local, ARPs for it and never reaches the gateway.
                          • Ping the gateway firstGateway works but nothing beyond: look past it. Gateway fails: check VLAN membership, cable, gateway address.
                          On a Windows host, ipconfig shows the address, mask and default gateway. Those three values are the first thing to read.
                          HACKTHESOCLesson 103Routing: static and inter-VLAN39 / 54

                          DHCP relay: ip helper-address on the client-facing SVI

                          A client with no address sends a DHCP Discover to 255.255.255.255, and a router will not forward that broadcast.

                          • Put it on the client-facing SVI or subinterface, never on the server side
                          • Discover becomes unicast; the SVI address goes in giaddr so the server picks a scope
                          • It also relays TFTP, DNS and NetBIOS broadcasts by default unless filtered
                          Pitfalls: the wrong interface, a server with no route back to the relay subnet, no scope on the server for the giaddr subnet, and a typo in the helper address. How the DHCP exchange works is in the DHCP lesson.

                          Static versus dynamic routing

                          What changes when the network grows, and how both feed the same table.

                          HACKTHESOCLesson 103Routing: static and inter-VLAN41 / 54

                          Static does what it was told; dynamic heals itself

                          Predictable, no overhead

                          Static routing

                          Costs no CPU or bandwidth. If the next-hop link fails but the interface stays up, the route stays and traffic is lost.

                          • Invisible to attackers who cannot listen
                          • A new LAN means touching every router

                          Reconverges automatically

                          Dynamic routing

                          Routers exchange the networks they know and each builds its own table. After a failure they recompute without human action.

                          • Costs CPU, memory, bandwidth, complexity
                          • False routes possible without authentication
                          Everything so far was configured by hand. That is manageable with two or three routers but becomes a liability as the network grows.
                          HACKTHESOCLesson 103Routing: static and inter-VLAN42 / 54

                          Static versus dynamic at a glance

                          FeatureStaticDynamic
                          Configuration effortHigh on large networksLow once the protocol is running
                          Reaction to failureNone, unless tracked or floatingAutomatic reconvergence
                          Resource useMinimalCPU, memory, bandwidth
                          PredictabilityTotalDepends on protocol and topology
                          Best forStubs, small sites, defaults, overridesLarger or redundant networks
                          Ask: how many routers need this route, how often does topology change, and what should happen automatically when a link fails? If it should heal itself, choose a dynamic protocol.
                          HACKTHESOCLesson 103Routing: static and inter-VLAN43 / 54

                          Protocol families all fill the same routing table

                          • RIPDistance vector, simple, hop count, AD 120.
                          • EIGRPCisco's advanced distance vector, AD 90.
                          • OSPFLink state, open standard, AD 110.
                          • BGPAn exterior protocol that runs between organizations.
                          • Same rules for allLongest-prefix match first, then administrative distance, then metric.

                          RIP, EIGRP and OSPF are interior gateway protocols: they run inside one organization.

                          How OSPF and EIGRP form neighbors and compute paths is the subject of the next lesson. For now a protocol is just another source filling the table you already know how to read.
                          HACKTHESOCLesson 103Routing: static and inter-VLAN44 / 54
                          A common pattern: OSPF inside the campus, plus a static default route at the edge that is redistributed into the protocol.

                          A floating static can also sit behind a dynamic protocol as a last resort, if its AD is higher than the protocol's, for example 130 behind OSPF's 110.

                          Static and dynamic are frequently combined. Every router learns the way out through the redistributed default.

                          A new floor, a Layer 3 switch, and two faults that hide behind each other.

                          HACKTHESOCLesson 103Routing: static and inter-VLAN46 / 54

                          Step 1 and 2: start at the host, then check the gateway

                          PC2 (192.168.20.60, gateway .1) cannot ping PC1 (192.168.10.50). Both sit behind Layer 3 switch SW1.

                          • PC2 cannot reach its own gateway: the fault is at or below the gateway
                          • Vlan20 is administratively down: the address was set but no shutdown was issued
                          Topology: SW1 has VLAN 10 and VLAN 20 with gateway .1 each, and a routed port 10.255.0.2/30 to edge router R1 (10.255.0.1), which also has the server network 10.50.0.0/24. The ipconfig output on PC2 is consistent, so we move on.
                          HACKTHESOCLesson 103Routing: static and inter-VLAN47 / 54

                          Two faults on SW1, two short fixes

                          The host settings check out, so the switch is the next place to look.

                          Vlan20 administratively down

                          Fault 1: SVI shut down

                          The address was configured but no shutdown never issued.

                          • interface vlan 20
                          • no shutdown

                          IP routing not enabled

                          Fault 2: routing disabled

                          show ip route answers IP routing not enabled, so SVIs cannot forward between VLANs even when both are up/up.

                          • ip routing in global configuration
                          • show ip route connected lists both SVIs

                          After both fixes PC2 can ping PC1 and its own gateway: the inter-VLAN path is repaired.

                          Stress that there were two faults, not one. Fixing the first alone would still leave the VLANs unable to talk.
                          HACKTHESOCLesson 103Routing: static and inter-VLAN48 / 54

                          Step 4: the return path on R1

                          VLAN 10 reaches server 10.50.0.10 but VLAN 20 does not. SW1 routes correctly, so check the return path.

                          • The source option uses the VLAN 20 SVI address, to test the VLAN 20 path
                          • R1 has a return route for VLAN 10 only
                          • The fix: a static route for 192.168.20.0/24 via the routed port
                          Echo requests from VLAN 20 arrive at the server, but the replies reach R1, which has no route for 192.168.20.0/24 and sends them out the default route to the ISP, where they are dropped. This is asymmetric reachability caused by a missing return route.

                          The repeatable troubleshooting method

                          1. 1Confirm host settingsAddress, mask and gateway must be consistent.
                          2. 2Ping the gatewayFails: look at the gateway. Works: look beyond it.
                          3. 3Check interface statusUse show ip interface brief.
                          4. 4Check tables in both directionsRouting table on every router in the path, forward and return.
                          5. 5Extended ping with a sourceTest from the right source address, such as a specific SVI.

                          Work from the host outward, change one thing at a time, and retest after every change.

                          Have students replay the scenario with this list: each step found one thing, in order. Changing one thing at a time is what keeps the diagnosis honest.

                          Key takeaways

                          1. 01A router matches the destination IP against its table; IP addresses stay end to end while MAC addresses are rewritten at every hop.
                          2. 02Selection order: longest prefix first, then administrative distance, then metric.
                          3. 03Static routes need a return route on the far router; a default route covers stubs; a floating static uses a higher AD as backup.
                          4. 04Inter-VLAN routing: router-on-a-stick, SVIs on a Layer 3 switch with ip routing, or routed ports using no switchport.
                          5. 05Hosts need a correct gateway; ip helper-address on the client-facing interface relays DHCP broadcasts.
                          6. 06Troubleshoot from the host outward: gateway ping, interface status, routing tables in both directions, one change at a time.

                          Check your understanding, question 1 of 3

                          A router holds a static route 10.1.0.0/16 via R2 (AD 1), an OSPF route 10.1.4.0/24 via R3 (AD 110) and a RIP route 10.1.4.128/25 via R4 (AD 120). Where is a packet for 10.1.4.200 sent?

                          Longest matching prefix is decided first, and 10.1.4.200 falls inside the /25, so R4 is used. AD only arbitrates between sources offering the exact same prefix, so the static route's low AD is irrelevant.
