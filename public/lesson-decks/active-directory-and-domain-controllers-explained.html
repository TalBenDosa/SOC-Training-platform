What Active Directory is

Microsoft's directory service: one database that knows every user, computer and resource.

HACKTHESOCLesson 68Active Directory and DCs6 / 50

Three jobs, held apart

A giant, secure company directory combined with a master key system.

Authentication

Proving who you are. When you log into your work laptop, AD verifies you.

Authorization

Deciding what you can do: which files, servers and apps, based on group memberships.

Directory

The single source of truth. Create, reset or disable one account and it takes effect everywhere.

The phone directory lists everyone; AD also controls the locks and checks identity at every door.

Centralisation is powerful in both directions.

One place to manage everyone is efficient for admins. For an attacker, that same place is the keys to the entire kingdom.

Control AD and you potentially control every account and every computer that trusts it.

Section 2 of 13

The Domain Controller: the server that runs AD

AD is the service and database; the DC is the machine that hosts and runs it.

HACKTHESOCLesson 68Active Directory and DCs9 / 50

What a DC does, minute to minute

  • Authenticates logonsHosts the Kerberos KDC (Key Distribution Center), which issues the tickets used for authentication.
  • Answers directory queries"What groups is this user in?" over the directory protocol LDAP.
  • Enforces policyDistributes Group Policy rules to users and machines.
  • Holds the databaseEvery DC stores a copy of the AD database in NTDS.dit.
  • Shares SYSVOLA network folder of Group Policy files every domain computer reads.
Organisations run more than one DC for reliability, and replication keeps their copies in sync.
HACKTHESOCLesson 68Active Directory and DCs10 / 50

Why the DC is the ultimate prize

NTDS.dit

Every object in the domain, and the password hashes of every account, administrators included.

DCSync, NTDS dumping

Read the file, or trick a DC into handing over its contents, and you hold the credentials to the whole organisation.

Tier 0

The most privileged, most protected asset class. Anything that runs code on a DC can rewrite the rules for everyone.

Compromise a Domain Controller is functionally the same as compromise the whole domain. Memorise that.

What a mid-size company's AD might look like

  • OUs matter: Group Policy is applied to them and admin control is delegated at them

Section 4 of 13

Users, groups, computers and SIDs

The records AD holds are called objects.

HACKTHESOCLesson 68Active Directory and DCs15 / 50

The objects that matter most

Users

A person's account: username, password hash, groups, attributes. Service accounts serve apps, often with strong privileges and rarely changed passwords.

Computers

Every domain-joined machine has a computer object and its own account to authenticate to the domain.

Groups

Grant permissions to many at once. Security groups assign permissions, distribution groups are email lists. Scopes: domain-local, global, universal.

Domain Admins, Enterprise Admins, Administrators, Schema Admins: any membership change (4728/4732) is a high-value event.

Rarely changed service-account passwords are the weakness behind Kerberoasting. Adding to Domain Admins is one of the first things an attacker does.
HACKTHESOCLesson 68Active Directory and DCs16 / 50

Reading a SID piece by piece

Golden Tickets forge SIDs and SID History abuse hides privilege in them. Recognising -500, -512, -519 tells you severity before you resolve the name.

FSMO roles: five jobs no two DCs share

Exceptions to multi-master replication: exactly one holder per scope.

HACKTHESOCLesson 68Active Directory and DCs19 / 50

The five Flexible Single Master Operations roles

RoleScopeWhat breaks without it
Schema MasterOne per forestNobody can extend or modify the AD schema
Domain Naming MasterOne per forestCannot add or remove a domain from the forest
RID MasterOne per domainDCs run out of RIDs, eventually no new security principals
PDC EmulatorOne per domainTime sync anomalies, password/lockout inconsistencies
Infrastructure MasterOne per domainCross-domain group membership references go stale
Every domain in a multi-domain forest has its own RID Master, PDC Emulator and Infrastructure Master.
HACKTHESOCLesson 68Active Directory and DCs20 / 50

Find the FSMO holders, and know the PDC Emulator

  • PDC Emulator: authoritative time source; processes password changes and lockouts first
  • A wrong PDC clock cascades into Kerberos failures domain-wide: tickets are time-sensitive
  • Seizing a role is emergency recovery; flag it outside a maintenance window
PDC Emulator and RID Master holders give outsized leverage, so they belong in Tier 0.

The Global Catalog searches every domain at once

A GC holds a partial, read-only replica of every object in every domain, on ports 3268 (plaintext) and 3269 (LDAPS). It powers UPN logon into child domains, address-book lookups, Universal Group expansion, and BloodHound forest recon.

Section 7 of 13

Sites, subnets and replication topology

Replication over a slow WAN should not behave like a fast local switch.

HACKTHESOCLesson 68Active Directory and DCs25 / 50

Intra-site versus inter-site replication

A site groups well-connected subnets; the KCC builds the topology on every DC.

Within a site

A tightly connected ring. Changes typically propagate within about 15 seconds of a notification.

Between sites

An elected ISTG designates bridgehead servers that replicate over site links on a schedule, e.g. every 3 hours.

Site links carry a cost (cheaper preferred) and a replication schedule. Clients log on to their local site's DC.

Sites mean a branch user authenticates against the branch DC instead of crossing a WAN link.
HACKTHESOCLesson 68Active Directory and DCs26 / 50

Normal topology is your baseline for DCSync

  • Replication uses RPC on 135 plus a high ephemeral range: expected, not alertable
  • DCSync makes an attacker machine impersonate a DC and request password data
  • A workstation issuing replication requests is not WAN traffic: it is DCSync
Know which hosts are really DCs and which sites and links exist, so replication-shaped traffic from anywhere else stands out.

LDAP, Kerberos, DNS, GPO and replication

Recognise each protocol and its port to read what a Windows network is doing.

HACKTHESOCLesson 68Active Directory and DCs28 / 50

The anatomy of the Windows network

  • LDAP: how you askQuery and update AD on 389 (636 encrypted). BloodHound uses it to map paths to Domain Admin.
  • Kerberos: how you prove yourselfPort 88. The KDC issues a TGT, then service tickets. NTLM is the older fallback.
  • DNS: how you find the DCsClients locate DCs via SRV records. Broken DNS means broken AD.
  • GPO: how rules are enforcedSettings applied to linked OUs, files pulled from SYSVOL. Edit a wide GPO, hit thousands of machines.
  • Replication: how DCs agreeMulti-master: a change on any DC flows to all. DCSync impersonates it.
Nearly every AD attack is an abuse of one of these normal mechanisms.

Group Policy order and SYSVOL/NETLOGON

Predictable GPO behaviour, and the shares that deliver it.

HACKTHESOCLesson 68Active Directory and DCs34 / 50

LSDOU: later settings win conflicts

  1. 1LocalGroup Policy stored on the machine itself.
  2. 2SiteGPOs linked to the machine's AD site.
  3. 3DomainGPOs linked at the domain level.
  4. 4OUOutermost OU down to the one directly containing the object. Applied last, so normally final.

Loopback overrides user GPOs for kiosk or lab machines: Merge mode adds, Replace mode ignores the user's normal GPOs.

An admin who can link a GPO to an OU can override anything set higher up for everyone inside it.
HACKTHESOCLesson 68Active Directory and DCs35 / 50

SYSVOL is a distribution channel for admins and attackers

GPO files

SYSVOL

%SystemRoot%\SYSVOL\sysvol\<domain>\Policies. Read at startup, logon and about every 90 minutes.

Logon scripts

NETLOGON

%SystemRoot%\SYSVOL\sysvol\<domain>\scripts holds legacy logon scripts.

Watch Event 5136

Abuse

A GPO with a malicious scheduled task, a modified startup script, or a relinked GPO pushes code to thousands of machines.

Monitor GPO changes (5136, a directory object was modified) and file changes inside SYSVOL and NETLOGON as part of watching Tier 0.

Worked example: what happens at logon

j.smith signs in to WORKSTATION01, then opens a folder on FILESERVER01.

HACKTHESOCLesson 68Active Directory and DCs37 / 50

The Kerberos conversation behind one logon

Two-step pattern: prove identity once for a TGT, then request a narrow ticket per service without retyping the password. That is why DCs can serve enormous organisations.
HACKTHESOCLesson 68Active Directory and DCs38 / 50

Why Event 4769 is the Kerberoasting detection

Normal workday

A modest, spread-out trickle of 4769s for the handful of resources a person actually touches.

Kerberoasting

Any valid account requests tickets for many service accounts in seconds, then cracks them offline. Tickets are encrypted with the service account's hash.

The burst is often for accounts that one ordinary user has no business touching. The shape stands out once you know normal.

Why AD is the crown jewel

The map of where attackers are trying to go.

HACKTHESOCLesson 68Active Directory and DCs40 / 50

The attacker's journey through AD

  1. 1Initial footholdAn ordinary workstation, often via phishing.
  2. 2EnumerationMap the domain with LDAP tools like BloodHound to find a path to privilege.
  3. 3Credential theft and escalationKerberoasting, credential dumping, Pass-the-Hash to climb toward Domain Admin.
  4. 4Domain dominanceReach a DC, extract NTDS.dit or DCSync, persist with a Golden Ticket.
Ransomware, espionage and insider abuse all converge on the same goal: control AD.
HACKTHESOCLesson 68Active Directory and DCs41 / 50

The events that carry most of the signal

  • 4624 / 4625Successful / failed logons.
  • 4768 / 4769TGT and service-ticket requests; 4769 spikes suggest Kerberoasting.
  • 4776NTLM validation; spikes suggest brute force or Pass-the-Hash.
  • 4720A user account was created.
  • 4728 / 4732Member added to a privileged global / local group.
  • 4662 / 5136Directory object access and modification: DCSync, tampering.
Defence is tiering: never expose Tier 0 credentials on lower-tier machines. A Domain Admin hash stolen from a laptop skips the whole journey. MDI watches AD for these techniques.

Detection is almost never "this event is bad".

A 4769 fires for every file-server access and every Kerberoast alike. It is this event, in this volume, from this source, in this sequence, that is abnormal.

Read events in sequences: a 4768 then a burst of 4769, a 4720 then a 4728. You cannot recognise abnormal until you have internalised normal.

Key takeaways

  1. 01Active Directory authenticates, authorizes and manages everything; its centralisation cuts both ways.
  2. 02The DC runs AD, hosts the KDC and stores NTDS.dit with every password hash, so it is Tier 0.
  3. 03Forest > tree > domain > OU; the forest is the security boundary, and RIDs like 512 and 502 mark privilege.
  4. 04A logon is a TGT (4768) then a service ticket per resource (4769); Kerberoasting is a 4769 burst.
  5. 05DCSync is replication from a non-DC; GPO edits in SYSVOL push code to thousands of machines.
  6. 06Defend with tiering and by watching 4624/4625, 4768/4769, 4776, 4720, 4728/4732, 4662/5136.

Check your understanding, question 1 of 3

An attacker controls a Domain Controller in the child domain sales.example.com, in the same forest as example.com. Which unit should the analyst treat as the security boundary when scoping the intrusion?

The forest is AD's real security boundary: owning one domain's DC gives a path to the rest, e.g. Domain Admin toward Enterprise Admin. OUs organise objects, domains still trust each other, and trees only describe a shared namespace.

Check your understanding, question 2 of 3

Event 4768 is logged for a user, followed moments later by one Event 4769 for a file-server resource that the same user just opened. What does this pair of events represent?

4768 logs the AS-REQ that issues a TGT; 4769 logs the TGS-REQ exchanging it for a service ticket. Pre-auth failures are 4771, and Kerberoasting is a rapid burst of 4769s for many service accounts, not one ticket for a resource the user opened.

Check your understanding, question 3 of 3

During triage a domain workstation (not a Domain Controller) sends a directory-replication request to a DC, captured as Event 4662 with replication GUIDs. Which attack does this match?

A non-DC requesting replication is the DCSync signature (T1003.006). NTDS.dit dumping happens on the DC itself, workstations read Group Policy from SYSVOL without replication, and DCShadow shows as a new server or DC object (5137).
