What Active Directory is

Microsoft's directory service: one database that knows every user, computer and resource.

HACKTHESOCLesson 68Active Directory and DCs6 / 86

A directory service: one system that knows everyone

  • Directory serviceA central database of every user, computer, group and resource, that also logs people in and decides what they can access.
  • At scale5,000 employees and 3,000 computers: AD is the one system that knows all of them and holds every account.

  • The analogyA company phone directory that also controls the locks and checks identity at every door.

Three jobs, held apart

A giant, secure company directory combined with a master key system.

Authentication

Proving who you are. When you log into your work laptop, AD verifies you.

Authorization

Deciding what you can do: which files, servers and apps, based on group memberships.

Directory

The single source of truth. Create, reset or disable one account and it takes effect everywhere.

The phone directory lists everyone; AD also controls the locks and checks identity at every door.

Section 2 of 13

The Domain Controller: the server that runs AD

AD is the service and database; the DC is the machine that hosts and runs it.

HACKTHESOCLesson 68Active Directory and DCs11 / 86

Active Directory and the DC are not the same thing

The service

Active Directory

The directory service and its database: the accounts, groups, policies and the rules for using them.

The machine

Domain Controller

A server that runs AD and does the work: authenticating users and answering directory requests. "The DC" is the heart of the Windows network.

Students mix the two up. AD is what; the DC is where. Attacks aim at the DC because that is where AD physically lives.
HACKTHESOCLesson 68Active Directory and DCs12 / 86

What a DC does, minute to minute

  • Authenticates logonsHosts the Kerberos KDC (Key Distribution Center), which issues the tickets used for authentication.
  • Answers directory queries"What groups is this user in?" over the directory protocol LDAP.
  • Enforces policyDistributes Group Policy rules to users and machines.
  • Holds the databaseEvery DC stores a copy of the AD database in NTDS.dit.
  • Shares SYSVOLA network folder of Group Policy files every domain computer reads.
Organisations run more than one DC for reliability, and replication keeps their copies in sync.
HACKTHESOCLesson 68Active Directory and DCs13 / 86

Why there is more than one DC, and what that means

  1. 1ReliabilityOrganisations run several DCs so that if one fails, others keep authenticating users.
  2. 2Each holds a full copyEvery DC stores its own copy of the AD database, NTDS.dit.
  3. 3Replication keeps them equalA change on one DC, such as a password reset, is copied to all of them within minutes.
  4. 4So every DC is a targetAny one of them holds every account's password hash, so each needs Tier 0 protection.
A common blind spot is the forgotten branch-office DC. It holds the same database as the one in the main datacenter.
HACKTHESOCLesson 68Active Directory and DCs14 / 86

Why the DC is the ultimate prize

NTDS.dit

Every object in the domain, and the password hashes of every account, administrators included.

DCSync, NTDS dumping

Read the file, or trick a DC into handing over its contents, and you hold the credentials to the whole organisation.

Tier 0

The most privileged, most protected asset class. Anything that runs code on a DC can rewrite the rules for everyone.

Compromise a Domain Controller is functionally the same as compromise the whole domain. Memorise that.
HACKTHESOCLesson 68Active Directory and DCs15 / 86

The most privileged, most protected asset class. Anything that runs code on a DC or holds Domain Admin can rewrite the rules for everyone.

HACKTHESOCLesson 68Active Directory and DCs18 / 86

OUs: where policy and delegation actually happen

  • Containers inside a domainAn OU might hold all Finance accounts, or all laptops in the London office.
  • Group Policy targets OUsSettings can be pushed to just the machines in one OU.
  • Admin rights are delegated per OUA regional admin can manage only their own OU, not the whole domain.
  • Why the SOC caresWhoever controls an OU's policy or delegation controls every object inside it.
OUs look like folders, but they are a control boundary for policy and administration, not a security boundary like the forest.
HACKTHESOCLesson 68Active Directory and DCs19 / 86

What a mid-size company's AD might look like

  • OUs matter: Group Policy is applied to them and admin control is delegated at them
  • Blast radius: a Domain Admin in one domain can often reach Enterprise Admin
  • Own any domain's DC and you have a path to the rest of the forest
Knowing whether you face one domain or a multi-domain forest shapes how far you assume an intrusion can reach.
HACKTHESOCLesson 68Active Directory and DCs20 / 86

How far can one intrusion reach?

Single domain

Most small and mid-size organisations. A compromised DC means the whole domain: every account and computer that trusts it.

Multi-domain forest

The forest is the boundary. A Domain Admin in one domain can often be leveraged toward Enterprise Admin; any DC is a path to the rest.

In scoping, find out early which shape you face. It changes how far you must assume the attacker can reach.

Section 4 of 13

Users, groups, computers and SIDs

The records AD holds are called objects.

HACKTHESOCLesson 68Active Directory and DCs22 / 86

The objects that matter most

Users

A person's account: username, password hash, groups, attributes. Service accounts serve apps, often with strong privileges and rarely changed passwords.

Computers

Every domain-joined machine has a computer object and its own account to authenticate to the domain.

Groups

Grant permissions to many at once. Security groups assign permissions, distribution groups are email lists. Scopes: domain-local, global, universal.

Domain Admins, Enterprise Admins, Administrators, Schema Admins: any membership change (4728/4732) is a high-value event.

Rarely changed service-account passwords are the weakness behind Kerberoasting. Adding to Domain Admins is one of the first things an attacker does.
HACKTHESOCLesson 68Active Directory and DCs23 / 86

Why service accounts are favourite targets

  1. 1They serve applicationsUser objects used by apps and services, not people.
  2. 2They hold strong privilegesOften far more access than an ordinary user needs.
  3. 3Passwords rarely changeSet once at deployment and left for years.
  4. 4Their tickets carry their hashService tickets are encrypted with the account's password hash, the weakness behind Kerberoasting.
Strong privilege plus a stale password plus a crackable ticket is why service accounts appear in so many intrusion reports.
HACKTHESOCLesson 68Active Directory and DCs24 / 86

Reading a SID piece by piece

Golden Tickets forge SIDs and SID History abuse hides privilege in them. Recognising -500, -512, -519 tells you severity before you resolve the name.
HACKTHESOCLesson 68Active Directory and DCs25 / 86

...-512

Domain Admins

A domain group: the domain identifier plus RID 512.

The built-in group on each machine. 32 is the local Builtin authority, not a domain.

This nesting is why a stolen Domain Admin credential opens every workstation and server, not just the DC.

FSMO roles: five jobs no two DCs share

Exceptions to multi-master replication: exactly one holder per scope.

HACKTHESOCLesson 68Active Directory and DCs29 / 86
Any DC can accept a change, except for five jobs that only one DC may hold.

Replication is multi-master. A few operations are so sensitive to conflicts that exactly one DC in the right scope performs each.

These five exceptions are the FSMO roles: Flexible Single Master Operations.
HACKTHESOCLesson 68Active Directory and DCs30 / 86

The five Flexible Single Master Operations roles

RoleScopeWhat breaks without it
Schema MasterOne per forestNobody can extend or modify the AD schema
Domain Naming MasterOne per forestCannot add or remove a domain from the forest
RID MasterOne per domainDCs run out of RIDs, eventually no new security principals
PDC EmulatorOne per domainTime sync anomalies, password/lockout inconsistencies
Infrastructure MasterOne per domainCross-domain group membership references go stale
Every domain in a multi-domain forest has its own RID Master, PDC Emulator and Infrastructure Master.
HACKTHESOCLesson 68Active Directory and DCs31 / 86

Two roles per forest, three per domain

Forest-wide

One holder each for the entire forest.

  • Schema Master
  • Domain Naming Master

Domain-wide

Every domain in a multi-domain forest has its own holder of each.

  • RID Master
  • PDC Emulator
  • Infrastructure Master
A three-domain forest therefore has 2 + 3 x 3 = 11 role assignments to know about.
HACKTHESOCLesson 68Active Directory and DCs32 / 86

The PDC Emulator: the role analysts meet most

  • Authoritative time sourceEvery DC and workstation ultimately syncs its clock to it.
  • Password changes firstChanges and lockouts are processed here first, so a new password works before replication catches up.
  • Legacy emulationStill emulates a Windows NT4 Primary Domain Controller for compatibility.
  • Security consequenceKerberos tickets are time-sensitive, so a wrong PDC clock breaks authentication domain-wide.
A good example of an obscure admin role with very visible security effects: lockout storms and Kerberos failures often trace back here.
HACKTHESOCLesson 68Active Directory and DCs33 / 86

Find the FSMO holders, and know the PDC Emulator

  • PDC Emulator: authoritative time source; processes password changes and lockouts first
  • A wrong PDC clock cascades into Kerberos failures domain-wide: tickets are time-sensitive
  • Seizing a role is emergency recovery; flag it outside a maintenance window
PDC Emulator and RID Master holders give outsized leverage, so they belong in Tier 0.

What each DC actually knows

A DC in sales.example.com does not hold the users of example.com. So how do you search the whole forest at once?
HACKTHESOCLesson 68Active Directory and DCs36 / 86

The Global Catalog: partial, read-only, forest-wide

Every object

A GC holds a replica of every object in every domain of the forest.

Partial

Only a subset of attributes, the useful search fields such as name and email, not every field.

Read-only

A lookup copy. Any DC can also be configured to serve as a GC.

The GC answers "where in the forest is this object?" without querying every domain one by one.
HACKTHESOCLesson 68Active Directory and DCs37 / 86

The Global Catalog searches every domain at once

A GC holds a partial, read-only replica of every object in every domain, on ports 3268 (plaintext) and 3269 (LDAPS). It powers UPN logon into child domains, address-book lookups, Universal Group expansion, and BloodHound forest recon.
HACKTHESOCLesson 68Active Directory and DCs38 / 86

What the Global Catalog makes possible

  • UPN logonSigning in as user@example.com when the user actually lives in a child domain.
  • Address-book lookupsExchange and Outlook search the whole forest through it.
  • Universal group expansionUniversal groups can hold members from any domain; only the GC can expand them at logon.
  • Forest reconBloodHound targets it: one GC query surfaces objects across every domain.
Ports 3268 and 3269 are deliberately separate from 389 and 636, so a client chooses forest-wide or domain-local search explicitly.

Section 7 of 13

Sites, subnets and replication topology

Replication over a slow WAN should not behave like a fast local switch.

HACKTHESOCLesson 68Active Directory and DCs40 / 86

Logical structure versus physical structure

Logical

Forests, domains and OUs: how objects are organised for administration, regardless of where machines sit.

Physical

Sites and subnets: a map of the real network, so replication over a slow WAN does not behave like a fast local switch.

Everything so far was logical. Sites exist for performance, but they also define what normal replication traffic looks like.
HACKTHESOCLesson 68Active Directory and DCs41 / 86

How a branch user ends up at the branch DC

  1. 1Register subnetsAdmins register each IP subnet under a site, e.g. 10.9.0.0/16 under Branch-London.
  2. 2Associate by IPEvery DC and client is placed in a site automatically from its IP address.
  3. 3Log on locallyThe client is pointed to its own site's DC instead of one across the world.
  4. 4Spare the WANFaster logons and far less replication traffic on expensive links.
If a London user suddenly authenticates against a New York DC, ask why: a down local DC or a misregistered subnet is normal; an attacker choosing a DC is not.
HACKTHESOCLesson 68Active Directory and DCs42 / 86

Intra-site versus inter-site replication

A site groups well-connected subnets; the KCC builds the topology on every DC.

Within a site

A tightly connected ring. Changes typically propagate within about 15 seconds of a notification.

Between sites

An elected ISTG designates bridgehead servers that replicate over site links on a schedule, e.g. every 3 hours.

Site links carry a cost (cheaper preferred) and a replication schedule. Clients log on to their local site's DC.

Sites mean a branch user authenticates against the branch DC instead of crossing a WAN link.
HACKTHESOCLesson 68Active Directory and DCs43 / 86

Normal topology is your baseline for DCSync

  • Replication uses RPC on 135 plus a high ephemeral range: expected, not alertable
  • DCSync makes an attacker machine impersonate a DC and request password data
  • A workstation issuing replication requests is not WAN traffic: it is DCSync
Know which hosts are really DCs and which sites and links exist, so replication-shaped traffic from anywhere else stands out.
HACKTHESOCLesson 68Active Directory and DCs44 / 86

Who should be replicating with a DC?

SourcePatternVerdict
DC01 to DC02, same siteRPC replication within about 15 seconds of a changeExpected: intra-site ring
DC03 bridgehead, across the site linkReplication on the link schedule, e.g. every 3 hoursExpected: inter-site
An ordinary workstationDirectory replication (DRSUAPI) requests to a DCDCSync: alert and investigate
The protocol is identical in all three rows. Only the source differs, which is why knowing the real DC list is the foundation of this detection.

LDAP, Kerberos, DNS, GPO and replication

Recognise each protocol and its port to read what a Windows network is doing.

HACKTHESOCLesson 68Active Directory and DCs46 / 86

The protocols behind one laptop's morning

  1. 1Find a DCDNS SRV record lookups on port 53 locate the domain's DCs.
  2. 2Prove identityKerberos on port 88: the KDC issues a TGT.
  3. 3Ask the directoryLDAP on 389 answers questions such as group membership.
  4. 4Pull policySMB on 445 reads GPO files from the DC's SYSVOL share.
  5. 5DCs stay in syncMeanwhile DCs replicate over RPC, bootstrapped on port 135.
If DNS is broken, AD stops working, which is why DCs usually run DNS themselves.
HACKTHESOCLesson 68Active Directory and DCs47 / 86

The anatomy of the Windows network

  • LDAP: how you askQuery and update AD on 389 (636 encrypted). BloodHound uses it to map paths to Domain Admin.
  • Kerberos: how you prove yourselfPort 88. The KDC issues a TGT, then a ticket per service. NTLM, the older fallback, is challenge-response on each connection, not ticket-based.
  • DNS: how you find the DCsClients locate DCs via SRV records. Broken DNS means broken AD.
  • GPO: how rules are enforcedSettings applied to linked OUs, files pulled from SYSVOL. Edit a wide GPO, hit thousands of machines.
  • Replication: how DCs agreeMulti-master: a change on any DC flows to all. DCSync impersonates it.
Nearly every AD attack is an abuse of one of these normal mechanisms.
HACKTHESOCLesson 68Active Directory and DCs48 / 86

Kerberos versus NTLM: two ways to prove identity

Default, port 88

Kerberos

Ticket-based. Prove identity once to the KDC for a TGT, then request a narrow ticket per service. Events 4768 and 4769.

Older fallback

NTLM

Challenge-response on each connection, not tickets. Domain validation logs 4776; spikes suggest brute force or Pass-the-Hash.

Students often meet 4776 before the NTLM lesson. The key is that NTLM has no ticket, so the hash itself is what gets reused in Pass-the-Hash.

How domains vouch for each other, and how to address any object.

Trust types and how far they reach

TrustHow it worksTransitive?
Parent-childAuto-created for a child domain in the same treeYes, two-way by default

ForestConnects two entire separate forestsCan be

Transitive trust lets compromise ride onward; non-transitive grants no further path. Direction: A trusts B lets B's users reach A's resources, not the reverse.
HACKTHESOCLesson 68Active Directory and DCs53 / 86

Two questions to ask about any trust

Transitive?

Transitive: compromise can ride onward to domains beyond the one directly trusted. Non-transitive (external trust): a dead end.

Which direction?

A one-way trust where A trusts B lets B's users reach A's resources, not the reverse. Two-way works both ways.

In blast-radius work, draw the trusts as arrows. Compromise flows from the trusted side into the trusting side.
HACKTHESOCLesson 68Active Directory and DCs54 / 86

Functional levels in four facts

  • What it recordsThe minimum Windows Server version every DC in the domain or forest runs, e.g. Windows Server 2016.
  • What raising unlocksNewer features such as stronger Kerberos protections and finer-grained password policies.
  • One-wayOnce raised, a DC running an older Windows Server version can no longer be added.
  • Why a defender looksA quick gauge of how modern the domain's authentication protections are.
A forest still at an old functional level is a sign that newer Kerberos hardening may not be available.
HACKTHESOCLesson 68Active Directory and DCs55 / 86

  • sAMAccountName = legacy short logon name, e.g. jsmith
  • userPrincipalName = email-style logon name, e.g. j.smith@example.com
  • objectGUID never reused; objectSID is the SID from earlier
Functional levels record the minimum Windows Server version on every DC. Raising is one-way and gauges how modern the Kerberos protections are.

Group Policy order and SYSVOL/NETLOGON

Predictable GPO behaviour, and the shares that deliver it.

HACKTHESOCLesson 68Active Directory and DCs58 / 86

LSDOU: later settings win conflicts

  1. 1LocalGroup Policy stored on the machine itself.
  2. 2SiteGPOs linked to the machine's AD site.
  3. 3DomainGPOs linked at the domain level.
  4. 4OUOutermost OU down to the one directly containing the object. Applied last, so normally final.
An admin who can link a GPO to an OU can override anything set higher up for everyone inside it.
HACKTHESOCLesson 68Active Directory and DCs59 / 86

Loopback processing: the computer decides

Normally user settings follow the user account's OU. Loopback, set on the computer, changes that.

Merge mode

The computer's user-settings GPOs apply in addition to the user's normal ones; computer settings win conflicts.

Replace mode

The user's normal GPOs are ignored entirely; only the computer's GPOs apply.

Used for shared or kiosk machines such as lab or conference-room PCs, where the machine's location should dictate the experience.
HACKTHESOCLesson 68Active Directory and DCs60 / 86
Whoever can link a GPO to an OU can override anything set higher up.

OU-level GPOs apply last, so they normally have the final word for every user and computer inside that OU.

That makes GPO link and edit rights a Tier 0 concern, not an IT convenience.
HACKTHESOCLesson 68Active Directory and DCs61 / 86

SYSVOL is a distribution channel for admins and attackers

GPO files

SYSVOL

%SystemRoot%\SYSVOL\sysvol\<domain>\Policies. Read at startup, logon and about every 90 minutes.

Logon scripts

NETLOGON

%SystemRoot%\SYSVOL\sysvol\<domain>\scripts holds legacy logon scripts.

Watch Event 5136

Abuse

A GPO with a malicious scheduled task, a modified startup script, or a relinked GPO pushes code to thousands of machines.

Monitor GPO changes (5136, a directory object was modified) and file changes inside SYSVOL and NETLOGON as part of watching Tier 0.

Two-step pattern: prove identity once for a TGT, then request a narrow ticket per service without retyping the password. That is why DCs can serve enormous organisations.

Why Event 4769 is the Kerberoasting detection

Normal workday

A modest, spread-out trickle of 4769s for the handful of resources a person actually touches.

Kerberoasting

Any valid account requests tickets for many service accounts in seconds, then cracks them offline. Tickets are encrypted with the service account's hash.

The burst is often for accounts that one ordinary user has no business touching. The shape stands out once you know normal.
HACKTHESOCLesson 68Active Directory and DCs68 / 86

The shape of a Kerberoasting burst

  • TimingMany 4769 events within seconds, not spread across a workday.
  • TargetsTickets for many service accounts, often ones this user has no business touching.
  • RequesterAny valid domain account will do, so the source is usually an ordinary user.
  • AfterwardSilence: cracking happens offline with no further contact with the DC.
Because the cracking is offline, the 4769 burst may be the only evidence on the DC. Catch the request pattern or miss the attack.

Tiering: keep Tier 0 credentials off lower tiers

Tier 0

DCs, Domain Admin accounts, and anything that can control them.

The cardinal rule

Never expose Tier 0 credentials on lower-tier machines such as ordinary laptops.

Why

A Domain Admin hash stolen from one laptop skips the whole journey straight to dominance.

Key takeaways

  1. 01Active Directory authenticates, authorizes and manages everything; its centralisation cuts both ways.
  2. 02The DC runs AD, hosts the KDC and stores NTDS.dit with every password hash, so it is Tier 0.
  3. 03Forest > tree > domain > OU; the forest is the security boundary, and RIDs like 512 and 502 mark privilege.
  4. 04A logon is a TGT (4768) then a service ticket per resource (4769); Kerberoasting is a 4769 burst.
  5. 05DCSync is replication from a non-DC; GPO edits in SYSVOL push code to thousands of machines.
  6. 06Defend with tiering and by watching 4624/4625, 4768/4769, 4776, 4720, 4728/4732, 4662/5136.

The forest is AD's real security boundary: owning one domain's DC gives a path to the rest, e.g. Domain Admin toward Enterprise Admin. OUs organise objects, domains still trust each other, and trees only describe a shared namespace.
